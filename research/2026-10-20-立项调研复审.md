## 0. 摘要

**建议做，但先缩到一条能用的 Windows 截图问答，并用少量真实题图做开工闸门。** 不建议按现有文档的完整 P0 一次性铺开，也不建议在第一条回答跑通之前做字幕流水线、资料库、安卓或番茄钟。

若这套工具要服务的是 2027 年招生的全国硕士研究生招生考试初试，初试时间是 **2026 年 12 月 19 日至 20 日**（[教育部规定](http://www.moe.gov.cn/srcsite/A15/moe_778/s3261/202609/t20260923_1451734.html)、[新华网 2026-09-24](https://www.news.cn/20260924/8cd76910a0154e30945718fc5beaf534/c.html)）。从本复审日算起大约还有 60 天。仓库里还没有应用代码。按下面的工作量假设，缩范围之后的截图闭环有机会在考前进入个人试用；字幕、知识库和安卓赶不上这一考季。仓库没有写明用户是否参加这一轮考试，所以上面只是条件，不是已确认的截止日期。

三条最大风险：

1. **960×720 网课画面能不能被 `deepseek-flash` 读对并算对，仍然完全没有实测。** 官方确认 Flash 支持识图、Pro 不支持识图。X 检索窗内没有 DeepSeek 公式截图实测；只有个别用户说 Flash 的数理内容不可用，样本极小，不能当成结论。
2. **Windows 执行层绑定的就是 DeepSeek 官方的 DeepSeek Harness（DSH），当前仍是预发布 `0.2.1-rc.2`。** 空会话烟测只证明宿主能起来。默认真包含编码 shell；两个插件未激活；SDK 的 `latest` 标签仍是旧的 `0.0.1-rc.1`。X 上讨论的 DSH 是这同一个产品，不是另一个可替换的学习框架。
3. **文档范围大于第一个可用闭环。** 需求、原则和 MVP 计划对「首版」的边界不一致。安卓历史接续、Office、目录跟踪和检索被写进了很靠前的工作包，而用户要的第一件事是：暂停本地视频、框选题目、得到完整讲解、能追问。

建议的下一步，按顺序，不并行铺开后续阶段：

1. 用用户自己截好的 8–12 张题图（不要从视频自动抽帧）在 DeepSeek 官方聊天或一次性脚本里问 `deepseek-flash`，事先写好「读对了 / 算对了」的判定。这一步失败就先停应用开发。
2. 只做 P0-01 骨架：真实前后端入口，健康状态诚实标出 Harness 与字幕尚未接入。
3. 固定 Harness `0.2.1-rc.2` 制品与哈希，做一个没有 shell、没有任意图片读取、没有网页 Search/Fetch 的学习 preset，打通一张用户图的真实流式回答和生成中停止。
4. 再做原地播放、用户确认选区、选区进输入框、保存并重开。字幕和知识库保持未就绪，不阻塞这条路径。

### 1.2 路线本身

现行决定写在 AGENTS.md 和技术选型方案里，本复审不改这条决定：

Windows 定制浏览器界面 → 项目业务后台与自有数据 → Harness 执行宿主及学习插件 → DeepSeek 官方 API。本地转写走独立 Python worker。安卓以后独立，不运行完整 Harness。视频问答的信息顺序是用户确认的截图和文字，不足时才读相关字幕，仍不足才查知识库。模型不能自动补视频画面，这条约束要落在工具白名单和执行 guard 上。

## 2. 现有文档审查

### 2.1 对 2026-10-19 立项报告的判断

**同意「建议立项，先做受控的 Windows 验证，再做视频截图问答」，也同意不要改回无 Harness 主线。** 报告把证据分成 E0–E4，没有把空会话或 60 秒 ASR 写成产品通过，这个纪律应当保留。

同意的具体判断：

- 五个开源整套产品不能直接变成这条学习闭环。对照表和许可差异写在 `research/立项调研-现有项目与复用对照.md`，本次没有重装那些产品。
- 业务数据必须留在本项目，Harness 会话只做映射。安卓旧回答不能在同步后重跑。
- 用量要保留 raw usage 再归一化。Harness 的 `inputTokens` 与 Chat Completions 的 `prompt_tokens` 不是同一个减法。缺失不能记成 0。
- ASR 的 DLL 搜索失败和时间轴越界是真实缺口，字幕阶段必须单独验收。
- 费用三情景是假设算术，不是月费预测。本次按现行人民币价复算了报告里的「常规、全空闲」例子，得数仍是 31.76832 元，四舍五入 31.77 元。价格页若再变，这组数字就失效。
- 个人使用阶段不必上分布式数据库，原件原地引用是对的。

需要收紧或质疑的判断：

1. **「已有足够的组件和本机资源证据支持继续推进」只够支持开工，不够支持相信产品有用。** 价值假设是：用户从这节 960×720 网课里框出的公式和图形，Flash 能读懂并给出可用的完整解答。这件事位于 E4，仓库明确没做。组件烟测通过不能代替它。开工闸门应放在少量真实题图上，而不是放在再写一层适配器上。
2. **MVP-A 能复用的 Harness 能力比文档篇幅所暗示的要少。** Office 转换、SenseVoice 录音 ASR、会话 FTS、官方 UI 插件都不在第一条截图问答的关键路径上。第一条路径需要的是：固定版本的宿主、一张用户图、真实流、生成中停止、用量和取消。插件净收益要等这条路径有了对照再谈，现在写百分比没有根据。
3. **P0-05 安卓历史接续不该挡住第一次可用回答。** 契约本身值得留样例，但把它放进 P0 退出条件，会在用户还不能提问时先做跨端状态机。首版范围写的是 Windows。
4. **竞品章节回答的是「要不要再部署一套 RAG 产品」，没有回答「这个人现在用现成软件能不能学」。** 第 3 节补上个人用户真正会打开的工具，以及 X 上这一个月的讨论。
5. **npm `latest` 的事实已经变了。** 10 月 19 日报告写 `@deepseek-ai/dsh` 的 `latest` 是 `0.2.0-rc.2`、`next` 是 `0.2.1-rc.2`。本次于 2026-10-20 读取 registry：`latest` 与 `next` 都已是 `0.2.1-rc.2`，`modified` 为 2026-10-19T06:29:58Z。同一天标签就会动。版本仍必须钉死哈希，不能改口说「现在跟 latest 就安全了」。SDK 客户端的 `latest` 仍是 `0.0.1-rc.1`，`next` 才是 `0.2.1-rc.2`，混装风险还在。

还有三处容易在实现时踩坑，现有总报告点到了，但没有写成硬约束：

- **图片只能出现在 user 消息里。** 本次抓取的英文视觉说明写明：`system` 或 `assistant` 消息里的图片会返回 400。Anthropic 兼容接口同样适用。跨端接续若把历史截图注入成 assistant 内容，会直接失败。历史题图必须放在 user 内容块里。来源：[Vision](https://api-docs.deepseek.com/guides/vision/)。
- **`detail=low` 会先缩到 512×512。** 同一页写明 `low` 先缩小；`original` / `high` 保留原图后再按像素规则缩放；单图上限 1024 token。公式上下标经不起这层缩小。学习 preset 不能沿用会压细节的默认值，并且要防 Harness 的 sharp 规范化再压一次。清晰度仍未实测。
- **960×720 落在视觉文档两个缩放档之间。** 文档写总像素低于约 544×544 的图会放大，更大的图会缩到约 1300×1300 的像素量。960×720 约 69 万像素，高于 544×544、低于 1300×1300。实际会不会被放大，本次没有调用 API，不能给出 token 数。源视频本身只有 960 宽，框选小区域也不会增加像素。这是素材限制，不是再加一个 OCR 模型就能在文档里消掉的。

### 2.3 过度设计与被低估的风险

过度设计主要在「第一条可用路径」之前堆了完整产品的数据面：执行代次、安卓 U2/A2 注入、Tailscale、sqlite-vec、Docling、LibreOffice Kit、watchdog、双层摘要。这些作为后续边界是有用的，作为 P0 退出条件会推迟用户第一次提问。开发规范要求先做最小纵向闭环，现有 P0 表比这个要求宽。

被低估的地方：

- **数学错误会以确定的语气出现。** 原则写了速度优先、不默认第二轮校验。这符合「默认完整解答」。X 上的个例和教育研究帖说明，完整解答若没有「这一步对照哪张图、哪几秒字幕」的依据，用户很难发现错步。依据可以是程序附上的来源，不必默认再调一次模型。
- **三套运行时的日常维护。** 浏览器、FastAPI、Harness 预发布宿主，字幕阶段再加 GPU worker。对个人工具，升级一次 RC 就可能让学习流程停摆。10 月 17 日起 GitHub 讨论区有多条 Windows 桌面版 0.2.1 启动崩溃报告（见第 4 节）。那是 Electron 桌面壳，不是本次已烟测的 wheel 内 Web Host，但说明同一版 Windows 表面并不均匀稳定。
- **11 月 1 日的 Search/Fetch 计费。** 今天距北京时间 2026-11-01 00:00 只有十余天。默认编码 profile 若带上网页工具，实验请求会在该日之后按次计费。学习 preset 必须显式关掉，并在出站记录里核对。这一点 10 月 19 日报告已写，这里因为日期更近而提高优先级。

| Buzz、faster-whisper | 本地转写与字幕导出 | 不是问答产品。本项目字幕阶段仍应直接用引擎，而不是嵌入 Buzz 的 Qt 队列 | 仓库已有对照；Buzz 仓库：[chidiwilliams/buzz](https://github.com/chidiwilliams/buzz) |
| 小猿搜题、作业帮、Gauth 一类拍照搜题 | 用题库或通用讲题给出步骤 | 对这节网课的板书和老师讲法没有时间点，也不是用户自己的资料库 | 本次只看到产品类别被提及，没有做评测 |

**判断：** 若只是「这道题怎么做」，现成的 DeepSeek 识图加系统截图已经够用，而且今天就能用。本项目值得做的部分是把本地长视频、用户确认的选区、时间点和以后的字幕/资料收成一次操作，并保证模型看不到未提交的画面。这个差别是工作流，不是另一个更会做题的模型。

仓库 10 月 19 日对照的 AnythingLLM、Open WebUI、Open Notebook、SurfSense Local、Buzz，结论仍然成立：可以借鉴附件、任务检查点和字幕格式，不应该再常驻第二套聊天或 RAG 平台。该对照没有覆盖上一张表里的个人工具。两张表一起看，才够决定「做不做」。

### 3.3 这对「该不该做」意味着什么

X 上的缺口与仓库的产品判断同向：字幕流水线已经有很多开源做法；通用截图 AI 也已经有人用；缺的是本地视频时间点、用户确认选区和后续个人资料放在同一次学习里。这个差异化成立，但它成立的前提是 Flash 能看懂用户的题图。若看不懂，集成播放器也不会比「截图粘贴到聊天框」更好。

因此替代方案的用法是：

- 闸门通过之前，学习继续用播放器加 DeepSeek 官方识图。不要等自研软件才开始刷题。
- 闸门通过之后，自研只替换切换和选区这两步，不先替换字幕和资料库。
- 不采用「再装 AnythingLLM / Open WebUI 当后端」的路线。那会变成两套会话。

## 4. 技术可行性与关键风险

### 4.1 DeepSeek API：本次按官方文档核实

X 汇总里的价格互相矛盾，有人民币和美元混用，也有一批文案高度相似的「Vision-Exp 一折」帖。那些帖不作为依据，例如 [@NOT7717，2026-09-23](https://x.com/NOT7717/status/2103189164590301341) 一类。下面只写本次打开官方页面读到的内容。

2026-10-20 抓取的中文价格页 [模型 & 价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing)：

| 项 | 官方写法 |
| --- | --- |
| 模型名 | `deepseek-flash`，版本 DeepSeek-V4.1-Flash-1017 |
| 识图 | Flash 支持；`deepseek-v4-pro`（DeepSeek-V4-Pro-0813）不支持 |
| 旧名 | `deepseek-v4-flash`、`deepseek-v4-flash-vision-exp` 仍可调用，但由 1017 提供服务，按 Flash 计价 |
| 上下文 / 最大输出 | 1M / 384K |
| Flash 人民币价，每百万 token | 缓存命中输入：空闲 0.02 元，高峰 0.04 元；未命中输入：空闲 1 元，高峰 2 元；输出：空闲 4 元，高峰 8 元 |
| 高峰 | 北京时间周一至周五 9:00–12:00、14:00–18:00，不含中国法定节假日；周末和法定节假日全天按空闲 |
| Search / Fetch | 各每 1,000 次成功请求 5 元。经 DeepSeek Harness、Claude Code 或 Codex 触发的服务端调用，北京时间 2026-11-01 00:00 起按次计费 |

同日英文页 [Models & Pricing](https://api-docs.deepseek.com/quick_start/pricing) 的模型事实相同。Flash 美元价是：缓存命中输入空闲 $0.003 / 高峰 $0.006，未命中输入空闲 $0.15 / 高峰 $0.30，输出空闲 $0.60 / 高峰 $1.20。Search / Fetch 为每 1,000 次成功 $0.75。中英文是两套标价，不是用汇率换算的同一张表。本项目记账用人民币页。X 上与官方页一致的转述可以保留为旁证，例如 [@ethanzhang_web3，2026-10-19](https://x.com/ethanzhang_web3/status/2112077202468782317) 写的闲时输入 $0.15、输出 $0.6。[@cccc2024cccc，2026-10-17](https://x.com/cccc2024cccc/status/2111488593973678438) 在纠正别人的输出价，说明帖子之间会算错；他的具体数字本次不另作依据。

[@taiyanghere，2026-10-08](https://x.com/taiyanghere/status/2108074998409957646) 称靠缓存和错峰把实际成本压到约每百万 token 0.13 元。这是个人账单叙述，不是官方单价，不能写进预算。[@NFT_Chen，2026-09-23](https://x.com/NFT_Chen/status/2102637791972900931) 与 [@_FORAB，2026-10-08](https://x.com/_FORAB/status/2108001021150822734) 比较了其他厂商价格。那些型号和标价本次没有打开对应官方页，不采用。

视觉限制以本次抓取的 [Vision](https://api-docs.deepseek.com/guides/vision/) 为准，仓库 10 月 19 日的转述仍然符合该页：

- 格式为 JPEG、PNG、GIF、WebP，按文件内容识别。
- 单图最多 1024 token；多图分别计算。像素低于约 544×544 会放大，更大的图会缩到约 1300×1300 的像素量。
- `detail=low` 先缩到 512×512。公式路径不要用 low。
- 图片放在 user 消息。system / assistant 中的图片返回 400。
- 请求体约 48 MiB；单张 base64 或外链图片约 32 MiB。本地文件用 base64 或 Files API，不要把 Windows 路径或局域网地址交给 DeepSeek 去下载。

思考模式官方默认开启。速度优先的基线仍应显式关闭，再用同一批题图和 `low` 对比。关闭思考是否损伤数学正确率，没有数据。

**验证方法：**

1. 用户从播放器或现有截图工具自行框选 8–12 张图，覆盖小公式、整板、图形、多小问。记录原图像素。不要为了测试自动抽帧。
2. 同一张图以 `detail=original`、thinking 关闭调用 `deepseek-flash`。事先写下可读性（符号、上下标、图形）和与已知解答是否一致。官方聊天里手测可以当作第一轮；自动化脚本只能在本机已有密钥的环境跑，密钥不入库。
3. 若原图读不对，再试同一选区的放大导出（只放大用户选区，不补画面），以及「本地公式 OCR 成 LaTeX 再发给 Flash」的对照。Pro 不能直接看图，所以 Pro 只适合作为文本对照，不能作为截图主模型。
4. 保存 raw usage、响应里的模型标识和墙钟时间。一次样本不写成准确率。

X 窗内没有 DeepSeek 公式截图的实测帖，所以没有任何帖子能填上这个洞。[@realduanyj，2026-10-12](https://x.com/realduanyj/status/2109705159060205807) 说 Flash 做数理时错误很多并已改用其他模型，浏览量个位数，只说明存在负面个例。[@GaoXiaoxiao2022，2026-10-07](https://x.com/GaoXiaoxiao2022/status/2107722997759140260) 则认为 DeepSeek 的数学推理有长处，复杂任务另用更贵的模型。两帖方向相反，都不能代替这节网课的题图。

旧文「用 AI 做考研数学一，我得了 136 分」（[网易转载，2024-12-30](https://c.m.163.com/news/a/JKM1CFEQ054535JN.html)）测的是当时的深度思考和其他产品，不是今天的 V4.1-Flash-1017，也不测 960×720 板书。只保留一个仍有用的现象：多题挤在一张图上时，当时的识别和解题明显差于单题。本项目「一张选区一道题」与这个现象同向，但仍要实测。

### 4.2 Harness：X 上的 DSH 与仓库里的 0.2.1rc2 是同一个产品

官方价格页把产品名写成 “DeepSeek Harness”，并把它与 Claude Code、Codex 并列，作为会触发服务端 Search/Fetch 的客户端。GitHub 仓库是 [deepseek-ai/deepseek-harness](https://github.com/deepseek-ai/deepseek-harness)。2026-10-17 的预发布 `v0.2.1-rc.2` 指向提交 `687f282`，说明里包含对 DeepSeek-V4.1-Flash-1017 以及 Search/Fetch 的适配（[Releases](https://github.com/deepseek-ai/deepseek-harness/releases)）。npm 包名是 `@deepseek-ai/dsh`。PyPI 的 `deepseek-harness-runtime-bin==0.2.1rc2` Windows wheel 仍在，文件名与大小 83,860,784 字节、SHA256 前缀 `d38c18f5117859fe` 与仓库 10 月 19 日记录一致。

X 帖 [@NFT_Chen，2026-10-02](https://x.com/NFT_Chen/status/2105810362201432464) 说 Claude Code 的 Mods 在向 “DeepSeek Harness”（DSH）靠拢。帖子讨论的是这个官方编码代理产品，不是另一个同名学习框架。仓库锁定的 `0.2.1rc2` 就是该产品的当前预发布版本之一。

由此带来的风险：

| 风险 | 已看到的事实 | 验证方法 |
| --- | --- | --- |
| 预发布接口继续变 | 仓库仍是 developer preview；10 月 19 日 `dsh` 的 `latest` 还被记成 `0.2.0-rc.2`，10 月 20 日 registry 的 `latest` 已是 `0.2.1-rc.2` | 锁定版本、wheel SHA256、profile 和插件闭包。每次升级先跑空会话，再跑一张固定题图。不使用浮动 `latest` |
| 装错 SDK | `@deepseek-ai/dsh-sdk-client` 的 `latest` 仍是 `0.0.1-rc.1`，`next` 才是 `0.2.1-rc.2`（本次读取 registry，`modified` 2026-10-17T08:39:03Z） | 若走 SDK 对照路线，三份版本一起钉死。空会话已经说明 Web Host 路径不依赖这份 SDK |

### 4.3 本地 ASR、公式与 Windows 交付

**ASR。** 方向仍是独立 Python worker 加 faster-whisper，不把 Harness 实验性 SenseVoice 当成网课流水线。X 窗内没有 SenseVoice 的 Windows 实测帖。faster-whisper 被多条帖子当成默认本地方案，见 3.2。另外：

- [@awe0_io，2026-10-07](https://x.com/awe0_io/status/2107679439190437933) 称 whisper.cpp 实时字幕里，小模型快但专业词差，small 以上更准但更慢。
- [@tongze13159，2026-10-18](https://x.com/tongze13159/status/2111875035782934982) 推荐 Buzz，作者自己写了未实测。
- [@laogeai，2026-10-13](https://x.com/laogeai/status/2110153151311643040) 介绍 whisper.cpp 可出带时间戳的字幕。
- [@xiaoxian_ai，2026-10-18](https://x.com/xiaoxian_ai/status/2111687863427539124) 称本地 whisper 字幕多出一个原声没有的词，且没有报错。
- [@aopesyaole，2026-10-12](https://x.com/aopesyaole/status/2109638575025467786) 称 Whisper base 把 2026 识别成 2016，术语表没有修好。

这些帖与仓库里的 60 秒结果放在一起，只支持两件事：本地转写可行；文本和时间轴都不能未经验收就拿去跳转或送进解答。仓库里的越界 end（61.43 / 62.65 秒）与上游长期存在的 VAD 时间戳问题同向。faster-whisper 讨论串 [issue #1119](https://github.com/SYSTRAN/faster-whisper/issues/1119) 在 2026-10-14 仍有人提交钳制时间戳的改动说明。本次没有把那个 PR 合进任何环境，也不把「升级到最新版」写成已修复。

**验证方法（字幕阶段，不阻塞截图 MVP）：** 在项目自己的 worker 里用显式 DLL 目录复跑同一 60 秒；对末尾越界做断言；用 3 段人工听写对照文字；再在播放器同时打开时看内存。失败的原始时间戳保留，不能只截断数字。

**公式识别。** X 窗内没有 DeepSeek 公式截图实测。相邻经验是 OCR 到 LaTeX 仍然容易错：

- [@liuguihua123，2026-09-25](https://x.com/liuguihua123/status/2103512065990410348) 称几百页公式 PDF 的 OCR 要逐个手改。
- [@flybird10649791，2026-10-16](https://x.com/flybird10649791/status/2110965800714854874) 称印刷体尚可，连笔和涂改失败，后改用豆包 API。
- [@burkov，2026-10-14](https://x.com/burkov/status/2110508196259332321) 提醒 OCR 后要检查图数、公式能否渲染、表格能否渲染。
- [@laogeai，2026-10-15](https://x.com/laogeai/status/2110535417590403167) 与 [@grok，2026-10-03](https://x.com/grok/status/2106188064208936990) 列举本地 OCR 名单。名单未实测，不能据此换成 PaddleOCR 或 LaTeX-OCR。

本项目默认不先做模型 OCR，这仍然合理：少一次调用，也少一条错识别链。前提是视觉闸门证明 Flash 能直接读这批图。闸门失败时，本地公式 OCR 只作为对照探针，不先做成产品功能。回答侧的 KaTeX 渲染也还没在本项目里跑过。模型若输出坏掉的 LaTeX，界面会显示源码。验证用一组固定的 Markdown 夹具加上一条真实回答即可，不必单独立项。

**Windows 交付。** 首版形态是本机后台加浏览器，不是安装包。P0-01 的进程清理、端口和隐藏窗口都还没实现。本机硬件记录仍是 Ryzen 7 7840H、约 16 GB 内存、RTX 4060 Laptop 8 GB。ASR 与 Harness 同时运行的占用没有测过。16 GB 内存上同时开浏览器播 3.4 小时视频、Harness 和 ASR，是字幕阶段的风险，不是截图 MVP 的前置条件。FFmpeg 本机构建被记录为 GPL-3.0-or-later；个人使用可以调用现成程序，以后若打包分发再单独做许可清单。

**数学解答不可默认再验一轮，但必须能回看来源。** X 上的学习研究帖样本很小，方向却一致：直接给答案之后，学生很少再追问。[@timmapuramreddy，2026-10-06](https://x.com/timmapuramreddy/status/2107451529624215767) 转述 Khanmigo 学校实验的数学提升有限；[@macroCapt，2026-10-13](https://x.com/macroCapt/status/2110084656678994130) 强调出错后的帮助。这些不是考研数学一的证据。产品上保留「默认完整解答」，同时在回答旁挂上用户那张图和时间点，让追问「检查这一步」是一次普通追问，而不是新的代理流程。

## 5. 成本与工作量

以下全部是假设，不是测量，也不是报价。

### 5.1 API 费用假设

人民币单价用第 4.1 节 2026-10-20 的官方页。思考关闭，不调用 Search/Fetch，失败重试另计。本地 ASR 没有云端语音费，电费不在表内。

10 月 19 日报告的三个月度情景（轻量 / 常规 / 高频，全空闲到全高峰约 6.00–12.01 元、31.77–63.54 元、141.89–283.78 元）在单价未变的前提下，算术仍然成立。它们不是这个用户的预测用量。

另设一组「若从 10 月 20 日用到 12 月 19 日初试」的用量，只用于看数量级：

- 60 天，每天 25 道题，共 1,500 次提问。
- 每次提问平均 1.2 次正常模型请求（含少量追问，不含工具轮和失败重试）。
- 每请求平均输入 4,000 token、输出 2,000 token，输入缓存命中 30%。输入已包含一张图，不再把 1024 token 上限另加一次。
- 不做字幕纠错，不做摘要代理。

则缓存命中输入 2.16M、未命中输入 5.04M、输出 3.60M。全空闲约 **19.48 元**，全高峰约 **38.97 元**。若每次请求另有 2,000 个思考 token 并按输出计价，空闲再加约 14.40 元，高峰再加约 28.80 元。真实高峰占比会落在两端之间，不会刚好是这两个数。

单张图即使打满 1024 token，空闲未命中也只有约 0.001 元。费用压力在长输出、思考和重试，不在原视频的 510 MB。

### 5.2 工作量假设

假设一名已经熟悉 React 与 Python 的开发者，以本项目为主要工作，使用文档中的那台 Windows 机器。环境问题、Harness 协议返工和视觉闸门失败都会使数字失效。本次没有任何实现速度的实测。

| --- | --- | --- |
| 视觉闸门 | 0.5–1 天 | 用户自备图；官方聊天手测即可。不写应用 |

## 6. 建议

**做。范围收到 Windows 上的视频主动截图、编辑、文字提问、完整讲解、停止和追问。** 不做的是：在这条路径可用之前实现字幕产品、知识库、Office、安卓、同步、番茄钟和学习伴侣。

这与 10 月 19 日「建议立项」同向，并多加一个条件：视觉闸门没有通过时，不继续堆 Harness 适配。闸门通过之后，仍然使用 Harness 作为 Windows 执行层，不改回直连主链。直连只保留为闸门里的对照，避免分不清是模型看不懂，还是宿主把图片压坏了。

### 6.1 最小切口

一条纵向路径：

1. 选择本机视频路径，登记资源身份，不复制原片。
2. 浏览器 Range 播放和 seek。
3. 用户暂停、截取当前帧、缩放和裁剪，确认后的选区进入输入框，并记下时间。
4. 补充文字，经业务后台发给固定版本的 Harness；模型只收到该选区。
5. 界面显示真实流式文本和公式；可以在生成中停止；可以追问；重开后消息还在。
6. 字幕和知识库显示为未就绪。信息足够时直接回答。

学习 preset 在这个切口里不注册工具。没有工具，就还没有自动补帧的路径。等字幕阶段再增加受 guard 限制的字幕读取。
