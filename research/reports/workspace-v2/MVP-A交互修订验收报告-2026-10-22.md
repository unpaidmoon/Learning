## 1. 交付行为

| 用户要求 | 当前实现 |
| --- | --- |
| Codex 式创建课程 | 独立课程显示名、原生目录选择、确认后才创建；取消选择不创建，无路径输入框；改名不改磁盘目录 |
| 精简侧栏 | 顶部选课程，下方文件树；仅刷新、显示名右侧悬停重命名、移除课程；左上按钮收起整个区域，保留学习状态 |
| 中间资源管理器 | 固定不可关闭“文件”标签；图标／列表、前后及上级导航、路径、当前目录搜索、排序、多选、右键与属性；内部复制／剪切／粘贴、移动、重命名和新建目录 |
| 外部资料进入 | 外部拖入／粘贴只复制，同名自动编号保留两份，无模式选择或额外成功提醒；原件保留；没有独立导入入口，侧栏刷新发现目录变化 |
| 删除与移除 | 本机固定卷删除使用 Windows 回收站，不降级永久删除；移除课程保留磁盘资料与聊天 |

| 直接对话 | 无开始问答页，直接输入；对话标题就是历史下拉；草稿自动保存，无保存按钮和常态页脚；首次入课建当次空聊，切历史同步标题、正文与草稿归属 |

| 视频进度条 | 悬停本地画面／时间预览；拖动圆点和目标预览更新，主视频按原进度继续；松开才提交一次跳转，保留原播放／暂停状态 |

## 3. 模型输入、用量与附件边界

真实复测固定 `account`／`deepseek-flash`／`high`、输出上限 16384、超时 300 秒，没有自动切模型或 API Key，没有额外 OCR／规划模型及隐式重试。只生成并上传两页 PDF 和 TXT／Markdown，未读取真实课程、视频、屏幕或系统剪贴板。每次出站均包含两页 PDF 和文本末尾标记，图片 SHA 集合严格等于本轮准备页面集合；原 PDF 二进制未发送，预览画面未发送。

三次真实 attempt：完整回答完成；在 provider 活动且已有 49 字正文时正常请求停止；同一会话接着完成。取消后 Host 保持存活，末次仍正确输出四处标记。两次完成用量已结算，一次取消最终用量未知；独立 reasoning 字段均缺失，不记零、不重复累计流式用量。不由这些标记题推断普遍数学正确率或速度达标。

**历史 PDF 重复输入是已知边界。** 本地完整浏览器实际 6 图、唯一 4 页、重复 2 页；真实三轮实际 2／4／6 图，各唯一 2 页，重复分别 0／2／4。原因是既有完整业务上下文和 Host 持久历史同时携带旧页，本轮没有引入持久附件水位去重。它不增加 provider attempt，但可能增加输入和更早触及最终请求体限制。没有为减少重复静默删除允许的历史或裁剪文档。

PDF 整份限 20 MiB、32 页、累计 8000 万渲染像素、12 MiB 派生 JPEG，处理子进程 60 秒；TXT／Markdown 限 1 MiB、20 万字符，严格 UTF-8。附件展开快照限 64 图／14 MiB／30 万文本字符，最终请求另有 24 MiB 编码体限制；这些保护不等于模型的全部上下文容量。超限明确拒绝整份文档／请求，不截断、不只发部分页面。固定 `pypdfium2==5.14.0` 和 PDFium 制品、RECORD、许可核查见 [依赖记录](附件PDF依赖核查-2026-10-21.json)。

## 4. 失败及修复保留

- 矩阵先用两个失败断言复现不可映射：可见字形已选全，但 KaTeX 不可见 strut 不在范围。修复按可见字形／结构判定，不放宽局部选区；原失败、局部 A 和完整矩阵复测均保留。
- 初始空聊草稿 GET 未完成时，原来 `saveDraft` 无条件 flush 导致“草稿版本未核对”，完整浏览器 `workspace-v2-browser-20261021-r3` 如实失败。修复只允许无本地修改且无截图／文件候选的空草稿跳过当前写入；dirty、冲突、附件保护不变。先 1 红再 4 条边界全绿，App 真实控制器整合及新完整浏览器均通过，见 [记录](initial-draft-navigation-20261022.json)。
- 早期文件 fixture 的 CRLF、扫描 PDF 生成、Windows CLI 参数过长、驱动作用域及轮询条件、测试期并行改动／旧构建配对失败均保留在各运行目录。早期约束为 4 图的断言没有覆盖旧历史重复，改为同时核实际、唯一、授权集合和重复数量；不把探索失败改成通过。
- 临时类型／旧测试预期、Ruff 和契约漂移在定向开发时出现，已修复再全量检查。最后 OpenAPI 的单次导入路径上限 100→1024 已重新生成，生成 TypeScript 字节相同；不掩盖之前检查失败。
