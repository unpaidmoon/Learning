# 原生课程目录选择修复

日期：2026-10-22。用户实测创建课程报 `PICKER_UNAVAILABLE`，已在项目 Python 环境和正式 HTTP 接口复现并修复。

## 原因与修改

旧 `choose_paths()` 在后台请求线程使用 `tkinter.Tk()`。本项目 Python 可导入 tkinter，但环境缺少其 Tcl/Tk 运行资源，窗口初始化抛出 `TclError: Can't find a usable init.tcl`，被转换成 `503/PICKER_UNAVAILABLE`。主线程直接调用也失败，问题发生在用户选择目录之前。

改用 Windows `IFileOpenDialog`，通过项目自有 `native_files.pick_paths()` 隐藏 COM 细节，不新增依赖、不修改全局 Python／PATH／HOME，不要求用户输入路径。每个调用线程初始化 STA，结束平衡释放 COM、结果对象和路径内存；取消返回空结果。全局非阻塞选择锁继续防重复窗口，失败也释放锁，稳定业务错误不被统改为不可用。底层同样支持既有显式多文件选择调用。

接口没有变化：`POST courses/folder/pick` 仅返回所选目录，取消返回 null；`POST courses/folder` 在确认后才创建，课程显示名独立。实现依据为微软 [Common Item Dialog](https://learn.microsoft.com/en-us/windows/win32/shell/common-file-dialog)、[线程 COM 初始化](https://learn.microsoft.com/en-us/windows/win32/learnwin32/initializing-the-com-library)与 [GetResults](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileopendialog-getresults)。
