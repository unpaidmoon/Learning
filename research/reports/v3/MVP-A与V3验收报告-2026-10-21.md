## 交付与边界

沿用原课程、聊天、附件、SQLite、Harness 适配、事件身份、提交去重、未知对账和 raw usage。新增原地视频及 Range、位置恢复、主动截图编辑、持久草稿、Markdown／KaTeX、整式引用、三栏布局与基础启动／退出。旧 0001 schema 不改；0002_media／0003_drafts 增量迁移，升级保留原聊天与附件，并生成迁移恢复副本。

用户主动截图时暂停视频；原图只在浏览器本机 IndexedDB 中供重裁。只有确认的裁剪 PNG 进入附件 API 和模型请求。视频读取仅由本机业务接口按 asset／version 完成，Harness 工具不能调用该路由补画面。来源版本、时间、坐标与编辑父子关系固化到确认附件和原输入快照，原件失效后仍可用已确认截图提问。

三栏中课程目录可收起，聊天宽度可调；普通发送不暂停视频。全屏问答后收起聊天恢复视频全屏并续播，同课程换资料／收放／主题不创建聊天。首次进入课程不自动打开旧资料；重开历史由用户选择。原件缺失、版本变化和错误重定位明确拒绝。

默认模型保持用户所选，不自动降级。固定 Harness 支持的思考为 off／low／high／max；应用 none 映射 off，medium／xhigh 在发布前明确拒绝。官方模型名和能力以 [模型元数据](https://api-docs.deepseek.com/api/list-models/) 为依据：Flash 图文与 Pro 文字分开，Pro 不应接收包含当前题图的输入；[官方能力表](https://api-docs.deepseek.com/quick_start/pricing/)亦明确该边界。实际请求与参数验证另记。

入口为根目录 `启动学习.cmd`／`scripts/Start-Learning.ps1`，复用项目环境与固定 Harness，默认打开学习页面。`-NoBrowser -NoHarness -Port 18769 -TimeoutSeconds 30` 以及启用正式 Harness 的 `-NoBrowser -Port 18798 -TimeoutSeconds 60` 均已实跑就绪和安全停止。页面关闭不退出后台；安全退出保存草稿与位置，有活动回答时确认，未知先对账，逐生成取消，随后清理所属实例。它不是无开发环境安装包。

## 素材、数学和等待

18 个定义 ID 冻结；M01～M06、L01～L03、P01～P03、B01～B03 为合成题图／文字用例，B02／B03 保留完整回合顺序。H02 复用用户此前已主动提供且确认的原请求 JPEG，hash `37e7e83aadf641d46d0113a2c74530159ca17be783bea5fe1567eed46ac6c3fb`、1280×540、69486 字节；本地固定 Host 先核同 hash，再真实提交。没有搜索其他用户图片、重新从视频补帧或把字体渲染称为真实手写。H01／H03 真实手写及新真实网课选区保持未覆盖。

数学核查按明确解析预期逐项检查读题、方法前提、运算和结论。已确认的 M01／L02 与 H02 授权依据保留；其他预期是助手按题文解析核查，仍需用户判断学习适用性，不能把回答模型自评或另一个评分模型当标准答案。小样本不能外推考研数学综合题准确率。

Flash／high 基线的 12 道 M／L／P 小题、H02 定位漏乘 2x、B02 明确更正和 B03 错误质疑已逐项核对；L01 存在行操作方向的表述小瑕疵，零等式等价和最终解正确，原文不改。[独立解析记录](v3-math-20261021-r1-review.json)按内容锚点核定的 17 个成功回合首次实质内容为 1.641～5.329 秒，这是 HTTP 观察与助手内容核查，不是用户实际学习体验。

首字符只作为传输诊断。首次有用内容须对具体增量内容复核；耗时只报实际样本，不宣称 p95 或固定节省比例。10 秒仍是体验目标，不能用状态、复述、思考文本代替有用内容，也不能为速度隐藏数学问题。

## 原失败、根因与复测

- 浏览器 r1 的同名视频标题／列表触发严格定位错误；登记播放已发生，但原轮保持 failed。runner 改精确定位后另开 r2／r3，不覆盖原结果。登记视频播放 r1 也是数字 JSON 采集错误，r2 新记录通过，原证据保留。
- 真实基线 B01 明确缺关键指数，模型仍先按常见三次方假设给答案，未满足必要澄清规则。最小修订 persona 后，原 B01、不同分子的缺指数题以及正常 M01 定向复测；[新结果](v3-ambiguity-retetest-20261021-r1.json)保留原 run ID 的拼写，未改原失败。
- 原 STOP 在业务 running 且已有正文时请求停止，最终 completed，不能标真正生成中停止通过。对齐 provider 账本后发现：provider 约 19.46 秒已结束，页面约 23.18 秒才显示正文，业务约 31.94 秒终态。根因为逐 token FULL SQLite 事务导致摄入积压。使用 diagnosing-bugs 工作流建立 1000 增量／事务数红测试后修复，并要求新停止例在点击时同时确认 provider 尚未终态。
- 初始 `deepseek-pro` 候选没有实际依据，真实 400 保留；改用真实模型名 `deepseek-v4-pro` 后图文拒答，官方能力核查显示 Pro 仅文字。修正 profile 能力声明与发布前校验，保持原选择，不把改模型重试冒充同次成功。[原错误名](v3-config-pro-none-20261021-r1.json)、[Pro 图文 none](v3-config-v4pro-none-20261021-r1.json)与[图文 high](v3-config-v4pro-high-20261021-r1.json)均保留。
- [强化停止复测](v3-stop-retest-20261021-r1.json)实际 3 次：8.594 秒时同 generation 已有 44 字正文，provider 未 request_finished、原始 SSE 无 message_stop；停止后 8.750 秒 cancelled，最终保留 82 字，边界 cancel_observed=true、timed_out=false。用量未结算保持 unknown。原题图仍在随后同聊天请求中，更正分母后完整得到 1／6。追问首正文 31.829 秒、实质推导锚点 32.657 秒、完整 35.688 秒，未达 10 秒目标。不同真实运行有模型波动，不把相对旧例的等待差值都归为事务优化收益。
- [Pro／none 纯文字](v3-config-v4pro-text-none-20261021-r1.json)最终结果 1／3，但 Taylor 五次项符号错误，数学检查保持 failed。[另选 high 的原例和不同题控制复测](v3-config-v4pro-text-high-20261021-r1.json)推导正确，不冲销 none 的原失败，不自动将该配置应用到用户；其中一题首正文 11.297 秒、完整 15.875 秒，也超过目标。
