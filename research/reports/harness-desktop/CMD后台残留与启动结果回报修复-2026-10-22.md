# CMD 后台残留与启动结果回报修复

用户反馈原 CMD 双击后闪退。本次按实际启动日志复现：窗口进程已经退出，旧的本项目后台仍监听 8766，后三次启动均报 `PORT_IN_USE`。PowerShell 原先 `Start-Process` 后立即成功退出，没有等待隐藏 Python 的结果，所以 CMD 看不到失败，也不触发其已有的失败暂停。

新增真实 CMD／Windows PowerShell 回归：隐藏 Python 输出 `SYNTHETIC_START_FAILED` 并退出 23，修复前 CMD 却返回 0；修复后显示该错误并返回 23。PowerShell 保留 UTF-8 BOM，固定子进程日志 UTF-8，保留进程句柄以可靠读取快速退出的 Windows 子进程退出码。成功启动等待 Electron 的 `did-finish-load` 窗口就绪标记，不再把 spawn 当成窗口已打开。

重复双击遇到占用时，只核对项目运行记录、真实 health 实例身份及私有 HWND／PID／可执行文件／创建时间；有效窗口则恢复并前置，不创建另一后台。其他占用或过期窗口记录继续拒绝，并显示错误；不按端口杀进程。窗口验证复用 `native_files.desktop_picker_owner`，新增路径参数仅为本地 Python 调用，不新增 renderer 权限。

本次实际恢复先核对旧后台身份，确认活动生成数为 0，通过原正常退出接口关闭；随后从 `D:/` 工作目录执行原始 CMD，正式后台和 Electron 页面已就绪，新窗口 PID 14504、原生窗口可见。再次执行同一 CMD 约 0.47 秒退出 0，stderr 为空，窗口仍为同一 PID；隐藏启动日志记录 `LEARNING_DESKTOP_ACTIVATED`。窗口保留给用户使用，旧 8765 实例未处理，没有模型调用。

验证：桌面 Python 测试和 owner 定向测试共 **18 项通过**；Ruff、JavaScript 语法和 diff 空白检查通过。新增回归包括隐藏启动失败返回码、同实例窗口恢复、不同 health 身份不能操作窗口、重复启动不再次 prepare／spawn。Windows 默认 pytest 临时目录权限错误使用项目内独立 basetemp 解决，没有修改系统目录权限。

本机证据：`.runtime/desktop/launches/` 原始失败日志；`.runtime/desktop/app/run/desktop-launches/37f638d070ab4ed39ea9a79e40508e01/` 本次正式后台／Electron 就绪日志；`.runtime/validation/desktop-cmd-flash-20261022-r2/result.json` 重复 CMD 与可见窗口验证。初次验证器使用捕获管道等待退出，后台继承管道导致其等待 EOF；重复验证改用磁盘日志和真实 CMD 的 `wait()`，不将验证器等待误记作桌面失败。
