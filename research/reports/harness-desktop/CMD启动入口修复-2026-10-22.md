# CMD 启动入口修复

日期：2026-10-22（Asia/Shanghai）。范围：用户反馈“cmd 打开报错”的启动链路补修。工作包状态见 [MVP 计划](../../../docs/plans/MVP开发计划.md)。

从项目外工作目录执行原始 `启动Harness桌面.cmd`，系统 `powershell.exe` 在 `Launch-Desktop.ps1` 报 `ParserError`、`ExpectedValueExpression` 和缺少右花括号，尚未创建后台日志；CMD 退出码却是 0。原脚本为无 BOM UTF-8，系统 Windows PowerShell `5.1.26100.6584` 按传统代码页读取中文字符串并错误识别引号。上轮测试验证了 Python 运行器及 Electron 窗口，没有覆盖 CMD→系统 PowerShell 这一层。

修复将 `Launch-Desktop.ps1` 保存为带 BOM 的 UTF-8，并在 `.editorconfig` 为此文件明确 `charset = utf-8-bom`，保留中文错误信息。CMD 保存 PowerShell 的失败退出码，错误时暂停以供查看，并将原失败码传出。

新增 [test_windows_entry.py](../../../scripts/desktop/test_windows_entry.py) 使用真正的 Windows PowerShell `Parser.ParseFile` 读取实际脚本，并通过真正的 CMD 执行带空格路径下的入口、检查被调脚本的 `exit 23` 得到保留。修复前两项均失败，修复后与原有准备／启动测试共 10 项通过，Ruff 通过。

实际复验从 `D:\Codex` 执行 `D:\Codex\Learning\启动Harness桌面.cmd`，返回 0；`8766` 业务接口与 Harness 均就绪，启动 stderr 为空；Win32 枚举确认所属 Electron 的“AI 辅助学习”窗口可见。记录位于本机 `.runtime/desktop/cmd-entry-fix-20261022.json`。本次未读取用户视频／屏幕、未调用模型，未停止原 `8765` 实例；新桌面窗口保留供用户使用。

此验证只覆盖启动故障，原始解析失败与先前完整问答验收仍按各自批次保留，不将本次启动成功重记为新的模型或学习体验验收。
