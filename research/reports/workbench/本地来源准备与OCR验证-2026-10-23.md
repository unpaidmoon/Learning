# 本地来源准备与 OCR 验证

本报告记录组件证据。工作包状态仅见 [MVP计划](../../../docs/plans/MVP开发计划.md)，全部场景和共同门槛仍待统一验收。

## 正式实现

`workbench/preparations.py`、`processing.py` 与 0012 增量迁移保存本地处理任务、逐页检查点、租约 epoch、操作回执和 OCR 原始结果。当前页优先，整份后台逐步处理；暂停、恢复、取消、明确重试、应用退出冻结和本地进程恢复均保留原结果。临时单页任务不恢复用户暂停的整份任务。当前问答和截图优先，播放期间降低后台调度频率；普通停止不杀 Harness。

正式 PDFium 5.14.0 所属隐藏进程只渲染已绑定课程 PDF；固定 Node 24.14.0 加 Tesseract.js 6.0.1 本地资源识别，不调用模型。保存原始文字、字符框、TSV/hOCR、位图摘要和原页变换，API 不返回私有路径及原始 HTML。结果发布与检查点原子提交，故障后明确重试可复用带完整性校验的私有结果，未自动再次识别。

固定资源入口为 `resources/workbench/engines.lock.json`、`ocr-runtime.lock.json`、`ocr-package-lock.json` 和原许可通知。正式安装器是 `scripts/workbench/prepare.py`；正式运行只使用 `.runtime/workbench/ocr` 和已部署 ASR 资源，不依赖调查环境。完整依赖与许可见 [OCR闭包审计](deepstudent-reuse-audit.md)、[ASR闭包](asr-deployment-closure.md)。ASR 正式独立 worker 已迁入，音频任务与字幕流程尚未接通，不能以模型成功初始化代替字幕验收。

PDF.js 5.4.624 接缝在 `frontend/src/reading/ocrLayer.mjs`，原 vendor 不修改。以保存的字符框构造文字层，原 canvas 保持；查找通过固定版本的提取完成围栏与公开 `setDocument` 接口刷新，不抢写内部提取数组。重建前取消旧 builder、替换 div，避免重复监听。活动拖选、未释放选区和提交中的快照会延后重建。接缝源码和独立实际制品证据见 [Viewer审计](pdf-ocr-layer-audit.md)。

阅读打开和当前页准备使用客户端顺序、原版本和 epoch。旧资料慢读结束后不能抢回新资料优先级；隐藏标签释放沿用原激活序号，避免 React 子项 effect 顺序使旧标签超越新标签。OCR 索引分页按页号扫描并重复新一轮，不用会漏掉倒序完成页面的时间戳游标。识别结果只用于本地阅读和用户明确选取，不在模型每轮前自动检索。

## 保留的失败

`workbench-ocr-reader-20261023-r1`：真实鼠标选择、复制、活动选区及原 canvas 保护通过，但引用 API 拒绝字框不匹配。`r2` 补存准确请求和当时 DOM 几何：提交 regions 最后混入全页控制框，后端正确返回 `PDF_SELECTION_MISMATCH`；整份暂停也通过。原失败、私有原始结果和冻结摘要保留。正式修复为仅对实际选中文字节点获取矩形，排除 Viewer 控制元素与父元素框，`r3` 14项通过；`browser/ocr-reading.png` 已目视检查。暂停控件用合成click事件保持待引用选区，恢复控件和选词/复制为真实浏览器操作；这不是实际Windows实窗或人工学习验收。

## 未覆盖

扫描教材的实际识别准确性、同页原生文字与扫描区域混合补层、复杂数学公式、Windows 学习体验、用户真实素材、字幕业务流程、完整归纳与全部13场景未由这些组件测试验收。当前 OCR 只补无原生文字页；不把原始识别结果当成可靠的公式识别。整份本地任务页数上限明确报错，超过时当前页独立处理，不静默截断完整范围。
