# 完整归纳的来源覆盖与统一成果验证

日期：2026-10-23。范围：正式后台、固定 Harness、本地 fixture 和自造 PDF 的真实模型调用。**不是 S04、S12 或 13 场景统一验收通过。**

## 正式实现

- 增量迁移 `0015_task_coverage` 保留原 v1 任务和原输入哈希；v2 分开保存来源声明、来源叶、生成工作、实际 run 输入和 Task 级保留成果对象。一个工作可读取多页／多份资料，多个工作写入同一成果。
- 创建时先持久保存请求及来源声明，不等待 PDF 解析或音轨探测成功。页数／音轨范围未知保持 `null`；坏 PDF 留下已绑定原版本的缺口，不写成 0 页。整课在后台处理前冻结成员和文件身份元数据，成员改变成为缺口，后添文件不加入原任务。
- 本地 PDF 对象检查区分文字、非文字对象、批注和未映射字符。可证明的空白保留本地证据；r12后非空页同时准备授权页图，因为纯文字对象也可能含上标、栏序或表格。字幕范围从冻结轨道的有效音轨和原始单位枚举，手改 head 在任务中冻结。不会补视频帧或屏幕内容。
- 文本按精确 Unicode codepoint 分段，单工作上限24000正文字符、96输入、96000材料序列化字符、6图及14MiB原始图像。密集显示框保留在来源存储，不全部塞入模型上下文；同页文字和版面一起分配。上限触发分工作或明确失败，不截掉原文后声称全文。每次实际输入保存内容哈希、身份、范围及attempt对应；fixture与真实出站证据分别标记。
- 首次有效结果才物化保留的成果 ID，默认索引。后续批次追加同一成果；引用白名单只检查本次写入的块，已完成内容保留原来源链。完整工作必须给每个实际输入叶对应来源引用。此检查不能代替语义质量验收。
- 同块并发编辑保留用户当前版本及 AI conflict 修订；无关块的手动编辑保留并允许追加。模型修订保持 `author=model` 和原 Task 身份。明确修改目标时，只读取指定旧修订的目标块及其身份，不由此授权祖先资料读取。
- 来源缺口、生成输出结构失败、目标编辑冲突、执行／输入证据未知分开处理。全部排除或全部空白不生成空材料请求，也不虚称已有成果。未知先对账原 run；恢复不重新创建请求。
- 明确重试已失败的本地 ASR，通过持久决定和稳定 operation ID 委托原 job／track／参数；丢失本地回执可取回原结果。手动暂停／取消不自动恢复。只有当前单位准备的冻结轨道，可建立同轨、同固定引擎的 full 准备，保留手改。

相关正式入口：`POST /learning/task-intents`、`GET /learning/tasks/{id}/coverage`、`POST /learning/tasks/{id}/source-gap` 及指定工作重试。桌面完整任务、成果库及原生业务工具仍在接入，不能把 HTTP 闭环称为全部用户体验完成。

## 图像派生与固定制品

固定 SEA 的原生附件服务可能先规范化、再生成模型请求编码，原始 PNG、normalized attachment、variant descriptor 与请求字节的摘要不同。正式私有准备经 `ctx.attachments.saveImage`、`ctx.llm.imageRequestTarget`、`ctx.attachments.readImageRequest` 得到真实请求字节摘要，保存原页／source version／run／request／epoch／model 的派生证据。

Boundary 仍使用精确摘要白名单；隔离任务另核图像出现顺序，缺图也拒绝。没有从实际请求中临时接受新摘要，没有设为无限制。文档页准备只接受业务层核过的文档页字节，模型工具不能提交路径、URL 或视频帧声明。原始 PDF 和页图像身份保留。

接口及发行制品的独立调查见[原生文档图像准备实证](native-document-image-preparation-proof.md)。正式运行使用 `harness/plugins/native-images.mjs`，不依赖候选或 probe 目录。固定 SEA 仍为 `0.2.1rc2`，SHA256 `f9ed01f241df37c50c702d81b6c226d576210b8f3947699735ca90285ea13365`；自有插件及 profile 哈希在 runtime.lock 中维护。
