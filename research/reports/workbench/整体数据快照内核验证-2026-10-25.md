# 整体数据快照内核验证

日期：2026-10-25。C-04／W-09 的基础增量；唯一工作包状态见 [MVP 计划](../../../docs/plans/MVP开发计划.md)。本次实现一致业务 cut 与已登记文件闭包，尚不是可用的完整导出／导入功能，也未实现离线聊天、可选原件归档或数据位置迁移。

## 正式实现

新增 `data_snapshot.py` 的 `BusinessSnapshot.capture()`，复用既有 Repository、SQLite backup 和原件受锁读取规则，不启动 Harness、模型、迁移恢复或读取课程原件目录。SQLite backup 取得同一已提交时点；后续闭包只从这份 cut 读取，后来的聊天写入不混进旧快照。

闭包包括**全部已登记 attachments**，不限于 message_attachments，因而保留尚未提交的草稿对象与整份附件；相同摘要字节只复制一次，业务身份仍在 DB 中分别保存。另按已存 document_image／document_region_image 来源复制 `learning-source-images` 中的不可变 PNG。旧 v2 crop 不重渲染、不更换 parser 或历史回执。

逐文件核摘要／实际字节，flush／fsync 后才交给下一层；缺失或损坏明确失败，不修补、删除或替换原资产。没有按整个数据目录递归复制，execution、Host home、browser、运行日志、凭据及模型文件均不在闭包中。尚未决的聊天／任务另列状态，缺失用量不补零。

`resources/data/schema-0033.json` 来自本项目自造空 0033 库的实际结构，213 个数据库对象；`columns-0033.json` 固定 86 张应用表和特定执行元数据键。未知表／列／数据库逻辑或未支持控制键拒绝，不在用户正文、模型文本或 raw usage 中盲目按敏感词删数据。当前没有 DB bearer 列，原历史 grants、NativeCall、图片／stage 回执和 usage 原样保留；它们仍必须在后续导入前被执行 fence 隔离，本内核不负责激活导入库。

## 实际验证及保留的失败

| 私有记录 | 结果 |
| --- | --- |
| `data-snapshot-20261025-r1.xml` | 6 失败。sqlite3 连接的事务上下文不等于 close，Windows 临时目录回收被占用句柄阻止。 |
| `data-snapshot-20261025-r2.xml` | 1 通过／5 失败。显式 closing 修好句柄后，发现 Alembic batch 反射可改变独立 FK 约束的输出顺序，原精确 SQL 比较误拒同一结构。 |
| `data-snapshot-20261025-r3.xml` | **6 通过，3.82 秒**。仅规范化 FK 声明顺序，保留每个 SQL token，不放宽未知逻辑；其余结构仍精确比对。 |
| `data-snapshot-native-20261025-r1/` | **passed**：复制自造材料真实模型数据后执行新内核，新增 provider／Host 为 0；cut 保留 16 份唯一任务 usage、3 条原生效果和3条历史失败 stage，原数据 SHA 不变，执行私有域未复制。 |

六项本地用例覆盖未提交附件、同字节不同身份、cut 后并发新聊天、正文含 authorization 字样仍原样保留、旧 crop 精确字节、损坏／缺失不修、未知表／控制键拒绝，以及 Windows 连接释放／临时目录清理。全部是独占自造数据，不读取用户真实 DB 或凭据。

## 继续实施

仍需版本化整包清单／校验、可选原件、离线聊天投影与固定 reader、导入空目标保护和持久执行隔离、来源重定位、操作回执、设置入口及整机迁移恢复。导入不得仅删旧 token 或改状态为 completed；旧 queued／prepared／unknown、旧 ready sid 的权限恢复都须统一阻止。普通 Windows 和用户数据迁移尚未验收，不能把本内核测试写成 C-04～06 已完成。
