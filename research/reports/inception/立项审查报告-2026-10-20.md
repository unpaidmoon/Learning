### 1.2 最重要的判断依据

1. **价值来自流程整合，模型解题质量仍需独立成立。** 用户实际是等并读完回答后返回视频，操作收益必须覆盖这整个流程；不能按发送后马上继续看片的假定估值。[需求基线](../../../docs/product/AI辅助学习项目需求总结.md "整理前第 90 行")
2. **Harness 路线存在，但目前只跑到空会话。** 脚本没有发送 prompt，拒绝 stub 无命中，原始结果也明确未测活动生成取消；其中 modelRequestsSent＝0 是预设标记，并非独立网络计数。强制终止 probe 进程树不证明产品可以正常退出。[原始结果](../../probes/harness-0.2.1rc2/probe-results.json "整理前第 4 行")、[取消边界](../../probes/harness-0.2.1rc2/probe-results.json "整理前第 34 行")、[清理方式](../../probes/harness-0.2.1rc2/probe-results.json "整理前第 66 行")
3. **默认配置与关键约束存在具体不一致。** 默认重试覆盖部分执行未知的错误；用量转换可能消除字段缺失信息；默认 Web 配置保留编码 shell。这些需配置或窄适配修正，不能只依赖提示词。详见 F02—F04。
4. **完整首版的工作量集中在专业交互、状态和交付。** 知识库用途、公式选区、文档保真和运行恢复均不是安装一个库就完成。现有计划已有补充清单，但尚未形成统一可执行的工作包和退出条件。详见 F07—F13。

## 4. 主要发现

排序按对学习闭环、用户资产和投入判断的影响。已确认问题指可从原始记录或固定源码确认的事实/默认不一致，**不表示尚不存在的正式应用已经发生事故**。

### F01｜待验证风险：核心执行链尚未穿过一次真实图文问答

- **场景：** 用户确认题图、发送文字，等待真实内容，并在生成中停止后继续追问。
- **证据与判断：** 脚本明确不发送 prompt，拒绝 stub 无命中；modelRequestsSent＝0 是预设标记，不是独立网络计数。首个 follow 项只是 snapshot，活动生成取消标为未测。[原始结果:4](../../probes/harness-0.2.1rc2/probe-results.json "整理前第 4 行")、[脚本:243](../../probes/harness-0.2.1rc2/probe_web_host.py "整理前第 243 行")。固定 Session Controller 有 prompt/follow/page/cancel，但 SDK 协议没有等价的现成实时 chunk 与中途取消；切换 SDK 语言不能补齐。[Session Controller](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/api/session-controller/README.md)、[SDK 限制](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/sdk/client/README.md#known-limitations-and-deferred-work)
- **影响/阻塞：** 是当前最影响路线与维护成本判断的不确定性。阻塞“正式应用接入已具备足够基础”的判断；不构成不可行证据。
- **最小建议：** 先 V1 验证学习 preset＋内部 Peer。SDK＋桥接只在主线确有受阻证据或比较收益时深入，不同时建设两套完整适配。
- **验证/通过：** 确认图真正进入模型；终态前收到真实增量；活动停止可确认且不杀宿主；下一问仍可用；重连能对齐原生成。保存实际事件/配置/请求身份，不能用最终文本回放或 idle cancel 代替。

### F02｜已确认默认不一致：有限重试仍可能违反“未知执行先对账”

- **场景：** prompt 或模型请求已发送，但网络超时、传输断开或回复丢失。
- **证据与判断：** 固定上游 normal 默认允许首次外再重试 5 次，包含 TIMEOUT、TRANSPORT 等，插件重新执行失败 step，每次是新请求。[重试配置源码:13](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/llm/llm/src/retry-policy.ts#L13)、[执行语义](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/llm/llm-retry/README.md)。与项目[未知状态约束](../../../docs/development/开发规范.md "整理前第 102 行")不能直接等同。仅把 5 次降为 1 次仍可能重复执行。
- **影响/阻塞：** 潜在重复计费与相互冲突答案。必须纳入恢复实施前 V1 设计，试用前通过故障验收。官方 retry 已有取消终止等待/恢复的语义；不能把“取消后又运行”归为已确认的默认行为，该负例用于检查应用的取消传递及恢复策略。
- **最小建议：** 初始诊断可显式 normal/maxRetries＝0；正式策略区分“已确认未受理、可安全重试”与“是否执行未知”。未知尝试先查询 Harness 记录/原生成，无法确定则保留 unknown，不自动重发。UI/业务/worker 不再叠模型重试；不承诺服务方恰好一次计费。
- **验证/通过：** 分别在接收前、接收回执丢失、首增量后断线、停止时断线制造本地 fixture 故障；计数实际出站尝试。未知路径没有第二次 prompt/模型尝试，已保存结果可恢复，取消不被恢复策略复活。

### F03｜已确认适配缺口：只保存 Harness 汇总 usage 不能证明“缺失不记零”

- **场景：** 上游响应部分用量字段缺失、结束前断流，或一个流重复回放累计计量。
- **证据与判断：** 固定 translate.ts 将 inputTokens/outputTokens 初始化为 0；updateUsage 遇 undefined 跳过，终态输出汇总 usage。因此字段缺失与明确零在该对象中可能不可区分。[初始化:99](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/llm/llm-deepseek/src/translate.ts#L99)、[更新:31](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/llm/llm-deepseek/src/translate.ts#L31)。这证明适配边界存在信息损失的可能，不证明官方正常响应总会漏字段。
- **影响/阻塞：** 会把未知消费写成事实零，影响真实账目和比较结果。阻塞试用用量验收。
- **最小建议：** 在可得的 provider/适配观测点保留原始用量、字段存在性、attempt 与来源；拿不到 provider raw 时保存原样 Harness 对象并明确 provenance，不重建虚构 raw。不能确认存在性的数值保持未知，允许已知部分与未知部分并存。总输入按对应协议的缓存/未缓存语义归一化。
- **验证/通过：** 用完整、缺输入、缺输出、断流、重复累计事件和 reasoning 样例核算；明确 0 与缺失不同，累计值只结算一次，reasoning 不在已包含的总输出上再加。真实终态与账目投影另验。

### F04｜已确认配置问题＋待验证风险：图片范围需要实际权限面闭合

- **场景：** 裁剪外含其他内容，用户只确认一小块；模型或资料正文试图诱导读取原帧、其他课程或任意路径。
- **证据与判断：** config probe 明确默认仍含 coding shell，[原始配置结果:11](../../probes/harness-0.2.1rc2/config-probe-results.json "整理前第 11 行")。学习 preset 尚未运行，不存在“已裁好权限”的证据。注册/schema 过滤与执行 guard 是不同层；工具 timeoutMs 声明本身也不等于执行器强制截止。timeout-policy 发出 abort 后仍等待工具完成，忽略 signal 的工具需要项目在 IO/所属进程边界处理，不能以加载 wrapper 就宣称硬截止。[tools 契约](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/core/tools/README.md)、[timeout实现](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/guard/timeout-policy/src/index.ts#L55)
- **影响/阻塞：** 违反用户最明确的图片与文件访问边界。V1 先证明可裁剪，试用前必须验证负例；W 新增文档/联网工具后重验。
- **最小建议：** 最小工具注册面、执行 guard 和自有 asset/attachment ID 授权共同限制。原帧仅供本地重编辑，模型附件只指向确认产物。文件类型和来源修订校验不能只信扩展名。若采用 Docling，禁止原视频进入通用解析入口：其新版已有视频关键帧能力。[Docling v2.140.0](https://github.com/docling-project/docling/blob/v2.140.0/README.md#whats-new)
- **外发配置：** 学习 preset 显式关闭 session-log-deepseek、plugin-package-inventory-deepseek 的额外贡献，逐项核对其他观测/日志出口与有效请求；它们不能由“正文未发送”推断已关闭。Session-log 是独立日志外传，关闭后再开启还可能补传未确认后缀；不把关闭它说成必然减少模型 token。[固定日志契约](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/session/session-log-deepseek/README.md)、[inventory源码](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/llm/plugin-package-inventory-deepseek/src/index.ts)
- **验证/通过：** 合成帧以选区内外不同标记检查出站图；未确认草稿/完整原图/邻帧/屏幕均不可得。越权课程、伪路径、资料内指令和新注册旁路失败关闭；文档原页可按授权读取，但不能取视频帧。工具实际受总预算、取消信号和超时执行器限制，超时返回后不继续无界读取。

### F05｜待验证风险：支持图片、上传成功和能看清数学是三件事

- **场景：** 小字、上下标、矩阵或手写被图片规范化压缩；含图对话切到纯文本模型；压缩后续问遗忘题图或更正条件。

### F12｜待验证风险＋明确环境缺口：数据安全依赖多持久域恢复，而非一张 SQLite 表

- **场景：** 截图文件已落盘但消息事务未提交；Harness 已生成、业务尚未保存；导出/跨盘迁移中断。

- **影响/阻塞：** 消息/附件丢失、错关联或重复派发直接破坏学习资产。最小发布与对账 T 前验；整体导入/离线查看/数据迁移 W 前验。

### F13｜待验证风险：无开发环境启动、故障隔离与睡眠恢复尚无产品证据

- **场景：** 用户双击、关网页、带任务退出；Host 或 worker 崩溃、Windows 睡眠后唤醒。
- **证据与判断：** 当前 P0-01 只是健康页和开发命令计划，[边界:7](../../../docs/plans/P0-01执行方案.md "整理前第 9 行")，不等于一键安装/运行。probe Job Object 是强制空闲清理，不是保存和优雅退出。Windows 有保持唤醒 API，但不能阻止用户主动睡眠/合盖；不能依赖睡前回调保存全部状态。[SetThreadExecutionState](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-setthreadexecutionstate)
- **影响/阻塞：** 若正式交付依赖开发机 PATH/现有 DLL，日常使用与维护成本可能失控。受控T先验安全启动、后台继续和基础退出/保存；建议独立日常试用尽早交付统一入口。无开发环境双击及完整运行管理作为W已确认硬要求，不把完整打包自动前置为受控T条件。
- **最小建议：** 一套监督/进程归属设施覆盖业务后台、Harness 和 worker，组件健康分开；默认不启用开机启动/保持唤醒/更新检查。持续检查点为主，睡前尽力补存；唤醒重连并对账。打包方案仍为候选，冻结环境会改变 DLL/子进程行为，不以开发态启动代替交付。[PyInstaller 官方边界](https://pyinstaller.org/en/stable/common-issues-and-pitfalls.html#launching-external-programs-from-the-frozen-application)
- **验证/通过：** 干净 Windows 普通用户环境无终端/开发工具能双击；中文路径、端口冲突、部分组件缺失可处理；看视频/旧聊天不被 AI/ASR 故障拖垮。确认退出保留部分回答/进度，只清理所属进程。限次恢复不循环；睡眠后手动暂停仍暂停，未知 AI 不自动重发；更新检查不自动安装，不建设版本回退功能。

### F14｜待验证风险：loopback 与同源不足以代表浏览器业务权限已完成

- **场景：** 学习软件运行时用户打开其他网页；模型回答/导出聊天包含恶意 HTML、链接或远程图片。
- **证据与判断：** 方案规定 127.0.0.1、同源、禁通配 CORS 和后端凭据隔离，[P0:110](../../../docs/plans/P0-01执行方案.md "整理前第 114 行")、[前端:330](../../../docs/architecture/前端方案.md "整理前第 332 行")，方向正确；未找到具体业务会话身份、Origin/Host/WS 握手授权的完整可验契约。跨域读限制与是否能发起有副作用请求不同；浏览器政策不能替代服务端授权。[MDN CSRF](https://developer.mozilla.org/en-US/docs/Web/Security/Attacks/CSRF)
- **影响/阻塞：** 本地文件读取、提交模型、退出和数据管理一旦开放，需要防非本应用页面使用。当前无应用，不能将其描述成已存在漏洞。T 交付前需边界测试，W 导入/导出开放后补验。
- **最小建议：** 本应用自己的本地会话/能力标识与请求来源校验，严格允许 Host/Origin/WS；它与 Harness Peer 凭据分开，不新增用户注册登录。按实际客户端选择相应 CSRF 防护，所有变更避免 GET；asset ID 不直接兑换任意路径。Markdown/公式默认禁任意 HTML/信任扩展，外链/远图受控，离线包自带资源且不因打开聊天调用外网。
- **验证/通过：** 在受控另一 origin 页面发请求/开 WS，不能读取资产、发模型或退出；未登记路径和越权 ID 被拒；危险 HTML/公式/URL 不能执行或绕过图片范围。前端构建、日志和离线包不含模型 key/内部 Cookie、完整 base64 或默认全资料。

### F15｜已确认维护边界＋待验证风险：复用净收益取决于实际分叉和运行时闭包

- **场景：** 内部协议升级、缺少原生包、某组件要求另一 React/布局系统，或为精简配置修改越来越多上游代码。
- **证据与判断：** Harness 仍为预览，内部 Host、SDK、插件与 UI 宿主不是一组独立稳定组件；当前无应用锁文件。默认制品 workspace-controller/Office 失活已确认，[结果:83](../../probes/harness-0.2.1rc2/probe-results.json "整理前第 83 行")。React/Cropper 等元数据存在不代表兼容通过；shadcn 源码可控也不等于无上游维护。
- **影响/阻塞：** 多运行时、内部协议和原生依赖可能主导长期维护。阻塞净节省比例、单一工期和“打包一下”的承诺；不构成现在换栈的依据。
- **最小建议：** 固定制品/完整依赖闭包/配置，业务接口隔离内部对象；先配置与窄适配，必要补丁有单独清单、来源、回归和退出路径。自有目录管理若不依赖 workspace-controller，可明确排除失活项；Office 按 W 阶段补齐，不能泛称警告无影响。不开第二完整聊天/RAG 服务，不新增不必要 TS 后台。
- **验证/通过：** 干净锁定安装可重现；核心契约回归覆盖升级差异；记录实际改动上游包数、补丁职责、修复/回归时间及运行资源。若最小闭环就需要多处核心分叉、每次修复要手改 runtime 或要求用户常规终端排障，应先停在路线验证，给出证据与最小替代组合，标“建议用户重新决策”，不能默认继续堆工作。

许可判断与 F15 分开：本次未发现足以否决个人自用立项的许可问题；实际再分发按第 5.3 节的具体制品核验，不据一个宽泛许可证名推断全链条。

### V2｜试用交付前：最小持久化、事件与故障窗口

- **假设/前置：** 在已获实施授权的最小业务存储和 Harness 适配中，自有数据能覆盖 DB/附件/执行日志之间的故障；使用临时 fixture 数据，实际 SQLite版本/journal明确。
- **操作：** 附件写入前后、业务发布前后、prompt入队回执丢失、部分流后断线、Harness已落盘但业务未保存、旧epoch迟到、重复连点分别中断；重启后恢复。加两课程切换及历史接续样例，合并已完成外部U2/A2两次后只执行新U3；无需网络同步或安卓。
- **指标：** 资产hash/消息数量/来源修订、实际派发数、终态与未知状态、事件水位、部分文本恢复、孤儿产物安全处理。
- **通过/失败：** 已确认保存的用户附件/修订不丢、不串聊；每个提交只有一个业务生成；未知不自动重发；已完成历史不重新执行。无法自动对账可以明确unknown，不能虚构完成。出现已确认资产丢失、错归属、未知派发第二次即失败。
- **失败处理/授权：** 修发布顺序、唯一键和恢复流程后重验相关窗口；不靠重复付费问题“补账”。新实验需额外授权；正式实施后可在其授权内做本地故障验证，真实模型不必参与每个故障用例。

### V3｜试用阶段：数学适用性、真实交互与实际价值

- **假设/前置：** 核心应用已可端到端使用，用户确认题图；存在可人工核对的标准答案/推导和同一使用者的当前流程基线。
- **操作：** 先小量代表样本，再经历数次实际学习；从暂停截图到读完回答、回全屏续播完整观察。数学样本及失败口径见第6.2节。界面操作对照可采用相同确定性回答；真实模型评价另记，避免比较不同模型后把差异归给UI。
- **指标：** 必要动作/找图上传/切应用次数；截图→入草稿；发送→首次有用内容；完整回答；读完→恢复播放；理解/推理/纠正错误、无谓检索、修复负担、raw usage与未知比例。
- **通过/失败：** 真流与活动停止、来源、重开保存、普通追问可用；完整输入不等待字幕/知识库。多次实际使用稳定少操作且用户愿意继续，目标样本的基础读题/更正/推导没有持续失效类别。数学错误如实记录，不能以“模型本来就会错”跳过；部分普通题超过10秒单独不判不交付。重复读错关键条件、同类推理持续失败、数据丢失或恢复严重打断属于不宜日常使用。
- **失败处理/授权：** 按图像/推理/上下文/检索/UI分别修；先缩小技术变量，必要时比较用户认可的模型/思考配置，不增加常驻复核。若界面节省小于额外等待/纠错/维护，先暂停扩展并重新评估完整首版投入。真实调用/新实验需授权，不能自动补图。

### V4｜完整首版装配前：公式选择的两条候选对照

- **假设/前置：** 成熟只读数学控件可比自建源码映射更低成本地满足已确认局部选择；只使用合成LaTeX，固定候选版本，经授权准备最小隔离页面。
- **操作：** 同批分式、上下标、根号、矩阵、积分上下限、多行等式和中文混排，逐项用鼠标选符号/子式，记录可见范围→导出表达→源消息修订；再验流更新、缩放、键盘焦点、深浅色与离线字体。
- **指标：** 选取正确性、所需操作、丢失/多带内容、不可选结构、所需私有API/源码修改及额外渲染成本。
- **通过/失败：** 选区与预览/输入表达一致，有稳定公开接口可维护，不要求用户重打LaTeX或截图。仅整式可选、经常多带未选内容或必须依赖大量私有DOM即该候选未通过。
- **失败处理/授权：** 比较另一候选/有限映射，保留T整式引用但不称W完成；确需重大范围取舍时再建议用户重新决策。需新增实验/安装授权；不需要真实模型或真实视频。

### V5｜完整首版文档能力交付前：实际格式与原页引用

- **假设/前置：** 固定PDF.js与Office Kit闭包可让用户在软件内读其数学资料并选取提问；用户提供/确认代表文件，精确Kit源码/制品/运行库/许可已对齐。
- **操作：** 文字/扫描/混合PDF分组；DOCX/PPTX及实际需要的旧DOC/PPT分别转换。检查公式、字体、图形、分页、区域/文字选择与原来源；源改版、取消、失败和缺字体再验。PDFium按受控串行/进程方式使用，不在线程里任意并发调用。[官方线程边界](https://pypdfium2.readthedocs.io/en/stable/python_api.html#incompatibility-with-threading)
- **指标：** 可读性/缺损，选择坐标/引用页正确性，缓存版本、取消释放、转换占用和实际分发体积。
- **通过/失败：** 代表文件的数学内容不被静默改变，选择内容与原页一致，错误可处理；未通过格式明确列为不支持/待补证，不能统一宣称“Word/PPT全兼容”。扫描区域图片提问与扫描文字选择各自报告。
- **失败处理/授权：** 先修运行库/字体和转换参数，仍失败才对照独立LibreOffice；同一接口内替换，不建第二套来源/队列。若真实核心资料无法阅读，提交证据与最小格式取舍供用户重决策。下载原生包、环境准备和新实验均需授权。

### V6｜完整首版字幕交付前：数学语音时间轴与前台并行

- **假设/前置：** 本地worker能产出有用辅助字幕，时间轴及手改可靠，后台资源档位可降低干扰；锁Python/wheel/DLL/模型snapshot，并授权必要音频窗口，不解码视频画面。
- **操作：** 先少量30—60秒含数学术语、字母、正负号、上下限、静音和段边界的音频，保存原始segments/人工听写/绝对时间；核越界、偏移与重叠。再与无ASR基线对照：实际播放器、截图、输入、Harness活动回答同时运行；暂停批量后仅处理按需片段，改字幕后迟到回报，worker崩溃/释放/重载；最后延长运行观察温噪与资源。
- **指标：** 有意义文字与关键术语错误、绝对时间偏差/越界、覆盖、重复、当前片段等待、播放/输入/截图卡顿、内存/显存、温噪和释放。时延阈值根据可感知影响及预先选定基线确定，不从单段峰值虚构。
- **通过/失败：** 不把越界/对不上的片段发布为可信定位；人工抽样能回到对应讲解，关键错误影响明确；手改与已提交片段保留，暂停意图不复活；默认与加速均不破坏前台。未定义人工时间容差前不称对齐合格，单纯数值截断不算通过。
- **失败处理/授权：** 先修分片/对齐/DLL/调度，一次改少量变量；无证据不归因显卡不足，不自动改云端ASR或恢复AI纠错。需额外实验授权，模型可优先使用已校验缓存；不得未经允许下载权重或整课跑测。

### V7｜完整首版交付前：资产迁移与 Windows 实际运行

- **假设/前置：** 同一持久层、附件清单、进程管理与对账可支撑整体迁移和无开发环境日常使用；准备明确授权的干净Windows普通用户环境及合成业务资产。
- **操作：** 一组含聊天/多图/公式/手改/来源版本的fixture，导出不含/含原件两种包；空目标导入、已有数据/损坏/缺附件拒绝、跨盘目录迁移中断；无网络/无后台打开查看包。用构建/解压制品双击，关闭网页后台继续，任务中退出；故障注入业务/Harness/worker，睡眠唤醒/合盖、端口冲突、设置默认与主动启用、更新只检查不安装。
- **指标：** 资产/顺序/修订/hash、错误后原数据是否可用、离线资源请求、路径/占用真实性；进程归属、停止/恢复、重启次数、暂停与未知AI状态、实际依赖/体积。
- **通过/失败：** 没有自动覆盖已有目标或丢资产，切目录失败旧位置可继续用；无需安装软件即可离线看聊天公式截图。无终端/开发环境能启动，组件故障不拖垮其他学习能力，退出清理自己进程，恢复有限且不自动重发未知AI，设置默认符合已确认规则。
- **失败处理/授权：** 分别修迁移发布和运行管理，不能以“用户自行复制数据库/手动启动组件”当通过；工程恢复不扩成历史备份产品。需新增实验/打包环境授权；本地fixture可验证大多数故障，不用真实付费模型反复崩溃测试。

知识库不另开无目标的“RAG跑分”：到用户指定用途讨论时，先收口任务/材料/验收，再对真正可能改变关键词/语义/解析选择的少量样例验证。Android/tsnet异地/VPN/实时草稿只列后续门槛，当前不执行、不前置。

### 6.2 数学验收建议样本与失败判定

建议试用前建立约18个基础案例的轻量集合，**这是验收设计建议，尚无对应题图或已执行结果**。不为凑题数下载题库或从视频抽帧。可先使用用户主动确认的题图与合成脱敏材料；配可核答案/推导，人工判定为主，确定性计算仅辅助适用的等式/数值核查，不默认让第二模型裁判。

| 样本组 | 建议数量 | 代表内容及观察 |
| --- | ---: | --- |
| 高等数学 | 6 | 极限/可导条件；定积分/反常积分；级数收敛；多元求导/极值；二重积分带区域图；综合证明。覆盖上下限、定义域和不同题目复杂度 |
| 线性代数 | 3 | 含参数矩阵的秩/方程组；特征值/特征向量；二次型。覆盖矩阵行列、参数分支和符号引用 |
| 概率统计 | 3 | 条件概率；联合密度与积分区域；期望/方差或参数推断。覆盖分段条件、范围和图表 |
| 手写过程与局部追问 | 3 | 正确过程求继续；某步错误求定位；方法不能继续需说明原因。题干与过程可分图，不能看漏其中一张 |
| 输入/纠正边界 | 3 | 关键符号模糊/图形缺失；明确更正条件后重答；正确答案遭错误质疑。观察必要追问、采用新条件和不盲目改口 |

从这些案例中选几例再做连续追问、长历史/压缩、重开与模型/思考变更，不必把所有题对所有设置做全排列。用合成资料另验权限/恶意指令，不用用户隐私图做安全fixture。

每例分开记录：

| 问题类别 | 失败判定 | 优先排查 |
| --- | --- | --- |
| 图像/读题 | 实际输入可辨却漏负号、上下标、条件或手写步骤，单次即记该例失败；缺必要图却自造条件同样失败 | 裁剪/规范化/请求图片与模型视觉，不能只改prompt |
| 推理 | 条件读对但关键论证、定理前提、运算/结论错误，或错误坚持 | 模型/思考配置、题型适用性和具体解释；不默认常驻复核 |
| 上下文 | 原图/文字仍在业务历史，却未进入本轮有效上下文；纠正后仍用旧条件 | 快照、压缩/offload、修订与绑定，不增加泛化“记住”提示掩盖程序遗漏 |
| 检索 | 输入充分仍查库；确有资料需求却不查；字幕未就绪被写未命中；无外部需求却联网 | 工具策略、权限、覆盖与来源，不复活找题 |
| 交互/保存 | 选区与发送范围不同，流是假回放，活动停止无效，重开丢图/串聊 | UI、事件/取消、持久层和对账 |
| 时间/有用性 | 首字很早但实质内容晚；早出方法后来推翻；多次追问才得到默认应给的完整答 | 分开记录有用内容、完整答与返工，不能只用TTFT |

数学试用门槛应由这些实际证据和用户使用判断确定，不预设准确率。每例按读题、推导、纠正和交互分别记通过/失败，任何漏关键条件或错误推导都不能因“尚未反复”免记失败。出现同类关键失败时，先定位根因、修正后复测原例及至少一个不同题的同类案例；再次失败则记为尚未解决的适用性问题，连同原始结果交用户判断是否适宜试用，不能只换一道容易题宣称解决。最小要求是代表性常见问题能按正确条件给可核完整解释；所有严重数据/权限/重复执行问题必须修复。复杂题失败如实保留并评估其对日常用途的影响，不能隐去难题得到漂亮比例。样本规模不足时只报逐例结果和观察分布，不宣称p95、全面正确或固定节省比例。
