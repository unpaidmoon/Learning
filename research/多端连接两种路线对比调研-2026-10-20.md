# 多端连接两种路线对比调研

讨论日期：2026-10-20。阶段：需求讨论；本次只查阅官方文档与源码，没有安装客户端、构建应用、开通服务器、部署隧道或进行网络实测。

## 1. 已确认事项与本次问题

用户已确认：Windows 在家开机联网时，手机或平板在外使用校园网、移动流量，必须能访问电脑资料、播放视频并使用电脑上的 AI 能力。

用户要求分别调查：

- A：Windows、Android 手机和平板额外安装并登录连接工具，学习软件使用该网络。
- B：连接集成到自有学习软件，用户无需另装连接工具。

以下建议尚未成为需求决定。Windows 为核心、业务数据自有、资料原地引用、后续才做完整 Android 与同步的既有原则保持不变。本调研不展开 Android 界面或视觉设计。

## 2. 先看结论

**两条路线均有技术路径，但承担复杂性的地方不同。** A 主要由成熟客户端负责组网、打洞和中继；B 可以复用成熟连接栈，也可以使用应用自身的公网 HTTPS 服务与中继，产品需要承担更多设备配对、连接状态和升级维护。

**建议把外置 Tailscale 作为未来网络验证的对照基线，暂不定稿。** 若不能接受 Android 与已有 VPN 的冲突，或“无需额外安装”是必要要求，应认真比较 B。B 无需自行发明加密或打洞协议，也不等于无需服务器、账号或持续费用。

| 比较项 | A：外置连接工具 | B1：内嵌连接栈 | B2：应用 HTTPS/WSS＋直连或中继 |
| --- | --- | --- | --- |
| 首次操作 | 安装、登录/加入网络、授权；学习软件再配对 | 安装学习软件，应用引导连接身份授权与配对 | 安装/打开学习软件、配对；服务部署由维护方承担 |
| 日常目标 | 连接工具常驻，打开学习软件即用 | 学习软件管理连接生命周期 | 学习软件自动接入自有服务、协商或选择路径 |
| Android VPN 槽 | VpnService 客户端占用一个活动服务名额 | 纯进程内 userspace 可以不占；若仍用 VpnService 则同 A | 普通应用网络通信不因本方案额外申请 VpnService |
| 浏览器/播放器复用 | 虚拟网络 IP 可供普通 HTTP 客户端访问 | 必须把内嵌拨号接到 HTTP/播放器/本地桥接 | 公网 HTTPS 可复用；WebRTC DataChannel 需媒体适配 |
| 直连失败 | 由工具按实际网络回退中继 | 复用栈可提供回退，仍需验证 | 项目必须提供中继、失败回退与重连 |
| 持续运维 | 商业服务承担一部分；自建控制/中继另算 | 依赖栈更新＋应用绑定层＋控制/中继 | 自有入口、证书、鉴权、信令、中继与流量 |
| 主要未知 | 实际校园网/运营商路径、VPN 并用 | Windows/Android 构建与生命周期、播放器接入 | 部署和流量预算、跨网络成功率、媒体适配 |

表中工作量、适配方式为本项目的工程判断；底层事实见以下官方依据，不能据此声称任一路线已兼容或已验收。

## 3. 路线 A：额外安装成熟工具

### 3.1 Tailscale

Tailscale 的连接包括 UDP 直连、DERP 中继和 tailnet 内指定的 Peer Relay。直连受两端 NAT、防火墙及 UDP 可用性影响；不能直连时可用中继。三者均使用 WireGuard 端到端加密，但 DERP 的吞吐和服务质量有限，不能把“连得上”等同于“视频必定流畅”。连接类型可用 `tailscale status` / `tailscale ping` 检查。[连接类型](https://tailscale.com/docs/reference/connection-types)、[DERP](https://tailscale.com/docs/reference/derp-servers)

对本项目的含义：现有 HTTP 资料、Range 视频与问答事件接口可以通过受限虚拟网络访问，不需要把媒体业务改造成远程桌面。应用仍需设备配对和用户鉴权，仅允许学习服务端口与接口；不把整个家庭局域网或 Harness 内部接口默认开放。这是项目设计建议，Tailscale 的机器注册密钥负责设备入网，并非学习用户登录。[Auth keys](https://tailscale.com/docs/features/access-control/auth-keys)

当前官方价格页提供个人非商业用途免费方案；**不能把源码许可、个人服务套餐和未来对外发布产品的使用条件合并理解**。本报告不固化设备数或价格，采用时重新核对账户实际套餐；自建中继、服务器公网流量和手机流量另计。[官方价格与用途说明](https://tailscale.com/pricing)

### 3.2 Android 与其他 VPN 的关系

Android 官方规定：每个用户或工作资料同时只有一个活动 `VpnService`，启动新服务会停止已有服务；首次还需要系统授权。分应用路由不产生第二个同时活动的 VPN 服务。该限制适用于采用此系统接口的 Tailscale、ZeroTier、WireGuard 等 VPN 客户端路线，**不适用于一切普通 HTTPS 连接**。[Android VPN 官方说明](https://developer.android.com/develop/connectivity/vpn)

因此有必要继续确认：用户是否需要连接学习电脑的同时保留现有 VPN、代理或网络加速工具。代理不一定采用 VpnService，不能仅凭“代理”名称判定冲突；是否并用需看实际工具、路由、DNS 和设备策略。把连接栈移入学习软件但仍使用 VpnService，不能消除此限制。

### 3.3 ZeroTier、Headscale、原生 WireGuard 的定位

| 候选 | 与 Tailscale 路线的差别 | 对本项目的判断 |
| --- | --- | --- |
| ZeroTier | 建虚拟网络，设备加入 Network ID 后在控制台授权；支持 Windows、移动客户端 | 可作另一个网络实测对照，不因同属组网工具就假定更快或更适合本地网络 |
| Headscale | 自托管 Tailscale 控制服务器的替代，仍需兼容的 Tailscale 客户端；与官方控制面的功能不完全一致 | 可减少对托管控制面的依赖，不能减少用户端安装；增加公网服务、TLS、版本兼容与运维 |
| 原生 WireGuard | 配置密钥、Endpoint、AllowedIPs 和必要的 NAT keepalive | 适合愿意自管公网入口/网关的场景；协议本身并不交付完整的设备发现、登录、自动中继和学习应用配对体验 |

ZeroTier 的加入与授权流程见[官方入门](https://docs.zerotier.com/start/)。其官方说明 UDP 点对点优先，TCP relay 是较慢的回退；自建 relay 要额外服务器。不能由官方桌面配置示例推导每个 Android 客户端都有相同配置能力。[TCP Relay](https://docs.zerotier.com/relay/)

Headscale 官方定位是控制服务器替代；其要求包括公网 IP、HTTPS 及现代 Linux/BSD 服务环境。功能是否覆盖某项 Tailscale 能力，应逐项核对目标版本，不把它称作官方服务的完整镜像。[功能范围](https://headscale.net/stable/about/features/)、[部署前提](https://headscale.net/stable/setup/requirements/)

WireGuard 官方 quickstart 展示 Endpoint、密钥与 `PersistentKeepalive` 的配置。对复杂 NAT 的穿透和无法直连时的公网网关，需要额外设计；keepalive 只维持映射，不让不可达端点自动变成可达。[WireGuard Quick Start](https://www.wireguard.com/quickstart/)

许可核查需要区分版本与组件。截至讨论日可定位的 ZeroTierOne 提交 `899352e38405968516bb12a770f0ac02f6058fa8`（2026-07-22），根许可将核心 Agent 代码列入 MPL-2.0，将 `nonfree/` 指向独立 Source-Available 许可；后者包含特定非商业范围与商业授权条件。不能沿用“整个项目一律 BSD/BSL”或“公开源码即可随意内嵌”的判断。外置个人使用与内嵌分发应分别核对所用制品。[根许可](https://github.com/zerotier/ZeroTierOne/blob/899352e38405968516bb12a770f0ac02f6058fa8/LICENSE.txt)、[nonfree 许可](https://github.com/zerotier/ZeroTierOne/blob/899352e38405968516bb12a770f0ac02f6058fa8/nonfree/LICENSE.md)

## 4. 路线 B：集成在自有学习软件

### 4.1 B1：复用内嵌连接栈

`tsnet` 官方定位是**在 Go 程序内嵌 Tailscale 的库**，采用 userspace 网络栈。它可以给程序自身提供 tailnet 身份和连接能力，不要求把程序所在设备全局接入虚拟网卡。它不是开箱即用的 Kotlin/Android 移动 SDK；Android 授权回调、JNI/Go 绑定、网络切换、休眠恢复、HTTP/播放器接入仍需项目实现并验证。[tsnet 官方文档](https://tailscale.com/docs/features/tsnet)

`libtailscale` 是通过 C 接口将 Tailscale 嵌入进程的项目，仓库采用 BSD-3-Clause；源码许可要求保留相应声明，但不同时授予托管服务套餐或商标使用权。其 README 给出 Go C archive/shared 构建方式，并未提供可直接承诺本项目 Windows＋Android 兼容的移动 SDK 支持矩阵。[仓库说明](https://github.com/tailscale/libtailscale)、[固定提交许可](https://github.com/tailscale/libtailscale/blob/d1dc45d039edb7759ecbee6ba2aea0c4bca884b8/LICENSE)

**已查到具体平台边界：**固定提交 `d1dc45d039edb7759ecbee6ba2aea0c4bca884b8`（2026-10-14）的 C 封装 `tailscale.go` 导入 `golang.org/x/sys/unix`，调用 `syscall.Socketpair`、`UnixRights`、`Sendmsg`；不能把这份 C 封装称为 Windows 直接可用。Makefile 有显式 iOS 构建目标，也不足以证明 Android 绑定、各 ABI 和前后台行为已兼容。Windows 可另评估 Go `tsnet` 侧桥接或平台适配，不能据 C API 名称直接选型。[固定源码](https://github.com/tailscale/libtailscale/blob/d1dc45d039edb7759ecbee6ba2aea0c4bca884b8/tailscale.go)、[固定 Makefile](https://github.com/tailscale/libtailscale/blob/d1dc45d039edb7759ecbee6ba2aea0c4bca884b8/Makefile)

工程推论：如果仅让本应用通过进程内网络栈拨号，不建立系统 VPN，则可以避免由本应用额外占用 VpnService 名额；但连接仍可能受现有 VPN 的底层路由和阻断规则影响，**不能承诺与所有 VPN 同时兼容**。嵌入方案还需要控制面登录/设备注册及直连失败后的中继；“不另装客户端”只解决安装体验，不会移除网络基础设施。

浏览器和原生播放器不会因某个进程拥有 tailnet IP 就自动使用它的 Dial。需要实现受控的 HTTP 适配、本地桥接或播放器数据源，确保鉴权、Range、取消、缓存和恢复语义保持一致。该项是项目推论，尚未编译验证。

### 4.2 B2：应用协议＋公网入口或成熟 P2P

一种较容易解释和维护的组合是：Windows 学习服务主动连接已认证的公网入口，手机通过 HTTPS 访问；问答状态与事件通过可恢复的 WSS/HTTP 事件接口传输，视频走可寻址的 Range/分段读取。若以后加入直连优先，可使用成熟的 WebRTC/ICE 机制，公网服务承担信令和必要的 TURN 回退。这是候选架构，不是现阶段开发任务。

WebRTC 官方说明信令不属于 WebRTC 标准，应用必须自行提供；很多网络无法建立直接连接，需要 TURN relay。因此只写“支持 WebRTC/STUN”不能构成异地必达方案；TURN 的容量、鉴权、可用性和带宽费用仍由部署方承担。[Peer connections](https://webrtc.org/getting-started/peer-connections)、[TURN server](https://webrtc.org/getting-started/turn-server)

WebRTC DataChannel 提供任意数据的 send/message 接口，**不会直接成为 HTML 视频元素的 HTTP Range URL**。对本项目本地课程视频，需要适配分块读取、seek、背压与播放器，或保持经 HTTPS 的媒体路径；不要因为 WebRTC 支持实时音视频就假定原有播放器无需改造。[Data channels](https://webrtc.org/getting-started/data-channels)

QUIC 是基于 UDP 的安全多路传输，可支持连接迁移与 NAT rebinding；它本身不是设备发现、NAT 打洞或中继服务。采用 QUIC 仍需可达端点、鉴权、失败回退，且 UDP 受阻时必须有其他路径。[RFC 9000](https://www.rfc-editor.org/rfc/rfc9000.html)

### 4.3 frp 或 Cloudflare Tunnel 能否简化 B

frp 可作为 Windows 主动出站的隧道组件。普通公网 HTTP/HTTPS 反向代理适合手机浏览器访问，但服务器、证书、应用登录和媒体授权仍要维护。其 token/OIDC 认证针对 `frpc` 与 `frps`，不能替代学习用户认证。[frp Authentication](https://gofrp.org/en/docs/features/common/authentication/)

frp 的 STCP/SUDP 要求服务端机器和访问端机器都运行 frp 客户端，因此“手机只打开网页”不能直接使用 STCP；若内嵌到原生应用，还需客户端集成。XTCP 可尝试点对点打洞，官方明确稳定性和成功率无法保证，可配置回退 STCP；仍须保留可用中继。[STCP/SUDP](https://gofrp.org/en/docs/features/stcp-sudp/)、[XTCP](https://gofrp.org/en/docs/features/xtcp/)

Cloudflare Tunnel 可以避开家庭路由器入站开放，但 **不能将免费 public hostname 隧道当作无条件的大视频中继**。官方 FAQ 明确：Free/Pro/Business 的公网 hostname 路由，视频和大文件需要适用的付费服务；私网路由不受该项约束，但通过 Cloudflare One Client、Mesh 或 WAN 访问，不能据此承诺“无需额外客户端的免费纯网页视频方案”。因此可调查其小型控制接口适配，但不作为本项目大视频的默认免费路线。[Tunnel 官方 FAQ](https://developers.cloudflare.com/cloudflare-one/faq/cloudflare-tunnels-faq/)

另有混合候选 Tailscale Funnel：Windows 运行 Tailscale，手机用普通浏览器访问公开 HTTPS 服务，不必在手机安装 Tailscale，也不必自行租用 VPS。其官方文档仍标 beta，流量经 Funnel relay，存在不可自行配置的带宽限制；公开入口须由本应用另做用户鉴权，不能将其与仅供 tailnet 访问的 Serve 混同，也不能据此保证视频体验。它是 B 的托管公网网关备选，而非已选方案。[Funnel 官方说明](https://tailscale.com/docs/features/tailscale-funnel)

## 5. 两条路线都必须承担的产品行为

以下为根据既有项目原则提出的设计与验收建议，未新增决定：

1. **配对与鉴权**：首次由用户确认设备，凭据可撤销；公网入口或 tailnet 地址只暴露学习 API，Harness 的内部 token、Peer、任意文件和系统操作不成为移动接口。
2. **视频路径与开销透明**：直连、中继、断线区分显示；家庭上行、手机下行与中继可用带宽共同限制传输。中继不减少 Windows 发出原文件的上行；除非另外缓存/转码，原件仍由 Windows 提供。是否缓存、转码另议。
3. **资料与同步分开**：连接工具只提供可达性，不会实现聊天合并、学习进度冲突、附件恢复或来源版本检查。聊天/记录/目录使用自有增量同步与稳定 ID；大文件按需获取，不能同步打开中的 SQLite 文件来替代业务协议。
4. **断线继续与对账**：Wi-Fi 切移动网络、应用重开后恢复事件游标和资料读取；已提交 AI 请求执行结果未知时先查状态，不能因重连直接再次计费生成。停止请求也需查明其最终状态。
5. **电脑不可用状态**：区分连接工具不可达、Windows 学习服务未运行、电脑睡眠/断网及来源文件缺失；不能把配置了隧道当作电脑永远可用。关机/离线时的安卓独立能力仍按议题 3 细化。

Windows 系统电源状态不同，休眠状态通常不继续执行应用；不能承诺 VPN 可以唤醒任意睡眠电脑。[Windows 电源状态](https://learn.microsoft.com/en-us/windows/win32/power/system-power-states)

Android Doze/App Standby 会延后后台网络与同步，内嵌长连接并不自动获得持续后台执行。应优先保证用户打开软件后可恢复；屏幕关闭后的即时后台同步、推送和保活需另行验证。[Android Doze 官方说明](https://developer.android.com/training/monitoring-device-state/doze-standby)

容量估算可采用 `流量 GB ≈ 视频平均码率 Mbps × 播放秒数 ÷ 8 ÷ 1000`；实际需加入协议开销、回退、重复下载和并发。项目技术原则第 10.2 节已记录样片为 510,261,596 bytes、12,300.817188 秒，确定性计算文件平均约 **0.332 Mbps**，包括音轨与容器；这不是峰值，也不能代表全部课程或保证不卡。费用应以未来选定的服务器地域、带宽/流量计费和实际观看量报价，不虚报固定月费。

## 6. 后续决策和验证门槛

需求层面优先继续确认：是否必须与已有 VPN 同时使用；是否接受首次外置工具安装；是否愿意承担公网中继的持续费用和维护。先明确取舍，再选择路线。

恢复实施后才进行以下验证：

| 验证 | 必须记录的证据 |
| --- | --- |
| 异地网络 | 用户实际家庭网＋校园网＋移动网络，分别记录直连/中继/失败；不只测同一 Wi-Fi |
| 视频 | 原码率课程播放与多次 seek、Range 正确性、长时间缓冲、链路切换；记录家庭上行及路径 |
| VPN 并用 | 实际现有工具、Android 版本、路由和 DNS；区分系统 VPN 与应用代理 |
| 应用恢复 | Windows 重启/服务退出、Android 后台与进程终止、睡眠恢复、凭据过期与撤销 |
| 问答对账 | 流中断后接续、重复提交保护、生成状态未知时查询、停止请求与最终状态 |
| B1 构建 | 固定依赖提交和构建工具，Windows/Android 目标 ABI 实际编译；HTTP/播放器真实接入 |
| 中继成本 | 目标地域实际可用性、吞吐、流量统计、报价和故障切换，不用官网覆盖地图替代 |
