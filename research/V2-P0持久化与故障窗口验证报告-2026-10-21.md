## 三侧身份、事件水位与用量

Host 相关用例同时保留业务 `chat_id/submission_id/generation_id/binding_id/epoch`，适配 `session_id/request_id/native_floor/native_turn`，Host page 的实际 cursor、event seq/type/turn，以及 provider boundary request ID、请求 hash、模式、图片 hash 与 raw usage。观察批次序号与原生事件水位明确分开，持久事件幂等依赖稳定 event ID；原生 seq 不被伪造为应用摄入计数。

用量保存 provider SSE 原始字段、字段存在性、是否 settled 及一次性结算身份。正文完成且输出用量缺失时仍为 unknown；取消没有最终结算时不把 message_start 的零初值当最终零。已完成历史只是业务记录，没有伪造 provider event 或 usage。

## 实施修复、原失败与复测

实施过程中审查并修正了：Service 与不可变输入快照的接缝、图片与更正的实际上下文构建、snapshot 正文恢复、同 binding 跨 generation 观察序号冲突、真实 boundary attempt 的业务映射、provider usage 包装的归一化、未派发 pending 的取消 fence、历史稳定 revision ID，以及晚到用量观察与固定结算身份。各自正式单元／契约测试由模块测试记录覆盖，V2 实跑使用修复后的正式路径。

保留两次 runner／fixture 失误，不当作产品恢复失败删除：

- `v2-storage-preflight-20261021` 的 V2-13 先构造了仍 pending 的旧问题，得到正确的 `CHAT_EXECUTION_ACTIVE`，未抵达拟验证的缺图窗口。修正为明确的存储层终态 fixture 后，`v2-storage-preflight-20261021-r2` 四项通过；没有冒称该规范化 fixture 是真实 provider 事件。
- `v2-first-host-20261021` 的 V2-06 错误要求崩溃后必须为 unknown；实际业务保持 running 且终态未提交，同样符合正确窗口。断言改为业务尚未终态，随后 `v2-terminal-host-restart-20261021` 对 V2-04／05／06 复测通过，并加入整个固定 Host 重启证据。

`v2-all-host-preexport-20261021` 整轮 V2-01～14 通过，共 10 次本地 Messages、真实模型 0 次；并行模块当时仍在收口，`source_changed_during_run=true`，因此只作预验收，不当作最终冻结结果。

当前源码的 V2-15 独立证据为 `output/playwright/p0-browser-cancel-security-final-20261021/security/v2-15-result.json`，汇总副本与三侧摘要在 `.runtime/validation/v2-browser-cancel-security-final-20261021/v2-15-result.json`。实际 `gate_waiting` 事件 sequence 19 后，浏览器已显示 36 字正文且停止按钮可用；点击后业务和 native 均 cancelled、部分正文完全相等、边界 I/O 断开且 Host 仍存活。后续追问在同 session／epoch 1 完成，旧正文不变。非法 WS 的浏览器关闭码 1006 是握手被 HTTP 拒绝的表现，不声称握手后 1008 关闭；错误来源 `/api/v1/exit` 的 403 只证明路由前统一来源 guard，当前没有正式退出 API，未据此宣称退出功能验收。此前仅安全组的证据保留，不覆盖或替代本次按钮复测。

正式应用 HTTP API 的首轮真实模型测试另外暴露取消未确认；原执行最终已知 completed，保留 1 次真实 attempt，没有自动重发。第二轮仅公平调度修复后，取消进入时 native 已完成，该轮未覆盖活动停止，正确保留 completed。根因是缓冲队列非空时没有让出调度，加上每段重复持久化已知 attempt／不变绑定，造成事件循环饥饿和显示滞后。正式窄修保留每段内容事务，在摄入后公平让出，重复映射仅在变化时保存；没有强置 cancelled、放松终态或回放最终文本。

修复后的正式 HTTP 真实模型验收有活动正文停止、部分内容保存、同聊天更正后追问，以及全应用重启后不重派发的实证；9 次本轮真实调用及此前 V1 的 8 次分别见 [P0 报告](P0-正式工程与执行数据基础验收报告-2026-10-21.md)，不混入 V2 fixture 计数。V2 的修后相邻回归包括本轮 V2-14 与新浏览器按钮组，以及 [`test_v2_http_cancel.py`](../backend/tests/test_v2_http_cancel.py)：实际 1000 段 reasoning SSE 到达门控后，正式 HTTP cancel handler 在仅 42 段／378 字符已入库时进入，单次 HTTP 请求耗时约 0.141 秒，Host 最终 cancelled、已生成的 9000 字符思考完整保留。该独立回归只有 1 次本地请求、0 次真实派发，`source_changed_during_run=false`，身份与原始记录引用已附入最终 JSON；不将一次合成观测推广成普遍性能承诺。

`v2-final-20261021` 预收口运行虽 14 项行为通过，但期间浏览器验收脚本按根任务增加按钮测试，冻结检查使其退出 1、状态 incomplete，未当作最终通过。随后待正式源码与验收脚本全部冻结，再执行本报告的 `v2-final-20261021-r2`，15 项全部通过；原运行记录保留。

## 清理与未覆盖

每个正式 Host 由本实例 Job Object 管理，最终记录剩余 PID 和端口关闭；普通停止使用 `session/cancel`，不以关闭观察连接或结束宿主代替。worker 退出只影响其自身，故障目录检查限制在 `.runtime/validation` 下；合成崩溃证据与已发布对象保留，不递归删除用户资产。

P0 采用明确的 lossless 上下文策略，尚未验收长历史压缩／长期资源占用；该聊天依赖的历史图片缺失时会阻止继续使用该上下文，可另开新聊。本轮没有建立上下文管理 UI、Android 或同步系统。电脑睡眠、掉电、介质物理损坏、正式安装包与双击交付不在 V2 证明范围，按后续运行阶段验证。完整视频截图交互、用户实际数学场景、主要学习流程和 10 秒体验目标仍需 MVP-A／V3，不据此称完整首版可用。
