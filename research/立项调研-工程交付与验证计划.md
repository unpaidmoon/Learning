# 立项调研：工程交付、依赖记录与验证计划

日期：2026-10-19（Asia/Shanghai）。

定位：个人 Windows 学习工具的工程立项依据。保持已确定的 Windows Harness 执行层、自有业务数据、后续安卓独立客户端路线；不以学习掌握度实验、商业市场规模或个人投入回报作为本轮立项条件。

## 1. 交付对象与运行方式

首版交付一个可启动、可暂停、可明确退出的本地应用：定制浏览器界面、项目业务后台、Harness 执行宿主、按需启动的 Python ASR worker。

- 开发态可使用 Vite 与 Python 独立环境；用户日常运行应由一个启动入口管理后台和浏览器。
- 关闭网页不结束后台任务；明确退出才关闭所属执行进程，避免遗留 worker 和占用显存。
- 运行组件、业务数据、模型缓存与临时处理目录分开。应用升级不替换学习数据目录。
- 项目独立 Harness home，不复用用户其他工作的默认 profile、凭据与执行日志。
- Web Host 的内部 Peer/Cookie 只归业务后台，不将其当作安卓同步身份。
- 本地业务模块与 Harness 插件通过小接口衔接，固定协议与契约样例，不把内部事件直接变为跨端消息协议。

Python SDK 打包运行时与 npm 启动路径的依赖不同，不能统一表述成“只需要 Python”或“一定要额外安装系统 Node”。具体制品以本轮发行核查和 P0 为准。

## 2. 版本冻结对象

冻结的不只是几个版本号：

1. Harness 源码提交、发行版本、目标 Windows 制品及其哈希。
2. 选定 profile、应用 patch、插件 bundle 与完整依赖闭包。
3. Web Remote／SDK 接入契约样例、序列化与事件投影版本。
4. 项目 Python 解释器及实际 SQLite 运行库、CUDA／cuDNN／cuBLAS DLL 来源。
5. FFmpeg 可执行版本、构建配置和路径。
6. ASR 模型来源、revision、计算类型、VAD 与切段参数。
7. 前端锁文件、React/播放器/裁剪器组合及公式渲染配置。
8. 数据 schema、导出格式、快照投影与检索器版本。

`latest` 标签不是冻结策略，源码包的版本字符串也不证明装到的发行制品与之相同。虚拟环境仍可能继承解释器自带的旧 SQLite。云端 DeepSeek 别名可能升级底模，需记录实际响应标识与测试基线，而不能承诺冻结服务端权重。

### 3.2 本机 FFmpeg 构建不是笼统的 LGPL 版本

本轮执行 `ffmpeg -hide_banner -L`，本机可执行报告 GPL-3.0-or-later；`-buildconf` 包含 `--enable-gpl`、`--enable-version3`、`--enable-libx264`、`--enable-libx265`。

官方说明 FFmpeg 默认许可与启用可选部分后的许可不同，因此交付清单必须按实际构建记录，不能只写项目名称。[FFmpeg 官方许可说明](https://ffmpeg.org/legal.html)

原型可显式使用本机现有 FFmpeg；正式交付再决定依赖既有程序还是附带已核对的制品。不由这一次命令输出推断整个项目必须采用某种许可。

## 4. 安装与打包应独立验收

先保证锁定环境中的一键启动，再验证打包；不将“开发机能 import”当作可交付。

若采用 PyInstaller，官方列明 Windows DLL 搜索路径会影响子进程、无控制台模式可能没有 stdin/stdout/stderr，多进程还需 `freeze_support()` 等处理。这些条件直接涉及 Harness、FFmpeg、GPU worker 的启动，打包后必须重测。[外部程序与 DLL](https://pyinstaller.org/en/stable/common-issues-and-pitfalls.html#launching-external-programs-from-the-frozen-application)、[多进程](https://pyinstaller.org/en/stable/common-issues-and-pitfalls.html#multi-processing)、[PyInstaller 许可](https://pyinstaller.org/en/stable/license.html)

推荐交付验证项：

- 冷启动时识别有效后台实例，避免重复绑定端口或重复转写。
- 自动打开项目界面，官方 Harness 界面不必显示；后台进程不弹出多个控制台。
- 用户主动选择课程目录时使用 Windows 文件选择能力，取得真实路径，不复制几十 GB 视频。
- 运行程序通过确定路径寻找 FFmpeg、Harness 与模型，不依赖用户恰好配置好的全局 PATH。
- 接入内部 Peer、WebSocket 丢失时重新建立连接，并校准已提交执行状态。
- 关闭网页后任务继续；暂停、退出、重启后状态和处理进度明确。
- 显式启动器环境配置只影响其子进程，避免改变系统全局环境。
- 安装包不包含用户 API key、Host token、Cookie、聊天或绝对路径诊断样例。

## 5. 持久性、备份与恢复

业务 SQLite、附件文件、原地引用原件、Harness 执行日志是不同的持久域，不能假定一个数据库事务就涵盖全部内容。

推荐顺序：先保存并验证用户附件，再在业务事务发布消息与引用；执行事件通过独立摄入记录幂等投影到消息。未发布的产物可回收，已被聊天引用的截图与人工字幕修订是用户资产，不作为普通缓存删除。

备份与同步分开：

- 备份保存业务 schema/消息、人工修订、已提交附件、导出清单和来源版本。
- 原片默认原地引用，备份是否包含原件应在导出选项中明确；文件被覆盖后不能假装仍可打开旧原视频。
- 索引可以重建，但检索器、解析器、源版本需记录，避免新旧向量或页码混用。
- Harness 日志用于执行恢复与诊断，不能直接成为安卓数据协议，也不把运行中的 SQLite 文件当同步单元。
- schema 升级前留可恢复副本，迁移失败保留原文件；索引升级可以重建，不能连带清除聊天。
- 重连、崩溃或付费请求结果未知时先对账原执行，不自动再次 prompt。

## 7. P0 进入实现的验证标准

以下标准为立项建议，需要在实际原型中执行，不能以文档核查标记通过：

### 7.1 执行和输入边界

- 用户已提交图片、文字正确进入模型请求；裁剪外原帧和相邻视频画面不在可见内容或工具返回中。
- 输入充分时，字幕为空、转写在后台、知识库未完成，都不阻塞回答。
- 请求使用应用提交身份与真实 Harness 会话/事件建立映射，不能只取下一次 idle 的最后文本猜归属。
- 停止回答调用真实取消，不能仅断开前端流或结束等待；不影响其他独立后台任务。
- 同一消息重复投递不会新建第二次业务生成；执行结果未知时先对账，不能声称云端恰好一次计费。

### 7.2 业务接续与来源

- 构造 Windows U1/A1、安卓离线 U2/A2、再次 Windows U3 的业务样例；无需先交付安卓应用。
- 合并两次 U2/A2 后，业务记录各一份，不调用旧问题；U3 的上下文含必要既有问答和已提交图片。
- 源文件移动后只更新本地定位，稳定资料身份和聊天来源不变。
- 原文件被新内容覆盖后，旧消息仍保留其截图和引用快照，不静默跳到新内容。
- 更新手动字幕后，旧后台纠错返回不能覆盖新修订；只有有效文本参与当前索引。

### 7.3 效率与资源

- 对截图到输入区的动作数、截图延迟、首字和完整回复时长分别记录；模型网络时间与应用开销分开。
- 回答流更新不能每 token 重建播放器和全部聊天公式。
- 记录冷/暖启动、进程数、RSS、GPU/显存与可用内存；单次测量不能称 p95。
- 比较前台单独运行与后台 ASR/纠错同时运行，记录卡顿和等待，而不只记录后台吞吐量。
- 用量统计分别计入普通回答、工具后续、摘要、重试和纠错；缺失 usage 保留未知。

## 8. 立项阶段的判断规则

建议先立项为**受控的 Windows 技术验证与视频问答 MVP**。Harness 架构决定保留，P0 验证的是如何接入和实际复用收益。

若 Web Host 适配不达标，先调整 Host/preset 或比较 SDK＋桥接；若仍存在严重障碍，形成证据提交后续架构决策，而不是自行恢复成旧的无 Harness 主线。若原型只能完成源码启动而不能实现真实流式、取消、业务接续和输入范围，则不能将其标记为可交付。

进入完整多端前，需要 Windows 业务数据与执行映射稳定；连接工具可换，业务事实和同步语义保持独立。上述阶段判断不要求新增复杂审批系统，也不改变用户“体验优先、允许修改组件源码”的决定。
