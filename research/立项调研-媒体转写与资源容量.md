## 5. 媒体、时间轴与中文数学字幕设计

### 5.1 分段读取，保存原视频绝对时间

按约 30～60 秒作为调度试验起点，使用少量重叠或停顿边界补充上下文；片长不是最终决定。窗口越长，优先任务插队和暂停就越慢；过短则增加边界重复、词语截断和处理开销。

每段至少关联 `asset_id/source_revision/window_start/window_end/processor_version`。在当前零起点样本中，字幕绝对时间由窗口起点加**经过范围检查的**片段局部时间得到。faster-whisper 已把 VAD 删去的静音映射回输入片段时间轴，不能再次手工补加静音时长；其他媒体的非零流起点需单独验证。本次实测说明返回值也可能越界，库提供时间戳不等于时间轴已验收。[固定版本 VAD 时间恢复源码](https://github.com/SYSTRAN/faster-whisper/blob/v1.2.1/faster_whisper/transcribe.py)

重叠段按时间归属与文本对齐去重，不让重叠文字重复进入知识库。纠错只替换稳定片段 ID 对应的文字，不由 LLM 重写整条时间轴。需要精细跳转时再评估字级时间戳；中文“词级”的分界和精度需用样本验证。

### 5.2 VAD、提示词与纠错边界

固定版本 VAD 默认 `min_silence_duration_ms=2000`、`speech_pad_ms=400`；先使用保守过滤，针对字母、短词和推导长停顿检查漏识别，再决定是否调整。优先复用库内 ONNX VAD，不另起一个重型 PyTorch VAD 服务。[固定版本 VAD 源码](https://github.com/SYSTRAN/faster-whisper/blob/v1.2.1/faster_whisper/vad.py)

数学术语词表是识别提示，不能保证符号、正负号、不等式和上下限正确。`initial_prompt`/`hotwords`、beam size、`condition_on_previous_text` 应作为小范围对照变量；依赖先前文字可能改善一致性，也可能传播重复或时间偏移。先固定基线、一次改一个参数，禁止把整份讲义当提示。[固定版本转写参数](https://github.com/SYSTRAN/faster-whisper/blob/v1.2.1/faster_whisper/transcribe.py#L705)

字幕初稿先显示、后台优化，沿用用户决定：不逐句标记存疑，不要求人工审核。后台保留原稿、修订和来源；界面只显示整体处理范围与进度。尚未覆盖的片段不能被解释为“没有相关内容”。

纠错由独立短任务调用 Harness 学习配置，只发送待修文字、少量相邻上下文和必要术语。不要自动获取画面核对公式，也不让纠错任务进入正在解题的聊天历史。异步纠错提交前比对输入版本，避免旧结果覆盖后续手动修改。

### 5.3 用户优先与后台调度

1. 视频播放、用户主动截图、聊天发送与本地保存优先。
2. 用户问题明确需要的字幕片段及其纠错次之。
3. 整课转写、普通纠错和资料索引后台执行。

首次只保留一个 GPU 重任务和一个模型实例；OCR 等未来 GPU 工具使用同一资源配额。Harness 插件只提交或观察应用任务，由应用调度器统一持有租约和检查点，防止两个队列重复转同一视频。

优先级在片段边界生效，不承诺即时抢占 GPU 内核。暂停后保存已完成片段；强制退出最多重做未提交片段。ASR 进程异常不能带走业务 API 和 Harness 宿主，字幕错误也不能阻塞直接截图解题。

## 6. 容量与成本估算方法

### 6.1 解码和存储

16 kHz、单声道音频的理论数据量为：

```text
PCM int16 bytes = 秒数 × 16,000 × 2
float32 bytes   = 秒数 × 16,000 × 4
```

60 秒分别约 1.92 MB 和 3.84 MB。整节样本若一次解码，分别约 393.63 MB 和 787.25 MB；这些还不含模型、特征、VAD 副本、解码缓冲和推理内存。有限窗口降低音频驻留量，但不代表整个 worker 只消耗几 MB。库的解码实现会收集输入音频数据，不能把三小时原视频直接当作无限流。[固定版本音频解码源码](https://github.com/SYSTRAN/faster-whisper/blob/v1.2.1/faster_whisper/audio.py)

应用新增存储应按下式规划，原地引用视频不重复复制：

```text
新增磁盘 = 选用模型 + 有上限的音频临时缓存 + 用户截图附件
         + 有效字幕及保留修订 + 文档解析/索引 + 聊天/业务数据 + 备份
```

文件大小不能直接代表转写工作量；按 ffprobe 获得的总时长、采样率和语音比例估算，视频码率差异可让相同 GB 对应不同小时数。没有本项目实测文本与附件分布前，不给“几十 GB 只需多少索引空间”的固定比例。

### 6.2 完成时间与前台等待

```text
RTF = 有效转写墙钟秒数 / 原输入片段秒数
整课时间 ≈ 冷加载 + Σ(定位解码 + VAD + 转写 + 提交) + 调度暂停
当前片段等待 ≈ 当前不可抢占片段的剩余时间 + 定位解码 + 该片段处理
```

RTF 分母固定使用原始片段时长，另外记录 `duration_after_vad`，防止以静音过滤后的短时长混算。模型加载、首次推理和 warm 分开计时；必须遍历 `segments` 才能算完整转写耗时，不能只计 `transcribe()` 返回生成器的时间。[faster-whisper 执行示例](https://github.com/SYSTRAN/faster-whisper#faster-whisper)

本次局部修正后得到单段 RTF 0.08054 / 0.06691；样本只有一段、没有完整应用并行或长期热状态，**不据此推算整课完成承诺**。厂商 README 的其他 GPU/音频基准也不能代替本机结果。

### 6.3 与 Harness、播放器并行

主机预算应包含 Windows 和其他应用、浏览器的视频/截图/公式、Harness 宿主及启用插件、项目业务服务、ASR，以及文件缓存和余量；GPU 预算包含其他进程、浏览器 GPU 使用和 ASR。修正后的短段显存采样最大值也不能当作长时间、不同片段或多任务的上限。

初始采用少量 CPU 线程、单任务、非大批量模式。线程数和 batch 提升要同时测前台延迟和资源占用，不能只测转写吞吐。[CTranslate2 性能建议](https://opennmt.net/CTranslate2/performance.html)

如果播放、截图或聊天交互退化，先减少后台并发与线程，暂停新片段领取；仍不足时再比较小模型或卸载空闲模型。降低 Windows CPU 进程优先级不能保证 CUDA 实时让路；具体资源阈值由完整应用基准确定。

### 6.4 token 控制

本地音频转写不产生云端模型 token；字幕纠错会。估算分别记录：

```text
纠错 input = 指令 + 术语 + 本段原稿 + 必要重叠上下文
纠错 output = 稳定片段 ID + 修正文
问答总量 = 用户提交图片/文字 + 必要历史 + 实际读取的字幕/资料
```

用真实 provider usage 分别累计纠错和问答，Harness 执行日志与业务任务建立映射；不要用字符数声称准确 token 数。按段合并纠错，不逐句启动代理循环，不给纠错配置检索/截图等无关工具。只对变化片段重做，并缓存已完成结果。

### 7.1 排障复验

音频读取命令的参数列表等价于：

```text
ffmpeg -hide_banner -v error -nostdin -ss 600
       -i D:\Download\26822053135-1-192.mp4
       -map 0:a:0 -vn -sn -dn -t 60
       -ac 1 -ar 16000 -c:a pcm_s16le -f s16le pipe:1
```

实现使用 subprocess 参数数组，不把命令文本直接交给 shell。PCM 转为 float32 数组后调用本地模型；输入来源、时段和参数连同结果一起记录。[FFmpeg 参数文档](https://ffmpeg.org/ffmpeg.html)
