# 内嵌连接项目候选调研

讨论日期：2026-10-20。当前仍为需求讨论阶段；本次只核对官方文档、固定提交源码及官方仓库制品元数据，没有构建、安装、部署或进行实际网络测试。

## 1. 问题与结论

用户已确认必须支持异地连接，并进一步表达：希望连接内置，Android 只安装自有学习软件，不额外安装 Tailscale 等客户端。

**有符合这个方向的项目，不需要自行发明 NAT 打洞、加密与中继协议。** 当前最值得继续比较的是：

1. **iroh／iroh-ffi：应用直接嵌入的连接库。** 官方 Kotlin／Android AAR 和 Windows 接入路径明确，优先调查。
2. **ZeroTier Sockets／libzt：进程内虚拟网络 Socket SDK。** 官方已有 Android 视频与 HTTP 示例，适合作为对照。
3. **EasyTier／easytier-ffi：完整组网能力加原生数据面 FFI。** 已找到具体库接口，不只是命令行工具；移动绑定、制品与接口维护成本仍待核实。
4. **OpenZiti：内嵌 SDK＋服务专属网络。** Android 有官方示例，但主要经自有路由网络转发，对个人项目的运维与视频流量负担较大。

这是候选排序，不是最终选型或恢复实施的决定。仅凭项目介绍不能保证校园网与移动流量下可达，也不能保证视频性能。

“只安装一个 App”与“能和其他 VPN 同时使用”是不同要求：前者用户已经表达，后者仍未确认。库在普通应用进程内使用 Socket、有条件不占用系统 VPN；若集成时仍使用 `VpnService`，同一用户或工作资料只能有一个活动系统 VPN 的限制依然存在。[Android 官方 VPN 文档](https://developer.android.com/develop/connectivity/vpn)

## 3. iroh：最接近“把连接能力放进自己的 App”

### 3.1 已有能力

iroh 在应用进程中建立带身份、端到端加密的 QUIC 连接，尝试点对点直连，必要时经 relay 回退。它的核心抽象是端点与连接，不要求先给整台 Android 设备装一张系统虚拟网卡。[官方简介](https://docs.iroh.computer/)、[固定核心仓库](https://github.com/n0-computer/iroh/tree/86b1242c50ec041b503f81767f2f242f304735dd)

官方语言支持包含 Rust、Kotlin、Python、Swift、JavaScript。Windows 可用 Rust 或合适绑定，Android 可用 Kotlin／原生库；不需要为了连接能力把 Windows 的 Harness 执行层更换成 Rust。[官方平台矩阵](https://docs.iroh.computer/languages)、[官方语言支持说明](https://www.iroh.computer/blog/iroh-language-support)

固定 `iroh-ffi` 的包版本是 `1.1.0`，依赖的 iroh 核心为 `1.0.0`，提供 `staticlib`／`cdylib`。不能沿用早期“整个 iroh 仍是 alpha”来判断本次版本；也不能把核心 1.0 外推成所有高层协议或绑定均已通过本项目验收。[固定 Cargo.toml](https://github.com/n0-computer/iroh-ffi/blob/3103bf5295be6d50c5272ff7a426e9b539f3f587/Cargo.toml)

### 3.2 Android 制品：官网与源码存在具体差异

在线 Kotlin 页面仍写：`computer.iroh:iroh` 为单平台制品，Android 需要自行构建。这段描述针对 JVM 制品，不能据此断言官方没有 Android AAR。[在线 Kotlin 文档](https://docs.iroh.computer/languages/kotlin)

固定源码的发布说明已经明确区分：

- `computer.iroh:iroh`：桌面 JVM JAR。
- `computer.iroh:iroh-android`：Android AAR，带 JNI 原生库与初始化类，并传递依赖 Kotlin API。
- Android Gradle 配置列出版本 `1.1.0`、`minSdk = 24`，并处理 Android JNA AAR 依赖。

依据：[固定发布说明](https://github.com/n0-computer/iroh-ffi/blob/3103bf5295be6d50c5272ff7a426e9b539f3f587/RELEASING.md)、[固定 Android 配置](https://github.com/n0-computer/iroh-ffi/blob/3103bf5295be6d50c5272ff7a426e9b539f3f587/kotlin/android/build.gradle.kts)。

本次对 Maven Central 官方仓库 `iroh-android/1.1.0` 的 AAR 与 POM 发出只读 HEAD 请求，均返回 200；AAR 的 `Content-Length` 为 24,558,667 字节。**这证明已存在对应远程制品，不代表已下载检查 ABI、能成功加载或已经跑通双端。**[官方 AAR](https://repo.maven.apache.org/maven2/computer/iroh/iroh-android/1.1.0/iroh-android-1.1.0.aar)、[官方 POM](https://repo.maven.apache.org/maven2/computer/iroh/iroh-android/1.1.0/iroh-android-1.1.0.pom)

### 3.3 基础设施与项目工作

内嵌客户端不消除中继：官方公共 relay 可用于开发或个人兴趣用途，但有限速、无 SLA，不应承诺其长期承担课程视频。正式使用可选择付费共享／专用中继，或自建 `iroh-relay`，自建仍需公网服务器、域名、TLS 与流量支出。[添加 relay](https://docs.iroh.computer/add-a-relay)、[公共 relay 政策](https://docs.iroh.computer/iroh-services/relays/public)

端点密钥提供连接身份，应用仍要完成设备配对、允许列表、撤销和业务权限。不能把“知道端点 ID”直接当作有权读取全部资料，不能向移动客户端下发整个服务项目的管理密钥。

Android 前后台切换需要管理端点生命周期与身份持久化；需要保持后台连接时，还要按 Android 规则设计相应服务。官方建议不意味着某个 OEM、系统版本或省电设置已经兼容。[官方 Kotlin 生命周期说明](https://docs.iroh.computer/languages/kotlin)

视频不是直接把 QUIC 连接交给现有播放器：需要播放器数据源、受限 HTTP 桥接或带范围读取的应用协议，保留 seek、取消、背压、来源版本与断点续传语义。这是本项目工程推论，尚未验证。

许可方面，固定 `iroh-ffi` 为 MIT／Apache-2.0 二选一；采用时保留相应声明并核依赖闭包，开源许可不赠送托管服务额度。[固定许可说明](https://github.com/n0-computer/iroh-ffi/blob/3103bf5295be6d50c5272ff7a426e9b539f3f587/README.md#license)

**判断：优先候选。** 包形态、应用内抽象和官方绑定方向贴合需求；尚缺固定双端制品运行、真实网络回退与视频读取验证。

## 4. libzt：已有 Android 视频样例的内嵌 Socket SDK

### 4.1 与 ZeroTier 客户端的区别

`libzt` 的官方名称为 ZeroTier Sockets，是跨平台加密 P2P Socket 库。应用可启动自己的节点、加入网络并使用库提供的 Socket；不是要求用户另外安装 ZeroTier One App。[固定 README](https://github.com/zerotier/libzt/blob/a707ea6ae0910efdc1125d04758c411e2e9ea4f9/README.md)

官方给出 Android AAR 构建目标与 Java 接口，以及 Windows PowerShell／CMake 构建路径。它提供的是进程内网络栈，不是让系统所有 HTTP 客户端自动获得虚拟网络能力。[固定构建配置](https://github.com/zerotier/libzt/blob/a707ea6ae0910efdc1125d04758c411e2e9ea4f9/CMakeLists.txt)、[固定构建脚本](https://github.com/zerotier/libzt/blob/a707ea6ae0910efdc1125d04758c411e2e9ea4f9/build.ps1)

与本项目最相关的证据是官方文档已有 Android AAR、`OkHttp`、`HttpURLConnection` 和 `ExoPlayer` 视频示例；ExoPlayer 示例将自定义 SocketFactory 接入 OkHttp 数据源。**有官方接入样例，不等于旧示例已兼容当前 Android／Media3。**[官方 Android 示例章节](https://docs.zerotier.com/sockets/#android-examples)

文档视频演示使用 VLC HTTP 流，不能把它当作本地课程视频的 HTTP Range／拖动播放验收。未来仍应分别验证 Range、鉴权、取消、大文件与播放器版本。

### 4.2 网络与维护成本

节点需要持久身份，私有网络由控制器授权；可用 ZeroTier 托管管理服务或自建相应控制／根基础设施。打洞失败时的实际转发路径与 TCP relay 配置必须针对 SDK 核实，不能直接照搬桌面客户端设置。[官方 Socket 身份与加入网络说明](https://docs.zerotier.com/sockets/)、[官方自托管入口](https://docs.zerotier.com/selfhosting/)、[官方 relay 说明](https://docs.zerotier.com/relay/)

本次日期截止查询定位到的仓库最近提交为 2024-11-07，固定核心子模块的许可标明 Engine 1.4.4；这个事实提示要先检查现代 NDK、Gradle、Windows 工具链和核心依赖维护情况。不能仅据较旧提交认定项目停用，也不能把 2026 年新版 ZeroTierOne 的能力与修复默认套到这个冻结 SDK。

### 4.3 许可不能只看 README 的 BSL 标签

固定 `libzt` 根许可标有 BSL-1.1，同时明确 `Change Date: 2026-01-01`、`Change License: Apache License version 2.0`，且正文说明到期后按转换许可授予权利。讨论日已晚于转换日。[固定根许可](https://github.com/zerotier/libzt/blob/a707ea6ae0910efdc1125d04758c411e2e9ea4f9/LICENSE.txt)

该提交固定的 `ext/ZeroTierOne` 是 `c53c6bd9c320ea839c525972d8afba448a58606e`；对应核心许可转换日为 `2025-01-01`，转换许可同为 Apache-2.0，也已经过期。不能拿目前另一个 ZeroTierOne 版本的许可，或 README 未更新的商业授权说明，直接淘汰这个冻结版本。[固定子模块](https://github.com/zerotier/libzt/tree/a707ea6ae0910efdc1125d04758c411e2e9ea4f9/ext)、[固定核心许可](https://github.com/zerotier/ZeroTierOne/blob/c53c6bd9c320ea839c525972d8afba448a58606e/LICENSE.txt)

这是对本次固定源码条款的读取；依赖与第三方声明、未来更新版本、商标及托管服务套餐应分别核查。采用旧冻结版本与升级现代核心也属于不同技术、许可评估，不能笼统宣布“所有 ZeroTier 组件现已 Apache”。

**判断：强对照候选。** HTTP／视频的集成证据直观；优先验证现代工具链、维护与回退路径，不能因旧 BSL 标签自动淘汰。

## 5. EasyTier：已有原生数据面接口，仍需区分库与成品 VPN

EasyTier 提供 Windows／Android 等平台的组网、打洞、加密与节点转发能力。成品 Android VPN 客户端与内嵌库是两个层次；“支持 Android”不能单独证明我们的 App 已有可直接调用的稳定 SDK。[官方仓库](https://github.com/EasyTier/EasyTier/tree/5af90471bfe654d097f7e488a2699f2850db7dd2)

固定源码已找到真正的内嵌入口：`easytier` 为 Rust library；`easytier-ffi` 为 `cdylib`／`rlib`，包版本 `0.1.0`，默认包含 `c-abi` 与 `ffi-dataplane`。所以它不只是“打包命令行到软件里”的候选。[固定库配置](https://github.com/EasyTier/EasyTier/blob/5af90471bfe654d097f7e488a2699f2850db7dd2/easytier-contrib/easytier-ffi/Cargo.toml)

原生数据面 ABI v3 明确列出 TCP connect／bind／accept／read／write 和 UDP 收发、完成队列、超时及取消；**该 ABI 文档注明只接受 IPv4**。这是具体源码接口证据，不应外推为整个产品只能用 IPv4，也不应将 `main` 的新增 ABI 当成某个正式发行版已经发布。[固定 ABI 文档](https://github.com/EasyTier/EasyTier/blob/5af90471bfe654d097f7e488a2699f2850db7dd2/easytier-contrib/easytier-ffi/DATA_PLANE_ABI.md)、[固定 C 接口](https://github.com/EasyTier/EasyTier/blob/5af90471bfe654d097f7e488a2699f2850db7dd2/easytier-contrib/easytier-ffi/src/lib.rs)

另有 Android JNI 管理／TUN 入口；它不自动等于 Kotlin 已完整封装数据面接口。本项目需选择 JNI／C 绑定还是 no-TUN＋SOCKS5 路线，并核实相关接口是否随目标版本发布、是否有 Android AAR 与 Windows 动态库，不能只靠 crate 名称通过兼容验收。[固定 JNI 源码](https://github.com/EasyTier/EasyTier/blob/5af90471bfe654d097f7e488a2699f2850db7dd2/easytier-contrib/easytier-android-jni/src/lib.rs)

no-TUN／userspace 模式可作为避免系统虚拟网卡的路径，但播放器与请求必须显式走选定代理或数据源，不会自动接管应用所有网络。公开共享节点的存在不构成视频中继容量或可用性承诺；自建可达节点仍有服务器与流量成本。[官方 no-TUN 指南](https://doc.easytier.cn/guide/network/no-root.html)、[固定 SOCKS5 实现](https://github.com/EasyTier/EasyTier/tree/5af90471bfe654d097f7e488a2699f2850db7dd2/easytier-core/src/gateway/socks5)

固定根许可为 LGPL-3.0，分发和链接方式需要按相应条款保留许可、库修改源码与替换／重新链接所需条件，不能按 MIT 依赖处理。[固定许可](https://github.com/EasyTier/EasyTier/blob/5af90471bfe654d097f7e488a2699f2850db7dd2/LICENSE)

**判断：保留第三候选。** 能力比“仅桌面 VPN”更贴合内嵌任务，但接口层较多，暂不能比 iroh／libzt 更早承诺移动端接入成本。

## 6. OpenZiti：可以内嵌，但属于不同的网络取舍

官方 Edge SDK 允许应用直接发现、提供和访问 Ziti 服务，无需另外安装 agent／proxy，并列出 Android Kotlin SDK。官方 Android 示例通过设备 identity 与注册凭据接入；这符合一个学习 App 的安装目标。[官方 SDK 入口](https://netfoundry.io/docs/openziti/maint/reference/developer/sdk/)、[固定 Android 示例](https://github.com/openziti/ziti-android-app/tree/2269801521e0970b8a5e239c2835a19d38356031)

它与 iroh 的直连优先路线不同：典型数据路径由 SDK 进入 edge router，经过 fabric 到提供服务的一端，控制器负责身份、策略与服务发现。不能把它解释成“打洞后手机与家庭 Windows 一定绕过公网节点直接传视频”。[官方数据路径说明](https://netfoundry.io/docs/openziti/learn/core-concepts/data-flow-explainer/)

Windows 可评估 JVM／Go／C SDK 的桥接或由学习软件管理 hosting 组件；本次没有验证目标 Windows 制品和绑定。JVM SDK 固定许可为 Apache-2.0；控制器、router 的部署、证书、运维和视频转发流量仍要承担，也可调查托管服务。[固定 JVM SDK](https://github.com/openziti/ziti-sdk-jvm/tree/f49b6286a86c23abdbe7be28b3f3c83a70939ae7)、[固定许可](https://github.com/openziti/ziti-sdk-jvm/blob/f49b6286a86c23abdbe7be28b3f3c83a70939ae7/LICENSE)

**判断：第四候选。** 内嵌定位清楚；如果更重视服务策略与统一可达、愿意长期承担路由基础设施，可继续调查。当前个人学习工具暂不优先于前三。

## 7. 其他路线的定位

| 路线 | 可以解决什么 | 本项目暂不放在前三的原因 |
| --- | --- | --- |
| Tailscale `tsnet` | Go 程序内嵌 tailnet，复用控制面、直连和中继 | 仍需账号／控制面；Android 绑定及播放器适配不如明确的 Android AAR 路径直接 |
| `libp2p` | Peer 身份、传输、发现、AutoNAT、DCUtR 打洞与 Circuit Relay | 组件组合与移动绑定工作较多；公共 relay 常有字节／时间约束，不能默认承担长视频 |
| 原生 WebRTC | Android／Windows 可集成；ICE＋STUN／TURN，支持 DataChannel | 信令与业务身份仍由项目提供；DataChannel 不是 HTTP Range URL，需另做视频数据源 |

依据：[tsnet 官方文档](https://tailscale.com/docs/features/tsnet)、[libp2p 打洞机制](https://libp2p.io/docs/hole-punching/)、[libp2p 规范的失败回退与限制](https://github.com/libp2p/specs/blob/master/connections/hole-punching.md)、[WebRTC TURN](https://webrtc.org/getting-started/turn-server)、[WebRTC 信令](https://webrtc.org/getting-started/peer-connections)、[DataChannel](https://webrtc.org/getting-started/data-channels)。

此前 `libtailscale` 固定 C 封装中的 Unix 专用调用仍是该封装的 Windows 边界，不能扩展为整个 Go `tsnet` 都不能在 Windows 内嵌。[此前核对的固定 C 封装](https://github.com/tailscale/libtailscale/blob/d1dc45d039edb7759ecbee6ba2aea0c4bca884b8/tailscale.go)

## 8. 本项目的建议边界与后续验证门槛

建议继续把“Android 一个安装包、日常自动连接”作为产品体验方向，优先比较 iroh 与 libzt，不要求用户额外维护通用 VPN；EasyTier 为第三候选。底层中继可以托管或自建，不需要在用户手机上增加第二个软件。

各方案都需要至少一条可靠的可达入口／中继回退；打洞只作为直连优化。校园网与移动网络可能封 UDP、限制端口或切换 NAT，任何方案都不能只用“支持 P2P”宣称异地必达。

连接范围仅限自有学习服务，不将 Harness 内部管理接口、全部文件系统或整个家庭局域网自动开放。Windows 继续使用 DeepSeek Harness；业务数据、同步协议、请求对账和课程资源身份继续归本项目，网络库只提供传输。

后续用户明确恢复实施后，验证最小范围应为：

1. 固定制品：Windows 加载／绑定，Android AAR 各实际设备 ABI；记录依赖版本与哈希。
2. 配对与撤销：扫码／口令绑定、身份持久化、丢设备撤销，拒绝未授权读取。
3. 路径：同网、校园网、移动流量，强制直连失败后的中继，显示实际路径和失败状态。
