# 统一学习入口定位与场景覆盖分析

调研日期：2026-10-23。依据用户本轮明确定位、“中国大学生学习场景与平台调研”、现有需求总结、13 场景收口和当前 MVP 计划，分析本科、硕士与博士的需求覆盖、优先顺序及外部工具分工。本文记录产品分析与接入证据，不代表接口已实测、应用审核已通过，亦不启动本轮新增接入开发。

## 一、定位：以 Harness 为交互中心的个人学习工作台

用户本轮明确：**“一个入口，在 Harness 里能完成所有的学习场景。”** 具体例子包括登录 Bilibili 后从收藏夹选择导入视频链接、从学习通课程选择导入资料和作业，以及英语学习时将生词通过墨墨 API 加入相应词本或学习对象。

据此，建议用以下产品描述约束后续设计：

> 从一个入口连接自己的课程、资料和工具，在 Harness 中围绕当前内容理解、练习、组织、复习与推进任务；需要专业能力时调用外部平台或引擎，结果继续归到当前学习项目。

“完成场景”应包含能实际打开材料、采取学习动作、保存或送出成果、看到真实结果以及下次继续。只有平台图标、网页书签、自然语言建议或一个“已同步”提示，都不足以证明闭环。

Harness 继续承担原生对话、模型选择与按需工具调用；项目承接资料视图、作答、卡片、待办、来源和状态。聊天可以发起动作、展示结果入口，长文阅读、做题、卡片翻面等仍使用合适的现有学习视图，不强制全部挤成聊天消息。

本轮分析承认用户提出的统一入口方向，不把“保留外部工具”解释为让用户重新手工搬运上下文。是否在应用内调用、采用嵌入视图、文件交换或最后由外部软件完成，要以真实能力与用户所得为准。对于必须去外部完成的环节，应明确呈现，并提供可返回的结果关联，不能宣称完全在 Harness 内完成。

## 二、现有需求已经覆盖什么

| 学习动作 | 对应已有需求 | 仍需避免的误判 |
| --- | --- | --- |
| 读教材、论文，选段解释与翻译 | S01、S02、S11，PDF／OCR／精确来源 | 能读论文 PDF 不等于有文献库、题录、引用和科研项目管理 |
| 看视频、听录音并追问 | S03、字幕与来源时间点 | 本地媒体闭环不等于 B站登录、收藏夹、在线字幕和受限课程均已打通 |
| 整章／整课整理 | S04，指定范围完整归纳与覆盖账 | 不能用几次搜索命中代替处理所选完整资料 |
| 做题、错题、生成练习与订正 | S05、S08 | 自用练习不等于读取学校作业、同步截止日、提交或取得教师成绩 |
| 知识记忆与复习 | S06，卡片／错题／路线汇总今日复习 | 已有本地复习要求，不应重新提出一套同功能卡片系统；外部单词状态另需接入 |
| 英语作文修改 | S07，原稿与修订、批改依据 | 不自动等同于学术长稿协作、期刊模板、参考文献与审稿回复管理 |
| 可视化与按目标学习 | S09、S10 | 可视化隔离执行不等于已授权任意 Python、实验软件或系统命令执行 |
| 整理长期学习成果 | S12、S13及成果编辑／导出／索引 | 生成报告和书不等于随手记录的个人笔记、实验日志或项目计划已完整覆盖 |
| 保存、继续与来源保护 | 课程、会话、成果、版本和持久任务规则 | 不能因接入外部账号就把整个账号所有资料作为当前模型上下文 |

由此，产品的主要增量应聚焦于：**材料进入、现实任务、外部能力衔接和成果继续使用**。对已确认的讲解、整理、练习与复习，应完成既有实现和验收，避免换名称重建一遍。

## 三、本科生的主要覆盖缺口

| 场景／缺口 | 已有基础 | 建议本项目承担的完整动作 | 建议优先程度 |
| --- | --- | --- | --- |
| 账号里的网课进入工作区 | 长期链接导入、S03／S04 | 连接账号→浏览允许的收藏／目录→勾选→归入课程→应用内学习→保留原链接和来源状态；获取链接、播放、字幕、保存本地分别标明可用性 | 高；B站适合作为课程来源候选，先验证授权与实际播放链 |
| 学校课程资料和真实作业 | 本地资料、S05 | 选择课程和文件／作业→保留课程、任务要求、附件、截止日→阅读与作答→保存草稿及返回原平台入口 | 高，尤其以本科为首批对象时；学习通先核权限与可导入内容 |
| 跨课程“今天学什么” | 今日复习、S10；计划和番茄钟保留后续 | 汇集手动待办、课程作业、考试日期、本人选择的学习任务及到期复习；从任务直接打开材料，完成后有实际进展记录 | 高；把已存在的今日复习整合进来，不复制复习排程 |
| 从阅读到生词复习 | S02、英语素材积累旧需求 | 明确选择生词→查词／解释→加入指定墨墨词本或学习单词→保留来源→显示实际成功／失败 | 高；动作短、与已有阅读强相关，正式 API 依据较明确 |
| 轻量个人笔记与摘录 | 已有成果可编辑，独立笔记旧记录暂缓 | 在当前资料旁记自己的想法、摘录和错误原因，关联页码／时间和问题；统一搜索与继续修改 | 中高；补轻量入口，先不重建成熟笔记软件的全部能力 |
| 专注与学习节奏 | 统计、计划、番茄钟均有后续方向 | 从当前任务开始计时／休息，记录实际投入；纸笔学习可纳入，规则需与旧计时待定项一起细化 | 中；适合做原生简单能力，不依赖外部番茄钟 API |
| 听力、口语和主动输出 | 媒体播放／ASR，S07 | 明确选听力片段→精听／听写／跟读／录音→对照或反馈→后续练习 | 中；播放音频和转字幕不能冒充口语训练；考试口语评分需另验证 |
| 编程作业与课程项目 | S05、S08、S09，文件与研究成果 | 读所选代码和题目、解释报错、生成修改建议、比较运行结果；按需关联 OJ／代码仓库 | 按专业提升优先级；完整 IDE、OJ 判题保留专业工具 |
| 课堂手写、纸质题与线下学习 | 已提交截图、图片、OCR | 纳入本人选定的笔记／题图，围绕真实内容继续；纸笔成果可回到课程 | 中；优先输入和回链，复杂手写画布后做或连接成熟工具 |
| 小组作业与汇报 | S12／S13及成果导出 | 为本人维护分工、资料与汇报稿，接收同伴明确提供的反馈，输出到共享文档 | 中；团队实时编辑与聊天保留外部，先完成个人一端 |
| 四六级、考研、考公、职业考试 | 练习、卡片、学习路线等已覆盖大部分学习动作 | 补考试日期、个人目标和所选官方要求，把已有资料、练习和复习组织到同一目标下 | 中；优先复用现有模块，不自建全部考试商业题库 |

“实际作业任务”与“AI 后台生成任务”语义不同：作业有发布人、截止日、提交与反馈；后台任务描述计算执行。建议在产品上区分，避免后台处理完成就把作业标成已交。

## 四、硕士与博士的主要覆盖缺口

硕士与博士共享很多科研流程，差别更多在课题周期、研究自主性、方法复杂度和成果要求；专业学位、学科与实验室要求还会改变重点。不能只按学历为每个人预设同一工具。

| 场景／缺口 | 与已有需求的关系 | 建议本项目承担 | 外部能力与优先判断 |
| --- | --- | --- | --- |
| 用课题组织长期工作 | 目前以课程为主 | 在同一学习组织体系中表达课程、备考目标、研究课题；课题内连材料、问题、产物、待办和决策 | 硕博高优先；不是另建第二套聊天／数据库，不默认打通全部项目上下文 |
| 文献库接入 | S01／S11能读、S13能研究，题录流程未完整定义 | 从指定 Zotero collection 选择题录和可访问附件，保留文献身份、DOI等已知元数据、PDF版本和页码 | 硕博最高优先候选；Zotero 有官方 API 与交换格式，全文可用性单独判断 |
| 证据整理和文献比较 | S13部分覆盖 | 跨明确选择的论文比较研究问题、数据、方法、结果与限制，结论逐项关联原文 | 高优先，是 S13 针对科研的具体化，不重建通用研究引擎 |
| 文献检索与新进展跟踪 | S13明确外部研究可作为基础 | 保存明确问题、检索条件和已看条目；用户主动查新时展示新增工作及来源 | 首先主动检索，持续订阅后做；数据库授权、索引和全文分开核实 |
| 学术写作与审稿迭代 | S07只明确英语作文，S12／S13可提供材料 | 对指定稿件段落／章节做结构、论证和引文核对，记录导师或审稿意见及处理结果；导出正式格式 | 高价值但范围较大，文献与来源基础稳定后推进；最终协作排版保留 Word／Overleaf |
| 研究思路、假设与决策记录 | 路线、报告和版本仅部分覆盖 | 记录为什么选此方向、证据、反例、方案变更和未解决问题，后续讨论能定位原材料 | 博士及长期课题高价值；不做默认全量个人记忆，也不以聊天摘要替代研究证据 |
| 实验／调研／访谈日志 | 现有13场景未覆盖完整操作链 | 轻量模板、方法解释、所选原始记录与结果解读；关联一次实验／访谈的输入输出和异常 | 依学科决定；正式原始记录、样本系统、临床／实验执行保留学校或课题组指定工具 |
| 数据分析与结果复现 | S08／S09仅覆盖解释与隔离学习产物的一部分 | 对选定数据解释方法、生成分析脚本、解释结果、保留脚本／参数／数据版本关系 | 对计算和量化学科优先；实际执行属于新增独立能力，不能直接继承图形渲染权限 |
| 代码仓库与环境 | 普通文件阅读不足以描述科研复现 | 选择仓库版本和文件、分析方法实现、关联实验报告与运行结果 | 学科专项；VS Code／Jupyter／Git等继续承担专业开发和执行 |
| 组会、学术报告与答辩 | 归纳与成果部分覆盖 | 从选定研究材料形成讲稿／提纲、记录导师问题、生成下一步待办与关联依据 | 中高优先且可复用现有成果；幻灯片精细排版和会议保留成熟软件 |
| 专利、标准和学科专用资料 | 通用文献阅读／研究可复用 | 以真实来源比较和解释所选资料，不将论文数据库视作所有学科资源 | 按需要接入，不能一开始覆盖所有数据库 |
| 多人协作和长期交接 | 当前个人项目与版本基础部分覆盖 | 保留可导出的资料清单、引用、笔记、脚本与成果，支持个人工作继续和明确分享 | 完整实验室管理、团队权限和实时编辑先保留外部；不扩成团队协作平台 |

依据示例：[安徽科技学院研究生培训](https://www.ahstu.edu.cn/yjs/info/1077/5485.htm)同时涉及文献检索、EndNote、Origin、Illustrator、论文及专利；[Zotero官方阅读与笔记](https://www.zotero.org/support/pdf_reader)可保留批注回链。校方训练证明场景真实存在，不能据此推算各工具在全国硕博中的占比。

## 五、哪些优先在本项目完成，哪些连接或保留外部

| 类别 | 本项目优先完成的部分 | 建议保留给外部软件的部分 |
| --- | --- | --- |
| 网课／学校课程 | 账号连接、选取导入、课程内阅读学习与提问、来源和进度 | 平台内容供给、课程发布、学校身份／成绩／正式考核；接口允许的嵌入学习可在本入口呈现 |
| 生词和记忆 | 在阅读处完成收词、保留原句与来源、实际写入反馈；本项目自有知识卡片沿用S06 | 墨墨已有词汇体系与其自身学习排程；不维护一套冒充其当前计划的副本 |
| 今日学习与专注 | 课程／课题待办、截止日、当前任务计时、已确认的今日复习 | 手机系统级限制、复杂日历协作等不必重建；没有公开接口时不假设可以读写外部专注记录 |
| 个人笔记与学习成果 | 简单摘录、自己的想法、带来源成果、修改与回看 | 复杂手写、成熟笔记插件生态、大型笔记库迁移和完整双向同步 |
| 文献 | 接入选定题录与附件、精读比较、引用回链、笔记和写作辅助 | Zotero／EndNote文献主库、成熟插件和引用格式生态；有必要时通过明确写操作回传 |
| 正式稿件与汇报 | 论证辅助、内容草稿、反馈处理、引用核对和导出 | Word／Overleaf协作排版、期刊模板、PowerPoint精细设计、正式投稿系统 |
| 数据／代码／模型 | 对选定材料解释、建议、生成脚本、解读结果与保存关联 | 专业 IDE、Jupyter、SPSS／Stata、MATLAB、Origin、工程仿真及计算资源 |
| 实验／临床／实地工作 | 方法学习、计划、明确输入的记录与结果讨论 | 仪器控制、正式样本／实验记录系统、临床操作及学校规定流程 |
| 团队 | 本人任务、明确共享材料与导出交接 | 群聊、实时多人编辑、组织权限、完整项目／实验室管理 |

这并非按“功能简单就自己做”划分。适合本项目长期持有的是学习上下文、选择范围、跨工具关联与持续成果；专业引擎和外部账号状态通过已验证的能力连接。

### 先采用单一状态归属，避免同步变成新的学习负担

- 学习通正式作业是否提交、成绩如何，以平台结果为准；本地只有草稿、待办或已确认回执，不能自己推定已交。
- 墨墨是否收词、加入了多少，以对应实际接口结果为准；云词本、学习单词、卡片不能混成一个“同步成功”。
- 本项目生成的知识卡片、错题与复习记录继续由本项目维护；送出到其他复习软件时明确外部副本，首期不默认承担完整双向排程合并。
- Zotero题录及其标识由文献库保持，本项目保留选中条目的映射与实际引用版本；创建本项目批注或报告不会自动改写文献主库。
- 用户明确点击“加入指定词本”等操作本身就是该动作的意图，不再层层重复确认。异步请求结果未知时先核对，不盲目补发；这沿用项目既有对账原则。

## 六、优先顺序建议与依据

### 判断方法

优先看四件事：能否完成真实高频动作、是否直接复用已有能力、是否显著减少手工搬运、外部能力是否有可验证路径。不用未经证实的全国市场份额打分，也不编造本科／硕士／博士覆盖百分比。

前轮真实统计中，2023 年中青校媒 167 校、3486 份问卷报告 64.9% 容易分心、50.6% 找合适学习内容费时间；它们支持研究专注和资料组织的价值，不能证明本项目一定能解决，更不能换算成番茄钟软件采用率。[原始报道](https://zqb.cyol.com/html/2023-05/05/nw.D110000zgqnb_20230505_1-07.htm)

2024 年发表的昆明高校 354 人调查中，B站 41.0%、中国大学MOOC 41.2%、学习通33.0%是当地混合学历样本的报告值，其中研究生仅37人。它说明这些入口值得验证，不能据此决定全国用户优先顺序。[原始论文](https://pdf.hanspub.org/ae2024145_1751166263.pdf)

### 第一优先：让统一入口产生实际闭环

1. **完成既有13场景和来源／成果底座。** 这是已确认目标，新增平台不替代或缩减原统一交付。远程内容将来需要保存来源平台、远程条目、版本、可用范围和本地缓存的关系；不能只在文件目录中放一个没有语义的URL。
2. **把B站、学习通、墨墨、Zotero分成具体连接动作核实。** 每次验证一个纵向动作，不先建设任意插件市场。B站收藏列表／链接导入／播放／字幕分别验证；学习通资料／作业分别验证；墨墨先选一种真实写入对象；Zotero先做选定集合的题录与附件接入。
3. **补今日学习的任务与截止日期。** 复用现有今日复习，将现实作业和自主学习待办接上，不要求所有任务由AI制定。
4. **优先实现短动作：阅读收词、来源摘录、任务打开材料。** 这些动作不需要用户先整理复杂知识系统，可直接连接已有阅读与保存能力。

这里的顺序是新增能力的建议验证顺序，不是替当前工作包排期，也不是承诺平台接入一定通过。

### 第二优先：围绕主要用户形成完整日常路线

| 首批使用者 | 建议重点路线 | 相应优先连接 |
| --- | --- | --- |
| 本科课程学习 | 课程资料与作业→今日任务→阅读／网课解惑→练习和错题→到期复习 | B站、本人学校实际使用的平台；墨墨作为英语短闭环 |
| 硕士课程与课题起步 | 所选文献→精读／术语→比较与笔记→组会／写作提纲→反馈待办 | Zotero优先，再按课程需求接学习平台；专业工具按学科 |
| 博士或长期研究课题 | 研究问题→证据与反例→方案／实验结果→论证→稿件修订与反馈 | Zotero、稿件交换及研究产物；代码／数据工具按实际工作流 |

如果三类人群都要服务，应共用学习对象、资料、动作与成果体系，再按任务显示入口。不要分别复制“本科版聊天”“硕士版聊天”“博士版聊天”。也不能用接通几个软件就宣称已覆盖所有学习体验。

### 适合随后补充

原生简洁番茄钟、轻量个人笔记、听力／口语训练、考试／项目日程、组会反馈和学术稿修订。轻量待办／摘录可以随上述闭环先进入；完整规划器、完整笔记系统、双向日历和高级统计不必一次做全。

### 按专业验证，保留外部引擎

代码运行与科研复现、统计分析、工程仿真、实验／访谈记录、论文协作和投稿。先明确本项目接受什么输入、能实际调用什么、怎样接回结果，再决定是否需要更深集成；没有官方能力或稳定验证时，明确提供导出／导入或外部打开。

## 七、用具体完成条件衡量“在一个入口完成”

| 场景 | 用户可观察的完成条件 | 不足以宣称完成的现象 |
| --- | --- | --- |
| B站收藏导入 | 能在本软件选择授权范围内的条目，导入到目标课程；实际可播放与不可播放清楚，允许的提问和来源回看可用 | 只显示登录成功、只保存收藏夹网页地址，或仅嵌入一个视频 |
| 学习通资料与作业 | 能选择允许读取的实际资料／任务，附件、要求、截止日保持一致，在工作区阅读作答并保留原平台状态入口 | OAuth成功、只导入PDF而丢失其作业要求，或把本地完成视为正式提交 |
| 墨墨生词 | 阅读中选词后，写到明确目标；展示实际接收结果，重试不重复写入，原文可回看 | API请求发出就提示成功，或者云词本成功后宣称已加入今日复习 |
| 文献精读与引用 | 指定题录／附件进入项目，解释和比较可定位原文，引用带真实文献身份并能继续写作 | 只有文件名和AI编出的作者年份，或题录可读就声称全文已获取 |
| 今日学习 | 作业、自主任务和到期复习可进入同一入口，打开对应材料，分别记录实际执行与待处理事项 | AI写了一份计划却没有可继续的任务或资料关联 |
| 专业工具协作 | 本次调用或交换的输入、结果、版本清楚，结果回到原任务，未自动开放无关数据 | 只给软件启动按钮，或写了一段没有执行的代码就宣称分析完成 |

这些是分析用的候选完成条件，尚未替代正式验收方案。后续若确定实施，再转成明确场景与实际验证。

## 外部接入官方证据

### 证据范围

本轮只读核实 Bilibili 收藏夹导入、学习通课程资料／作业导入、墨墨生词写入这三个示例。未登录用户账户、获取凭据、发出账户写请求或下载视频。这里将“账户能授权”“接口允许读取何种数据”“用户能在网页看到何种内容”分开判断；一种成立不自动证明另外两种成立。

“未证实”表示在本轮可查阅的公开官方目录及文档中没有核实到目标能力，不表示断言平台绝无此接口。第三方逆向接口、浏览器会话与平台正式开放 API 也不能混称。

| 用户期望的连接动作 | 已核实的官方能力 | 仍未核实的部分 |
| --- | --- | --- |
| 登录 Bilibili，选择收藏夹中的视频链接导入 | 官方开放平台有账号授权、公开用户信息、视频稿件管理和授权数据能力；具体接口有 scope，并需要申请权限和用户授权。[B1][B2][B3] | 没有核实到公开正式的“读取当前用户收藏夹与收藏视频列表”权限及接口，不能由用户公开信息、稿件查询或账号授权直接推导支持。保存视频链接与取得视频文件、字幕、离线观看权限还需分别核实 |
| 登录学习通，选择课程资料和作业导入 | 超星有官方微服务开放平台，公开文档包含 OAuth、用户信息、应用接入及管理员审核；不是“超星完全没有开放接口”。[C1][C2] | 没有核实到面向普通学生、经其个人授权即可读取课程资料文件及作业内容的公开正式接口。OAuth 认证、获取用户信息不等于拥有课程资料或作业权限；需要进一步向平台确认可申请的接口与学校／机构授权条件 |
| 将阅读中遇到的生词写入墨墨 | 墨墨背单词云词本有正式创建、查询、更新、删除接口；另有直接添加学习单词的公测接口。墨墨记忆卡是另一组牌组／卡片能力。[M1][M2][M3] | 云词本创建成功不能直接当作所有词已加入当天学习计划。直接添加学习单词接口有公测、同步与单词额度条件；不能承诺任意字符串都成功进入学习 |

### 墨墨：云词本、学习计划与记忆卡分别处理

墨墨官方文档与可公开下载的 OpenAPI 规范区分了以下对象：[M1][M2]

| 对象 | 官方 API 证据 | 语义与限制 |
| --- | --- | --- |
| 墨墨背单词的云词本 | `GET/POST /api/v1/memo/notepads`；单个云词本另有读取、更新、删除 | 用来组织词汇文本、标题、简介、标签等。适合“把本篇阅读生词整理为一个云词本”的动作，不是修改平台公共基础词库 |
| 墨墨背单词的学习单词 | `POST /api/v1/memo/study/add_words`，名称为“添加单词（公测）” | 通过查询得到单词 ID 后添加，一次最多 1000；返回实际 `added_count`。已添加或用户单词上限不足会影响成功数量。官方要求 App 开启自动同步，并声明公测可能调整、不保证可用性 |
| 墨墨记忆卡（Markji） | 规范中单独提供自建牌组、章节、卡片和文件相关接口 | 适合自制问答／挖空／其他知识卡片，不能把它当成墨墨背单词的词表接口。当前能核实新建卡片、读取自建牌组等，不把这些泛化为任意牌组操作权限 |

个人使用可从墨墨背单词 App“我的 → 更多设置 → 实验功能 → 开放 API”取得个人访问凭证，请求使用 Bearer token。[M1] 面向其他用户分发的应用另有正式开放平台：开发者需有绑定手机号的墨墨背单词账号、创建应用并审核，之后由其他用户授权。后端应用使用 OIDC Authorization Code，纯前端应用使用 OIDC PKCE；获批 scope 和用户 access token 决定可访问范围。官方还要求可访问的 HTTPS 主页及同域回调，应用 secret 不得泄露。[M3]

因此，用户提出的“点一下，把生词写入墨墨”有明确官方接入依据；产品仍应区分实际完成的是“保存云词本”“加入学习单词”还是“生成记忆卡”，并依据接口实际成功结果反馈，不能只显示一个含义不明的“已同步”。这是根据接口语义作出的设计推论，不是本轮实施结果。

### Bilibili：账号授权不能推导收藏夹读取

官方目录当前列出账号授权、用户管理、视频管理、数据开放、专栏和直播等能力。[B1] 具体“获取已授权用户基础公开信息”文档使用 `USER_INFO`，其用途是头像、昵称、openid 等；“查询用户已授权权限列表”也明确需要申请权限及用户授权。[B2][B3]

这些证据足以支持“平台存在正式授权和按权限调用机制”，但不能把 `USER_INFO`、`USER_DATA` 或稿件查询解释为收藏夹读取。比如官方稿件编辑／删除接口围绕授权用户发布的稿件，和该用户收藏的他人视频是不同对象。[B4] 本轮在公开官方目录与针对收藏夹的站内检索中未核实到相应接口或 scope，故该连接动作的正式 API 可用性仍待平台确认。

第三方整理的网页接口即使请求发送到 Bilibili 自有域名，也不因此成为官方承诺给第三方使用的开放接口。网页登录后可见收藏夹、能手工复制视频地址，同样不足以证明可稳定批量导入。本轮没有验证网页授权会话方案或稳定性，也没有从“导入链接”延伸到下载视频。

### 学习通：已有 OAuth，课程资料与作业权限仍需单独确认

超星公开接入文档说明个人开发者只能使用 OAuth 认证对接接口；同时支持自建应用、市场应用，市场应用完成对接测试后联系管理员审核上架。[C1] 其认证 code 文档更新于 2025-12-10，要求账号已处于 passport 登录状态，并说明应用权限、回调域名、一次性 code 和有效期等检查。[C2]

这能证实正式第三方身份接入路径，不能证明 OAuth token 可用于任意课程资源接口。公开目录可见身份／用户信息／通讯录等文档，但本轮没有找到能够证明普通学生可以授权外部应用批量列出并导入课程资料文件与作业内容的正式接口说明。

因此，不能现在承诺“登录就一定能导入整门课”，也不能断言“必须校企合作才可能做到”。尚需确认的是目标资料／作业接口是否对第三方开放、哪些应用类型可申请、是否需要学校或机构额外授权，以及课程教师设置的可见／下载范围。网页登录会话读取是另一个需要单独验证的技术路线，本轮没有登录或试验。
