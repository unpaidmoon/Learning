**J：** P0 显式配置推理强度，比较 `off` 与 `low` 的数学解答质量和响应／用量，再定默认。以下情景以 `off` 为计费基线，不假定 low 与 off 的正确性相同，也不默认增加第二轮验证或多个代理。

**A：** 每 1000 次请求，若平均额外产生 2000 个推理 token，就增加 2M 输出：当前 Flash 输出项额外为空闲 ¥8／高峰 ¥16；思考历史回传引起的后续输入增量还需另算。已经包含在 `outputTokens` 中的 reasoning 不能再次加到总输出里重复计费。

## 3. 可以复算的成本公式

### 3.1 按真实请求汇总

对每个模型请求尝试 `j`：

```text
M_j = 归一化后的未命中输入 token
H_j = 缓存命中输入 token
O_j = 总输出 token（包含协议计入的思考／工具参数／最终答案）

C_model = Σ_j (M_j × p_m,j + H_j × p_h,j + O_j × p_o,j) / 1,000,000
```

`p` 随模型、时段、价格版本变化。字幕纠错、上下文摘要、自动标题、检索后继续回答、失败重试都属于真实请求，应纳入 `j`；一次用户发送不等于一次 API 请求。

当前表为缓存命中／未命中两档输入价，不套用其他提供商的缓存写入倍率或 TTL 单价。需要为模型、服务端工具或后续远端 embedding／OCR 新增调用时，独立归类后加总，不隐藏进“问答一次”。

### 3.2 Harness 与其他协议的 usage 不能混算

**C：** Harness `TokenUsage` 规定 `inputTokens` 为未缓存输入，`cacheReadTokens`、`cacheWriteTokens` 是互斥的其他输入类别；完整输入是三者之和。DeepSeek Chat Completions 的 `prompt_tokens` 则是总输入，不能对两个对象应用同一套减法。[Harness TokenUsage 定义](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/llm/llm/src/types.ts#L168-L189)

**J：** 应保存 raw usage，并归一化成 `input_total/cache_hit/cache_miss/output_total/reasoning` 等自有字段；若出现 cache creation，按服务实际定义核对后归入输入账目，不在已有总数上重复加。先使用服务回传计量，另保存账单估算及价格版本。流中间块的累计 usage 不能逐块相加，断流缺 usage 标记未知，不能记成零。

### 3.3 工程可控的场景公式

设月内有：

```text
Q   = 用户问题数（追问也算一次）
r   = 每个问题的平均正常模型请求次数（含补字幕/补资料，不含失败重试）
i/o = 每个正常请求的平均输入/输出 token
h   = 问答输入中的缓存命中比例
T   = 新增需要纠错的课程小时数
ci/co = 每小时纠错的累计输入/输出 token
A   = 上下文摘要等辅助请求次数
ai/ao = 每次辅助请求的输入/输出 token

H = Q × r × i × h
M = Q × r × i × (1-h) + T × ci + A × ai
O = Q × r × o + T × co + A × ao
```

本模型对纠错和辅助调用假设缓存命中为 0，所有 token 均是**跨实际请求累计**的计费数量，不是单份资料只数一次。额外失败重试单独加，不偷偷包括在 `r`。

## 4. 三个假设月度场景

### 4.1 共同假设

全部为 **A：情景假设**，没有使用用户实际行为、字幕密度或付费请求结果：

- 每月按 30 天计算；用户问题包括文字追问。
- 全部调用 Flash，thinking 为 off；输入均包括实际携带的图片、文字、必要历史、工具 schema 与工具结果。
- 每小时字幕纠错累计输入假设 16000 token、输出 12000 token。输入含术语、上下文重叠和调用说明；输出假设返回完整修正版。音频时长本身不能推出这两个数。
- 辅助请求为按规则触发的长对话摘要等，不默认包含自动复盘、AI 学习伴侣、多代理和自动标题。
- 新导入课程小时数只在第一次转写／纠错时计，重开已完成资料不重复算；修改后的重算若实际发生再追加。
- 无失败重试、无付费网页 Search/Fetch、无其他远端 OCR/embedding；本地 ASR 不产生云端语音服务费，但本机电力、存储、运行资源不在此模型 token 账中。

### 4.4 哪些变化最影响结果

**A：** 保持其他条件不变，额外 1M 未命中输入增加空闲 ¥1／高峰 ¥2；额外 1M 输出增加 ¥4／¥8。当前价格下，冗长输出和 thinking 输出可能比继续压缩一张已清晰的题图更值得优化。

如果三个场景实际均无缓存，空闲时段结果分别约 ¥6.49、¥37.27、¥184.22。即使缓存完全失败，也不能省略当前解题需要的条件；真实长对话若远大于假设输入量，费用仍可能继续上升。

字幕采用小片段有利于即时可用，但过短会重复发送系统说明、术语和邻接上下文；分段纠错的 `ci` 需要实测。可以批量处理一组相邻片段、按变更更新、已处理不重复调用，但不能未经测试宣称节省固定比例。

## 5. 重试、默认贡献与外部工具

### 5.1 默认重试不会自动等于一次消费

**C：** Harness normal 默认在首次之外最多重试 5 次，适用 EMPTY_RESPONSE/RATE_LIMIT/SERVER/TIMEOUT/TRANSPORT；策略属于 provider 的 `retryPolicy`，执行插件自身没有独立 config。always 模式可持续重试；每次是新的 provider 请求。[默认策略源码](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/llm/llm/src/retry-policy.ts#L14-L24)、[重试计费说明](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/llm/llm-retry/README.md)

**J：** P0 显式有限重试，避免前端、业务层和 Harness 同时重试。幂等 request ID 防止重复点击导致本地重复派发；它不能保证超时后服务方尚未计费。对已产生部分答案的断流，保留部分结果、标记状态，通过明确恢复动作继续；取消不得被外层自动恢复机制重新提交。未知尝试保留实际 attempts，不用 `成功问题数×平均单价`冒充账单。

### 5.2 两个默认贡献项的收益须准确描述

| 真实插件 | 今日复核默认 | 建议与费用边界 |
| --- | --- | --- |

两者是请求元数据，不进入 messages／工具 schema。Session-log 关闭后重新打开会补传未确认后缀，包含关闭期间记录；inventory 开关读取时机与 session-log 不同，应按所选版本应用配置并重启验证。[Session log](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/session/session-log-deepseek/README.md)、[inventory 源码](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/llm/plugin-package-inventory-deepseek/src/index.ts)

### 5.3 网页工具与本地知识库分开

**D：** 当前中文价格页列 Search、Fetch 每 1000 次成功请求各 ¥5，并说明相关服务端工具调用将于北京时间 **2026-11-01 00:00** 起按次计费。不是本地课程检索费。[官方网页工具价格与起算时间](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)

## 7. P0 实施边界与待验证项

**P0 是 Windows 核心流程和执行接入的最小工程验证，不包含安卓同步、完整格式兼容、伴侣动画、番茄钟或复盘产品实现。** 它也不是学习成效或个人 ROI 实验。

1. **接入可靠性：** 定制 UI 经自有业务接口接 Harness，流、停止、消息归因、恢复和同会话串行正确；Web Host 内部 Peer 与 SDK＋桥接的入口按既定方案验证，不改为放弃 Harness。
2. **截图正常路径：** 用户主动截图裁剪＋文字输入，图像足够时一次模型请求即可完成；不等待字幕、无额外 OCR 模型、不预读整课字幕或全库。
3. **按需补充：** 字幕／知识库工具只按阶段开放，未就绪与未找到分开；关键图像缺失请求用户补充。禁用模型 shell／任意 `read_image`／视频取帧，用工具 guard 实际验证不能绕过。
4. **原始资产归属：** 图片、聊天、来源和任务状态用自有 schema；Harness attachment/session 只作执行映射，内部文件路径不进入跨端业务契约。
5. **费用可追溯：** 每次真实请求记录 purpose、attempt、模型、配置、开始结束、输入各类、输出、reasoning、结束状态、缓存和估算价；完整流结算一次，未知计量保留未知。
6. **显式默认：** 列出实际 profile 工具、thinking、输出上限、摘要、图片 offload、自动标题、重试与额外贡献项；没有通过配置导出和调用记录验证前，不声称“已无额外调用”。

P0 需输出的工程证据：可复现 profile／锁文件、端到端请求事件样例、正常与异常执行用量、同题 `off/low` 对照、一次字幕补充与一次资料补充记录、没有自动取帧工具的实际注册与拒绝样例。所有收益与费用系数再由这些数据替换假设。
