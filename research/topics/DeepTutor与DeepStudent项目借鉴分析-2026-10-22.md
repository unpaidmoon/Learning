# DeepTutor 与 DeepStudent 项目借鉴分析

日期：2026-10-22（Asia/Shanghai）。性质：产品与源码研究建议，不是开发执行授权、依赖选型决定或验收报告。

## 1. 判断

**DeepStudent 更适合借鉴阅读与提问的交互，DeepTutor 更适合借鉴资料来源、索引恢复与检索验证。** 本项目继续使用 Harness 原生对话与执行能力、自有课程和业务数据，将适用的学习能力接在现有工作区上。两者都不能仅凭功能数量证明比当前路线更适合用户。

对本项目最有价值的不是再增加一套聊天、插件平台或学习桌面，而是完善一条具体路径：读到不懂的内容 → 选取文字或局部图片 → 检查草稿中的引用 → 提问 → 从回答返回原文。后台解析和索引应让这条路径更可靠。

## 3. 最值得借鉴的部分

以下“怎么用”均为结合本项目需求的设计推论，不表示本轮新增实施范围。

| 借鉴点 | 查到的依据 | 对本项目的价值与取舍 |
| --- | --- | --- |
| 选区作为独立上下文，加入草稿后再发送 | DeepStudent 将选区文本快照和来源定位加入结构化引用，并在代码注释中说明旧整文档引用曾扩大到整本书。见[选区接入](https://github.com/helixnow/deep-student/blob/635216503c0b34bdf812e17942e0f09f51872e6f/src/features/pdf/components/PdfSelectionActions.tsx#L216-L244)。 | 直接服务已确认的 PDF 文字与图片选区需求。保留实际选取内容、可预览移除、多选区共同进入现有草稿；不能将手动选区悄悄换成整页或全文。 |

## 4. 不宜直接照搬的行为

### 4.1 DeepStudent：交互可借，输入与身份契约必须重做核对

- **跨页定位不足。** 所查 `resolveSelectionPage` 取 DOM Range 的 `startContainer`，只能确认起始页；不能据此宣称支持本项目要求的跨页完整来源。见[定位实现](https://github.com/helixnow/deep-student/blob/635216503c0b34bdf812e17942e0f09f51872e6f/src/features/pdf/components/PdfSelectionActions.tsx#L153-L172)。
- **来源版本与长选区处理不同。** 所查选区引用结构未带本项目要求的来源版本，超过 20,000 字符会截断；见[引用字段与序列化](https://github.com/helixnow/deep-student/blob/635216503c0b34bdf812e17942e0f09f51872e6f/src/features/chat/context/selectionRef.ts#L36-L112)。这不证明其整个 VFS 没有版本管理，但该引用链不能直接当作满足当前契约的现成组件。
- **翻译会传前后文。** PDF 动作将 `contextBefore/contextAfter` 交给翻译状态，见[组件传参](https://github.com/helixnow/deep-student/blob/635216503c0b34bdf812e17942e0f09f51872e6f/src/features/pdf/components/PdfSelectionActions.tsx#L144-L151)。本项目明确只译用户所选内容；借入口，不沿用自动扩充上下文。这里是静态传参证据，没有抓取实际模型出站。
- **媒体问答、转写和检索策略存在差异。** 所查媒体问答入口新开会话，媒体工具接外部 ASR，知识检索还有更宽的来源／记忆与联网策略；源码位置见[专项报告](DeepStudent源码借鉴分析-2026-10-22.md)。本项目同课程沿用当前会话、保持本地转写、当前课程和明确外部需求边界。
- **通用文本过滤可能不适合数学资料。** 所查索引过滤不将数学符号计为常用字符，比例低于阈值会拒绝该段，见[过滤逻辑](https://github.com/helixnow/deep-student/blob/635216503c0b34bdf812e17942e0f09f51872e6f/src-tauri/src/vfs/indexing.rs#L130-L191)。据此推论，公式密集资料需要单独验证；本轮没有测出实际漏检率。
- 自由桌面多窗口、自动笔记／题库／卡片、整课图文讲义、B 站导入和学习统计都不因参考项目已有实现而自动成为新增范围。视频关键画面自动入模型尤其不能借用文档图文检索许可。

### 4.2 DeepTutor：不迁入问答编排与额外执行层

- **当前 deep_solve 不是固定多代理流水线。** 它复用同一聊天 agent loop，添加计划、步骤完成门槛和有界重规划，见[循环定义](https://github.com/HKUDS/DeepTutor/blob/a31d82624c27d75f4e771d4fcb78dce16470b383/deeptutor/capabilities/solve/loop.py#L1-L29)。这些步骤是否提升数学效果需要实测，不能据宣传推断。默认加入会改变本项目速度优先的解题路径。
- **部分知识库首轮前会预检索。** 所查 agent loop 与传统 RAG seed 路径会为部分附加知识库补检索上下文，并非全部依赖模型随后按需调用；例外与源码位置见[专项报告](DeepTutor源码借鉴分析-2026-10-22.md)。本项目不复制该前置流程。
- **搜索存在自动找题分支。** 见[搜索入口](https://github.com/HKUDS/DeepTutor/blob/a31d82624c27d75f4e771d4fcb78dce16470b383/deeptutor/services/rag/pipelines/llamaindex/pipeline.py#L271-L294)。这与本项目取消按题号／题意找原题的决定冲突。
- 图像阅读中另调视觉模型转文字的路径，不能自动成为本项目主问答前的额外 OCR 模型调用。图文读取应遵守已确认的文档区域权限，字幕工具不补帧。
- 可视化、引导练习、生成教材等可以保留为未来用户主动需求的研究对象；不把它们加入当前 PDF／字幕／知识库交付，也不默认用提问式教学替代完整解答。

## 5. 借鉴优先级与代码复用判断

这是后续设计讨论的价值排序，不是工作包排期：

1. **优先参考已确认需求的交互。** PDF 选区卡片、独立翻译、原文定位与阅读状态；本项目跨页、多区域、版本快照和完整输入约束高于参考实现的局部契约。
2. **优先参考支撑可靠性的工程。** 同一份文字／OCR产物服务阅读与索引，来源身份和索引状态清楚，检查点恢复与版本发布可验证。
3. **接入已有 Harness 路线。** 人工搜索和只读 skill 共用项目检索服务，不新增知识库聊天，不每轮预检索。具体首批知识库任务及整章／整课归纳分期仍未决定。
4. **把执行和阅读细节用作审查清单。** 事件去重、恢复先对账、停止后保留部分回答、用户向上阅读的滚动行为；已有能力应复用而非再造。
