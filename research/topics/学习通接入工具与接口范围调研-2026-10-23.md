# 学习通接入工具与接口范围调研

检索日期：2026-10-23。本文核对超星官方开放接口、只读MCP、课程资料／媒体工具、章节PDF和作业题目导出器，作为随后grilling的事实依据。以下研究记录保留成文时的建议与未验证状态，不代表应用审核或运行验证通过。

本日后续：用户已完成逐项确认，正式范围见[学习通平台接入需求收口](../../docs/product/学习通平台接入需求收口-2026-10-23.md)，先不开发。下文“尚未收口”“下一步建议”等按当时研究阶段理解，不能覆盖后来确认，也不能由需求确认反推工具已经可用。

## 主要结论

1. 有接近本项目需求的现成实现组合：`Xuexitong-mcp`覆盖课程和资料区、作业列表／截止等查询，章节PDF工具补课件扫描，题目导出器补作业／测验正文。没有核实到一个已验证、可直接嵌入本项目并完整覆盖所有课程场景的成品SDK。
2. 官方OAuth能证明身份接入，不能由此推断普通学生应用已经获得课程、资料、作业业务接口。第三方网页会话工具提供另一类实现证据，两者分别看待。
3. 资料区文件、章节内课件和视频是不同入口；作业列表与元信息不等于题干，考试安排不等于试卷。按这些对象分别验收，避免用一个“课程已导入”掩盖缺口。
4. 有原始文件下载路径，也有平台转换PDF。不能把预览PDF或逐页图像包装成教师原始PPTX。
5. 题目导出依赖当前账号已经能打开的页面；教师未公布的标准答案不能从“导出器有答案字段”推断可获得。工具推断、用户作答和页面明确标准答案须分开保存。
6. 对真正播放、正式提交、学校任务点计入和总评成绩，现有只读／导出工具没有提供完整验证。本项目内学习记录与学校正式状态是两套事实。

### Xuexitong-mcp：适合读目录和任务元信息，不能当完整作业导入

[README](https://github.com/DanMo661/Xuexitong-mcp/blob/ebce2cc735bc7acc45fac7ccf32bcefe1a6b2a54/README.md)列16个工具，声称作者于2026-09用真实账号验证；这是作者报告，不是本轮验证，也不保证各学校均相同。已核[client.py](https://github.com/DanMo661/Xuexitong-mcp/blob/ebce2cc735bc7acc45fac7ccf32bcefe1a6b2a54/xuexitong_mcp/client.py)和[server.py](https://github.com/DanMo661/Xuexitong-mcp/blob/ebce2cc735bc7acc45fac7ccf32bcefe1a6b2a54/xuexitong_mcp/server.py)：

- `fetch_courses`读课程，`fetch_materials`按课程和班级参数读资料区，支持文件夹；`download_material`实际请求下载入口、处理重定向并流式写本地文件（client第615—689行）。这是文件下载实现，仍需核真实文件类型和完整性。
- `parse_homework_detail`只输出标题、题量、满分、起止时间和得分，**不输出题干、选项、附件和标准答案**（第170—205行）。`fetch_homework_detail`的输入又是当前列表序号，不是项目稳定作业身份。
- `fetch_chapters`只解析章节层级和任务点进度，没有视频媒体URL、字幕或全附件枚举（第827—877行）。`fetch_exams`解析考试安排表，不能说它已取到试卷。
- `find_course`按精确名称／包含名称返回首个匹配；同名课程、不同班级必须改成用户明确选定的稳定对象，不能直接照搬模型自由课名参数。
- `get_homework_detail`展示层只要存在deadline就追加“已截止”字样（server第319—321行）；其他日期处理中也有无年份时间推断。后续应以有效原始时间及真实状态判断，不直接采信该显示文本。
- 通知主要返回截断摘要；`fetch_pan_files`固定`page=1,size=100`，不能将单次结果标成完整云盘。
- “只读”指平台业务语义，不是所有请求均GET：登录与部分查询实际使用POST；下载／导出还会写本地。上游通用`save_dir`、账号密码工具参数、自动重登／重试和悬浮窗定时扫描，都需要按本项目已有边界适配，不能整包原样赋予模型。

没有执行MCP服务、调用登录或发出用户课程请求。本项目的课程隔离、实际选取范围、凭据私有、来源版本、持久任务和对账不由上游MCP声明替代。

### 题目导出器：可读已显示内容，须保留答案身份

`chaoxing-work-export`的[README](https://github.com/chenhuilin2/chaoxing-work-export/blob/8112e612f2fb3a05cf2b5f8dc632ae90f9b97713/readme.md)与[题目模型](https://github.com/chenhuilin2/chaoxing-work-export/blob/8112e612f2fb3a05cf2b5f8dc632ae90f9b97713/src/domain/question.ts)覆盖题干、选项、图片、正确答案、用户答案、解析、错题和页面来源，支持章节批量抽取及Word／TXT／Markdown。它依赖用户已登录、已打开并加载的页面，而不是学生正式开放API。

关键限制：

- [common-answer.ts](https://github.com/chenhuilin2/chaoxing-work-export/blob/8112e612f2fb3a05cf2b5f8dc632ae90f9b97713/src/extractors/common-answer.ts#L122)在页面没有标准答案、但批阅为正确时，可能把“我的答案”回填`correctAnswer`。这是根据批阅推断，不是平台明确公开标准答案。本项目应分开保留来源，不能仅复制该字段当原始正确答案。
- 富文本类型主要是文本、图片与换行，保留粗斜体及上下标；本轮没有复杂公式完整度证据。图片受跨域或权限影响时可出现占位，不能仍宣称导入完整。
- 同源iframe可递归、跨子域通过脚本消息桥接；这不表示本项目任意网页view直接可读，也不表示可以读取未开放页面。
- 它导出已有题目，未提供本项目向学习通正式提交答案和取得平台回执的完整流程。访问未开始作业／考试页面是否触发计时或状态变化，仍需后续受控验证，不由“未点提交”推定无任何副作用。

另一个[suyu-ops导出器](https://github.com/suyu-ops/chaoxing-question-exporter/blob/0664cf6a4719972116b7b6f6b92a71af11332144/README.md)覆盖随堂／章节测验、作业、已批阅考试与题库编辑。其README明确没有标准答案时可把“我的答案”放到“附加答案”中，不能视为标准答案；单题分数用于内部错题判断，却不写入导出文件。因此有导出文件也不等于保留了完整平台批阅记录。

这两个工具可作为“选择可访问题目→整理→本项目本地练习／错题”的实现参考。题干、用户原答、老师反馈、页面标准答案、工具推断和AI补充应有各自身份；具体纳入范围由下一步grilling确认。

### Chaoxing-PDF-Dumper：补章节PDF，不承诺全格式原件

[技术说明](https://github.com/Fiatnorm/Chaoxing-PDF-Dumper/blob/47888560933d5f09add0bb391b5318b91378cd39/docs/TECHNICAL.md)和[固定脚本](https://github.com/Fiatnorm/Chaoxing-PDF-Dumper/blob/47888560933d5f09add0bb391b5318b91378cd39/chaoxing-courseware-dumper.user.js)依课程／班级／章节参数读取目录与卡片、抽附件objectid、请求`ananas/status`、按状态中`pdf`字段判定PDF候选，支持章节／文件勾选、串行下载及取消。它不是仅凭页面截图合PDF的脚本，也不保证能取每个文件的可编辑PPTX原件。

所取内容可能是平台提供的PDF预览／转换件；候选URL包含`download/pdf/http`。后续需要按实际响应区分原文件与转换件，不能只以源标题或下载后扩展名判断。其`npm test`只是`node --check`语法检查，文档另列真实浏览器手测清单；本轮未运行该工具的检查或真实页面测试。

### 学无止下载器：有近期成品声明，尚无可直接嵌入证据

[作者官方教程](https://www.xuewuzhi.cn/chaoxing_downloader)显示Windows版本V2.19.59，2026-10-15发布，教程更新2026-10-03；声明可用实际课程URL和账号选择章节、视频、课件／资料下载，范围受课程开放与账号权限影响。

这是成品能力声明，不能直接当本项目已获得SDK或调用契约。网页“源码分析”明确是离线教学示例，不含真实平台登录、鉴权、解密和媒体传输；演示成功不能证明学习通媒体已取到。本轮未下载、安装或运行其成品，也未核到可直接用于本项目的正式嵌入接口。

## 下一步grilling建议

先确认平台动作边界：建议学习通端以读取和导入为首批目标，本项目内允许正常学习、作答、保存和复习，正式提交／开始考试／写入学习记录另行决定。这样“只读接入”不误伤本项目已有成果写入与练习功能。之后再逐项讨论课程和资源选择、在线／本地形态、作业／章节测验／批阅记录、截止提醒等，不将建议预写成确认需求。

学习通需求讨论不改变已确认的B站第一个接入和各平台单独验收顺序，也不扩大当前13场景范围。本轮没有写入正式学习通接入需求或变更MVP工作包状态。

## 证据口径

- 官方接口依据超星开发文档；第三方工具依据维护者 GitHub 仓库、固定源码、提交及 release 元数据。
- 未安装依赖、启动服务、登录账户、取得用户凭据、请求用户课程或执行账号写入。源码可读、README 有声明与当前真实账户可用是三种证据，本文分别标注。
- “没有核实到”表示本轮公开检索和阅读的证据范围，不断言平台绝无该能力。认证 API、机构业务 API、学生网页登录会话也不能混为同一类权限。
- 原始 PPT/PPTX、平台转换后的 PDF、逐页图片合成 PDF、截图是不同资源形态。文件名含 PPT，或者网页可以预览 PPT，均不足以证明工具取回原始可编辑演示文稿。
- 自动播放、提交任务点、刷课、自动答题不是资料导入；本轮不把这些能力计入候选工具的资料与媒体覆盖。

企业命题中也存在泛雅 AI 应用与接口合作的官方线索，例如 [服务外包创新创业大赛 A12 超星集团赛题](https://www.fwwb.org.cn/topic/show/08edec1e-9ea4-41c3-b4f6-6c01f61d0333) 提到样本课件、开放 API 设计规范与示例，以及泛雅测试环境。该证据只说明特定合作／比赛背景下有数据和接口支持，不能推广为普通学生账号普遍具备相同权限。

### 对教师、学生和管理员的区分

官方微服务文档中的“个人／企业开发者”是应用接入主体；教学系统中的“学生／教师／机构管理员”是业务角色，两组概念不能互相替换。教师可在界面操作某功能，也不表示学生 token 具备该功能，更不表示第三方应用被授予同样权限。下面两个第三方旧工具使用的是网页 Cookie 和课程 URL，不是上述微服务 OAuth。

### VirtualTowel/ChaoXingDownloader

[固定 README](https://github.com/VirtualTowel/ChaoXingDownloader/blob/5c97aa4e41d3c6ae2509efaa9032ed80e647d961/README.md) 将主要用途写为批量下载课程页面“资料”栏内容，要求先修改 `userdata.py`；同时明确 `kejian` 爬虫不完善、不建议使用，只适用首页一个视频或 PPT 的情形。

| 需求 | 固定源码实际做法 | 可确认与未覆盖 |
| --- | --- | --- |
| 登录／选课程 | 从用户提供的课程 URL 和 Cookie 开始请求 | 没有现成账号密码／扫码登录，也没有“列出全部已选课程后点选”的实现证据。用户需先定位课程链接 |
| “资料”目录与子目录 | `ziliao.py` 从课程导航找资料入口，解析表格；遇文件夹递归 `coursedata`，遇文件取 `objectid`，生成 `cs-ans.chaoxing.com/download/{objectid}` | 有资料文件树遍历与对象下载路径；依赖旧版固定 CSS／表格结构，不能保证覆盖当前页面、每个镜像站或权限设置。[资料爬虫](https://github.com/VirtualTowel/ChaoXingDownloader/blob/5c97aa4e41d3c6ae2509efaa9032ed80e647d961/ChaoXing/spiders/ziliao.py) |
| 文件下载与命名 | Scrapy `FilesPipeline` 用 item 文件 URL 下载，按抓到的资料路径与名称保存；配置启用该 pipeline | 这是直接对象文件路线，不是浏览器截图或逐页渲染 PDF；但具体返回是 PPTX、PDF、视频还是其他格式必须看服务端文件响应，不能仅凭 objectid 承诺取回原始 PPT。[下载管道](https://github.com/VirtualTowel/ChaoXingDownloader/blob/5c97aa4e41d3c6ae2509efaa9032ed80e647d961/ChaoXing/pipelines.py) |
| 章节课件／视频 | `kejian.py` 遍历章节链接，读 `knowledge/cards`，正则仅取第一个 objectid，访问对象下载地址并取响应文件名 | 明确存在“每页第一个对象”限制，没有完整枚举多附件类型；README 的限制比“支持所有课件视频下载”窄得多。[章节爬虫](https://github.com/VirtualTowel/ChaoXingDownloader/blob/5c97aa4e41d3c6ae2509efaa9032ed80e647d961/ChaoXing/spiders/kejian.py) |
| 作业、字幕、音轨 | 在所读固定源码中未发现专门导出、格式转换或流选择实现 | 不能把普通对象下载泛化为作业题干／提交内容导出、CC 字幕、AI 字幕或音频分轨能力 |

此工具抓取请求与文件保存是旧网页结构适配，不是平台正式 API；源码中“下载文件”的意图也不能代替真实账号下权限与副作用的验证。研究未请求任何实际课程。

### fichas/Down_Mooc

[固定 README](https://github.com/fichas/Down_Mooc/blob/9777755cdf44aadb10100ddcd6437f2f16afe98c/README.md) 分无 Cookie 与 Cookie 两个脚本；对 Cookie 方式限定为已选课程中已开放章节。虽然介绍称课程内容获取工具，**实际主要产物是 URL 文本清单，不是下载完成的课程资产**。

| 脚本 | 固定源码实际做法 | 可确认与未覆盖 |
| --- | --- | --- |
| [mooc.py](https://github.com/fichas/Down_Mooc/blob/9777755cdf44aadb10100ddcd6437f2f16afe98c/mooc.py) | 不传 Cookie，GET 用户提供的公开课程页，用正则抽取媒体地址写 `output.txt`，生成 `name.bat` 重命名脚本 | 不负责真正下载视频；无全账号课程列表；README 明确无法下载受权限限制课程。重命名脚本不是资料原格式证明 |
| [mooc_cookie.py](https://github.com/fichas/Down_Mooc/blob/9777755cdf44aadb10100ddcd6437f2f16afe98c/mooc_cookie.py) | 人工输入课程 URL 与 Cookie，解析 courseId／clazzid；读章节目录，遍历 `knowledge/cards`，从 iframe 的 `data` 取 objectid，构造 `cs.ananas.chaoxing.com/download/{id}` 写入 `output.txt` | 是章节对象链接枚举。没有网页扫码登录、课程总览／交互筛选、断点下载、完整性校验、字幕或作业导出实现 |

该脚本还定义了从 `attachments` 识别 `insertdoc/insertvideo` 的函数，但固定源码的主流程实际调用的是 iframe 提取函数，不能把未调用分支直接计为已实现的文档／视频完整枚举能力。`output.txt` 中对象能否以当时 Cookie、Referer 和权限取得正确原件，仍需后续受控验证；没有下载结果时不得标成“导入完成”。

两个脚本均不提供逐页截图合 PDF 的实现；因此不能说它们“只会截图”，也不能反过来说只要 URL 生成成功，就一定得到教师上传的可编辑原件。对视频而言，它们没有显式解析 CC／AI 字幕、分辨率、音视频分轨或付费解锁，不能补写这些支持。

## 本轮能确认的接入范围

| 目标动作 | 证据结论 |
| --- | --- |
| 普通学生走官方 OAuth 登录后列出所有课程并拉资料、作业 | 身份授权有依据；对应普通学生业务数据接口尚未证实 |
| 学生拿自己的课程 URL／Cookie，枚举该课资料目录并下载对象 | 有 ChaoXingDownloader 2020 年源码实现线索；当前可用性、覆盖和返回文件真实性未验证 |
| 枚举已开放章节的媒体／文档对象链接 | 有 Down_Mooc Cookie 脚本实现线索；只生成链接清单，不等于下载完成 |
| 保证 PPT 都是原始 PPTX，资料全覆盖 | 两工具均无足够证据；须逐对象区分实际格式、权限、失败和遗漏 |
| 导出作业题干／附件／学生已提交答案 | 这两个资料媒体工具没有相应实现证据；由其他专项工具另行研究 |
| 导出字幕、自动分离音轨、取当前视频完整媒体 | 没有这两个工具的专门实现／实测证据，不能由“视频链接”泛化推出 |
