# Bilibili 解析工具与接入范围调研

检索日期：2026-10-23。本文比较BBDown维护分支、yt-dlp、bili-sync系及旧bilibili-api，结合本项目已讨论的手动导入、在线播放、字幕优先及可选本地保存需求，确定可继续验证的范围。研究不代表接入、下载或实施授权；B站内容范围仍在逐项讨论。

## 主要结论

1. 现成工具的声明与源码范围已经包括普通视频、多P、合集、收藏夹、平台字幕、音频／视频下载；部分工具还处理番剧、会员内容、充电专属和已购课程。没有必要仅因早前未查到正式开放API，就断言不存在第三方接入路径。
2. 优先比较BBDownT与BBDownNext，yt-dlp作为Python集成／元数据解析的对照候选。它们都是候选，尚未决定采用；没有本机真实平台／账号验证，不能标可交付。
3. 原版BBDown和Nemo2011/bilibili-api均已归档，默认分支代码已撤下或清空，不能按旧教程直接选为当前维护依赖。现存fork须单独检查维护与发行制品。
4. “能处理会员／付费链接”只说明有对应逻辑。实际完整媒体受当前账号资格、购买／充电状态和接口下发结果影响。试看、元数据和不可播放占位不能当完整保存。
5. 下载器不是完整播放器，也不承担本项目的课程条目、重命名、移动、进度、来源与问答。HTTP任务API不等于现成账号／收藏夹浏览API；在线学习仍需适配并实际验证音视频、拖动、续播和媒体获取。

## 可支持范围的综合判断

| 范围 | 当前证据 | 对本项目的结论 |
| --- | --- | --- |
| 普通BV／AV、多P | 两个BBDown维护分支的文档，yt-dlp固定源码均覆盖 | 有现成解析基础；每P独立条目与原顺序仍由本项目组织 |
| 合集、系列、指定收藏夹内容 | BBDown分支、yt-dlp和bili-sync有对应处理 | 可作为待验证输入；列出指定收藏夹内容不等于已完成“账号下全部收藏夹→手动选择”的应用界面 |

| 平台普通CC和AI字幕 | BBDownT发行tag文档有语言及AI策略；BBDownNext区分两类；yt-dlp读取字幕列表和时间文本 | 可以按用户要求优先平台已有字幕；须确保没有被默认AI过滤、登录态或元数据查询错误漏掉 |

| 本地保存 | 工具负责下载和音视频合并 | 本项目维持同一资料身份、来源、进度与本地优先播放；源可用不等于下载已完成 |
| 高画质／大会员内容／番剧 | 有登录态、清晰度和番剧处理逻辑 | 可以列为账号有权限时的条件验证项，不能保证每种编码、地区或媒资均可用 |
| 充电专属 | BBDownNext与yt-dlp有试看识别；bili-sync-up有权限受限状态与占位 | 有资格的完整流需真实账号样例；无资格的试看／占位不得当完整视频 |
| 已购课程 | 两个BBDown分支声明课程；BBDownNext和yt-dlp有PUGV分集与可看判断 | 可作为独立内容类型验证，不由“课程下载”推断所有已购课程都成功 |
| 文件管理、预览图、进度、问题来源 | 解析器可给标题、封面和标识等基础数据 | 由本项目实现并验收；原链接、分P、远程版本和本地副本不能丢失关联 |

## 与本轮讨论直接相关的处理建议

- 收藏夹仅用于浏览和手动选取导入，不运行NAS工具的自动周期同步、全量下载或删除规则。
- 多P按标题建文件夹、每P独立展示并保持原顺序；解析失败／只回首P时明确缺口，不当整组导入成功。
- 保存本地后保留同一条目，优先本地播放，沿用进度与历史问答；实际本地媒体须完整可播，不因进程退出码0就判定成功。
- 已有字幕优先；普通CC、平台AI、本地ASR、用户手改分开标识。普通CC分类不保证人工校对；不能把弹幕XML当语音字幕。
- 字幕接口失败、缺少登录态、策略过滤和真正没有字幕是不同状态。排除这些误判后，再按已获用户许可的音频转写路线处理。
- 在线播放需验证实际轨道、请求条件、可播放编码、音视频组合、拖动、刷新与恢复。解析出URL不等于现有单文件播放器直接可用，也不宜将临时媒体地址作为永久来源标识。
- 来源读取与视频画面提交规则继续有效，解析器不会因此获得自动抽帧或扩大模型可见画面的权限。

以上是从当前用户决定与工具证据推导的适配重点，不启动代码、账号登录、下载或真实素材测试，不替代仍在进行的grilling收口。

## 证据口径

- 本轮读取项目维护者的仓库、README、源码、提交、release 元数据和 issue，未登录 B 站账户、获取用户 Cookie、下载真实视频／音频、安装或运行下载依赖。
- 下文“支持”若无单独声明，表示固定源码／文档有对应实现或声明，**没有表示在本机、当前 B 站接口和真实账号下实测成功**。
- 这些工具使用 B 站网页／客户端接口和用户登录会话；项目 README 不是 B 站官方对第三方 API 的稳定性保证。扫码登录也不等于 B 站开放平台 OAuth。
- **源码 HEAD 与已发布制品分列。** HEAD 的新功能不自动算进旧 release；本轮没有安装 release 核验，也没有把上游单元测试存在当成自己运行通过。
- 公开元数据、链接、字幕、音频、视频是不同输出；能取得链接／标题不能推导能取得完整媒体。平台提供的普通 CC 与 AI 字幕也不是本项目重新运行 ASR；视频本身没有相应字幕时不能凭此承诺存在。

## BBDown 维护分支

### 能力对照

| 需求 | BBDownNext 固定 HEAD | BBDownT 固定 HEAD |
| --- | --- | --- |
| 登录与凭据 | 文档提供 Web／TV／App 扫码登录、凭据状态和 Web 刷新；可接收 Cookie／access token。[N1] | Web `login`、TV `logintv` 扫码；可手工 Cookie／access token，说明 Cookie 刷新字段。[T1] |
| 收藏夹与列表 | `FavListFetcher` 可读指定收藏夹、分页、回填多 P；无显式收藏夹 ID 时探测默认收藏夹。不能把此机制说成现成“所有收藏夹选择器”。[N2] | README 声明合集／列表／收藏夹／空间解析，`-p` 选择分 P，交互选择流；仍需应用将解析结果包装成自己的课程选择界面。[T1] |

### 充电专属和试看必须分开

BBDownNext HEAD README 写明：没有相应 UP 主充电权限时，接口可能仍返回成功，但媒体只有几分钟；默认识别并跳过，`--allow-preview` 可保留并标记试看。README 声称有对应充电权限的登录账号可正常下载完整视频，这只是维护者声明，本轮没有实测。[N1]

源码 `PageDownload` 使用“充电专属标志＋实际流时长明显短于完整时长”判断截断，默认抛 `ChargedPreviewException`；10 月 18 日提交另加入播放载荷 `is_preview` 拒绝逻辑。两者体现工程处理，不能保证检测覆盖所有音轨／视频轨组合。[N4]

BBDownT 仍有 [issue #32](https://github.com/LOVAHE/BBDownT/issues/32)，2026-10-13：报告同一个成品内视频和主音频约 6 分钟，另一配音轨约 20 分钟。该报告说明只检查容器总时长可能漏掉残片；它是用户报告，未在本轮复现，不能据此断言所有当前版本都有同样缺陷。另有 [#34 下载失败报告](https://github.com/LOVAHE/BBDownT/issues/34)，2026-10-18。BBDownNext [#2](https://github.com/KaiHuaDou/BBDownNext/issues/2) 则针对空间动态接口 HTTP 412，不应泛化成所有普通视频均失败。

### 集成边界

`serve`／JSON API 文档描述的是任务创建、查询和下载流程，不能直接当作已经完成账号登录、收藏夹浏览与网页播放器桥接的一整套产品。BBDownNext README 还说明任务并发默认不限，serve token 需显式配置；若后续复用，应在自己的受控适配层处理，而非照搬默认。[N1][T2] 本轮未建立或执行适配器。

两分支仓库均标MIT；这只说明源码许可证，不等于外部视频内容许可。BBDownNext README另有个人学习研究／非商业用途说明，若之后交付或分发，应保留README与LICENSE间的表述差异供选型核查；本文不把它简写为已完成许可审查。[N5][N1]

## bili-sync 原项目与维护分支

这组工具主要面向 NAS 周期性同步到本地媒体库，定位比“输入链接解析”更重。原项目 README 确认收藏夹、合集、稍后再看、UP 投稿、视频分 P、音视频流选择和 FFmpeg 合并，以及失败后下一轮重试。[S1] 这类重试与周期扫描默认不能直接变成本项目行为。

| 能力 | 原项目固定 HEAD | bili-sync-up 固定 HEAD |
| --- | --- | --- |
| 登录 | README 有用户凭据认证／刷新；源码还有生成与轮询二维码登录路由，故不能只凭旧 README 说不支持扫码。[S2] | README 及凭据实现提供 Cookie／扫码相关流程；不能当作正式 OAuth。[U1] |
| 收藏夹选择 | 源码含收藏夹适配、`me/favorites` 页面；配合视频源与过滤规则组织同步。[S1] | README 明确显示用户收藏夹、快速选择；合集／系列可按 UP ID 查看。[U1] |
| 多 P／合集 | README 声明收藏夹、列表／合集与视频分页下载。[S1] | 延续相关能力，另扩展课程／番剧源；这只是分支实现证据，不代表实测每种媒资可下载。[U1] |
| CC／AI 字幕 | 固定`video.rs`的`get_subtitles`明确以`.filter(\|v\| !v.is_ai_sub())`排除AI字幕；不能误写成默认可保存AI字幕。[S3][S4] | 字幕源码明确保留普通字幕，按开关及首选语言纳入 AI；同语言优先普通字幕，AI 首选缺失时回退中文。[U2] |
| 视频／音频 | 选择最优音视频流、下载后合并，侧重媒体库同步；未证实现成“仅输出稳定播放流信息”的公共嵌入契约。[S1] | 存在 `audio_only` 与 M4A 模式、字幕等 sidecar 控制，具体配置需核所选 release。[U3] |
| 充电视频 | 不从原项目一般下载声明推断完整充电视频能力 | 更新日志与 workflow 明确无权限时保留封面／元数据、生成不可播放占位；可按视频源关闭充电媒体下载。这是识别及状态处理，不能叫作已下载完整视频。[U3][U4] |
| 已购课程 | 本轮未核实原项目课程能力，不能借分支能力补到原项目 | 固定 tree 有 `adapter/pugv.rs` 与 `bilibili/pugv.rs`；仍需按账号购买与播放权限实际验证，不能由路径存在承诺所有已购课可用 |

bili-sync-up `workflow` 中，`is_charge_video && !charge_can_play` 被视为锁定并创建占位；关闭源级充电下载则连媒体／占位都不生成。`video.rs` 对试看及充电权限错误返回受限状态。**库中存在一条记录、封面或 `.mp4` 占位，不是完整下载成功。**[U3][U4]

原版与该分支 License 均为 MIT；源码仍在且有 release 资产，不代表所有功能在目前平台接口下可用。本轮未下载可执行文件，也未运行其后台同步、删除、自动重试或凭据刷新。
