# 围绕 DeepSeek Harness 开发：职责、开发方式与实际收益

调研日期：2026-10-20（Asia/Shanghai）。对应《需求总结》第 0 节议题 2。本文是讨论材料，**不新增产品决定，不恢复构建，不将研究或 probe 标成正式应用验收**。只读核对官方仓库、发行元数据与本仓库已有证据；未安装/升级依赖，未运行 Harness 或付费模型，未取得视频画面。

## 1. 结论先行

围绕 Harness 开发，项目会从“自己组织模型调用和工具执行”，变成“开发学习产品，同时组合、约束和接入一个现有的 Agent 执行宿主”。它可能省去模型适配、工具循环、执行日志和部分恢复基础设施的重复开发，但本项目仍需完成课程、阅读/播放、截图编辑、业务历史、资料检索、学习记录及后台任务。现有官方包的职责与这些产品能力并不重合。[S2][S3][S4][S5][L1]

**对用户有感的收益，主要来自自有界面与学习流程；Harness 的直接收益主要在工程基础设施。** 更顺手的截图、原文引用和更准确的资料定位，需要项目自己设计；Harness 不会因位于执行链路中就使数学更准、首字更快或 token 更少。是否值得，要同时比较少写了多少代码、加了多少适配与维护，以及相同学习任务的实际表现。本文后半部分给出评估方法，没有现成收益百分比。[S3][S6][S7][L2]

当前 Windows Harness 主选、完全定制 UI、自有业务数据、禁止自动补视频画面的原则继续有效。隔离适配器是为了控制上游变化，不能据此自行改回无 Harness 主线。内部 Web Host 接入仍优先验证；SDK＋桥接是接口对照，两条路径都使用 Harness 执行。[L1][L3]

## 3. Harness 与项目各负责什么

| 能力 | Harness 能提供什么（官方/源码） | 本项目必须负责什么 | 当前边界 |
| --- | --- | --- | --- |
| 模型调用 | provider、Messages 请求、图片请求适配、模型流与错误分类 | 学习默认参数、凭据生命周期、中文错误与费用展示 | provider 存在；真实学习调用未验收 [S6] |
| Agent 执行 | 模型→工具→继续回答的 loop、执行中状态 | 学习说明、输入优先级、何时允许补字幕/查资料 | 不另外搭第二套规划 Agent [S2][S3][L1] |
| 工具机制 | schema、参数校验、注册、scope、guard、执行/取消流水线 | 字幕/题号/资料工具及其授权范围；禁止补帧的强制约束 | 框架提供机制，业务规则须编写 [S4] |
| 执行会话 | Session event、持久日志、执行恢复的基础机制 | 完整可见聊天、提交与生成、答案对应关系、跨端历史 | 两种数据分开，以映射衔接 [S5][L5] |
| 图片附件 | 校验、规范化、去重与执行附件/请求图 | 用户确认选区、原始裁剪、来源时间点、编辑关系、资产保留 | 可有必要执行副本；不上传完整视频 [S8] |
| 上下文与用量 | token meter、压缩、图片 offload、重试事件 | 保护当前题目条件、raw usage 归档、未知与重复计量处理 | 压缩/重试可能增加调用，须显式配置 [S7][S9][L1] |
| 插件与配置 | Cordis 服务、生命周期、profile、bundle、patch | 学习 preset、固定依赖闭包、插件选择和兼容检查 | “everything is a plugin”不等于“学习功能已齐全” [S2][S10] |
| 后台工作 | 当前 Agent 的临时 jobs 及输出观察 | 长视频 ASR、持久任务、检查点、优先级、暂停/退出与恢复 | jobs 不排队、不抢占，活跃记录不会跨进程恢复 [S11] |
| 文档能力 | 可选 Office→PDF、已有官方预览界面 | 课程资料身份、题号定位、OCR/索引、范围与引用、英语阅读片段 | 转 PDF 不自动产生课程 RAG [S12][L1] |
| 产品与跨端 | 可供 Windows 侧调用的执行宿主 | 播放/截图、三栏布局、PDF 交互、学习记录、导出与后续安卓/同步 | Harness session 不是本项目跨端协议 [L1][L3][L5] |

提示词负责指导输入充分直接答，guard 强制检查课程/资料 ID、用户提交附件与读取范围。`restrict()` 只缩小继承工具面，scope 自己注册的工具仍可见，因此注册面与实际调用都须受控。[S4][L6]

## 4. 与普通应用开发的区别，要分两个基线

| 比较项 | 简单模型 API 应用 | 同等完整能力自行开发 | 基于 Harness 的项目 |
| --- | --- | --- | --- |
| 初期代码 | 文字/图像输入与流式 API，往往较轻 | 先补工具执行、状态和日志 | 先固定宿主、学习 profile、接入协议和映射 |
| 工具调用 | 无工具时无需 loop | 自己实现 schema、分发、取消、错误与继续 | 复用执行框架，编写学习工具和 guard |
| 恢复/重试 | 常见简单实现未覆盖 | 自建日志、attempt、部分输出和恢复语义 | 复用部分运行事实，同时处理应用/宿主边界 |
| UI 与业务数据 | 自有 | 自有 | 仍应自有；不能把执行日志直接当业务聊天 |
| 长期变化 | 跟随模型 API/SDK | 维护完整执行栈 | 跟随 Harness 与插件/制品，同时维护窄适配 |
| 容易忽略的成本 | 以后补可靠性 | 自建系统规模 | 进程/协议/闭包、双持久域与内部接口变化 |

这是工程分析，不是已测工时。普通应用也会复用模型 SDK、数据库和现成组件，并非全部从零实现；核心区别是 Agent loop、工具与执行会话语义是否由独立 Harness 宿主承担。若只做“发一张图、回一段话”，简单 API 实现的初期成本通常更低；把它与配置完整的 Harness 比较，只能得到基础调用的增量成本。若目标包括工具、连续历史、执行恢复、受控重试和后续插件，则必须再比较相同功能、相同可靠性标准的完整自研成本，才看得见复用是否有效。[S3][S4][S5][S7][L2]

后端工作的一部分从执行引擎实现转为组合与验证。资料定位、来源版本、长课转写与业务身份，两种完整方案都要开发。[L1][L3]

## 5. 架构和一次提问会有什么变化

建议保留当前规划的模块方向：

```text
自有 React UI
  └─ 本项目业务 API、资产与完整聊天
       ├─ 媒体/截图、资料服务、持久任务 → Python ASR worker
       └─ ExecutionAdapter
            └─ 固定版本 Harness Host
                 ├─ provider、agent loop、工具 guard、执行日志
                 └─ 学习工具 → 调用上述本项目服务
```

这是未实现的职责草图。提问经过：保存用户确认输入/`submission` → 创建版本化 `generation` → Harness 请求/会话 → 瞬态流与持久结算 → 业务幂等写回。学习工具复用同一资料服务和 ASR 调度。[L1][L3][L5]

新增的关键工作是**跨边界一致性**。应用保存输入与 Harness 接纳执行并非同一事务；连接断开也不说明请求没有执行。需要维护业务 conversation/submission/generation 与 runtime session/request/event/attachment 的映射，区分 accepted、running、completed、cancelled、failed、unknown。结果未知先查询/对账，不凭超时自动再问一遍；本地幂等也不能承诺服务方恰好一次计费。[S3][S7][L3][L5]

### 5.1 Web Host 与 SDK 的具体影响

| 路径 | 已有能力 | 项目新增工作 | 本仓库状态 |
| --- | --- | --- | --- |
| Web Host 内部 Peer（主选验证） | Session Remote 的 prompt/follow/page/cancel，follow 有真实 assistant stream 路径 | Peer token/Cookie、HTTP envelope、WebSocket mux、事件投影和重连；按固定内部版本维护 | 空会话 create/follow、idle cancel 和 Peer 重连有局部证据 [S3][L4] |
| 官方 SDK＋自有桥接（对照） | 启动同版本 runtime、stdio JSON-RPC、会话及持久事件通知 | 当前 wire 缺实时 assistant chunk 和 mid-turn cancel，需补桥接能力 | 不能只调用高层 `run()` 就承诺实时和停止 [S13][S14] |

这两种是不同协议，不可把 Web 方法或字段直接套给 SDK。SDK 的 `finalResponse` 是一次活动区间内最后提交的根回答，并不保证与某一条输入严格一一归因；同一业务聊天需串行活动执行，并核对 request/turn/step 关系。关闭观察流也不是停止模型，普通停止不能通过杀整个 Host 实现。[S3][S13][S14][L6]

当前方案不需要再加一套 TypeScript 业务后台；Python 窄适配是否足够仍须实测。`--no-open` 能避免自动展示官方页面，但 Host 仍可能加载 Web profile 的有关包，不能因此声称默认载荷已被完全裁剪。[S1][L4]

## 6. 插件复用到底能省什么

建议按“能直接作为 Host 能力使用”“需要适配”“只借鉴或不启用”逐项评估，不以插件数量计收益。

| 插件/能力 | 有机会复用的实际内容 | 仍需支付的适配成本 |
| --- | --- | --- |
| 官方 DeepSeek provider、agent loop、tools、Session persistence | API 协议和执行基础设施 | 学习参数、guard、输入/结果映射、用量与恢复验证 [S4][S5][S6] |
| compaction、token meter、图片 offload、retry | 上下文和失败执行的现成机制 | 保护当前题图、摘要预算、有限重试、辅助调用统计 [S7][S9] |
| Office→PDF | 转换、源版本校验、缓存和取消 | 原生 sidecar/字体、Windows 制品、排版、业务身份和读取权限；不是 OCR 或 RAG [S12] |
| SenseVoice 录音 ASR | CPU 本地识别、资源准备和 worker 管理参考 | 长视频切段、时间轴、GPU 调度与持久恢复仍需另做；不能等同三小时课程字幕 [S15] |
| 官方 UI 插件 | 部分展示、工具卡片、控件的代码和交互设计 | Slots/Conversation/Remote、样式、共享 React、业务动作映射 [S16][S17] |
| session-query / jobs / MCP | 执行历史查询、临时工具作业、外部工具接入机制 | 课程知识库、持久调度、资料本身仍由应用提供 [S10][S11][L7] |

官方 Plugin Market 默认没有 index source；有市场读取/安装机制不证明已有可直接使用的数学学习插件。当前查过的官方能力不能直接覆盖完整“播放→截图编辑→字幕/资料→持续问答”产品。第三方是否存在合适方案仍属未知，不能把未检查的市场包当作已经省下的开发量。[S10][L7]

还需区分插件、skill 与 MCP：Cordis 插件提供服务和受管理的执行生命周期；skill 可以提供任务说明或资源，但不能代替 UI、业务数据服务或执行 guard；MCP 提供工具连接方式，实际 server、资料索引与权限仍须配置/提供。首版优先用能明确界定职责的薄桥接，不因存在其中一种机制就认为另两种工作已完成。[S2][S4][L7]

候选记录入口/版本/哈希、依赖、实际激活、平台资源、数据/权限、取消和许可。包可下载、peer 声明或 `dump-config` 有配置都不等于运行通过；已有两个失活模块是反例。[L4]

## 7. 完全定制 UI 不需要照搬官方界面

当前项目可以让自有 React 只连接业务后台，再由后台访问 Harness，无须在页面内挂载官方聊天。代价是项目自己实现消息、公式、真实流、停止、引用与错误状态；执行层复用不会自动生成学习界面。[L1][L6]

具体到本轮需求：可收起课程目录、阅读/播放与聊天三栏及宽度调整，公式/推导/局部子式再次加入提问，以及将跨页英语文章和配套题目作为一个阅读片段加入 AI 草稿，都属于项目 UI 与业务引用服务。Harness 可以接收最终选定的上下文，但不会自动实现这些选择、草稿预览、来源回看和范围更新；相关交互细节与是否进入首版，仍按需求文档的已确认/待定状态处理。[L10]

官方 UI 本身是浏览器 Cordis 插件应用：Host→Remote→Client model→UI adapter→Conversation→Slots→React。大多数 UI 插件依赖这套宿主，而不是通用 React 组件库。加载 Host 工具插件，与在自有 React 页面直接复用对应卡片，是两件工作。[S16][S17]

可比较自有 UI 选择性移植、为少量插件补有限接口、保留官方客户端宿主并替换布局三种深度；后者需要承担 Loader、Client models、Slots 与共享模块的整体兼容。这些是对照选项，未新增选定方案。建议先为有明确价值的一个展示样本核查移植量，再决定是否承担更多官方 UI 宿主。更换 root 并不保证所有插件无需修改；React peer 或开发依赖的范围也不等于实际 hooks、renderer、共享模块组合已兼容。[S16][S17][L2]

## 8. 调试方式会从“一条 API”变成“多层执行对账”

| 故障表现 | 优先检查哪一层 | 需要的证据 |
| --- | --- | --- |
| 课程/原文引用不正确 | 自有业务数据/检索 | asset/revision、题号或片段范围、检索结果和引用 |
| 已点发送但没有执行 | submission→adapter→Host admission | generation/request ID、accepted/inbox、Peer 状态 |
| 没有实时字，最后一次性出现 | follow/桥接/前端 | 瞬态 stream 与最终 durable event 的分别到达时间 |
| 停止按钮只停止动画 | 业务 cancel→agent/tool | 活动 generation、cancel 结果、模型/工具是否实际结束 |
| 重开后重复消息或串题 | 快照、事件序号与绑定版本 | Host generation、event seq、attempt/stream revision、幂等摄入 |
| 某插件静默不可用 | profile/注入/制品闭包 | 展开配置、激活诊断、实际 controller/provider 调用 |
| token/费用异常 | provider 与辅助调用 | raw usage、重试/摘要/标题次数、缓存与图片请求版本 |

官方提供实验 Inspector，可检查 Host/Client 的 Cordis 树、Sources 和 Host fetch；这是调查依赖与请求的帮助，不会自动生成本项目跨 submission/generation 的业务链路。完整官方开发者面板也未因此集成到本项目自有 UI。[S18][L1]

建议使用可关联但脱敏的诊断：业务 ID、runtime ID、事件/attempt、时延和错误码。Peer token、Cookie、模型 key、图片 base64 和整份资料不进普通日志。调试抓取应按需开启，且不能为调试自动补取视频原帧。[L1][L3]

必要的关联链应可追到 `submission → generation → runtime session → turn/step → event seq → raw/normalized usage`。丢失连接、用户要求停止、服务已确认取消、请求结果未知应分别记录，不能将断线或停止前端接收流统一当作执行取消。[S3][S13][L3]

验证应分层：固定 fixture 验证协议/状态→无模型空会话→已配置真实模型的截图与文字→生成中停止/断线恢复→视频播放与后台处理并行。最终文本回放不能冒充真实流，idle cancel 不能冒充活动生成中取消。[L1][L4]

## 9. 长期维护：少维护一些执行代码，多维护一组边界

可能减少 provider、工具执行和部分日志代码的维护，同时新增内部协议、插件/native 闭包及业务/执行数据一致性的维护。[S3][S4][S5]

建议固定一组制品与配置，受控升级；记录 hash、patch、实际激活清单、协议样例与自有变更。优先通过插件和窄适配使用机制，少改上游内部；若不得不 fork，明确修改范围、维护人和上游同步方式。开发预览期的升级成本应实记，不以“开源”推断长期免费维护。[S1][S2][L3][L4]

Host home 与业务数据分开，正常情况下换执行制品不应要求迁移课程/聊天；但执行日志格式兼容仍须检查。Harness 的持久化后端有历史格式处理机制，也有明确格式边界，不能承诺任意旧版/降级都可读。业务资产的导出、备份、恢复及后续安卓接续仍由本项目负责。[S5][L5]

软件许可也分层：Harness 主项目 MIT 不表示 Office、原生库、模型及所有插件都同一许可；选择移植的 UI 代码与随应用分发的依赖应分别记录。[S1][L3]

## 10. 当前实际证据支持到哪一步

### 10.1 已有的局部运行证据（2026-10-19，不是本次重测）

`probe-results.json` 记录 `modelRequestsSent=0`。隔离 Windows runtime 能 `--version`、启动 Web Host、不显示官方 UI 地建立 API Peer、创建空 Session、取得 follow snapshot、调用 idle cancel、断开后拒绝旧 Cookie、重新 connect。使用的 runtime wheel 已在历史报告核对 SHA256。[L4][L8]

同一短样本约 `1.513 秒`到 Host ready，100 ms 采样的进程工作集之和观察最大 `318,836,736 字节`，约 `304.1 MiB`。这不是严格冷缓存，也不是唯一物理内存，样本只有无模型短空会话；**不能据此外推完整应用、长期驻留、ASR 并行或 p95**。[L4][L8]

默认制品有两项整体未激活：workspace-controller 缺 `@deepseek-ai/dsh-host-directory-picker`，Office provider 缺 `@deepseek-ai/libreoffice-kit`。后者不代表“只有预览按钮坏了”；前者也不只是文件夹选择按钮。它们说明 Host ready 与 package/profile 存在，均不能代表完整能力通过。[L4][L8]

### 10.2 仍待验证

- 学习 profile 能否实际启动，所需服务全部激活，无编码 persona/任意 shell/read_image/补帧旁路。[L3][L9]
- 用户选区经附件和 provider 后的公式清晰度、真实逐字流、活动生成取消、工具取消与下一题接续。[S3][S8][L3]
- 页面关闭/重开、Host 重启、执行结果未知时的对账和恢复，无重复答案或重新计费请求。[L3][L5]
- compaction/offload 后当前题图、条件和用户修正仍正确；费用与辅助调用完整可解释。[S7][S9][L3]
- 真实问答与视频/ASR 并行的交互、CPU/内存/GPU，以及首次安装/升级/故障排查成本。[L2][L3]
- 已有 Android 历史作为已完成记录接续，不重新执行旧问题的契约样例；不等于现在交付安卓。[L3][L5]

所以现有证据足以继续讨论并保留 Harness 主线，尚不足以声称“学习 MVP 已跑通”或“已证明比普通应用更省”。

## 11. 怎样判断实际收益

### 11.1 分开评估产品收益、工程收益与运行成本

| 维度 | 建议测量 | 应如何解释 |
| --- | --- | --- |
| 学习操作 | 从定位/截图到提交的时间、完成任务的步骤、回到原文次数、重问/补交次数 | 主要评价 UI/资料流程；不直接全算 Harness 收益 |
| 回答效果 | 条件/题图理解、数学正确性、修正接续、引用是否支撑答案 | 使用固定题集和人工标准；框架名不代表质量 |
| 执行体验 | 提交→accepted、首段可见文本、完成、停止生效、断线恢复；按成功/失败分别记录 | 分开模型等待、图片上传、Host/适配与渲染成本 |
| 工程投入 | 基础设施省写工时、学习适配工时、定制 UI 迁移工时、诊断与升级工时 | 比较相同完成标准，不以代码行数或插件数代替 |
| 可靠性 | 重复提交、未知结果、旧回调、异常重启、图片范围旁路 | 关键约束应逐项通过；平均速度不能抵消数据/范围错误 |
| 模型成本 | 每次任务原始 usage、缓存、思考/输出、摘要/标题/重试、图像请求 | 缺失为未知；不能将流式累计值逐条相加 |
| 运行/交付 | 冷/热启动、闲置/生成中/并行资源、安装体积、native 下载和更新回滚 | 相同机器、相同条件记录；不从语言名推导性能 |

以上是评估建议，尚未执行；速度、收益和质量门槛应在目标任务和硬件基线清楚后讨论确认。[L2][L3]

### 11.2 公平对照应该控制什么

已有研究提出直连 API 诊断基线、Harness Web Host 主线和 SDK＋桥接对照。直连仅用于回答执行开销问题，不建立第二条生产栈，也不构成默认回退。[L2][L3]

比较前需控制：

1. 相同 DeepSeek model/provider 语义、thinking/effort、输出上限、温度、工具模式与并发。Harness 官方 route 使用 Messages；不能把 Chat Completions 参数直接拷贝后当作相同请求。[S6]
2. 相同文字、有效历史、题图、工具定义和工具返回。记录实际请求图尺寸/编码/字节；若 Harness 做了规范化，基线应使用相同最终图或明确分开测其影响。[S6][S8]
3. 相同重试预算、摘要/标题/额外贡献开关、超时和取消条件。默认 normal retry 是五次重试；always 可能持续，辅助调用不能从费用表消失。[S7]
4. 记录冷热缓存、执行次序、网络/限流和并行工作；允许的条件下重复与交叉顺序。分布指标须有足够样本，单次不能称 p95。[L2]
5. 用最终正确结果与对应原始 usage 对账，同时记录失败/停止/未知，而非只选最快成功样本。[L3]

Session log 外发与 token 还需区别：官方 `session-log-deepseek` 默认贡献日志后缀，文档明确这部分为零模型输入 token、增加 HTTP 字节。关闭它有助于控制外发范围，但不能将减少的字节直接宣称为 token 节省；OTel 是另一开关。[S19]

### 11.3 工程收益的实际记账方法

对每个明确需求，记录等能力自研的估算/样本投入，以及 Harness 接入、插件适配、升级诊断的实际投入。净工程收益是避免的基础设施开发与维护，减去上述增量成本；不能把未验证估算包装成结果。

建议先以真实截图问答、受限资料工具、取消/恢复、一个插件样本揭示成本；区分一次性接入与每个插件都需重写。当前确认方法，明确恢复实施后再执行。[L2][L3]

若核心输入范围、消息/执行归属、实时停止和恢复未通过，不能用“后续插件很多”代替证据；若成本主要集中在某个内部接口或 UI 宿主，先修正该组合和复用深度，并提出有证据的替代接入方式，仍保持已定 Harness 执行主线。[L1][L3]
