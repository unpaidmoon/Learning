## 现有核心路线（讨论基线）

```text
Windows 定制浏览器界面
    → 项目业务后台与自有数据
    → Harness 执行宿主及学习插件
    → DeepSeek 官方 API

本地转写/资料处理 → 独立 Python worker → 应用任务与产物
```

绝大多数问题使用用户提供的上下文；明确引用先定位，其余由主回答模型按需请求检索，程序限制范围和开销。默认读取当前课程的字幕及关联资料，明确需要外部信息时才联网。正常检索自动完成，真正失败或缺少必要信息时才提示，用户随时可停止。首版问答工具只读，AI 不自动补取视频画面。

保留本地自动转写，取消字幕 AI 纠错／校准。原始资料原地引用，完整聊天与已提交附件由项目管理。依据见 [Harness 调研](research/Harness开发模式与项目收益调研-2026-10-20.md) 与 [按需检索调研](research/按需上下文检索触发与等待控制调研-2026-10-20.md)；研究形成时的建议以需求总结中的后续确认结果为准。

本轮方向是 Windows 为整个产品的核心，Android 围绕连接 Windows 设计。旧方案中的安卓独立基础学习与直接问答能力保留为讨论基线，电脑离线时保留多少能力将在议题 3 中细化；不要求安卓运行完整 Harness。连接已确认 tsnet 内嵌与优先官方托管方向，具体兼容仍待验证，业务同步由项目负责。
