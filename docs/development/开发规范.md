## 2. 目标目录

以下为当前目录职责。尚未实施的模块按需建立，不预建空壳；根目录只保留项目入口、协作规则和必要工程配置：

tests/
  contracts/                跨模块与 Harness 契约验证

  development/              开发规范、环境命令、迁移记录

### 文档与证据归属

- 需求以需求总结为准；工作包状态只在 MVP 计划维护；工程规则在本文件维护；API 字段来自正式源码与生成契约；实际验收结论以对应报告为准。README 和导航简述并链接，不复制整段历史。
- 持续维护的需求、规范、方案不必加日期；单次研究、验收报告和迁移记录保留日期，运行批次使用稳定 run ID。工程目录英文小写，说明文档可用中文名。
- 仓库文档内部使用相对链接。移动文件时同步更新链接、命令、路径计算、忽略白名单和源码清单。`scripts/check_docs.py` 检查导航；不校验远程网址或标题锚点。上游第三方通知按原制品保留，内部指向上游仓库的相对引用不改写。
- 验证方案与记录模板在 `docs/validation/`；执行报告及脱敏结果按批次放 `research/reports/`。历史 JSON、失败、冻结 hash 和报告代码块不为迁移改写；旧路径通过迁移表解释，新路径回归另记证据。

- 被忽略不等于可删除。清理前区分用户资产、私有证据、执行状态和可重建缓存；本次目录整理不删除本地产物。依赖锁、许可证和上游来源说明保持各自归属。

## 3. 模块与接口

按 Module／Interface 设计：小接口隐藏较多实现细节，复杂性集中在相应 Implementation，不把第三方对象扩散到调用方。

| Module | 主要职责 | 不承担的职责 |
| --- | --- | --- |
| 课程与资源 | 稳定身份、原地路径、来源版本、目录跟踪与重定位 | 模型执行会话与 UI 内部状态 |
| 媒体与编辑 | Range 播放、用户主动截图、裁剪关系与附件结果 | AI 自行寻找视频画面 |
| 会话与上下文 | 完整业务历史、提交/生成、上下文快照 | 将 Harness 内部日志当跨端 schema |
| 执行适配 | Harness 生命周期、Peer、请求/事件/取消映射 | 业务数据库所有权与另一套聊天真相源 |
| 后台处理 | 唯一持久任务身份、租约、检查点、ASR 与产物提交 | 重复建立一套全课任务调度；已取消的字幕 AI 纠错 |
| 资料检索 | 用户已提交引用的来源定位、覆盖状态、有效版本召回和引用 | 自动按题号／题意找题或建立专用题目目录；把全部聊天、行为事件默认加入资料索引 |

不为只有一个简单调用的函数建立通用工厂，不为未来所有能力预先建插件总线。跨模块依赖优先显式传入，以同一接口验证真实行为。

## 4. 应用契约与数据

### 4.1 类型与契约来源

本轮已落地的最小身份、发布、执行／事件、水位、取消与用量契约见 [应用契约](../architecture/应用契约.md)，其字段以正式源码和生成 OpenAPI 为准，不新增独立协议真相源。

- Python 网络 DTO 用明确的 Pydantic 模型，前端使用生成的 OpenAPI 类型或可复用契约；同一 API 字段不维护两份独立手写真相源。
- `contracts/` 中生成的应用 schema 标明来源和生成方式；外部 Harness 协议样例标明版本/提交，不伪装成应用 schema。
- 外部 SDK、原生事件、路径和错误在适配器内转换；HTTP 路由不堆放领域逻辑。
- 不以 `any`、无约束字典或宽泛异常吞掉边界问题。必要兼容代码限定范围并保留测试。

### 4.2 身份、版本与状态

- `course_id/asset_id/chat_id/message_id/submission_id/generation_id` 是稳定业务身份，不能使用文件路径或数组位置替代。
- 源内容修订、派生产物修订和模型生成分别记录；修改旧题干后，旧答案仍绑定原输入。
- 时间存储明确 UTC 与单位，界面按用户时区显示；视频定位使用整数毫秒，转换供应商秒值时显式处理。
- 页序、印刷页码、页面标签与坐标系统分开保存；无法定位时提供明确降级，不返回猜测坐标。
- 状态区分 pending/running/completed/failed/cancelled/unknown 等实际语义；unknown 不是未执行，也不是零费用。
- 后续新增消息按 ID 与回答关系合并；LWW 只处理可变字段，不能整条聊天覆盖。首版用确定性样例验证接续契约，不先实现网络同步。

### 4.3 持久化与资产

- 使用 schema 迁移管理业务数据库，迁移前可恢复；升级索引不删除聊天。
- 查询与写入使用短事务，模型网络与 GPU 计算不持有数据库写锁。
- 附件先安全落地再发布业务消息，事件摄入幂等；针对 DB/文件/Harness 多持久域做对账与故障测试。
- 用户已提交截图、手动字幕、聊天是资产。只在明确生命周期下回收临时音频、无引用产物或可重建索引。
- 旧原件被覆盖且没有版本副本时，显示当时快照与来源不可用；不能把旧引用跳到新题。
- 议题 15 不做历史备份；整体导出／导入用于设备迁移。默认导出全部软件业务数据及附件，可选包含原始视频和课件；保存来源版本与附件完整性信息，未含原件时支持重新定位。
- 导入只做整套迁移恢复，暂不合并已有数据；目标已有数据时明确提示、不自动覆盖。导出与目录迁移保持业务数据和附件一致，不以简单复制运行中的数据库文件代替完整方案；既有 schema 迁移前可恢复要求继续有效。
- 导出包附带浏览器可直接离线查看的聊天记录，保留消息顺序、公式、截图和来源名称；无需安装本软件。具体格式、离线显示、完整性与迁移失败恢复待验证，详见需求总结第 0.15 节。
- 启用 WAL 前检查实际 SQLite 修复版本；只建立 venv 或固定 ORM 不代表更新了 SQLite。

2026-10-21 本轮落地使用 SQLAlchemy 2.0.43／Alembic 1.16.5，实际 Python SQLite 3.45.3 采用明确的 `journal_mode=DELETE`、`synchronous=FULL`、`foreign_keys=ON` 与 15 秒忙等待，不启用 WAL，不替换全局 DLL。迁移使用事务性 DDL，已有数据库升级前通过 SQLite backup API 生成并校验本地迁移恢复副本；这不是产品历史备份功能。Windows 附件发布先写 staging 并 fsync，再用带 WRITE_THROUGH 的 MoveFileExW 发布，业务消息随后在短事务内引用不可变附件；失败窗口与恢复结果以 V2 逐例记录为准，不仅凭代码策略宣称掉电／迁移安全已验收。

### 4.4 后续多端连接与媒体状态

议题 6 已收口，完整需求见 [需求总结第 0.8 节](../product/AI辅助学习项目需求总结.md#08-议题-6多端连接进度与远程视频已收口)。以下适用于后续多端阶段，不要求当前安装依赖或恢复构建：

- 按 tsnet 内嵌与优先官方托管方向封装连接 Interface；Windows 管理随软件交付的隐藏 Go 组件，Android 内置 Go 网络模块，运行时细节留在 Implementation。业务接口与 Harness 内部管理协议分开，不将内部凭据或任意目标代理能力开放给远端。
- 每份资料的进度及最近使用记录由 Windows 统一管理；各端打开读取、使用中定期更新，切换／暂停／退出补存。采用版本和实际操作规则去旧，不能按网络到达顺序或最大页码／时间点覆盖；不可达时保留本地状态待核对，完整离线能力按议题 3 复核。
- 视频恢复位置后缓冲就绪即自动播放；进入课程展示目录，不自动打开上次资料。用过的条目按最近成功打开时间倒序，未用的排后按文件名自然排序；后台下载与同步不算使用，进入课程或主动刷新时重排。
- Android 按播放范围读取并边播边缓存，主动完整离线保存与临时缓存有不同生命周期。缓存键包含来源版本及所需媒体变体身份，旧来源不得混用；用户主动保存内容不按临时缓存自动回收。
- 完整下载默认等待 Wi-Fi，移动流量为单次明确选择；日常点播自动播放。带宽不足允许 Windows 按需转码、自动降码率并保留原画选择；验证公式／板书可读性，调度服从前台播放和问答，不扩大模型可见视频范围。
- 恢复实施后分别验证 Android 普通 App 接入、双端生命周期、现用 VPN 并用、异地直连／中继、网络切换、范围读取／拖动／取消、缓存版本与进度旧更新；不以官方 API、补丁提案或同网 smoke 代替真实验收。共享对话和实时草稿继续按议题 12 一起交付，不新增同视频多端播放联动。

## 5. Harness 与模型执行

- 保持独立应用数据与 Harness home；通过 `ExecutionBinding`、上下文快照和事件映射衔接，名称/字段按实现统一。
- 先审查 V1 固定制品、profile、Windows 虚拟原生模块路径与短缓存补丁，再迁入正式 `harness/` 和执行模块；正式运行不得依赖 `research/probes`、旧 probe 环境或临时验证运行目录，不机械复制整个 runner。记录版本、来源、hash、闭包和实际激活／工具／系统内容。
- 内部 Peer token、Cookie 与模型凭据由后台管理，不传入前端或同步为安卓身份。
- SDK JSON-RPC 和 Web Remote 是不同协议。内部适配按固定版本实现；真实 follow、停止和重连必须实际验证。
- 同一聊天串行分发活动生成，使用 generation/epoch 隔离旧回调；重复提交与重连先核原执行。
- 安卓已完成历史只入库，必要时重建执行快照；不能伪造原生 assistant/tool 日志或重新生成旧答案。
- Windows route 使用 Harness 官方 provider；直接模型调用仅作受控对照或后续安卓本端能力，不形成隐式第二条主执行链。
- 显式设置思考、输出、摘要、图片 offload、重试与额外贡献开关。普通模型请求、工具后续、摘要和重试分别计量；不安排字幕 AI 纠错请求。
- 重试按执行确定性分类。Harness默认TIMEOUT/TRANSPORT等重跑不能直接沿用；仅减少次数仍不满足未知先对账。隔离初测可明确maxRetries=0，正式策略只对可确认未受理的情况有限重试；无法确认维持unknown，不以服务方恰好一次计费作保证。
- 在实际出站边界记录所有模型attempt，含标题/摘要/工具续答/内部替换。用户已给予项目级真实调用长期授权：已获准任务内按需自主调用和必要复测，不设总次数或固定费用额度，不逐批申请预算；历史有限额实验保留原账本，新自主调用单独记录且不重置历史。用户模型/思考选择仍保持。
- 输出量和观察／超时按具体技术任务配置，可根据证据自主调整；不把旧V1的8192 token／180秒固化为项目成本限制。授权取消的是人为消费限额，不改变执行未知先对账、输入范围和凭据保护等既定约束。
- 议题 16 已确认模型与思考强度由用户选择，不为省钱自动切换模型或降低思考；默认配置通过实际数学题测试确定，暂不设固定费用上限，用量如实记录。完整结论见需求总结第 0.11 节。
- 采用明确引用程序定位、其余主回答模型按需工具的路径，不默认增加独立分类模型。用户上下文为主，定位信息可见；默认当前课程，联网须对应明确外部信息需求，课程未命中不自动升级联网。
- 首版学习工具只读；校验课程、来源版本、附件 ID、读取范围、返回量、调用次数和总等待，嵌套或新注册工具不得绕过 guard。课程变更由界面发起的业务功能负责，正常聊天/附件保存不算模型写工具权限。
- 检索简短状态、来源和按需详情映射到自有 UI；正常过程自动处理，真正失败或缺少必要信息才提示，用户可停止。超时与有限重试由系统执行，未知生成先对账，具体数值待验证，不把首次有用内容目标当统一硬截止。
- raw usage 保留，转换为自有计量结构；区分各协议的总输入、缓存与输出，避免流式累计/推理 token 重复计数。
- raw usage注明provider或Harness来源、字段存在性与attempt/结算身份。上游转换中的默认0不能证明原字段存在；拿不到provider raw则如实标不可得，不反推虚构原始值；缺输入/输出、取消/断流保留对应未知。
- 当前题图、条件和用户修正由业务快照确定性保护，并核实际有效请求；不能以默认compaction的token尾部或image-offload占位语义保证当前题目保留。应用与Harness只保留一套明确摘要责任，不重复每轮付费摘要。
- 学习profile显式关闭session-log-deepseek/plugin-package-inventory-deepseek额外贡献，核其他日志/观测出口及实际出站。日志外发与模型token不是一回事，不能以关闭它承诺token节省。
- 工具restrict/schema只过滤部分可见面，执行guard及工具内部课程/资源/版本/附件校验仍必需。timeout-policy发abort后仍可能等待不合作工具，IO/所属进程边界要能停止；不能把timeoutMs声明当硬截止。
- 日志使用稳定业务 ID；不记录模型 key、Peer 凭据、完整图片 base64 或默认全部资料文本。调试内容按需最小化、脱敏并限期保存。

## 6. 视频输入、字幕与后台

- 播放使用登记 asset ID 到文件的 Range 路由，不整文件读入内存、不把完整视频转 Blob/base64 后播放。
- 用户主动截图使用视频原始尺寸，编辑坐标与导出一致。完整原图仅本地重编辑，模型只接收用户确认选区。
- 不允许模型通过 shell、任意 read_image、浏览器控制或其他工具补视频画面；有界资料查询不得成为取帧旁路。
- 测试默认使用合成或用户提供的图片；真实问答验收使用用户主动提交的图片，不自动从网课生成补充图。
- ASR 在独立 worker 中单模型起步，只解码有限音频。必要 DLL 与环境在子进程配置，不改变全局 PATH。
- 电池供电时照常转写，不因拔掉电源自动暂停；后台默认偏向降低发热和风扇噪声，允许耗时更长，提供“加速处理”选项，两种模式均服从播放、截图和当前问答优先。
- 转写完成或长时间暂停后自动释放转写模型占用的内存和显存，下次按需加载；保留字幕、用户修改及任务进度，不自动恢复手动暂停的批量队列。恢复实施后验证资源限制、加速档位、释放时机、实际回收与加载等待，不预先承诺功耗、噪声或性能。
- 优先级在片段之间生效；不承诺即时抢占 GPU。已提交检查点复用，未提交片段可安全重做。
- 议题 13 已确认导入后自动安排缺少可用字幕视频的整课转写，当前观看的视频优先，其余后台排队，支持按课程或视频暂停。批量暂停与当前问题的按需片段处理分别控制：暂停后仍可自动处理必要片段，结束后不得自动恢复批量队列，用户可停止当前处理；具体接入与生效方式待验证。
- 后台转写正常完成只更新进度，不弹窗、不发声音；确实需要用户介入的问题才主动提醒。恢复实施后验证此边界，不能将需求确认记为已实现。
- 取消字幕 AI 错字纠正／校准；转写和手动编辑按稳定片段 ID、来源版本更新，旧结果不能覆盖新来源或手改，不让问答模型改写字幕及时间轴。
- 记录覆盖/等待状态，区分尚未处理与未检索到。字幕未就绪不能阻塞输入充分的题目。
- 关闭网页后后台继续；明确退出只清理所属进程，不能误杀用户其他 Python、Node 或 Harness 工作。
- 议题 14 已收口（需求总结的议题 14 收口记录）：第一版安装或解压后双击统一入口即可启动后台并打开学习页面，不要求终端、开发环境或手动启动组件；默认手动启动，可主动开启开机启动。有任务时退出先提示，确认后保存已有内容与检查点、尽快停止并退出，不等待全部完成。
- 后台异常自动恢复须有次数限制，接回页面与已保存进度，失败或需要用户操作时才主动提醒；AI 未知执行先对账、不自动重发。AI／转写组件启动失败只影响对应功能，其余学习功能可用，说明影响并提供重试入口。
- 默认遵从 Windows 睡眠设置，不因后台任务自动保持唤醒；提供用户主动开启的保持唤醒选项。睡眠前尽可能保存进度，唤醒后恢复并核对 AI 执行状态。实际恢复预算、停止生效、故障隔离与睡眠／唤醒效果待验证，相关运行管理已按议题 8 纳入完整首版，不将需求确认记为完成。

## 7. 环境、依赖与格式

- 前端基础组件、样式体系、图标及同类直接能力原则上各选一套；新增组件先核查能否复用已有能力，不照抄演示站完整依赖。间接重复先尝试兼容去重，确实无法消除时记录是否进入产物、实际体积和运行影响及保留理由，不用强制覆盖掩盖不兼容。
- 统一维护颜色、排版、间距、圆角和状态规则，媒体、截图及文档控件按同一设计语言适配；不把专业库的内部状态或样式体系扩散为业务契约。具体底座、版本、主题与中文公式实际效果均须验证。

- 前端目标使用 pnpm 和跟踪的 `pnpm-lock.yaml`；Python 使用 uv、项目环境与 `uv.lock`。初始化时确定并验证实际版本后写入 manifest。
- Harness 固定源码/发行制品、哈希、profile/patch 与插件闭包；前端依赖和 GPU 模型也记录版本，不跟随 `latest` 自动漂移。
- 议题 17 已收口：依赖按实际需要升级，不持续追新；更新前完成相关验证再推送。更新默认不检查，提供手动检查及用户可主动开启的自动检查选项，检查不自动安装；不做版本回退功能，既有数据库迁移前可恢复和资产保护要求继续有效。已按议题 8 纳入完整首版，具体效果待验证，详见需求总结第 0.10 节。
- 全局环境与 research probe 只作调查证据，不是正式依赖；模型可复用经校验的缓存，避免重复下载。
- 配置中显式区分数据目录、缓存、程序与原始素材；媒体路径不硬编码为开发机路径。
- Python 使用 Ruff 格式/检查；前端使用 TypeScript 检查、ESLint/Prettier。具体配置在初始化代码时落地，未落地前不声称相应检查已通过。
- 使用 UTF-8、LF；Python 4 空格，TS/JSON/YAML 2 空格。遵循仓库 `.editorconfig`，不为无关格式进行批量改写。
- 选择性复用上游代码记录来源、版本、修改和相应许可；不将整个依赖或模型链笼统标成 MIT。本项目对外许可尚未另行决定。

## 8. 测试策略

本地浏览器边界：loopback、同源与禁通配CORS不是完整业务授权。应用自己的本地会话/能力标识、允许Host/Origin/WS握手与必要CSRF防护留在业务接口，与Harness Peer身份分离，不新增用户注册登录。状态变更不用GET；文件只按已登记业务ID/版本/授权读取，不提供任意路径代理。Markdown禁任意HTML，数学信任/复杂度受控，答案远图/URL不自动加载任意外网；离线查看资源本地提供，不携带模型/Peer凭据。

| 层级 | 重点 |
| --- | --- |
| 单元 | 状态机、来源版本、窗口边界、幂等键、上下文选择等有独立行为的规则 |
| 契约 | Harness 固定版 envelope/事件、接口 DTO、usage、图片允许范围与取消语义 |
| 集成 | 临时业务 DB、附件发布、恢复对账、任务检查点及旧结果失效 |
| 浏览器 E2E | 主动截图到输入、图文流、公式、停止、追问、重开历史和不依赖字幕 |
| 真实配置验证 | 已配置模型和 GPU 的短样本；与 mock 结果分开报告 |

普通确定性测试仍使用本地fixture/mock；需要验证模型真实行为时，按项目级长期授权和已配置环境自主执行，不再单独申请调用次数或费用额度。两类证据分别记录；缺少素材或环境时明确缺口，不以mock冒充真实模型。

测试技术基线为 pytest、Vitest 和固定 Playwright CLI；项目 `tests/e2e/test_browser.py` 通过真实 Chromium、正式启动器／ASGI 和可选正式 Host 本地 fixture 验证，不使用 `@playwright/test`。快照先于元素引用，浏览器产物保存在忽略的 `output/playwright/`；合成界面截图不包含真实视频或屏幕。针对关键行为写必要测试，不为简单文案或纯样式添加无价值测试；不以 mock 通过宣称真实模型通过。

V1—V7的分阶段方案、样本与记录模板见[验证入口](../validation/README.md)。先V1组件判定，再经明确授权进入应用；V2/3验试用，V4—7在对应完整首版功能前验，不全部前置。每次记录授权/版本/输入/失败/未覆盖；真实流、活动cancel、数学读题与推理、文字/扫描PDF、Office转换与保真、短ASR与并行分别下结论。

有用内容时间从发送到足以继续学习且未被后续推翻的解题内容；首字/thinking/状态只作诊断。每例关键条件/推导错误即失败，同类问题修复后复测原例及另一同类题。10秒仍体验目标，不改统一硬截止、不以速度放宽代替数学/保存验证。

## 9. 变更与完成标准

1. 先确定本次工作包、接口和影响，再实现最小完整闭环。
2. 范围内自主修复；发现外部兼容限制记录证据和选项，不反复询问已确认原则。
3. 运行适合变更的类型、格式、契约、集成或 E2E 检查；一轮通过后不无理由扩大和重复测试。
4. 更新契约、运行命令、计划状态和有变化的文档；使用真实命令和结果，不写“全部通过”而无范围。
5. 完成说明包含行为变化、验证和未覆盖项。截图/UI 观察、token/性能结果、组件通过和产品通过分开记录。
6. 提交、推送或发布遵循用户已有授权；未获授权时不自动执行。
