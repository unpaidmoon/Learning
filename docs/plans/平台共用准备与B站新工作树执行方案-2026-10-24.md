# 平台共用准备与B站新工作树执行方案

日期：2026-10-24（Asia/Shanghai）。依据：用户接受并行条件，明确“先开始平台接入的共用准备开发，明确与13场景开发的接口和文件责任边界，不要影响正在进行的工作。从B站接入开始，使用新工作树开发。现在给出一个执行方案”。

最新指令已授权共用准备及B站作为本次实施方向，覆盖此前这两部分“先不开发”的限制；其余7个平台不据此自动开工。**本轮交付执行方案，尚未创建新工作树、安装依赖或修改业务代码。** 后续实施按本方案在独立工作树推进，已授权范围内的常规步骤不重复请求批准。唯一工作包状态继续在[MVP开发计划](MVP开发计划.md)维护，不将授权、编写方案和代码已完成混为一谈。

## 1. 目标和已有依据

- 需求来源：[共用准备需求](../product/平台接入共用准备需求收口-2026-10-24.md)、[B站完整需求](../product/Bilibili平台接入需求收口-2026-10-23.md)、[八平台交接](八平台模块化并行开发交接方案-2026-10-24.md)。本方案安排实施顺序，不缩减已确认功能。
- 先用B站打通可使用的纵向闭环，再补齐B站完整范围。共用代码仅实现实际需要的模块启停、连接、导入、来源映射、任务和权限，不为其余7个平台预建空实现或通用插件总线。
- 13场景继续在原工作树按原范围交付；平台不加入13场景验收门槛，也不要求其暂停全部开发。平台依赖哪项能力，就在该项接口稳定后集成，不等待作文、交互书、离线成果包等全部完成。

## 2. 当前工作区事实与基线策略

编制方案时，仓库只有`D:\Codex\Learning`一个工作树，所在分支为`codex/harness-desktop-flow`，HEAD为`b3adb5b3b284245ee289caec11510c92bf533f3e`。大量13场景源码、桌面文件、第三方复用代码及需求文档尚未提交，数据库迁移目录已经出现`0022_subtitle_read_waits.py`。以上为此次只读检查的快照，不视为未来开工时的固定版本或完成证据。

新开发位置采用`D:\Codex\Learning-platforms`，分支采用`codex/platform-common-bilibili`；若位置或分支已存在，先检查归属，不能覆盖或删除已有工作。

不能仅从当前HEAD开工作树就开始接入，也不要求把原工作树全部提交或暂存。实施时采用以下方式：

1. 记录原分支、HEAD、索引状态，以及拟纳入的源码、配置、锁文件、测试和正式文档清单；纳入所需的未跟踪正式文件及本地路径依赖，例如正式桌面与第三方复用源码。
2. 按明确清单读取内容并保存hash，前后复核清单及hash；正在变动的相关文件待稳定后重新核对，不拼接不一致文件或将文件hash相同当成运行验证通过。
3. 新工作树从记录的HEAD建立，在**新工作树内**覆盖经核定的当前源码快照，保留新增与删除语义，核对清单后形成一个只用于开发的基线提交。原工作树分支、索引、源文件和运行实例保持原位。
4. 基线不复制`.local`、`.runtime`、`.venv`、`node_modules`、用户数据库、登录状态、浏览器profile、私人素材和运行产物；fixture只纳入经核定的小型合成／脱敏输入，固定制品按来源锁和hash准备。
5. 记录基线提交与后续平台提交的分界。**基线快照包含未完成的13场景内容，不整支合并回原分支，也不把该基线提交作为平台改动cherry-pick。** 以后只集成基线之后明确属于本任务的提交／补丁，在最新13场景代码上重新验证。

这样保留平台所需的现行学习能力，又不通过stash、切分支、重置索引或批量提交打断原工作树。若快照暂时无法稳定，可先推进不依赖该变化的B站解析fixture与接口测试，实际桌面集成等待可复核基线。

## 4. 需要冻结的最小Interface

下面规定行为与归属，不预填网络DTO字段真相源。平台自有Pydantic模型放在接入目录；正式对外字段由应用源码及生成契约产生。用真实宿主Adapter与确定性fixture验证同一个Interface，不重建通用插件协议。

| Interface | 平台提供 | 学习宿主提供／需要扩展 | 必须保持的约束 |
| --- | --- | --- | --- |
| 模块与连接访问 | 独立开关、私有连接、启停撤销及可用能力判断 | 在请求创建、队列执行、媒体会话和原生工具入口调用检查 | 全关闭零平台访问；旧上下文和排队请求在停用后不能继续访问；已出站保留回执 |
| 浏览与导入 | 所选连接的收藏夹／视频／分P、手选导入计划、供应商稳定对象与缺口 | 将所选内容发布为课程内稳定资源，接回文件管理与已有操作回执 | 默认当前课程；幂等导入；多P标题文件夹／独立条目／原顺序；不自动导入整个收藏夹 |
| 媒体与本地副本 | 当前授权下的媒体解析、短期播放会话与下载结果、完整性及受限状态 | 按业务资源身份打开远端或本地，沿用进度／截图／聊天；给同一条目附本地副本 | 不把临时URL作为永久身份，不将Cookie／带凭据URL交给模型或前端业务脚本；保存本地不重复建条目 |
| 字幕及音频准备 | 平台字幕与来源分类，或确认确实无可用字幕后的获准音频输入 | 发布平台轨道、复用本地ASR和准备队列，提供既有受限字幕引用 | 查询失败／缺权限不当无字幕；不覆盖手改；不自动补画面或扩大日常字幕读取范围 |
| 持久任务与来源 | 接入任务的业务输入、远端连接绑定、操作检查点、字节／逐项结果 | 复用既有任务身份、调度和恢复，将平台来源映射到版本／成果／回执 | 不另建任务中心或隐式重试；账号切换不重绑旧任务；未知先核对，恢复不重复导入／下载发布 |
| UI与原生指令挂载 | 设置／导入视图、必要操作定义、连接状态与稳定错误 | 现有设置、资源区、Harness原生“＋”／指令和对话、已有任务呈现中的挂载点 | 保留一套输入与指令机制，工具只按当前需要暴露；其余7平台不加载 |

当前`MediaStore`以本地路径及字节Range为主，`SourceStore`只读约束也不是任意远端资料入口；`TranscriptStore`的已有本地发布路径不等于已经能发布平台字幕。因此远端资源、远端媒体会话和平台字幕发布必须有明确的宿主扩展，不能简单塞入URL或调用内部方法就算接入。

每个宿主扩展交付一份小型变更说明：调用目的、输入／结果、所属课程与连接、幂等／版本、暂停／停用／未知行为、确定性测试。公共文件合并前由主线负责人核对最新实现并应用最小变更；尚未接通时用fixture推进平台内部开发，不能将其标成实际工作台已支持。

## 5. 隔离运行配置

- 新工作树独立准备锁定的Python环境、前端依赖、构建输出和固定Harness运行时，不共写原工作树`.venv`、`node_modules`、构建目录或运行状态。允许按hash复用不可变的下载缓存，不复用活动宿主和登录会话。
- 新工作树使用自己的业务数据、Harness home／Peer、日志、Electron user-data和平台凭据，不接原开发实例的数据库，不让新迁移跑到用户正常使用的数据上。
- 后台端口可选`8876`，桌面调试端口可选`9346`；启动前检查空闲，冲突则换空闲端口并记录，不停用占用进程。网页开发若另开Vite也使用独立空闲端口。
- 现有`AppConfig`支持`LEARNING_APP_DATA_DIR`、`LEARNING_APP_RUNTIME_DIR`及`LEARNING_APP_SECRET_FILE`；桌面启动已有`--backend-port`、`--data-dir`和`--user-data-dir`。实施时复核实际启动链及Harness内部端口，不能只改一个HTTP端口就认定全面隔离。
- 模型密钥仍只从原有私有配置的`DEEPSEEK_API_KEY`读取；需要真实调用时可只读引用原私有文件，不复制密钥、Peer token或登录状态，不输出值。B站连接在新工作树自己的私有存储建立，不复用／导出用户浏览器会话。
- 不修改原启动CMD、全局PATH或HOME，不自动退出／重启原应用。只管理所属进程；后台下载及ASR受控并发，不能用并行压测抢占原工作台的学习资源。

## 6. 实施步骤与阶段出口

以下为同一目标的内部顺序，不是将B站完整需求拆小后宣布全部交付；不估算未经验证的工期。

### 步骤一：隔离基线及接口落点

- 建立新工作树及可核对基线，验证运行目录、端口和所属进程隔离；先跑与所复制学习能力相关的最小基线检查，记录继承缺口。
- 固定本方案第3节的文件责任，将第4节宿主扩展与现行13场景代码逐项对照；不预占下一个迁移编号，合并时从最新head分配。
- 出口：平台可以独立开发／测试；原工作树源码、索引和运行实例未被实现步骤改变，来源与接口缺口有记录。

### 步骤二：B站所需的最小共用准备

- 完成默认关闭、按需加载、连接状态／私有存储、请求与执行检查、停用撤销、导入计划、来源／任务宿主Adapter，以及必要设置／手选视图。
- 共用注册信息可表达8个平台的独立选择与可用状态，但本次仅接通B站实现；其余平台不初始化SDK、不启动进程，也不因列在设置中便宣称已可用。
- 外部写入确认与对账规则保留在共用需求中；当前B站不回写观看历史，不为墨墨／Zotero提前实现专有写业务或空壳接口。后续写平台接入时再补齐对应能力。
- 用明确命名的fixture平台Adapter验证共用行为，不将其注册为真实已支持平台，也不创建其他7个平台的SDK或运行进程。
- 出口：全部关闭及仅B站启用、账号／课程隔离、停用后的旧调用拒绝、本地资产保留、失败／未知与恢复的确定性测试通过。

### 步骤三：B站解析与首个实际学习闭环

- 基于[已有工具调研](../../research/topics/Bilibili解析工具与接入范围调研-2026-10-23.md)中的固定候选，核对选定版本源码、制品hash、许可证、实际输出及只读副作用；确定一个主引擎，并用本项目Adapter隐藏第三方协议。不把旧研究声明当当前可用结论，不做多引擎隐式自动重试。
- 先完成普通单视频／多P链接的解析、手选导入、资源区展示、实际在线播放／提问／进度及同一条目保存本地。首个真实素材优先使用用户明确指定或已确认范围的样例；若尚无样例，先用合成媒体验证宿主链路，不擅自扩大素材范围。
- 媒体会话验证音视频分离轨、编码、Range／拖动、CDN访问条件、临时地址刷新和本地回退；不能用外部网页打开、仅元数据或先下载完整视频伪装在线播放通过。无权完整访问或无法在当前播放器安全播放时报告具体缺口。
- 公共挂载补丁先应用到新工作树用于集成验证，再由主线负责人择机应用到13场景最新代码；不把整份旧公共文件覆盖回去。
- 出口：普通视频的实际桌面纵向流程有分层证据；阶段结果只称普通样例闭环，不称B站全部验收。

### 步骤四：补齐B站完整范围

- 完成账号连接、收藏夹分页浏览与手选、多P及合集关系、专用图标／预览／改名／移动；收藏夹变化不自动导入，缺分P不冒充完整。
- 接平台普通CC／平台AI字幕，缺失时获取音频并复用本地ASR；当前观看优先、后台受控、暂停恢复和手改保护保持。
- 核对下载完整性、同一条目优先本地、重开恢复、标题／路径变化、版本及旧问答关联。封面／字幕是本地UI或资料输入，不自动作为模型可见画面。
- 会员、充电、已购课程按实际有权样例逐类验证，保留试看／缺项／受限／未知区别；账号样例不足的类别明确未覆盖，不自行缩减承诺或标整体通过。
- 出口：原B站需求逐条有实现与证据，或明确指出尚未满足的阻断及所需素材／权限。

### 步骤五：在最新主线集成及分别验收

- 再取13场景最新接口／公共文件核对兼容性，只转移平台基线后的本任务改动。公共文件改动由主线负责人按当前实现集成；不整支合并含13场景快照的开发分支。
- 生成契约、依赖锁和迁移统一落定；新工作树基于最新主线版本重新执行必要回归，保留之前冻结的测试与失败记录。
- 分别验收共用准备和B站模块；不代替13场景统一验收。需要额外真实账号或素材时，仅请求缺失的具体输入，不反复确认已有开发授权。

## 7. 验证及集成门槛

| 维度 | 必须有的证据 |
| --- | --- |
| 不干扰原工作 | 源码／索引无实现步骤越界、数据根／端口／进程隔离、原实例未被停用或迁移；只读对照可能看到13场景自身继续变化，不能据此误判平台写入 |
| 模块隔离 | 全关闭无平台SDK／进程／工具／后台访问；只启用B站不加载其余模块；停用拒绝旧会话／已排队访问，已出站回执不丢 |
| 身份和来源 | 账号／课程／分P隔离，重复导入不重复建资源；本地保存、改名移动沿用进度与问答；旧版本不改指 |
| 真正媒体学习 | 实际播放、音画同步、拖动／续播、显式截图范围、同一资源保存本地及优先本地、受限／试看／残片识别 |
| 字幕和恢复 | 平台字幕优先，无字幕与失败分开；音频ASR、手改保护、当前优先、断线／取消／重开与结果未知核对 |
| 13场景回归 | 涉及的本地文件管理、视频截图问答、阅读／字幕来源、任务恢复、原生工具范围和停止／用量对账；不将平台失败塞进13场景原交付范围 |
| 证据分层 | 静态／确定性测试、合成浏览器、真实平台／账号、真实Harness／模型及实际学习体验分别报告；未跑不标通过 |

失败或受阻先留在新工作树，不打开主线的默认平台开关。若集成后需撤回，只撤回本任务挂载与能力装配，不回滚13场景整个分支，不自动删除已保存资料、用户字幕或历史。数据库撤回不能直接用破坏性降级；使用已核对的迁移恢复／前向修复方案。
