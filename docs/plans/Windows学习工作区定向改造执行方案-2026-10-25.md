## 3. 必须实现的用户行为

| 场景 | 目标行为 |
| --- | --- |
| 直接使用聊天 | 不建课程、不打开文件也可使用；普通聊天不自动带资料 |
| 添加散落本地资料 | 默认复制到软件管理的未分类文件夹，原文件不动；同名自动编号保留两份，沿用已有复制行为 |
| 打开平台内容 | 可进入未分类或指定课程；平台链接仍为资料条目，完整下载由用户主动选择 |
| 在课程中新建对话 | 自动将该课程添加为工作区；之后可手动添加其他课程 |
| 浏览另一门课程 | 不更换当前对话、不自动增减该对话工作区，已开始的生成保持原归属 |
| 查看历史 | 使用 Harness 统一历史；恢复消息及关联工作区，不复制多份聊天 |
| 生成并保存文档 | 默认保存到创建该对话时的课程；独立对话默认未分类；明确指定时按本次要求保存 |
| 添加工作区或切换阅读内容 | 不自动改变生成文档的默认保存位置；默认保存位置不是聊天分类规则，也不授予额外读取权限 |
| PDF 阅读与提问 | 原生文字层直接选取、复制、添加到对话；纯扫描图片不提供 OCR 补字，用户可以截图提问 |
| 直接问“这页” | 仅在明确提问意图和允许范围内按需读取已有原文；无文字层时说明限制，不自动截图或 OCR |
| 查看回答来源 | 引用放在回答中，点击在中间资料区打开并定位原文；无法定位时不猜测 |
| 使用字幕 | 用户明确要求读取、获取或生成字幕时才调用 Skill；打开、播放、普通问答和缺少资料均不自动触发 |
| 生成结束 | 在原对话提供文件入口，不自动打断阅读；明确要求“生成并打开”时再打开 |

未分类目录默认放在已有软件资料管理位置下，复用现有路径配置和文件操作能力，不另建全局资料库或迁移现有用户文件。具体目录名、内部字段及实现类名属于工程选择，不额外要求用户配置。若默认保存目标缺失或不可写，明确提示选择有效目标，不能静默保存到后来浏览的课程。

## 4. 执行顺序与交付物

### 步骤 1：解除课程门槛，接入未分类资料

与步骤2一起完成基础关系调整，避免先改界面、随后因身份模型返工。

- 将“正在浏览的课程／资料”“当前对话”“对话关联的工作区”和“默认生成文件位置”分开处理；使用项目业务身份映射，不以 Harness 内部事件代替业务协议。
- 普通聊天允许工作区列表为空；未分类资料有实际复制目标，但不能因为保存目录存在就默认允许 AI 读取整个目录。
- 复用文件复制、同名编号、读取、版本及进度能力，支持无课程本地资料入口。复制失败不宣称导入成功，不动外部原件。
- 不创建新的任务管理界面。必要的数据结构调整只覆盖上述关系，兼容旧课程、聊天、附件与来源记录；不做整库整理或删除旧表。

主要落点：[桌面桥接](../../desktop/client/learning-bridge.js)、[资料目录](../../desktop/client/course-library.js)、[课程文件](../../backend/src/learning_app/course_files.py)、[原生业务映射](../../backend/src/learning_app/workbench/native_business.py)、[业务存储](../../backend/src/learning_app/storage/repository.py)。具体接口与迁移按现行源码确认，不预写另一份字段规范。

交付物：不建课程即可聊天和添加资料，文件复制有正确去处，原件及旧聊天保持可用。

### 步骤 2：使用原生工作区和统一历史，落实保存目标

- 复用 Harness 原生工作区选择／添加和历史入口。解除 `chooseCourse`／`syncSession` 等造成的强制联动，不重建会话列表和聊天框架。
- 将现有多课程读取能力映射到对话工作区集合，允许普通对话不关联资料。现行“四个课程”等实现限制需核是否实际需要，不直接宣传为新产品规格。
- 生成文件目标在明确请求执行前确定，默认使用创建对话时的课程或未分类；后续切换阅读不改变正在执行的写入位置。
- 旧单课程对话兼容到原课程工作区和默认保存目标，保留同一聊天身份、历史消息、附件、旧来源与执行记录。不得将旧未完成／未知请求自动重发。
- 来源身份、可读工作区、当前提交范围及写入目标分别核对，新增工作区不改写历史权限和旧引用。

主要落点：桌面桥接、原生业务映射、[现有读取范围](../../frontend/src/workbench/ReadCourseScope.tsx)、[来源授权](../../backend/src/learning_app/workbench/source_grants.py)、[执行工具](../../backend/src/learning_app/execution/native_tools.py)、[执行守卫](../../harness/plugins/learning-guard.mjs)。

交付物：同一对话可以显式添加多个课程，浏览课程和历史管理互不干扰，文件保存位置稳定可解释。

### 步骤 3：移除已取消的功能和自动运行链

- 取消“学习成果与任务”“问答来源”独立面板，以及独立翻译／逐段对照、做题／判分／重做、复习卡片／排期、学习路线、交互图、作文多轮批改、深入解题专用流程的入口和调用能力。普通 AI 对话仍可讨论这些内容。
- 取消课程目录的后台全文发现／提取／知识库索引和 OCR 功能，包括启动扫描、阅读焦点触发、自动恢复及对应 UI／工具入口；不以“改成手动 OCR”保留已取消能力。
- 阅读器正常渲染和使用 PDF 自带文字层继续保留；用户请求时在授权范围内即时读取原文，也继续保留。这两者不等于预先建立课程知识库。
- 取消视频激活／播放触发字幕准备，以及普通问答缺字幕时自动创建转写的回退。用户未明确要求字幕时，缺少字幕只说明限制，不偷偷转写。
- 移除自动触发和取消能力的工具注册／执行入口，不能只改前端显示或提示词。旧排队任务不能在升级后自动恢复已取消功能；原回执及数据保留。
- 保留明确任务需要的异步执行、停止、结果保存和防重复机制；字幕显式转写可复用本地 ASR 子过程。不得直接删除整个共享队列、宿主或存储模块导致保留能力断裂。
- 旧 OCR 结果、字幕、成果、用户修改和来源快照保持可读，不重新识别、不自动清理；不为删除历史兼容代码追加一轮大重构。

主要落点：[Workbench](../../frontend/src/workbench/WorkbenchPanel.tsx)、[任务表单](../../frontend/src/workbench/TaskComposer.tsx)、[PDF 阅读器](../../frontend/src/reading/PdfReader.tsx)、[PDF 准备调用](../../frontend/src/reading/preparation.ts)、[字幕会话](../../frontend/src/media/SubtitleSession.ts)、[启动装配](../../backend/src/learning_app/app.py)、[资料准备服务](../../backend/src/learning_app/workbench/processing.py)、[课程索引器](../../backend/src/learning_app/workbench/corpus_indexer.py)、[附近字幕读取](../../backend/src/learning_app/workbench/nearby_subtitles.py)。

交付物：启动、导入、打开资料、播放和普通聊天均不会创建被取消的准备任务；专用功能真正退出产品，历史内容得到保留。

### 步骤 4：打通按需读源、原生选字和引用回跳

- 复用 PDF.js 原生文字层，修正选取到引用的实际衔接；不增加全文预处理门槛。纯扫描 PDF 正常显示，用户主动截图后才能将图片用于 AI。
- 精确选区沿用“添加到对话”，保留来源、草稿和发送动作；普通选中不请求模型。
- 当前资料仅作为可被用户明确指代的对象，正文不默认附入普通聊天。由主回答模型根据用户需求调用受限读源／查找能力，不增加专门的意图分类模型、规划轮次或每轮预检索。
- 移除对旧课程索引服务的依赖，按明确需求在已授权资料中查找／读取原文；不开放任意磁盘路径、终端或 URL，不用预建向量库或全课缓存替代已取消体系。
- 来源点击直接在中间资料区打开对应资料和原版本位置；不通过恢复独立来源面板完成跳转。

主要落点：[PDF 适配器](../../frontend/src/reading/pdfAdapter.ts)、[回答选区](../../desktop/client/answer-quotes.js)、[原文读取](../../backend/src/learning_app/workbench/reading.py)、[来源](../../backend/src/learning_app/workbench/sources.py)、原生业务映射及执行守卫。

交付物：普通对话干净独立，“这页”及精确选区可自然提问，引用可以返回原文，扫描件采用截图路径。

### 步骤 5：接回保留 Skills 和已有平台能力

- 讲义／笔记、资料对照／专题研究、交互书继续经对话使用；复用现有生成和保存代码，去掉任务表单前置，不把表单字段逐项搬成聊天反问。
- 字幕作为 Skill，由用户明确的字幕需求触发；原生显式入口和自然语言均可表达需求，不要求只能输入斜杠命令。普通“解释这题”不视为字幕授权；缺字幕也不自动升级成转写授权。
- 明确字幕任务中优先复用指定范围的已有字幕；获取平台字幕及必要转写按该任务的明确范围执行，转写不足以推断时只问必要问题。结果在原对话呈现，处理与保存范围不扩大到整课其他视频。
- 普通文档生成采用已确认默认位置，文件入口回到对话；无请求不主动生成，生成结束不抢占阅读区。交互书仅适配入口和保存，不新增内部交互设计。
- 平台方面只对接已有可用实现与所需宿主扩展，支持课程／未分类去处、新工作区权限、显式字幕行为；保留账号、来源版本、模块启停、外部写入确认和未知结果对账。
- 本次不把八个平台各自完整接入作为 Windows 改造的放行前提；未就绪的平台继续保持明确状态，不以 mock 宣称真实接入完成。

主要落点：原生业务映射、[用户请求学习能力](../../backend/src/learning_app/workbench/requested_learning.py)、[任务执行器](../../backend/src/learning_app/workbench/executor.py)、[字幕](../../backend/src/learning_app/workbench/transcripts.py)、[本地转写](../../backend/src/learning_app/workbench/transcribing.py)、现有 Harness 配置／工具注册及平台分支明确的接口补丁。平台内部协议不扩散到公共界面。

交付物：保留能力可由自然语言调用；字幕只有明确请求才处理；现有平台内容可以按新交互规则使用。

## 5. 最小验收与停止条件

以下是后续实现的必要行为清单，不要求为每项新增脚本或分别跑所有证据层。优先复用已有 fixture、操作入口和有效记录，将能串联的行为放进同一正常使用流程；只对真实改动补充检查。

| 编号 | 必须覆盖的行为 | 最小观察重点 |
| --- | --- | --- |
| V-01 | 无课程聊天与未分类复制 | 不先建课即可使用；文件进入未分类副本，外部原件未变；同名保留两份；普通聊天不自动读取整个未分类目录 |
| V-02 | 多工作区、历史与文档保存 | A中新建、添加B、浏览B后仍是同一对话；统一历史可继续；默认保存A、独立对话保存未分类，显式目标覆盖默认；草稿及旧生成不串归属 |
| V-03 | 原生 PDF 与按意图引用 | 自造有文字层PDF可选字、添加、读当前页和引用回跳；纯扫描页只显示并支持主动截图，不创建OCR；普通聊天不携带当前资料正文 |
| V-04 | 已取消能力和后台准备确实停止 | 本地检查相关注册／触发路径，并在启动、导入、开PDF、激活视频和普通问答的正常流程核对无新增自动索引、OCR或转写任务；不以长时间压力或全故障矩阵代替此检查 |
| V-05 | 显式字幕与保留生成能力 | 用户明确要求字幕时正确调用和限定范围，未要求时不触发；笔记／报告原对话返回文件，保存一次、不抢占阅读；交互书沿用原有有效证据，只检查本次变更的入口／保存 |
| V-06 | 变更直接影响的保存／权限／兼容 | 用最小本地数据核旧对话／附件／来源保留、未授权资料不可读、重复提交不重复落盘。仅在相关代码改变时复测对应失败路径，沿用其他证据 |

平台接口有实际改动时，将一个已有可用接入的受影响操作并入上述流程；不重验全部平台。真实模型仅在本次工具／提交链实际变更且本地证据不足时进行必要短验证，明确复测目的和输入范围；不为每个UI项都调用模型。需要交付新运行包时，稳定后集中构建核对；平时不反复整包重建。

正常主流程和直接相关必要检查通过、没有影响正常使用／保存／权限／重复执行的已知阻断问题，即交付。跨环境、性能量化、压力、大样本、长时间稳定性和追加故障组合默认不做；未覆盖项如实说明，不虚记通过，不安排等价替代验证。

## 6. 投入、疑点与交付说明

- 通过复用底座、解除有限绑定、移除不需要的执行链和集中定向验证减少工作量；不把既有约40小时投入作为新一轮时长依据，也不以固定小时轮次代替效率改进。
