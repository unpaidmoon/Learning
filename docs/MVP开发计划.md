# MVP 开发计划

更新日期：2026-10-19。当前状态：**规范已建立；正式应用尚未初始化，以下开发任务均未标记完成。**

## 1. 当前可交付目标

先完成 Windows 上可实际使用的视频截图问答闭环：

> 原地选择视频/课程 → 播放和跳转 → 主动截图并编辑 → 补充文字 → Harness 真实流式解答 → 停止/追问 → 保存并重开聊天。

截图与文字充分时，不等待字幕、知识库或 Office 处理。默认连续聊天，由用户选择开启新对话。

里程碑顺序是开发切分，不是取消字幕和资料需求。MVP-A 优先形成截图问答，字幕 B、资料 C 随后落实；安卓、完整同步、番茄钟、伴侣和复盘后续实施。

## 2. 已有证据与明确缺口

| 已有局部证据 | 不能算已完成的项目 |
| --- | --- |
| Harness `0.2.1rc2` 隔离启动、空会话 create/follow、idle cancel、Peer 重连 | 学习 profile、真实图片、实时文本、中途停止、执行接续 |
| 自有素材的小范围 Range 响应 | 真实浏览器长视频播放、跳转与截图 |
| 60 秒 turbo GPU 推理，进程内修正 DLL 搜索后可运行 | 正式环境打包、数学准确率、时间轴、整课与前后台并行 |
| 中文 FTS 内存例 | 完整课程资料检索或题目定位 |

当前必须处理的已知问题：

- 默认制品 workspace-controller 因目录选择 seam 缺项未激活；应补齐后验收，或明确采用自有目录管理并排除不需要的失活模块，不能只忽略警告。
- Office provider 缺 LibreOffice Kit，完整 Office 后续验证；截图 MVP 不需要先下载全部 Office 资源。
- SDK 没有现成实时 chunk 和单会话中途 cancel，不能把 SDK 通知或最终文本回放当实时体验。
- 本机 Python 自带 SQLite 3.45.3 不作为正式多连接 WAL 基线；需已修复运行库，或在原型明确采用普通 journal。
- 60 秒 ASR 输出有 61.43／62.65 秒末尾越界，字幕阶段需调查和对齐；简单截断不是修复精度。

详细来源：[立项报告](../AI辅助学习项目立项调研报告.md)和对应 `research/立项调研-*.md`。

### MVP-A 验收

- [ ] 用户截图确认后直接进入输入区，无须另存或重新选择图片文件。
- [ ] 模型只获得用户确认选区与必要历史，不含裁剪外原帧、邻近视频画面。
- [ ] 字幕未完成、知识库为空时，充分的图文输入仍可完整回答。
- [ ] 输出是真实生成中的事件；可停止活动生成，状态和消息归属明确。
- [ ] 连续追问保持当前题目条件和附件，用户可自主新建聊天。
- [ ] 重启后台/重开网页后消息和附件可恢复；重复提交不创建第二个业务生成。
- [ ] 来源文件移动/缺失状态明确，不能静默指向不同版本。
- [ ] 记录操作、响应和资源基线，不从单次结果宣称 p95 或固定节省比例。

## 5. 字幕 B 与资料 C

| 阶段 | 工作包 | 进入/退出要求 |
| --- | --- | --- |
| B-01 | 固定 ASR 环境 | 明确模型、DLL 与 worker 启动环境，真实短段推理，不靠全局 PATH |
| B-02 | 修复时间轴 | 窗口范围、绝对时间、重叠去重和对齐样例通过，保留原始诊断 |
| B-03 | 唯一持久队列 | 应用任务表唯一持有任务；Harness 工具映射调用，不另建重复全课队列 |
| B-04 | 前台优先与恢复 | 验证片段间插队、暂停、worker 重启、已提交结果复用、手改优先及并行体验 |
| C-01 | 目录自动跟踪 | 防抖/稳定检测/启动对账，来源与产物版本匹配 |
| C-02 | 文档与题目对象 | 按格式分阶段，题干/小问/图形/跨页/页码完整，原文可回看 |
| C-03 | 检索和引用 | 结构定位、中文预分词、按需语义召回；有效版本、coverage 和来源精确 |
| C-04 | 导出与恢复 | 业务、附件、人工修正和来源清单可检查、恢复；不直接复制运行数据库作为同步 |

B/C 的问题不阻塞先打通截图问答，但对应能力对外可用前须完成相应验收，不能在界面假装已经就绪。

## 6. 协作与状态更新

- 每次只推进可验收工作包，先说明编号、接口和文件责任；跨文件工作保持一个集成负责人。
- 状态使用待开发、进行中、待验证、已验证、受阻；记录命令、环境、结果和未覆盖范围后才改为已验证。
- 受阻需写明具体证据与下一步，继续其他独立工作，不虚构完成或重复询问已确定原则。
- 没有真实模型条件时，保留对应验收未通过；mock 结果单独记录，不妨碍完成其他开发。
- 代码初始化后补实际命令与测试定位，必要的重大技术变更记录到 `docs/adr/`，避免把研究结论埋在聊天中。
