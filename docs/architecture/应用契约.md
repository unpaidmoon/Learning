# 应用契约

2026-10-21 MVP-A 增补：在下列 P0 执行与存储契约上添加媒体、草稿、确认图来源及受控退出。字段仍以正式源码生成的 [OpenAPI](../../contracts/openapi.json) 为准，未建立第二套会话或执行实现。

## MVP-A 媒体与草稿

- `courses/{course_id}/videos` 与主动 `pick` 仅用于用户发起的本机视频登记；原件不复制。视频内容通过 `videos/{asset_id}/content?source_version=...` 的有界 Range 读取，支持 GET／HEAD、206、416、If-Range，不经 Harness 附件或整片 Blob。登记与显式打开进行流式内容 hash 校验；Range 复用验证签名与只读源句柄。原生文件选择是用户交互，登记 API 不是模型工具。
- 播放位置为整数毫秒，`expected_revision` 做 CAS，允许主动倒退并拒绝迟到保存。进入课程不自动打开资料；用户主动打开后恢复位置并播放，浏览器阻止自动播放时显示继续播放入口。原件缺失、版本不符或重定位到其他内容明确拒绝；原有来源不静默指向新版。
- 用户主动截图在浏览器暂停当前视频并获取原尺寸原图。原图只存本机 IndexedDB 供重编；后台不接收原图。确认时只上传裁剪产物，附件来源绑定原资源版本、时间、源尺寸、源像素裁剪及编辑根／父附件。重裁发布新确认附件，已提交旧附件不可变。
- `chats/{chat_id}/draft` 持久保存文字、确认附件 ID、条件、更正和用户模型选择。修订 CAS 拒绝过期写入；提交接受后的 `draft/clear` 同时核提交身份、输入内容与修订，重复清空不误清新草稿。浏览器本机保护与未确认回执不作为第二份业务聊天真相源。
- 提交从已确认附件来源派生并核对当前课程的 locator，固化进原输入与上下文快照；原件缺失时，已确认题图仍可用于提问，不通过来源补取视频画面。无来源的原有附件兼容，跨课程来源不能通过直接提交绕过。
- 同次使用按课程保留当前聊天；收放聊天、主题、全屏与同课程换视频不新建聊天。切课程只改变页面归属，后台继续原生成。重开历史为用户主动选择。

## MVP-A 选择与退出

- 每个 generation 固定其模型、思考、输出和超时。固定 Harness 会话支持的思考为 `off/low/high/max`，应用 `none` 明确映射关闭语义 `off`；`medium/xhigh` 在发布前拒绝，不能自动降低强度。模型选择经固定 profile 登记和实际出站边界逐 generation 校验。
- 官方 `deepseek-v4-pro` 仅文字，当前附件或保留题图历史会在新提交发布前返回 `MODEL_IMAGE_UNSUPPORTED`，不丢题图、不自动换模型。已存在 submission 仍先由原 payload hash 路径判断回执／冲突，后续题图不能阻挡旧提交的幂等回执。固定 Host 不能表达该模型官方 `leading-only` 元数据，因此不伪填 `in-history`，应用 system 保持固定；Flash 仍明确声明图文及 in-history。
- `runtime` 只暴露业务实例、活动生成与退出状态。`prepare-exit` 与提交共享发布锁，冻结后拒绝新提交；有活动或未知执行时要求明确确认，未知先对账，尚未终态才逐 generation 请求取消。部分内容和未知用量保留，不自动重发。
- `runtime/exit` 仅对实际拥有本后台的 launcher 写入实例邮箱；核当前进程、实例与运行记录，不按旧 PID 杀进程。launcher 再完成生命周期与所属 Job 清理。普通“停止回答”只取消当前生成，不关闭宿主；关闭网页不发退出请求。

## 身份与所有权

| 业务身份 | 本项目持有的含义 |
| --- | --- |
| `course_id`、`asset_id`、`source_version` | 课程、原地资源及特定内容版本。路径只是可变定位信息；旧引用不静默指向新内容 |
| `chat_id`、`message_id`、`revision_id` | 课程内聊天、消息及不可变输入修订；完整业务历史保存在 SQLite |
| `attachment_id`、`snapshot_id` | 用户确认附件，以及本次生成的有效上下文快照；均包含内容完整性依据 |
| `submission_id`、`generation_id` | 用户一次明确提交与对应的一次逻辑生成；实际模型 attempt 另记，不用一个生成冒充一次计费 |
| `binding_id`、`epoch` | 业务聊天与 Harness 执行会话的映射及其代次；Harness 会话不是业务聊天身份或跨端协议 |

浏览器发送前建立 `submission_id` 并保留待核对输入。相同身份、相同内容重复提交返回原生成；身份相同而内容改变返回冲突。发布提交时在一个短事务中保存用户消息、输入修订、上下文快照、生成及助手占位；派发前另行准备并保存执行绑定，随后取得待派发生成的唯一 claim，再调用 Harness。已落库的 `pending` 可按已知尚未派发路径恢复；`dispatching`／结果未知不能自动当作未派发重新 prompt。

执行适配把业务聊天映射为内部 `conversation_id`／`session_id`，保存 `request_id`、`native_floor`、`native_turn` 和接受状态。实际出站请求必须带本生成的有效 marker，允许图片 hash 在实际出站边界检查；不依赖最后一条回答、文件路径或请求到达顺序猜归属。Peer、Cookie、Remote envelope、provider key、内部 binding 元数据只留后台；公共生成 DTO 只暴露业务身份、状态、正文／思考、水位及用量。

## 状态、事件与水位

MVP-A 真实流验证发现逐 token 独立 FULL 事务会积压，使页面 running 落后 provider 终态。本轮改为有界接收队列 256、最多 32 个内容事件／25ms 窗口一批持久化；仍逐个保存原事件身份、内容、顺序和水位，不折叠或漏记 usage。每批原子提交，before-commit 故障回滚整批，after-commit 仅在整批已持久后逐接受事件触发；重放继续按原身份幂等。确定性 1000 增量事务数从 1001 降至不超过 40，不能把不同真实模型运行的等待差值全归为此修复收益。

提交接受回执、实际活动、正文、思考和终态分别处理。正文或思考增量都属于活动；接受回执不等于答案已完成。界面可见的核心状态包括 `pending`、`dispatching`、`accepted`、`running`、`cancelled`、`completed`、`failed`、`truncated`、`unknown`，未知保留原因，不显示为未执行。

`execution_events` 以 `(binding_id, event_id)` 幂等摄入；相同身份内容不同报冲突。正文增量的事件身份由内部会话／attempt／chunk index 派生，终态由原生持久事件序号派生。相同事件重放不会重复追加正文、创建消息或累计用量。

`NormalizedEvent.seq` 与公共 `event_watermark` 是生成投影的观察序号；重启时从业务已保存的投影水位继续分配，不能冒充 Harness 持久日志序号。`native_seq`／binding 的 `last_event_watermark` 是 Harness 持久事件水位；活动流另有 `nextIndex` 用于 chunk 去重。恢复先取得原会话 snapshot／page，再按原 turn、request 和稳定事件身份补摄入；快照按原生水位替换该生成内容，不重新追加整段回放。

摄入同时核 `generation_id`、binding 和最新 `epoch`。旧绑定／旧代次事件写入拒绝诊断，不更新新生成；同一代次的已终态生成也拒绝迟到的非幂等增量。切换课程只切换页面归属，后台生成继续写入原聊天。

## 附件、来源与上下文

附件只来自用户主动选取并确认的图片。后台核媒体类型、尺寸、字节及 hash，先写 staging 并 fsync，再安全发布不可变对象，随后业务消息事务引用它。文件落地、数据库事务、Harness 持久域分别对账；未引用产物只识别为 orphan，不自动删除用户资产。缺失必要确认图会阻断依赖提交，不能略过图片、补原帧或换新版图。

原件保存稳定资源身份、来源版本和当时定位；内容覆盖、移动或缺失的状态可区分，重定位必须校验版本。旧提交的题图、条件与修订不被新草稿覆盖。完整历史与模型有效上下文分别保存，执行快照保护当前题图、条件和最新更正；本轮关闭自动压缩／image offload，溢出不能悄悄丢图重发。

已完成外部 U2／A2 只按消息和修订身份合并到业务历史，重复合并不派发旧问题、不伪造 provider 日志或 usage。必要时将旧 binding 标 stale，下一次明确提交 U3 才建立新 epoch 并带入允许历史。该契约由固定样例验证，不包含同步网络或 Android 实现。

## 取消、未知与用量

停止通过单会话 `cancel` 发出意图，保留已收到的正文／思考；只有原执行的持久终态决定最终是取消、已完成或未知。停止不等于断开浏览器观察，也不关闭整个 Host。provider IO 由所属取消路径中断，HTTP 解析器由读取线程关闭，避免并发关闭。确认终态后才能安全继续下一问；未知时先对账原会话，不自动重新提交。

每个实际 provider 出站 attempt 在独立边界记录，再映射进业务 `outbound_attempts`；fixture 的本地 Messages 与真实出站区分，取消／失败也保留 attempt。计数不构成次数或固定费用上限，模型与思考遵从用户配置。

用量保留 provider raw observation、字段存在性、归一化值和结算身份。缺字段、取消后无最终结算均为未知，不把 message_start 的输出零当最终零。累计流式值取最新快照，不相加；独立 reasoning 字段缺失为未知，不能再重复加到总输出。usage 观察事件身份包含观察内容摘要，结算按 provider request 的稳定 `settlement_id` 管理，允许未结算观察更新为最终观察；已结算数据冲突报错，重复对账不重复结算。正文完成与用量已知／未知相互独立。

## HTTP、WebSocket 与生成契约

服务只监听 loopback，仍严格核 Host／Origin。浏览器从 `/api/v1/session` 获得应用自己的 HttpOnly、SameSite cookie 与 CSRF token；写操作需要匹配的 `X-Learning-CSRF`，WebSocket 需要允许 Origin、应用 cookie 及 `learning.<csrf>` 子协议。它们与 Harness Peer 凭据分离；文件只按已登记附件业务身份读取，不提供任意磁盘路径路由。当前没有业务远程退出接口。

后台 Pydantic DTO 是 HTTP 类型来源。`scripts/export_openapi.py` 在不进入 lifespan、不打开业务库、不启动端口／Host、不读取凭据的情况下导出 `contracts/openapi.json`；固定 `openapi-typescript` 生成 [api.ts](../../contracts/generated/api.ts)，前端从该类型导入。根 `contracts:check` 核实际导出与生成类型漂移，不维护另一份手写字段真相源。

本轮证据分层保留：正式存储及故障测试、固定 Host 本地 fixture、真实模型、真实 HTTP／WebSocket／Chromium。P0 验证界面不等于学习软件试用或完整首版；数学排版、视频截图流程和用户学习效果属于后续 MVP-A／V3。
