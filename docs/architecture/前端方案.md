## 1. 方案结论与阅读方式

采用 React＋TypeScript＋Vite 的定制单页界面，以用户已确认的 shadcn/ui 源码组件＋Tailwind CSS 建立统一设计语言。浏览器只连接本项目业务后台；Windows 文件、持久化、后台任务、模型凭据和 Harness 内部协议留在后台。媒体、图片裁剪、文档和公式继续复用成熟实现，不另起一套聊天执行或存储体系。

视觉采用温和放松的 DeepSeek 蓝白，正文和公式舒展、导航与工具紧凑，默认浅色、可手动切深色。专业组件的工具栏、弹窗、错误与加载状态沿用同一规则。既有大肥鱼聊天壁纸方向保留，陪伴互动按原定后续分期交付。

用户不需要检查代码或选底层依赖。判断效果的依据应是实际中文、公式、题图与可操作页面；工程侧负责检查实现、依赖、输入权限和状态恢复。建议在恢复实施后先验证一个主学习页面样板，再推广到其他页面。这是本方案推荐的评审方式，尚不是此前已收口的用户决定。

## 3. 页面与工作区

### 3.1 页面职责

| 界面 | 主要内容 | 行为依据 |
| --- | --- | --- |
| 课程入口 | 课程项目、主动导入、归档与重新打开 | 原件原地引用；不创建系统软链接；不新增课程之间的排序设计 |
| 主学习工作区 | 可收起课程目录、中间播放或阅读、右侧当前聊天 | 学习区与聊天宽度可调；工具不占用大块正文空间 |
| 聊天历史 | 当前课程的历史查找、选择与接续 | 保留并复用 Harness 的基础交互，业务记录和身份归本项目 |
| 截图编辑 | 用户刚触发的截图、缩放和平移、选区、确认与取消 | 确认后才进入提问附件，加入草稿与发送分开 |
| 任务面板 | 转写与资料任务、进度、暂停恢复、必要错误 | 不设置默认学习统计仪表盘，不用完成弹窗和声音打扰正常学习 |
| 设置与数据管理 | 模型、思考强度、明暗、数据位置、迁移、运行、资源与更新 | 界面反映真实可用能力和当前保存状态 |

历史、任务和设置适合用工作区面板或独立路由呈现，具体采用方式以样板中的空间和返回体验决定，不为每项操作增加一层全屏页面。未来需要导航定位时，使用薄的客户端路由；可评估 React Router 的浏览器路由模式，不引入 SSR、服务端组件或新的前端业务服务器。

### 3.2 课程目录与资料打开

进入课程只展示目录，不自动打开上次资料。用户打开具体视频后，读取该视频的位置，定位并在缓冲就绪后自动播放；文档恢复自己的阅读位置。浏览器阻止播放时显示明确的继续播放入口，不假装已经播放。[浏览器播放限制](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)

课程内用过的资料按最近成功打开时间倒序，未用的排在后面按文件名自然排序；后台下载和同步不计为使用。只在重新进入课程或主动刷新时重排，不在点击过程中移动条目，也不增加另一套排序选项。

目录中的资料身份使用 `asset_id` 与来源版本；显示名称、格式和必要状态。文件找不到时给出重新定位入口，旧聊天、截图和来源名称继续保留；来源已经变更时不能把旧引用静默指向新内容。

### 3.3 中间学习区与内部多窗口

早期单资料视图和完整首版多窗口共用同一资料视图接口。完整首版在中间区域管理内部窗口的位置、大小、叠放和当前焦点，右侧聊天保持可用；这不是独立操作系统窗口，也不要求移动端提供相同布局。

窗口布局只保存应用自有的几何数据与资源身份，第三方拖拽状态不成为长期协议。窗口缩放后把标题栏和必要操作保持在可访问范围；拖拽不误触页面文字选择，公式选取时不启动窗口移动。

打开讲义、切换阅读资料或遮住视频时保持视频原播放状态。普通窗口失焦不等于暂停，播放器不能因为被另一个面板遮住就卸载。多视频同时打开时的音频与活动播放器归属尚需验证和细化，不擅自增加“失焦即暂停”规则；来源回看应明确定位到来源资源对应的播放器。

### 3.4 沉浸式播放

沉浸播放打开问答时，视频在左、聊天在右、目录隐藏；关闭聊天框后恢复视频全屏并继续播放，当前对话保留。进出全屏、收放聊天不创建新对话。截图仍自动暂停；普通发送和追问不强制暂停。

浏览器全屏建议作用在可包含视频与聊天的应用容器，而非仅对原生 `video` 进入全屏，避免右栏无法出现。使用 Fullscreen API 的请求、退出和状态事件处理权限拒绝及用户按 Esc 退出；拒绝时保留可用的应用内沉浸布局，不声称进入系统全屏。[Fullscreen API](https://developer.mozilla.org/en-US/docs/Web/API/Fullscreen_API)

## 4. 统一视觉与交互规则

### 4.1 视觉基线

以学习内容为视觉中心：用少量蓝色强调当前选择和主要操作，以白色或柔和中性色承载正文，通过间距、对齐和轻量分隔建立层次。避免为了展示功能把页面做成密集数据卡片，不用装饰遮住题图或推导。

“DeepSeek 蓝白”是用户确认的方向，精确色值尚未锁定。恢复实施时以用户认可的实际参考核对蓝色，建立明暗色阶；正文、选中态和按钮文字分别测对比度，不直接把品牌蓝用于所有文字。

| 语义 token | 浅色用途 | 深色用途 |
| --- | --- | --- |
| `background`、`foreground` | 柔和浅背景与清楚正文 | 深色背景与清楚浅色正文 |
| `surface`、`surface-muted` | 阅读、输入和次要导航层级 | 用有限亮度差区分层级 |
| `primary`、`primary-foreground` | DeepSeek 蓝系主要操作及其文字 | 对深背景调整后的同色系操作色 |
| `accent`、`accent-foreground` | 选中、悬停与键盘焦点附近的轻强调 | 可辨认但不大面积发光的轻强调 |
| `border`、`ring` | 轻分隔与可见焦点 | 分隔与焦点均需独立可辨 |
| `success`、`warning`、`destructive` | 必要的业务状态 | 保持语义一致，并辅以文字或图标 |

token 通过 CSS 变量集中维护，与 shadcn 的语义颜色约定映射；业务页面不各自写一组蓝色常量。播放器、编辑器、PDF 工具栏和弹窗使用同一映射。[shadcn 主题机制](https://ui.shadcn.com/docs/theming)

### 4.2 字体、密度与尺寸建议

以下为工程起点，不是用户已确认数值或最终样式。用实际窗口与内容调整后集中固定，不逐页自行修改。

| 项目 | 建议起点 | 检查重点 |
| --- | --- | --- |
| 聊天正文与问题输入 | 16–18 CSS px，正文行高约 1.6–1.8 | 中文连续阅读、题图旁文字、输入多行不挤压工具 |
| 侧栏与辅助说明 | 13–14 CSS px，主要操作不依赖小字 | 长课程名可识别，次要文字不能淡到难读 |
| 工具控件 | 约 32–36 CSS px 高，清楚焦点与标签 | 鼠标易点，不能因图标变小同时缩小整个点击区域 |
| 间距 | 以 4、8、12、16、24 为有限尺度 | 正文段落与公式留白比工具栏更舒展 |
| 三栏初始宽度 | 目录约 224、聊天约 440 CSS px，学习区使用余量 | 允许拖动；小窗口不机械保留这些宽度 |
| 圆角与阴影 | 少量统一层级，弹出层适度阴影 | 不给每段推导、每个操作重复加卡片和阴影 |

正文优先使用 Windows 清楚可读的中文系统字体及明确后备；数学使用所选渲染器的配套字体。字体、图标、样式和公式资源随本地应用或离线查看包提供，不依赖外部字体 CDN 才能阅读。专门引入字体须说明可读性收益、体积与许可。

### 4.3 明暗、壁纸与动态

默认蓝白浅色，用户手动切换深色后保存偏好并在下次启动恢复。防止启动时先闪出错误主题；切换只改变呈现，不重建聊天、播放器或草稿。当前没有要求自动跟随 Windows，不替用户新增自动切换规则。

大肥鱼壁纸在聊天背景层呈现，内容承载层保持足够遮罩或底色，分别检查浅色、深色、长推导和题图。壁纸是既有视觉需求，不据此提前开发养成、动态伙伴或额外模型人格。

常规反馈优先使用基础组件已有状态与轻量 CSS 过渡；必要的展开和切换保持短促，不以持续漂浮、闪烁或滚动装饰占据学习区。尊重减少动态的系统偏好。Magic UI、React Bits 和独立动画引擎不是默认依赖，只有明确价值并核查重复后才取用。

### 4.4 可读性与可操作性

把普通文字对比度至少 4.5:1、大号文字至少 3:1 作为验收目标，并按 WCAG 对大号文字的定义判断，不能把任意加粗小字算作大字。此目标不是已经取得无障碍合规结论。[W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

所有高频操作有可发现的鼠标入口；图标按钮具有可访问名称，菜单、分隔拖动、弹窗与输入区有可见键盘焦点。快捷键须避开中文输入法和浏览器冲突，输入法组合输入期间不误发送。弹窗关闭后焦点返回合理位置，拖拽和公式选取不互相抢占事件。

在常见 Windows 缩放与浏览器缩放下检查布局。窗口变窄时优先使用可收起目录和可调分栏，必要时提供资料聚焦视图；不隐藏未发送输入或让重要按钮移出可操作范围，也不把此处扩写成 Android 响应式产品设计。

## 5. 成熟库选择与采用门槛

### 5.1 主体技术

| 能力 | 推荐实现 | 采用条件 |
| --- | --- | --- |
| 页面与构建 | React＋TypeScript＋Vite，静态资源由本地业务后台同源提供 | 配套版本完成类型检查、构建和真实浏览器验证后固定；本轮不指定 `latest` |
| 基础 UI 与样式 | 已确认 shadcn/ui 源码＋Tailwind CSS | 选择一套主要底座和有限组件，统一 token；不照抄演示站依赖 |
| UI 底座 | 优先验证 Base UI，Radix 为有证据的兼容备选，最终只选一套 | 弹窗、菜单、选择器、Tooltip、中文输入法、键盘焦点、内部多窗口弹出层与依赖检查通过后固定 |
| 服务端数据 | TanStack Query | 管课程、历史分页和任务快照；唯一业务存储仍在后台 |
| 临时共享状态 | Zustand；单视图状态优先 React 本地 state/ref | 仅放跨视图编辑和工作区状态，不复制第二份可写聊天数据库 |
| 接口类型 | 从业务后台 OpenAPI／schema 生成或复用 | REST 与流事件均有自有契约来源，不手写两份独立字段真相源 |
| 图标 | 单一图标库，优先评估与所选 shadcn 预设一致的 Lucide | 按需取用，不为少量图标增加第二套图标包 |

shadcn 在 2026 年 7 月将 Base UI 设为新项目默认，并继续支持 Radix；当前官方上下文也区分 `base`、`radix`、`aria`。本项目没有既有前端，建议沿当前新项目方向优先验证 Base UI，不能把 shadcn 必然等同于 Radix，也不因此同时安装三套。[官方默认底座公告](https://ui.shadcn.com/docs/changelog/2026-07-base-ui-default)、[shadcn Skills 与项目配置](https://ui.shadcn.com/docs/skills)

### 5.2 专业能力

| 能力 | 候选主选与后备 | 必须验证的行为 |
| --- | --- | --- |

| 三栏调整 | shadcn Resizable 源码组件，底层复用 `react-resizable-panels` | 最小可用宽度、键盘调整、折叠后草稿与播放不丢；核对所选版本 API 与尺寸单位 |
| 内部自由窗口 | 评估 `react-rnd` 等同时提供移动与尺寸调整的实现 | 叠放、焦点、边界、缩放坐标、页面选择冲突、隐藏后视频不卸载 |

分栏与内部自由窗口是不同布局职责。若确需两个布局库，先核查是否能用同一成熟实现覆盖、实际重叠与成本；不再额外直接叠加独立拖拽、手势和尺寸库。不能用只支持固定网格或停靠标签的方案，代替已确认的自由移动和叠放能力。

shadcn Resizable 已包含分栏能力，不再为同类功能引入 Split.js；完整首版自由窗口另按实际行为验证。候选能力来源见 [Resizable](https://ui.shadcn.com/docs/components/base/resizable) 和 [react-rnd](https://github.com/bokuweb/react-rnd)。

专业库的既有证据见[前端与安卓扩展选型依据](../../research/topics/前端与安卓扩展选型依据.md)、[技术选型方案](AI辅助学习项目技术选型方案.md)。这些记录中的版本是历史核对候选，不等同于本方案已经解析和验收的依赖组合。

### 5.3 复用 Harness 的范围

保留并复用 Harness 已有对话、模型与思考选择相关功能和交互能力；执行经后台适配。官方聊天 UI 插件依赖其宿主，不能直接当成通用组件库加入。对消息、附件、模型选择器逐项核查可抽取的源码和交互，再融入自有设计系统；不因为有一套新 UI 就重复实现执行、模型路由或会话存储。

不默认引入带另一套 agent runtime、消息真相源或自动模型调用的聊天框架。AI Elements 等单个呈现组件可作后续候选，但不能连同演示中的模型 SDK、消息协议和供应商接口一起照搬。

## 6. 组件源码与依赖治理

基础组件放入项目的 `components/ui`，记录上游来源、提交或发布版本、相应许可和本地修改。开发者通过这些组件组合页面，不在每个业务模块重写按钮、弹窗、提示和输入状态。只有实际重复的业务组合才抽出共享组件，不预先建立通用 UI 插件平台。

| 层次 | 项目维护内容 | 更新方法 |
| --- | --- | --- |
| 设计规则 | token、字体角色、密度、交互状态和专业组件映射 | 集中调整，检查浅深色及代表性页面 |
| 基础组件源码 | 选用的 shadcn 组件及项目修改 | 对比上游差异，审查后合入，不盲目覆盖 |
| 业务组合 | 课程条目、附件预览、来源卡片、消息、任务条目 | 按业务契约演进，不依赖第三方内部对象 |
| 专业库 | 锁定版本的依赖及薄的能力适配 | 核兼容与行为，再调整适配内部实现 |

新增依赖前，先说明实际需求、已有组件为何不能满足、是否引入第二套基础 UI／样式／图标／渲染能力。对确定引入的包检查直接与传递依赖、许可证、浏览器支持和生产产物，而非只看包大小或星数。

兼容重复优先去重；无法消除时记录包路径、原因、是否进入前端产物、实际成本及退出条件。不得强制覆盖不兼容版本，也不得用“源码复制”掩盖组件隐含的运行时依赖。开发辅助 MCP、Skills、浏览器工具与产品运行时分别记账。

恢复实施后固定包管理器、精确直接版本与 `pnpm-lock.yaml`；复制的组件源码和 Skills 同样记录上游快照。检查命令须在真实执行成功后才写入运行文档，本方案不提供已经可用的安装或启动命令。

## 7. Module 与目录职责

按[开发规范](../development/开发规范.md)组织 Module／Interface。每个 Module 用少量业务能力隐藏复杂的 Implementation；第三方组件可在内部替换，调用方不学习其状态结构。下面是拟定目录，不要求当前创建空目录。

```text
frontend/src/
  app/                    页面装配、导航、主题与全局错误边界
  components/ui/          纳入项目维护的基础组件源码
  styles/                 token、排版、密度与专业控件主题映射
  features/
    courses/              课程目录、资源登记、归档与重定位
    workspace/            三栏、资料视图、内部窗口与焦点
    media/                播放控制、进度与用户主动截图
    capture/              本地编辑、确认选区与附件产物
    conversation/         当前对话、输入草稿、提交、流与历史
    references/           来源回看、资料选择与数学片段引用
    documents/            PDF与转换预览的阅读 Implementation
    tasks/                后台任务快照、暂停与恢复
    settings/             模型、外观、数据及运行设置
  contracts/              从项目契约生成的类型入口
  platform/               本地业务请求、订阅、原生选择桥适配
```

| Module | Interface 的业务表面 | Implementation 隐藏的内容 |
| --- | --- | --- |
| Workspace | 打开／聚焦资料、呈现来源、调整学习区 | 内部窗口几何、第三方拖拽与层级 |
| Media | 播放、暂停、定位、查询当前状态、响应用户截图动作 | 播放器 store、DOM、解码事件、Canvas 与帧就绪 |
| Capture | 编辑一次截图、确认或取消、输出选区附件 | 完整本地图、选区变换、裁剪库与 Blob 生命周期 |
| Conversation | 读历史、保存草稿、提交、订阅与停止、核对执行状态 | HTTP／事件传输、序号、去重与局部流缓冲 |
| References | 构造可检查的业务引用、回到来源 | 文档坐标、公式结构与 LaTeX 片段映射 |
| Tasks 与 Settings | 查询、变更允许的任务或配置并观察实际状态 | 后台调度、Windows 进程、模型及凭据存储 |

后台 HarnessAdapter 是真正隔离 Host／SDK 的 Interface。前端不建立另一个直连 Harness 的 Adapter，也不获得内部 Peer token、Cookie 或执行 home。只有确有不同实现的专业能力才建立替换接口，不对每个普通 React 组件套一层抽象。

## 8. 数据、草稿与执行状态

### 8.1 状态所有权

| 状态 | 唯一持久依据 | 前端持有内容 |
| --- | --- | --- |
| 课程、资料、历史、附件、任务、用量 | 自有业务后台与业务存储 | Query 中的可更新快照 |
| 活动生成 | 后台 submission／generation 及执行事件映射 | 当前可见增量、状态和事件水位 |
| 当前问题草稿 | 建议按 `chat_id` 存入项目草稿仓储，并返回修订与保存确认 | 即时输入、待保存修订；不可把未确认保存显示为已保存 |
| 工作区布局与主题 | 项目偏好存储；启动主题可使用小型本地缓存 | 当前焦点、拖拽状态和明暗呈现 |
| video DOM、Canvas、Blob、临时原帧 | 相应视图或编辑 Module 的本地生命周期 | ref 与受控资源句柄，不放入可序列化全局数据库 |

草稿持久化是本方案为避免丢输入提出的工程方式，具体保存时机、失败保护与附件落地需要验证。输入变化做合并保存，切课程、换对话和关闭前尽力补存，但不能依赖浏览器关闭事件保证完成。保存失败时保留当前草稿和可处理提示；不得为修复保存失败自动发送给模型。

前端可合并一次编辑中的写入，但不能用迟到的保存响应覆盖较新的草稿。附件确认上传与草稿保存分开追踪；已保存、保存中和未保存错误必须对应实际后台确认。

### 8.2 自有业务契约

| 契约 | 建议包含的最小信息 | 不携带的内容 |
| --- | --- | --- |
| Chat／Message | 稳定身份、课程归属、消息顺序、回答关系、输入修订、正文和引用 | Harness 内部日志作为业务消息格式 |
| Attachment | `attachment_id`、尺寸、类型、确认范围、来源版本与摘要 | 可随意读取原帧或磁盘的路径权限 |
| SourceReference | `asset_id`、版本、视频毫秒或文档页／区域、消息／公式片段位置 | 仅题号即可自动找题的指令 |
| Submission／Generation | `submission_id`、`generation_id`、状态、所属聊天和请求输入版本 | 以当前页面索引代替执行身份 |
| AppEvent | 契约版本、序号、业务身份、事件种类、增量或快照修订 | 供应商原始事件对象和内部凭据 |
| Usage | raw usage 的业务投影、已知／未知、归属与去重身份 | 以缺失当零、把累计值逐片相加 |

网络 DTO 与流事件 schema 归项目契约统一管理。前端类型从相同来源生成或复用；运行时检查关键事件身份、版本和有效字段。以上字段是接口设计建议，不是已实现或已经冻结的后台 schema。

### 8.3 提交、停止与未知状态

| 业务情形 | 界面表现与动作 | 禁止的推断 |
| --- | --- | --- |
| 用户准备发送 | 检查文字、已确认附件及引用，冻结该次输入快照并创建 submission | 当前草稿之后的编辑自动改变已提交题目 |
| 提交中 | 显示发送状态；客户端防连点，后台按身份幂等 | 按钮禁用就能保证服务方只计费一次 |
| pending／running | 显示实际状态、真实增量与停止入口 | 把最终答案回放当真实生成 |
| 用户停止 | 发取消请求，先显示停止中；收到终态或对账结果后更新 | 点击瞬间就宣称取消成功，或杀整个宿主 |
| completed／cancelled／failed | 保存实际终态、部分正文和错误归属，允许后续明确操作 | 把失败状态解释成服务方从未执行 |
| 断流、睡眠或状态不明 | 保留已知内容，显示连接恢复／结果核对中，查询后台执行 | 自动重发同一问题或自动另建生成 |

同一聊天串行活动生成，具体跟进与历史操作保留 Harness 基础交互能力。前端动作不能绕过后台的串行、去重和执行归因。用户切课程后旧流按原 `chat_id` 和 `generation_id` 继续，不追加到新课程页面。

### 8.4 事件恢复

前端只订阅本项目业务流。建议用 HTTP 提交／取消／查询，配合 SSE 或等价的可恢复增量传输；具体传输以流式、取消和重连验证选择，不把传输库当作执行恢复机制。

事件带水位和业务修订，重复事件去重、旧 epoch 拒收；发现序号缺口、后台重启或绑定变化时取快照对齐。未发送的草稿与活动答案增量分开更新。Query 的默认重试和断线刷新须按操作类型配置：读取可受控恢复，生成提交不自动重试；不能用缓存刷新再次执行模型。

## 9. 核心流程的具体设计

### 9.1 播放与用户截图

1. 用户选择具体资源，后台返回登记资源的媒体地址与版本，浏览器按 Range 读取，不将完整视频下载成 Blob。
2. 截图按钮或应用内快捷键产生一次用户动作凭据，播放器暂停，确认当前已呈现帧和源尺寸。
3. 本地编辑视图显示此次截图，用户缩放、平移、框选并调整；取消不增加附件，已有文字与其他附件不丢。
4. 确认时按源图坐标导出选区，登记来源、视频时间和版本；只把确认产物加入草稿，用户补充文字后发送。
5. 完整原图与裁剪关系仅在本地受限重编辑路径保留；重新打开编辑沿用原截图，不重新读取附近帧。

外部粘贴只处理用户主动提供的图片，来源未知时如实标注，不猜视频时间。多图分别预览、移除或重裁；原图、裁剪结果和已发送附件有不同版本与生命周期，重裁草稿不能覆盖旧问题的附件。

截图时刻、图像清晰度、设备像素比、黑边、滚轮与拖拽、取消重做都必须在浏览器验证。允许本地保存完整原图不等于允许将它交给模型；后台仍依据确认产物和权限白名单检查模型输入。

### 9.2 对话与输入区

对话按课程项目组织。打开软件、切换课程或主动新建默认开始新对话；选择历史可接续。同次同课程内收放问答、进出全屏及切资料不更换聊天身份。

输入区组合文字、确认图片与来源引用，提供清楚的发送范围。引用卡片可检查和移除，切换选取方式不清空已有草稿。提交时绑定原输入修订；用户明确纠正题设后按新输入继续，仍有歧义才追问，不为纠错新增常驻复核界面或额外模型轮次。

模型与思考强度在可发现位置手动选择和更改，值来自实际 Harness 配置能力；修改对哪次后续生成生效要清楚，不能悄悄改变已经开始的生成。没有可用配置时显示状态，不展示一个实际无效的选择器；不自动为费用降低模型或思考。

消息阅读区域保留用户滚动位置。用户正在看上文时，新增回答显示可返回最新位置的提示，不强行持续拉到底部；向上加载历史避免整页跳动。完整历史由业务存储保留，前端分页和模型上下文精简是不同问题。

### 9.3 Markdown 与公式

保留原始 Markdown／LaTeX 和内容修订，显示层解析为文字、数学与来源块。流增量写入当前回答缓冲，小批量更新当前内容，不逐 token 重新解析整份历史。未闭合公式片段先用可读的临时文本呈现，闭合后再渲染；不让一条暂不完整公式使整条回答消失。

Markdown 默认不启用任意原始 HTML，链接和图片只经过受限处理；数学渲染关闭不必要的信任能力并限制异常复杂输入，单个公式报错可显示其原文。项目管理的图片使用附件地址，不因答案包含远程图片 URL 就自动外发资料或拉取任意网络资源。[react-markdown](https://github.com/remarkjs/react-markdown)、[KaTeX 配置](https://katex.org/docs/options)

长公式在自身区域可横向查看，不撑开整个聊天区；不把公式渲染成不可选的纯图片来绕过布局问题。离线查看复用数学样式与字体，公式渲染和选取能力分别验收。

若既有链路需要大量自建流式修补，可用相同 fixture 验证 Streamdown 的字符串渲染与未闭合片段处理，数学与中文插件按需取用。它不要求把本项目改成 AI SDK 执行协议；若采用则替换原渲染链，不同时维护两套。其默认 HTML、图片与链接策略仍须收紧到本项目要求，不能仅凭默认 sanitize 就认为范围已经受控。[Streamdown 配置](https://streamdown.ai/docs/configuration)

### 9.4 公式符号与局部子式引用

整条公式和整步推导快捷引用可先交付，完整首版必须支持 Windows 精确选取某符号或局部子式。KaTeX 负责排版，不据此假定已经提供稳定的结构子式选取或 LaTeX 源码映射。

建议在 References Module 内保留原始公式、稳定公式身份与内容修订，验证可复用语法分析能力、结构片段与可见符号的映射。普通浏览器选区可用于文字，但分式、上下标、根号、矩阵和多行环境需专门验证；不能把依赖私有 DOM class 的临时做法当长期契约。

选取后预览表达式及来源消息，再加入草稿；对多义或不连续范围先让用户看清结果，不能自动扩成整条式子、用模型 OCR 替代已有表达式，或悄悄补入未选的条件。交付引用记录源消息修订、公式身份及所选表达，保证历史回看与旧来源一致。

这项能力由D-01/[V4执行方案](../validation/V4-公式局部选择执行方案.md)独立验证。新增值得对照的成熟候选是MathLive只读mathfield的公开selection/getValue接口，不等于原始LaTeX字符偏移或所有符号自然可选；先与KaTeX＋项目映射比较，再决定一条主要渲染链。若未通过，试用可先整式引用，完整首版不能标局部完成，也不默认叠加完整数学编辑/渲染系统。

### 9.5 资料阅读与来源回看

PDF 显示原页，文字层选取与区域选取分别对应业务引用。扫描件可以先通过用户确认区域形成图片提问，但不能宣称已具备扫描文字选择。页序、印刷页码、页面标签和几何坐标分别记录，缩放或旋转不改变源坐标身份。

PPT／Word 通过后台受控转换形成预览，转换中、失败和原件变更均可见；不在浏览器中再搭一条独立 Office 转换流水线。派生预览与原版本绑定，不把预览页码直接冒充原文件的精确定位。

回答来源以简洁卡片或标记呈现，详细过程按需展开。视频时间点在来源对应的当前播放器定位；资料引用回到相应原页或选区。来源缺失或版本失效时保留当时快照和名称并说明状态，不偷偷跳到新版。此路径针对已提交引用和按需资料来源，不恢复按题号或题意找题。

## 10. 后台接入与输入权限

| 前端请求类型 | 后台职责 | 前端约束 |
| --- | --- | --- |
| 选择文件／目录 | Windows 原生选择桥登记资源 | 普通浏览器文件输入不能提供可原地引用的真实路径；不默认整文件上传复制 |
| 播放／阅读 | 按资源身份、版本及 Range／页面输出内容 | 不传任意磁盘路径，不把 Harness 附件路由当长视频服务 |
| 保存草稿／附件／消息 | 业务持久化与完整性确认 | 保存正常发生，但不自动触发模型调用 |
| 提交／订阅／停止／核对 | 映射业务生成与 Harness 执行，输出自有状态 | 不直连模型、内部 Peer 或任意工具 |
| 读取来源与任务状态 | 按当前课程、版本和工具策略输出 | 不预读无关正文，不在后台未命中时自动改为联网 |
| 运行与数据管理 | 持有任务、进程、目录迁移和一致性 | UI 不以自行杀进程或复制活动数据库代替后台命令 |

前端设计发送范围预览，后台执行权限校验，两者共同落实输入边界。模型只得到本次确认的图片及相关已提交历史图，不能得到裁剪外原帧、邻近帧或任意屏幕。受限文档工具可读取相应文档原页，不得借此获取视频画面。

生产页面与业务请求优先同源；开发代理只是开发安排。模型 Key、内部 Peer Cookie／token、任意路径读取能力不能进入前端构建、URL、浏览器存储或诊断日志。请求错误带稳定代码、可处理状态和业务身份，面向用户显示中文解释，不把所有错误都压成“网络异常”。

## 11. 任务、运行与数据管理界面

| 功能 | 必须呈现的状态或操作 | 已定默认与保护 |
| --- | --- | --- |
| 本地转写 | 按课程／视频查看进度、暂停恢复，当前问题所需片段可单独停止 | 缺少可用字幕时自动排队、当前观看优先；批量暂停后不因片段处理而恢复整队 |
| 后台通知 | 正常完成安静更新状态，需要介入时显示原因和操作 | 不弹完成弹窗或发声；不新增字幕 AI 纠错 |
| 前台优先与资源 | 普通处理／加速状态、暂停和资源释放状态 | 电池供电照常转写；默认降低发热噪声，完成或长暂停释放模型资源，不自动恢复手动暂停 |
| 启动与退出 | 后台连接、恢复进度、明确退出动作 | 双击统一入口；默认手动启动，可主动开机启动；关闭网页后台继续，有任务时退出先确认 |
| 睡眠与故障 | 重新连接、进度恢复和执行核对 | 默认遵从 Windows 睡眠；可主动保持唤醒；未知 AI 执行不自动重发，组件故障局部隔离 |
| 更新检查 | 手动检查、主动开启自动检查、可用更新状态 | 默认不检查；检查不自动安装，不建设版本回退产品功能 |
| 数据位置 | 当前路径与占用、整体迁移动作和结果 | 原件原地引用；迁移由后台完成一致性与恢复保护 |
| 整体导出／导入 | 默认全部业务数据，原件包含选项，进度与完整性结果 | 不做历史备份；不合并已有数据，目标有数据时提示、不自动覆盖 |
| 离线聊天查看 | 消息顺序、公式、截图及来源名称 | 独立于在线模型和软件后台；资源随包提供，不依赖网络字体或图片 |

只为实际交付能力开放有效操作。尚未接通的试用阶段功能明确不可用或按阶段不展示，不用永远成功的模拟按钮掩盖缺口。知识库的前端只在已确认范围内显示必要来源与处理状态；独立使用方式仍等待用户指定细化。

## 12. 性能与可靠性

播放器、输入区、活动消息和任务面板各自订阅必要状态，避免播放进度和模型 token 触发整个工作区重渲染。当前生成的缓冲与已完成消息分开处理；在真实历史出现瓶颈后再评估列表虚拟化，检查卸载对公式选择、滚动和复制的影响。

PDF 按可见页和有限邻近页呈现，释放无用画布；这是文档显示缓存，不授权模型读取邻近视频帧。截图使用 Blob／受控附件地址，结束编辑释放无用对象 URL，完整视频不进入全局内存状态。隐藏视频保持既定播放状态，资源释放不能偷偷改变该行为。

后台负载与前端并行时记录输入、播放、截图、公式渲染和滚动体验。10 秒仍是日常大多数问题出现有用内容的目标，不是本方案已经测得的性能，也不是所有检索或生成的统一超时；数学效果、保存和主要操作仍须通过验证。

按数据读取、保存、任务命令与生成提交分别制定恢复策略。前端重连可以重新获取快照；模型结果未知先对账，进程恢复由后台完成，浏览器不能同时补出第二套自动重启与模型重试链。

### 13.2 给 Codex 的固定任务依据

每个前端工作包引用本方案、当前任务与已有组件清单，说明输入、预期行为、暂不实现范围和验收场景。已确认的蓝白温和、阅读密度、用户输入范围和依赖规则优先于外部 Skill 的默认审美；不为“更有设计感”擅自换色、增加重动画、采集视频或扩大首版。

开发依照真实产品内容与统一 token，不以营销首页、英文短句和空白卡片当学习界面参考。新增组件先查项目现有实现和所选底座，再查固定版本上游能力。复用和取舍写进改动说明，不能仅声称“采用最佳实践”。

可以增加一份精简的设计规则索引供 AI 每次工作查阅，但它只引用已确认需求和本方案，不再复制出多份独立的需求真相源。需要 Skill 配套 `PRODUCT.md`／`DESIGN.md` 时也应采用引用和受控摘要，避免生成的新文件覆盖既有讨论结论。

### 13.3 让没有前端经验的用户判断方向

建议把主学习页面样板作为第一个可见检查点：包含真实长度的中文、多行数学、合成题图、侧栏、输入附件和一个可操作错误状态。样板可以使用确定性模拟数据验证布局，但须清楚区分模拟内容与已接通的功能。此评审安排在用户明确恢复实施后进行，不在当前阶段自动创建原型。

用户只需描述体验，例如“聊天太窄”“公式挤”“蓝色抢眼”“不知道下一步点哪里”。开发方负责把反馈对应到 token、组件或布局规则，修改同类页面，并说明影响；不让用户自行判断 React、依赖或状态机是否正确。

重点请用户看整体样板、关键学习流程和明显改变体验的选择，常规可逆修复继续自主推进，不为每个按钮或每次微调请求确认。样板认可后保存版本、设计规则和同场景截图作为后续对照；前端方案文本不能代替实际体验评审。

### 13.4 浏览器证据与真实资料的界限

自动浏览器截图、视觉检查和录屏使用合成资料或用户明确授权给 AI 查看范围的 fixture。不能为了界面质检自动拍下真实视频完整画面、桌面或裁剪外区域；真实资料验收仍由用户主动截图确认范围后供 AI 查看。仅授权播放原视频不等于授权把其画面传给编码模型。

浏览器检查覆盖打开、输入、拖动、停止、错误和恢复，不只检查页面能加载。报告分别说明静态检查、合成浏览器验证、真实 Harness 图文流、生成中停止和实际学习体验；空会话取消、模拟增量与截图不能互相冒充验收。
