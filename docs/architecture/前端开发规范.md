# 前端开发规范

日期：2026-10-21。适用于本轮重设计的 Windows MVP-A，以及以后在同一前端中增加页面或组件的开发。

本文规定视觉、组件、交互和实现边界，不维护工作包完成状态。完成状态只在 [MVP 计划](../plans/MVP开发计划.md)维护；需求优先级见 [需求总结](../product/AI辅助学习项目需求总结.md)，业务接口见 [应用契约](应用契约.md)，通用工程要求见 [开发规范](../development/开发规范.md)。后续改动须同时满足这些文件，不能把视觉复刻解释为重建聊天执行层。

## 1. 决策、证据与适配的区别

### 1.1 用户已经确定的方向

- 参考 Codex 桌面端的视觉和组件交互，结合学习流程设计。
- 以实际 Codex 配色为基准，替换原 DeepSeek 蓝白方向；本轮取消大肥鱼形象、壁纸和陪伴装饰。
- 常态界面为左侧课程切换与当前课程文件树、中间资料标签及单一内容区、右侧 AI。资料为主，AI 栏可调宽、可收起。
- 历史对话入口位于右侧 AI 栏顶部，不在左侧文件树下常驻另一份对话列表。
- 首先用有内容的学习界面评价效果：视频或资料、中文长回答、数学公式、截图附件和引用卡片同时存在。空白欢迎页不能替代这一验收画面。

上述决定优先于旧方案中的“中间文件管理器”、蓝白配色和大肥鱼壁纸安排。课程根目录、导入、文件身份及版本规则继续遵守已确认需求。

## 2. 页面结构与空间规则

### 2.1 常态工作区

| 区域 | 内容与责任 |
| --- | --- |
| 顶部栏 | 产品名、当前课程、连接状态、主题、账号入口及安全退出；不铺设第二条功能宣传横幅 |
| 左侧栏 | 顶部切换课程和打开课程文件夹；主体为当前课程文件树；底部放账号与连接信息 |
| 中间区 | 顶部资料标签，同一时刻只展示一个文件；下方为视频、图片、文本或当前不支持格式的主动打开入口 |
| 右侧 AI | 顶部历史对话、新对话和收起入口；主体流式回答；底部持久输入区、附件和引用 |

进入课程不自动打开上次资料。普通切换文件、标签、收放 AI 和进出全屏均不创建新对话。同次使用同课程沿用当前对话；用户显式新建或选择历史时才改变对话。换课程时，旧生成仍归原课程原对话继续。

当前实现基线见 [App.tsx](../../frontend/src/App.tsx) 与 [styles.css](../../frontend/src/styles.css)：

- 工作区占 `100dvh`，最小高度 `480px`，内部内容各自滚动，避免浏览器整体滚动挤走输入框。
- 左侧宽 `248px`；视口不超过 `1100px` 时为 `216px`，不超过 `850px` 时为 `185px`。
- AI 初始宽度为主学习区的 `35%`。分隔条宽 `5px`，可拖动或聚焦后用左右方向键调整；范围 `28%—65%`。AI 内容通常最小宽 `300px`，窄断点为 `280px`。
- 桌面页面最小宽度为 `720px`；本轮没有由此宣称手机布局或 Android 可用。新增断点不得把三栏挤压成不可操作的窄条，应先保护内容和输入区，再设计显式收放。
- 顶栏最小高 `48px`，资料及 AI 顶部工具栏高 `43px`。资料标签超宽时在标签条内滚动，不撑大内容页。
- 容器及其 Grid/Flex 子项使用 `min-width: 0`、`min-height: 0`；长文件名省略，长公式与代码块在自身区域横向滚动。

这些是本轮项目基线，后续若调整，须同步改实际样式、本文数值和对应视觉记录，不能只修改方案文字。

### 2.2 全屏工作区

全屏对象是容纳视频与 AI 的工作区，而非只能显示视频的原生 `<video>` 全屏。纯视频全屏隐藏顶部栏、目录与资料标签；唤起 AI 后仍在全屏内形成左视频、右当前 AI。关闭 AI 后恢复纯视频并续播，同一对话保持。

独立快捷键与右侧触边入口同时保留，触边入口平时不常驻。普通唤起 AI、发送和追问不强制暂停；截图明确暂停。删除旧视频下方“播放视频／截图提问／视频全屏”三按钮排布，播放控件集中在视频区域内。

### 2.3 标签与媒体状态

多个标签只代表多个已打开资料，不代表自由多窗口或同屏并排资料。切离视频时暂停并保存位置；切回时恢复切走前状态：原本在播则续播，原本暂停则保持暂停。关闭标签、切课程、退出前须处理位置及草稿保存失败，不能以隐藏组件当作保存成功。

文件打开绑定 `asset_id + source_version`；旧标签或旧来源发现内容变化时显示可处理错误，不静默读取新版。未知格式列在文件树中，但“列出”不等于“已接通阅读、解析或模型访问”。当前图片和纯文本可在内容区阅读；PDF 当前给出系统默认程序入口，完整 Office、ASR 和知识库用途不在本轮扩展范围。

## 3. 主题、文字与图形

### 3.1 唯一主题入口

主题以 `.app-shell` 和 `.app-shell.dark` 的语义 CSS 变量为入口。默认浅色，手动深浅切换保存在 `learning.theme`。业务组件使用语义变量，不复制另一套主题 Provider，也不直接依赖安装包中的混淆变量名。

下表是当前项目值，作为后续开发统一基线；其中有静态 seed 参考，也有为本项目层次、阅读和状态做的适配，不能逐行宣称是 Codex 原样数值。

| Token | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--background`、`--surface` | `#ffffff` | `#181818` | 页面与主阅读面 |
| `--surface-elevated` | `#ffffff` | `#232323` | 输入框、弹窗等抬升面 |
| `--foreground`、`--primary` | `#1a1c1f` | `#ffffff` | 正文及主要按钮 |
| `--primary-foreground` | `#ffffff` | `#181818` | 主要按钮内文字 |
| `--secondary` | `#f3f3f3` | `#303030` | 次级背景 |
| `--muted` | `#f3f3f3` | `#ffffff0d` | 悬停及低强调底色 |
| `--muted-foreground` | `#737373` | `#afafaf` | 辅助文字 |
| `--border` | `#00000014` | `#ffffff16` | 分栏、普通边框 |
| `--border-heavy` | `#00000026` | `#ffffff26` | 强分隔、键帽等 |
| `--accent` | `#339cff` | `#63a8f8` | 焦点和必要强调 |
| `--destructive` | `#ba2623` | `#fa7772` | 错误及危险操作 |
| `--sidebar-background` | `#f7f7f8` | `#141414` | 低权重文件导航面 |
| `--chat-user` | `#f3f3f3` | `#303030` | 用户消息块 |

Tailwind `@theme inline` 只映射上述项目变量。新增控件需接入既有 token；确有新语义时，在唯一主题入口同时补齐浅深色。视频舞台、截图遮罩等具备固定媒体含义的黑白底可以局部定义，并说明用途。

### 3.2 中文与数学排版

| 用途 | 当前基线 |
| --- | --- |
| UI 字体 | `-apple-system, BlinkMacSystemFont, "Segoe UI", "Microsoft YaHei UI", sans-serif` |
| 导航与紧凑工具 | 常用 `11—13px`，有意义的动作保持完整中文名称 |
| 聊天消息 | `14px`；消息容器行高 `1.75`，Markdown 正文行高 `1.85` |
| 纯文本资料 | `15px`、行高 `1.9`，保留换行，允许长行断开 |
| 输入框 | `14px`、行高 `1.65`，最小高 `72px`、最大高 `200px`，不以单行输入替代多行提问 |
| 公式 | 本地 KaTeX 字体；相对字号 `1.08em`；独立公式在自身块横向滚动 |
| 引用卡片 | 正文通常 `12px`、行高 `1.65`，保留渲染公式与来源入口 |

Windows 实际字体回退由系统决定，静态 CSS 不能证明每台机器渲染完全相同。不得为了复制英文演示的密度压缩中文、长推导或上下标。正文不加入壁纸、渐变底、常驻陪伴图或高频动效。

Markdown 使用统一 [MarkdownAnswer](../../frontend/src/chat/MarkdownAnswer.tsx)。禁原始 HTML，回答图片不自动联网加载，外链由用户主动打开并隔离 opener。KaTeX 的受控选区标记只供本模块精确映射，不开放任意回答 HTML、远程资源或一般 `trust` 能力。

### 3.3 间距、圆角、图标与层级

- 新布局优先复用 `4 / 8 / 12 / 16 / 24 / 32px` 间距层级；既有标签、工具栏和紧凑控件存在适配值，不做无关批量格式重排。
- 普通输入和中型控件以 `8px` 圆角为基线，紧凑图标按钮常用 `7px`；引用卡片 `9px`、主弹窗 `16px`、聊天输入框 `22px`。圆角随职责选择，不为每个页面另造一套。
- 常用图标按钮 `30×30px`；当前本地 [Icon](../../frontend/src/components/ui/Icon.tsx) 使用 `24×24` viewBox、`1.6` 描边、默认 `18px`，文件行常用 `16px`。这是项目维护的 SVG 体系，不能声称提取自 Codex 原图标。
- 图标继承 `currentColor`。装饰图形 `aria-hidden`；可操作图标按钮必须有准确的 `aria-label`，`title` 只作补充。
- 普通分区靠轻边框、背景和间距区分；阴影限于输入面、菜单、弹窗等必要抬升。常规弹窗层当前 `z-index: 100`，选区引用浮层 `80`，截图蒙层 `10000`；新增浮层须确认全屏容器与 Portal 层级，不随意堆叠更大数字。

## 4. 组件状态与可操作反馈

以下状态是新增及修改组件必须检查的契约。具有 `role` 或通过类型检查，不等于这些状态已全部验收；实际覆盖以本轮验证记录为准。

| 组件/状态 | 应呈现的行为 | 保持的数据与边界 |
| --- | --- | --- |
| 初次加载 | 在本区显示正在加载；必要动作禁用 | 不清空已保存资产，不把加载误写为空列表 |
| 空课程/空目录/空对话 | 给一个与当前区域相关的主动入口 | 不预填假文件、假回答或默认发送问题 |
| 后台失联 | 显示稳定错误码与重连动作 | 保留草稿、附件、部分回答；视频与文件功能按自身可用性判断 |
| 账号不可用 | 说明问答影响并给账号入口 | 不把业务后台在线等同于模型可用，不自动切 API Key |
| Disabled | 原生 `disabled`、明确的不可操作状态 | 不只用灰色样式伪禁用，重复点击不产生重复请求 |
| Hover/Focus | 低强调悬停；可见键盘焦点环 | 不以悬停作为唯一入口；`focus-visible` 使用 `2px` accent 外框、偏移 `2px` |
| 文件行/菜单 | 文件名与图标为主，低频整理进入明确菜单 | 真实删除需确认；重命名、移动与移除课程语义分清 |
| 标签 | 当前标签可辨，关闭按钮独立，长标题省略 | 单内容区；关闭或切离视频保存状态 |
| 输入框待发送 | 图片与引用作为独立可移除卡片 | 文本、其他附件和原有条件保持；引用不变成编辑框里的 LaTeX |
| 生成中/停止中 | 显示当前状态与对应停止动作，保存部分结果 | 停止对应 generation，不杀整个 Host |
| 请求结果未知 | 显示“核对提交/执行”入口并锁住重复派发 | 先查询原 submission/generation，不能静默重发 |
| 草稿保存冲突 | 明示新版本冲突与恢复入口 | 不覆盖较新服务端或本地编辑，不以保存失败清空草稿 |
| 文件操作待对账 | 显示 operation_id 对应的记录与状态 | 未确认前不再叠加移动、替换或删除 |
| 截图/公式不支持 | 显示具体原因、取消或重新选择入口 | 不改取其他画面，不退回整式冒充局部选区 |

错误就近显示；跨区域断连才使用全局错误条。异步结果须检查所属课程、对话和请求世代，防止过期响应更新另一课程。可恢复错误不能用成功 toast 掩盖。

### 4.1 对话与输入框

- 用户消息为低强调消息块；AI 回答直接排版，不为每段正文再套一张卡片。思考内容可折叠，与正文、费用和错误分开。
- 历史选择、新对话及收起在 AI 顶部。新对话是显式操作；文件标签和全屏状态不触发新建。
- 输入区固定在 AI 区底部。普通 Enter 换行；`Ctrl+Enter` 或 `Cmd+Enter` 发送；输入法组合态不发送。
- 用户离底部不少于 `72px` 时停止自动追底；继续生成不把用户强拉回下方。再次回到底部才恢复追随。
- 模型与思考选项来自当前官方能力目录或明确的 fixture 目录。旧选择不可用、目录为空、模型不支持当前图像历史时，保留输入并禁发或提示；不得自动换模型、思考、凭据或丢弃题图。
- 仅有引用卡片、没有问题文字和图片时提示补充问题，不能让前端放行后再由后台以 `INPUT_EMPTY` 拒绝。

### 4.2 文字与公式引用卡片

用户在单条回答里选择真实范围，点击临时“添加到对话”才形成卡片。普通选择、复制和取消选区不改变草稿；撤销逐条公式的常驻引用按钮。

`DraftReference` 使用 `reference_id / message_id / text / markdown / source_start / source_end`。范围偏移为原始回答 Markdown 的 **UTF-16 code unit**，与 JavaScript 字符串一致；不是渲染后文字偏移、字节偏移或 Python 字符索引。普通及混合范围应对应连续源码切片；纯公式子范围允许只为渲染加一层数学定界符。标准 `\(...\)`、`\[...\]` 归一化须保留到原始源码的边界映射。

已映射的普通文字、整条公式和部分可精确对应的公式子式可以形成卡片。跨回答、不连续或无法可靠映射的复杂公式范围应拒绝并显示 `FORMULA_SELECTION_UNMAPPED`；不得扩大成整式、另取截图、调用 OCR 或辅助模型猜测选区。

后台校验来源属于当前对话的回答、范围和内容匹配；不匹配返回 `REFERENCE_SOURCE_NOT_IN_CHAT`、`REFERENCE_RANGE_INVALID` 或 `REFERENCE_SELECTION_MISMATCH`。引用独立保存于草稿，提交时通过正式 `references` 字段传输，由后台冻结入现有不可变输入；前端不得再自行拼接一份条件造成重复。历史消息恢复引用卡片，卡片来源能定位原回答，每张可单独移除。

### 4.3 弹窗与菜单的键盘要求

弹窗使用准确标题、`role="dialog"`、`aria-modal`，打开时焦点进入弹窗，关闭后返回触发入口；Tab/Shift+Tab 不应落入背景操作。可取消的弹窗提供 Escape 和可见关闭入口；危险操作不能靠 Escape 或普通 Enter 意外确认。菜单与标签需要键盘可达，关闭按钮不能嵌套在另一个按钮中。

当前实现的语义标签、焦点样式与具体自动用例需要分别检查；焦点循环、屏幕阅读器、高缩放和高对比度尚未专项通过时，交付报告必须保留这些未覆盖项，不能由“添加了 ARIA”推成完整无障碍合规。

## 5. 键鼠与整软件截图

### 5.1 当前默认键位

| 操作 | 当前行为 | 适用范围 |
| --- | --- | --- |
| `Ctrl+Shift+S` | 暂停当前视频，开始软件可见区域拖选截图 | 当前应用文档内，包含全屏；不是 Windows 全局截图 |
| `Ctrl+Shift+A` | 唤起 AI；全屏中再次操作可关闭 AI | 当前应用内，同一课程对话 |
| 空格/单击视频 | 播放或暂停 | 视频控制拥有交互时 |
| 双击视频/ESC | 进入或退出工作区全屏 | 原生全屏退出由浏览器负责 |
| 短按左右方向键 | 后退/前进 `2s` | 不在输入、聊天或其他交互控件内 |
| 长按右方向键 | 识别后临时 `2x`，释放恢复原倍速 | 当前阈值 `400ms`，失焦和卸载也恢复 |
| `M` | 静音切换 | 排除输入、聊天及交互控件 |
| 全屏视频区域滚轮 | 音量每次 `5%`，边界 `0—100%` | AI 区正常滚动聊天 |
| 非全屏音量控件滚轮 | 同上 | 视频其他区域不劫持滚轮 |
| `Ctrl/Cmd+Enter` | 发送提问 | 非 IME 组合态，且满足可提交条件 |
| 截图中 ESC | 取消本次选区 | 保留已有草稿与附件 |

短按与长按、单击与双击必须分辨，当前单击等待 `220ms`；双击不能叠加两次播放切换。以上阈值和音量步进为项目默认，不属于用户指定数值或 Codex 取证结论。热键监听应解绑，隐藏或切离的播放器不能继续抢键；输入法、按钮、链接、文本域、选择框和聊天滚动均保持自身操作。

### 5.2 截图管线与能力边界

正式管线是用户快捷键 → 暂停 → 冻结当前可见应用 DOM → 按住拖选 → 松开确认 → 精确选区加入草稿 → 展开 AI 并聚焦输入 → 用户补充问题后发送。不会因松开鼠标自动调用模型。

[workspaceSnapshot](../../frontend/src/media/workspaceSnapshot.ts) 读取计算样式、当前显示的视频/Canvas、同源已显示图片和本地字体，以当前视口及滚动裁切生成浏览器本地冻结图。CSS 坐标与 `devicePixelRatio` 转换后，裁剪结果必须对应用户选择的真实像素范围；字节尺寸、裁剪坐标和后台来源尺寸相互校验。

- DOM 原图和重编辑原件只留浏览器本地，模型及后台只收到确认的选区图片。`origin="workspace"` 不冒充视频原帧，原图不另存桌面、下载或独立截图目录。
- 不使用 `getDisplayMedia`、系统全屏截图、浏览器控制、取相邻帧或补原帧来扩充范围。重编辑继续使用同一原截图和编辑根身份。
- 隐藏、视口外和滚动裁切外内容不作为可见截图内容。读取同源字体仅用于保持已显示文字；不以截图名义读取其他用户资料。
- 外域资源、不可读取的视频/Canvas、尚未就绪的画面、可见 iframe/object/embed 等不支持内容明确失败；不联网补取、不改走系统截图。相关错误包括 `CAPTURE_EXTERNAL_RESOURCE`、`CAPTURE_CONTENT_UNAVAILABLE`、`VIDEO_FRAME_UNAVAILABLE`、`CAPTURE_RENDER_FAILED`。
- DOM 重绘不天然等同操作系统截图。公式、分式、上下标、字体和滚动位置必须逐项做合成像素与人工可读性核对；边界数值通过不能掩盖某类公式缺笔画或位置错误。
- 快照、上传、来源登记、草稿保存各自可能失败。确认后的选区保留供明确重试或取消，不因失败替换原文字和其他附件；保存退出应等待这些已确认动作处理完毕。

## 6. 文件、账号和聊天的数据契约

### 6.1 课程文件操作

每门课程一个真实本地根目录，课程名与根目录名绑定；外部导入默认移动，可显式选择复制，已经在根内的文件保持原地。冲突由用户选择保留两份、跳过或明确替换。符号链接、目录联接、绝对路径穿越、`..` 和磁盘根目录不作为课程内操作的旁路。

真实变更必须具有 `operation_id`。前端在派发前保留操作身份，超时或断连后先读取该操作记录，不能换新身份自动重复移动、替换或删除。`prepared / filesystem_done / needs_review` 是需继续核对的状态；已完成结果可按原身份取回。部分复制、替换失败或文件与元数据均已改变时，不把不确定状态当作干净失败。

“从课程移除”只改变关联，不删除目录、聊天或截图；“删除磁盘原件”是另一项明确确认的操作。旧未绑定课程不能以空更新返回移除成功。既有真实用户资料不得为测试或迁移被自动搬运。

文件正文只经已登记业务身份与版本路由返回；当前文本使用 `text/plain`、`nosniff`，媒体响应服从受限内容策略。HTML、SVG 等主动内容不嵌入同源阅读区，使用显式外部打开入口。文件名、扩展名和列表状态不授予模型读取任意文件的能力。

### 6.2 官方账号与模型

默认走官方账号，API Key 是用户主动选择的另一条路线。账号不可用、额度不足或模型无权限时，不自动切凭据或降低模型；问答故障不应使已可用的文件、播放和业务保存一起失效。

[AccountPanel](../../frontend/src/account/AccountPanel.tsx) 契约为 `connected`、`onChanged?`、`onClose?`。前端从 `/account` 读取公开状态，`/account/sign-in` 启动官方授权，在官方浏览器页面完成登录，再刷新状态；支持取消本次授权、退出、刷新以及显式 `/account/route` 切换。API Key 不在前端输入或读取，仍只来自项目私有配置；账号凭据由官方 Harness 管理。

公开 DTO 只含路线、可用性、授权阶段、官方授权 URL、经过筛选的资料、余额状态、模型目录等。`credential-stored` 表示已保存凭据，不独自证明额度或模型推理成功。余额未知保持 `unknown`，不显示成零；模型的图像能力与思考档位取实际目录，不把旧固定模型假定硬套账号路线。

健康状态分别呈现业务后台、Harness 和问答能力。`question_answering_ready` 是当前路线的独立本地属性，读取时不发起网络请求；Host 已连接不等于问答可提交。前端发送条件应使用问答能力，不只检查后台 `ready` 或 Host 状态。该属性也不是一次模型推理成功的探测结果。

不得把 Cookie、账号 token、Peer token、私有配置路径、完整内部协议或密钥写入前端构建、业务公共 DTO、提示词或日志。官方登录是用户在官方页面操作，不要求用户向开发聊天粘贴密码、Cookie 或 token。账号授权、只读目录/余额、真实模型推理属于三个不同验证结论。

### 6.3 草稿、发布、生成与恢复

服务端草稿为权威持久状态，包含文字、确认附件、条件、更正、引用、模型及思考选择。当前使用 revision 乐观并发、本地编辑保护、`250ms` 合并保存与串行 flush；切课程、新建/选择历史及退出前保存，失败保留原输入并明确提示。

提交前生成稳定 `submission_id` 并保留待确认内容。只有确认原提交已接受才按该身份清除匹配草稿；不同内容、新 revision 或新卡片不得被迟到回调清空。结果未知先查询原提交，普通重连不创建一份新提交。

生成状态、部分正文、停止、对账与最终用量来自正式业务服务。流式用量只更新快照，不逐块相加；缺字段保持未知。停止只取消对应 generation，不以关闭整个 Harness 宿主替代。换课程或关闭网页不等于退出后台，后台结果归原对话保存。
