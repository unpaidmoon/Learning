# 前端开发规范

2026-10-26已确认并实施的桌面顶部规则：资料首标签显示当前浏览工作区名，其下单行导航与路径、搜索、添加及更多；搜索按需展开，添加集合本地资料／新建／粘贴／平台导入，更多集合刷新／视图／排序，复用Harness Menu及其选中与键盘行为。AI顶部以原生总结标题为主，右侧仅工作区图标、笔形新对话、收起，三个图标常驻；历史列表每条标题旁的重命名／归档在悬停和键盘聚焦时显示，另有已归档入口及取消归档。截图快捷键与消息附件能力保留，移除的是顶部按钮。视频完整画面优先，播放器按源比例适配、不裁切拉伸，容器多余区域使用主题背景，控制栏贴合画面边界，源视频自带黑边不自动裁切。该规则优先于下方旧“文件”固定标题及AI工具全部悬停显露的描述；状态与证据仅见MVP计划。

2026-10-24后续平台接入规则（需求确认、先不开发）：设置管理按需启用及连接，资源区承接手选导入，操作使用Harness原生“＋”／斜杠指令／自然语言；不新增平台专属收词／成果导出菜单、任务面板或另一套指令框架。“＋”保留原生入口语义，不能做成仅附件入口；原附件、图片确认和明确提交边界继续保留。候选、目标与内容在对话内审阅确认，持久任务可在既有入口找回。具体规则见[共用准备需求](../product/平台接入共用准备需求收口-2026-10-24.md)，实现须核对固定版本原生扩展点，不以本文冒充运行验证。

2026-10-22 最新精简规则：常驻区域只保留课程、资料导航、当前对话和输入；不铺设欢迎页、空态说明、重复目录标题和项目计数。课程操作与 AI 工具在悬停／键盘聚焦时显露，文件选择后再出现相应操作，左下统一“设置”入口，内部 ID 不作标题。UI 字体沿用 Harness `--dsw-font-family`，主要导航／课程名／文件名／对话标题统一 14px、辅助控件 12–13px；代码和 KaTeX 字体不被统一覆盖。布局默认课程 240px、AI 440px，中间自适应，窄窗口遵从原生侧栏收起语义，保留拖宽和 AI 收放。轻反馈与菜单采用原生 fast token（100ms），项目面板采用默认 token（200ms），是项目设计选择，不宣称原生所有组件均为此时长；拖动和减少动态效果时禁用相应动画。文件对话框管理焦点和 Esc，已有操作／结果未知守卫继续。上述规则覆盖下方早前存在冲突的字号、35% 默认 AI 宽度和常驻入口描述。

2026-10-22 新增桌面试用授权：本轮以固定 Harness 官方客户端的主题、组件、输入框、消息渲染和交互为基础，**布局和学习功能设计沿用本项目的左课程目录、中资料、右 AI**，不照搬 Harness 的聊天主区／右侧资料布局。中间保留固定“文件”标签、可关闭的视频标签和单资料展示；新增控件复用其共享 React 与原生组件。下方 Codex 风格 token 继续描述既有浏览器界面，不用于覆盖此次桌面样式。项目业务身份、图片确认范围、执行守卫、取消及未知对账仍必须遵守 [应用契约](应用契约.md)。此次只覆盖视频截图问答的纵向流程。

## 1. 决策、证据与适配的区别

### 1.1 用户已经确定的方向

- 参考 Codex 桌面端的视觉和组件交互，结合学习流程设计。
- 以实际 Codex 配色为基准，替换原 DeepSeek 蓝白方向；本轮取消大肥鱼形象、壁纸和陪伴装饰。
- 常态界面为左侧课程切换与当前课程文件树、中间资料标签及单一内容区、右侧 AI。资料为主，AI 栏可调宽、可收起。
- 右侧 AI 直接显示对话输入区；历史选择合并进顶部左侧对话标题，不单列“历史对话”选项，不再以“开始问答”欢迎页阻挡输入。
- 首先用有内容的学习界面评价效果：视频或资料、中文长回答、数学公式、截图附件和引用卡片同时存在。空白欢迎页不能替代这一验收画面。

- 创建课程使用原生文件夹选择和独立显示名；左侧整栏可收起，中间常驻“文件”标签与图标资源管理器。
- 外部资料粘贴／拖入只复制，重名自动保留两份；内部整理按最新选择恢复，删除进回收站。
- “＋”采用Harness原生入口并支持指令调用，不限于附件；聊天附件支持图片、PDF、TXT／Markdown，PDF默认整份、超限明确拒绝。视频拖动预览只供本地显示。指令调用按2026-10-24共用准备需求后续实施，不宣称已通过。

上述决定覆盖旧蓝白／大肥鱼、课程名绑定目录、外部默认移动及冲突询问、仅图片附件、空问答欢迎页等冲突规则。前一轮“取消整理功能”已由后续选择 B 更新为中间资源管理器支持真实内部整理；不能混用中间讨论的旧结论。稳定文件身份、来源版本、用户提交范围和执行守卫继续保留。

## 2. 页面结构与空间规则

### 2.1 常态工作区

| 区域 | 内容与责任 |
| --- | --- |
| 顶部栏 | 产品名、当前课程、连接状态、主题、账号入口及安全退出；不铺设第二条功能宣传横幅 |
| 左侧栏 | 顶部切换课程和创建课程；主体为当前课程文件树，课程行提供刷新、鼠标靠近／聚焦时可用的右侧重命名和移除入口；整栏可收放，不在此重复中间的整理工具 |
| 中间区 | 最左固定不可关闭的“文件”标签，默认图标浏览当前课程根目录；其他资料标签可全部关闭，同一时刻展示文件浏览器或一个资料 |
| 右侧 AI | 左侧对话标题兼历史下拉，新对话和收起在同一顶部；主体流式回答；底部输入区、附件和引用，无开始问答页及常态保存页脚 |

进入课程不自动打开上次资料／历史对话；中间显示“文件”页，右侧直接显示对话输入区。第一次进入课程建立当次空对话，同课程在本次使用中沿用当前聊天；并发请求按课程复用在途创建 Promise，不重复创建，也不另建临时草稿真相源。身份／草稿版本尚未就绪时输入可暂禁用，但不改回“开始问答”欢迎页。普通切换文件、标签、收放 AI 和进出全屏均不创建新对话。用户显式新建或选择历史时才改变当前对话；创建空聊不派发模型。换课程时，旧生成仍归原课程原对话继续。

当前实现基线见 [App.tsx](../../frontend/src/App.tsx) 与 [styles.css](../../frontend/src/styles.css)：

- 工作区占 `100dvh`，最小高度 `480px`，内部内容各自滚动，避免浏览器整体滚动挤走输入框。
- 左侧宽 `248px`；视口不超过 `1100px` 时为 `216px`，不超过 `850px` 时为 `185px`。
- AI 初始宽度为主学习区的 `35%`。分隔条宽 `5px`，可拖动或聚焦后用左右方向键调整；范围 `28%—65%`。AI 内容通常最小宽 `300px`，窄断点为 `280px`。
- 桌面页面最小宽度为 `720px`；本轮没有由此宣称手机布局或 Android 可用。新增断点不得把三栏挤压成不可操作的窄条，应先保护内容和输入区，再设计显式收放。
- 顶栏最小高 `48px`，资料及 AI 顶部工具栏高 `43px`。资料标签超宽时在标签条内滚动，不撑大内容页。
- 容器及其 Grid/Flex 子项使用 `min-width: 0`、`min-height: 0`；长文件名省略，长公式与代码块在自身区域横向滚动。

这些是本轮项目基线，后续若调整，须同步改实际样式、本文数值和对应视觉记录，不能只修改方案文字。

### 2.2 全屏工作区

全屏对象是容纳视频与 AI 的工作区，而非只能显示视频的原生 `<video>` 全屏。纯视频全屏隐藏顶部栏、目录与资料标签；唤起 AI 后仍在全屏内形成左视频、右当前 AI。关闭 AI 后恢复纯视频并续播，同一对话保持。

独立快捷键与右侧触边入口同时保留，触边入口平时不常驻。普通唤起 AI、发送和追问不强制暂停；截图明确暂停。删除旧视频下方“播放视频／截图提问／视频全屏”三按钮排布，播放控件集中在视频区域内。

### 2.3 标签与媒体状态

“文件”标签固定在最左且不可关闭。其他资料标签都可关闭，包括最后一个视频；最后关闭后自动回到文件图标视图，原视频不能由迟到回调重新打开。多个资料标签不代表自由多窗口或同屏并排资料。切离视频时暂停并保存位置；切回时恢复切走前状态：原本在播则续播，原本暂停则保持暂停。关闭标签、切课程、退出前须处理位置及草稿保存失败，不能以隐藏组件当作保存成功。

文件打开绑定 `asset_id + source_version`；旧标签或旧来源发现内容变化时显示可处理错误，不静默读取新版。未知格式列在文件树中，但“列出”不等于“已接通阅读、解析或模型访问”。资料阅读与聊天附件解析是不同能力：本轮新增整份 PDF 聊天附件不自动代表内置 PDF 阅读器或 Office 支持。课程文件中的未支持格式继续给出主动系统打开入口；完整 Office、ASR 和知识库用途不在本轮扩展范围。

## 3. 主题、文字与图形

### 3.1 唯一主题入口

主题以 `.app-shell` 和 `.app-shell.dark` 的语义 CSS 变量为入口。默认浅色，手动深浅切换保存在 `learning.theme`。业务组件使用语义变量，不复制另一套主题 Provider，也不直接依赖安装包中的混淆变量名。

下表是当前项目值，作为后续开发统一基线；其中有静态 seed 参考，也有为本项目层次、阅读和状态做的适配，不能逐行宣称是 Codex 原样数值。

| Token | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--background`、`--surface` | `#ffffff` | `#181818` | 页面与主阅读面 |
| `--surface-elevated` | `#ffffff` | `#232323` | 输入框、弹窗等抬升面 |
| `--foreground`、`--primary` | `#1a1c1f` | `#ffffff` | 正文及主要按钮 |
| `--primary-foreground` | `#ffffff` | `#181818` | 主要按钮内文字 |
| `--secondary` | `#f3f3f3` | `#303030` | 次级背景 |
| `--muted` | `#f3f3f3` | `#ffffff0d` | 悬停及低强调底色 |
| `--muted-foreground` | `#737373` | `#afafaf` | 辅助文字 |
| `--border` | `#00000014` | `#ffffff16` | 分栏、普通边框 |
| `--border-heavy` | `#00000026` | `#ffffff26` | 强分隔、键帽等 |
| `--accent` | `#339cff` | `#63a8f8` | 焦点和必要强调 |
| `--destructive` | `#ba2623` | `#fa7772` | 错误及危险操作 |
| `--sidebar-background` | `#f7f7f8` | `#141414` | 低权重文件导航面 |
| `--chat-user` | `#f3f3f3` | `#303030` | 用户消息块 |

Tailwind `@theme inline` 只映射上述项目变量。新增控件需接入既有 token；确有新语义时，在唯一主题入口同时补齐浅深色。视频舞台、截图遮罩等具备固定媒体含义的黑白底可以局部定义，并说明用途。

基础 `font:inherit`／`color:inherit` 重置放在 `@layer base`，不能用未分层的全局规则盖住 Tailwind 组件变体，否则主按钮会文字与底色同色。原生 `select` 的 `option`／`optgroup` 同时指定主题文字色与背景，浅深壳明确对应 `color-scheme`。验证须展开菜单，并检查按钮默认、悬停、禁用及实际弹窗；DOM 含有标签不等于文字可见。2026-10-22 此类故障已复现并补检查，见[颜色与局部算符补修](../../research/reports/workspace-v2/UI颜色与命名算符局部引用修复-2026-10-22.md)。

### 3.2 中文与数学排版

| 用途 | 当前基线 |
| --- | --- |
| UI 字体 | `-apple-system, BlinkMacSystemFont, "Segoe UI", "Microsoft YaHei UI", sans-serif` |
| 导航与紧凑工具 | 常用 `11—13px`，有意义的动作保持完整中文名称 |
| 聊天消息 | `14px`；消息容器行高 `1.75`，Markdown 正文行高 `1.85` |
| 纯文本资料 | `15px`、行高 `1.9`，保留换行，允许长行断开 |
| 输入框 | `14px`、行高 `1.65`，最小高 `72px`、最大高 `200px`，不以单行输入替代多行提问 |
| 公式 | 本地 KaTeX 字体；相对字号 `1.08em`；独立公式在自身块横向滚动 |
| 引用卡片 | 正文通常 `12px`、行高 `1.65`，保留渲染公式与来源入口 |

Windows 实际字体回退由系统决定，静态 CSS 不能证明每台机器渲染完全相同。不得为了复制英文演示的密度压缩中文、长推导或上下标。正文不加入壁纸、渐变底、常驻陪伴图或高频动效。

Markdown 使用统一 [MarkdownAnswer](../../frontend/src/chat/MarkdownAnswer.tsx)。禁原始 HTML，回答图片不自动联网加载，外链由用户主动打开并隔离 opener。KaTeX 的受控选区标记只供本模块精确映射，不开放任意回答 HTML、远程资源或一般 `trust` 能力。

### 3.3 间距、圆角、图标与层级

- 新布局优先复用 `4 / 8 / 12 / 16 / 24 / 32px` 间距层级；既有标签、工具栏和紧凑控件存在适配值，不做无关批量格式重排。
- 普通输入和中型控件以 `8px` 圆角为基线，紧凑图标按钮常用 `7px`；引用卡片 `9px`、主弹窗 `16px`、聊天输入框 `22px`。圆角随职责选择，不为每个页面另造一套。
- 常用图标按钮 `30×30px`；当前本地 [Icon](../../frontend/src/components/ui/Icon.tsx) 使用 `24×24` viewBox、`1.6` 描边、默认 `18px`，文件行常用 `16px`。这是项目维护的 SVG 体系，不能声称提取自 Codex 原图标。
- 图标继承 `currentColor`。装饰图形 `aria-hidden`；可操作图标按钮必须有准确的 `aria-label`，`title` 只作补充。
- 普通分区靠轻边框、背景和间距区分；阴影限于输入面、菜单、弹窗等必要抬升。常规弹窗层当前 `z-index: 100`，选区引用浮层 `80`，截图蒙层 `10000`；新增浮层须确认全屏容器与 Portal 层级，不随意堆叠更大数字。

## 4. 组件状态与可操作反馈

以下状态是新增及修改组件必须检查的契约。具有 `role` 或通过类型检查，不等于这些状态已全部验收；实际覆盖以本轮验证记录为准。

| 组件/状态 | 应呈现的行为 | 保持的数据与边界 |
| --- | --- | --- |
| 初次加载 | 在本区显示正在加载；必要动作禁用 | 不清空已保存资产，不把加载误写为空列表 |
| 空课程/空目录/空对话 | 空目录维持文件浏览器；AI 保留输入框，不显示“开始问答”欢迎页 | 未选课程时按业务状态控制输入，不预填假回答或自动发送问题 |
| 后台失联 | 显示稳定错误码与重连动作 | 保留草稿、附件、部分回答；视频与文件功能按自身可用性判断 |
| 账号不可用 | 说明问答影响并给账号入口 | 不把业务后台在线等同于模型可用，不自动切 API Key |
| Disabled | 原生 `disabled`、明确的不可操作状态 | 不只用灰色样式伪禁用，重复点击不产生重复请求 |
| Hover/Focus | 低强调悬停；可见键盘焦点环 | 不以悬停作为唯一入口；`focus-visible` 使用 `2px` accent 外框、偏移 `2px` |
| 文件行/菜单 | 文件名与图标为主，内部整理在中间资源管理器，侧栏避免重复工具 | 删除进回收站；课程显示名修改、文件改名、内部移动、移除课程语义分清 |
| 标签 | 当前标签可辨，关闭按钮独立，长标题省略 | 单内容区；关闭或切离视频保存状态 |
| 输入框待发送 | 图片、文档与引用作为独立可移除附件／卡片；“＋”只显示图标 | 文本、其他附件和原有条件保持；引用不变成编辑框里的 LaTeX |
| 生成中/停止中 | 显示当前状态与对应停止动作，保存部分结果 | 停止对应 generation，不杀整个 Host |
| 请求结果未知 | 显示“核对提交/执行”入口并锁住重复派发 | 先查询原 submission/generation，不能静默重发 |
| 草稿保存冲突 | 明示新版本冲突与恢复入口 | 不覆盖较新服务端或本地编辑，不以保存失败清空草稿 |
| 文件操作待对账 | 显示 operation_id 对应的记录与状态 | 未确认前不再叠加移动、替换或删除 |
| 截图/公式不支持 | 显示具体原因、取消或重新选择入口 | 不改取其他画面，不退回整式冒充局部选区 |

错误就近显示；跨区域断连才使用全局错误条。异步结果须检查所属课程、对话和请求世代，防止过期响应更新另一课程。可恢复错误不能用成功 toast 掩盖。

### 4.1 对话与输入框

- 用户消息为低强调消息块；AI 回答直接排版，不为每段正文再套一张卡片。思考内容可折叠，与正文、费用和错误分开。
- 对话标题本身是历史选择入口，不在其右侧再摆单独历史控件，也不在下拉选项中增加“历史对话”占位项。新对话与收起在 AI 顶部；文件标签和全屏状态不触发新建。
- 切历史要先处理当前草稿及待处理附件，再同时更新标题、消息和草稿所属聊天。异步保存／读取绑定原课程、聊天和课程世代；等待期间换课程，迟到回调不能改写新课程的当前聊天记忆，也不能只换标题而仍显示旧正文／草稿。
- 输入区固定在 AI 区底部，草稿自动保存。移除其下方全部常态说明、保存状态文字和手动“保存草稿”按钮；保存失败／冲突等异常就近呈现并保护输入，不因隐藏常态状态而吞掉失败。普通 Enter 换行；`Ctrl+Enter` 或 `Cmd+Enter` 发送；输入法组合态不发送。
- 用户离底部不少于 `72px` 时停止自动追底；继续生成不把用户强拉回下方。再次回到底部才恢复追随。
- 模型与思考选项来自当前官方能力目录或明确的 fixture 目录。旧选择不可用、目录为空、模型不支持当前图像历史时，保留输入并禁发或提示；不得自动换模型、思考、凭据或丢弃题图。
- 仅有引用卡片、没有问题文字和已确认附件时，不能让前端放行后再由后台以 `INPUT_EMPTY` 拒绝。上传、解析或截图加入未完成／失败时不能漏掉附件发送其余问题。

### 4.2 文字与公式引用卡片

用户在单条回答里选择真实范围，点击临时“添加到对话”才形成卡片。普通选择、复制和取消选区不改变草稿；撤销逐条公式的常驻引用按钮。

`DraftReference` 使用 `reference_id / message_id / text / markdown / source_start / source_end`。范围偏移为原始回答 Markdown 的 **UTF-16 code unit**，与 JavaScript 字符串一致；不是渲染后文字偏移、字节偏移或 Python 字符索引。普通及混合范围应对应连续源码切片；纯公式子范围允许只为渲染加一层数学定界符。标准 `\(...\)`、`\[...\]` 归一化须保留到原始源码的边界映射。

普通文字、完整公式和可精确对应的子式可以形成卡片。用户提供的 `M =` 与整个 2×2 分块矩阵选择曾报 `FORMULA_SELECTION_UNMAPPED`，本轮已复现并修复；完整矩阵及相邻连续文字／标点不能笼统归为“不支持复杂公式”。矩阵结构和选择范围都须保留。跨回答、不连续或无法可靠映射的局部范围仍明确拒绝；不得扩大为其他未选内容、另取截图、调用 OCR 或辅助模型猜测选区。

固定 `katex@0.16.22` 的 `det`／`sin`／`log` 等命名算符 AST 缺少 `loc`，使用同版本 lexer 的原始 token 与解析器确认的算符对账补位，保留 nonce 信任和 UTF-16 精确范围；不得凭显示文字或重复次数猜位置。`\det M = \det A \det` 可单独引用，不补后面的 `B`；算符词内只选 `de` 不补成 `det`。升级 KaTeX 须复测重复算符、分式、注释、定界符及排版宽度；内部 lexer 不兼容时保守失败，不放宽来源校验。

本轮矩阵回归以 `M=\begin{pmatrix}O&A\\B&E\end{pmatrix}.` 为合成复现，须同时覆盖行内／独立公式、可见 `M` 到句点的真实 Range、公式外相邻句号，以及只选单元 `A`。整式覆盖以实际绘制文字和 SVG／分数线等结构判断，不要求用户选到 KaTeX 不可见的 strut 布局节点；完整选区保留原 LaTeX 和 UTF-16 边界，未选后文不能带入。单元 `A` 仍只引用 `$A$`，不能因为同处矩阵而补入整式。该回归不构成全部矩阵环境或复杂局部范围均已支持的保证。

后台校验来源属于当前对话的回答、范围和内容匹配；不匹配返回 `REFERENCE_SOURCE_NOT_IN_CHAT`、`REFERENCE_RANGE_INVALID` 或 `REFERENCE_SELECTION_MISMATCH`。引用独立保存于草稿，提交时通过正式 `references` 字段传输，由后台冻结入现有不可变输入；前端不得再自行拼接一份条件造成重复。历史消息恢复引用卡片，卡片来源能定位原回答，每张可单独移除。

### 4.3 弹窗与菜单的键盘要求

弹窗使用准确标题、`role="dialog"`、`aria-modal`，打开时焦点进入弹窗，关闭后返回触发入口；Tab/Shift+Tab 不应落入背景操作。可取消的弹窗提供 Escape 和可见关闭入口；危险操作不能靠 Escape 或普通 Enter 意外确认。菜单与标签需要键盘可达，关闭按钮不能嵌套在另一个按钮中。

当前实现的语义标签、焦点样式与具体自动用例需要分别检查；焦点循环、屏幕阅读器、高缩放和高对比度尚未专项通过时，交付报告必须保留这些未覆盖项，不能由“添加了 ARIA”推成完整无障碍合规。

### 4.4 创建课程与中间资源管理器

创建弹窗参考用户给出的 Codex 项目弹窗：课程名称、已选文件夹展示、选择按钮、取消和确认创建。名称可编辑，不把文件夹路径做成必填文本输入；原生选择完成后才能确认创建，取消选择不创建半成品课程。课程名是软件显示名，不借重命名课程修改磁盘根名。

Windows 选择器由 `native_files.pick_paths()` 调用系统 `IFileOpenDialog`，前端不承担 COM／线程或 Tcl/Tk 配置。2026-10-22 已先复现缺少 `init.tcl` 导致的 `PICKER_UNAVAILABLE`，再补真实窗口取消、选择中文目录、重复请求和确认创建验证，见[补修报告](../../research/reports/workspace-v2/原生课程目录选择修复-2026-10-22.md)。下方第二轮 seam 记录保持原批次含义；当前目录选择已增加实际 Windows 证据，系统剪贴板没有因此增加真实覆盖。

“文件”页默认图标视图，显示当前课程真实根目录中的全部资料，允许切列表。文件夹单独导航；前进／后退、面包屑／上级、排序、名称搜索和多选只能作用于当前课程范围。文件双击或明确打开才切到相应资料标签，普通选择与查看属性不构成模型提交。

当前名称搜索只筛选当前文件夹的文件名，不递归、不读文件正文。排序覆盖名称、类型、大小、修改时间；单击选择，`Ctrl` 多选、`Shift` 连续选择、`Ctrl+A` 全选。文件区支持 `F2`、`Delete`、`Ctrl+C/X/V`；这些快捷键不能在名称／搜索输入框里截获普通编辑。右键菜单支持上下方向键与 Home／End。属性读取真实名称、根目录／相对路径、大小和创建／修改时间；缺失值显示“—”，目录大小不递归扫描后伪报为零。

复制、剪切、粘贴、内部移动、文件改名、新建文件夹和回收站删除集中在中间资源管理器的工具／右键／快捷键入口。外部粘贴与拖入一律复制，复制后自动编号保留同名；不出现外部移动／替换模式选择或额外确认。根目录与内部路径仍需后台守卫，UI 选择不能扩大模型文件权限。

浏览器 File／目录拖入中的文件按逐文件 raw 上传处理，空目录通过有操作身份的目录创建保留，缺失父目录逐级创建、已有目录合并，不能静默丢掉空目录。当前单文件至多 `8 GiB`、单批至多 `10,000` 个文件／目录节点、目录至多 `64` 层；每项独立稳定 `operation_id`，未知结果中止后续项，重挂后只核对原身份不重发。正常复制可显示进行中进度，但不额外弹方式确认或成功 toast。当前内部剪贴板只支持同课程，跨课程复制／移动不属于此实现；外部复制入口也不能扩大模型的跨课程资料读取权限。

### 4.5 聊天附件入口

输入区左下使用纯“＋”图标并有准确的可访问名称。支持图片、PDF、TXT／Markdown，不把文件选择器接受任意格式等同于后端已能处理。每份附件展示名称、处理状态与移除入口；上传／解析中或失败时不得被忽略而发送其他问题。

PDF 默认整份是用户允许的发送范围；后台完整处理后再发布模型输入，达到明确限额、加密、损坏或不能完整解析时返回可处理失败，不只取前几页。TXT／Markdown 保留完整文本语义，不当作可执行 HTML 或脚本。选择／上传到草稿不自动调用模型，不自动纳入课程目录，也不自动建立知识库。图片、截图选区和文档分别保留来源，不能混淆文档整份授权与视频／屏幕的确认选区授权。

实际附件卡片经 `AttachmentMetadataResponse` 恢复类型、文件名、页数／字符数与下载入口；图片继续使用原有本机裁剪确认流程，文档不伪装成 `<img>`。统一使用原有 `attachment_ids` 随草稿及提交保存，不另建一份文档草稿。文档上传携带稳定 `upload_id`，失败后显式重试沿用该身份，回执不明先核对对应 metadata；文件未加入／处理失败时保留待处理 File 并禁发，切课程前 `saveDraft` 不得跳过待处理附件。正常自动保存无按钮／页脚，异常和未知执行提示就近放在输入区上方。

本轮附件处理上限来自 [document_processing.py](../../backend/src/learning_app/document_processing.py) 与 [documents.py](../../backend/src/learning_app/documents.py)，不是官方模型能力保证：

| 层次 | 项目上限及失败方式 |
| --- | --- |
| PDF 原件 | 非空、最多 `20 MiB`，`1—32` 页；加密、损坏或超过页数整体拒绝 |
| 全份 PDF 准备 | 全部页面渲染，累计最多 `80,000,000` 像素、`12 MiB` 页面 JPEG；长边至多 `1600px`，缩放至多 `2×`；不漏页、不仅渲染前几页 |
| 文本原件 | UTF-8（可带 BOM），最多 `1 MiB`、`200,000` 字符；二进制 NUL、编码错误整体拒绝 |
| 应用保护快照的附件展开 | 本轮展开的唯一原件合计最多 `64` 张图片、`14 MiB` 图片字节和 `300,000` 文档文本字符；超限拒绝当前输入，不静默删附件或历史；不等同于 Host 累积历史后的最终请求张数 |
| 最终出站请求 | 编码后的请求体最多 `24 MiB`，超限整次拒绝；仍须接受 provider 自身限制，不静默去页或换模型 |
| PDF 处理执行 | 隐藏的所属 Python／PDFium worker，串行 gate、`60s` 技术超时，结束／失败均清理；不持整个业务 Repository 锁等待渲染，不占住当前流与取消入口 |

PDF 逐页 JPEG 作为主模型图像输入，TXT／Markdown 作为完整文本输入；这不是原生二进制 PDF 直传，也不是额外 OCR／辅助模型。PDF 与图片要求所选模型支持图像；不能为了让请求通过丢掉页面或自动换模型。原件与全部派生页具有不可变身份和 hash，页面记录不完整或与原件不符时返回 `DOCUMENT_INTEGRITY_ERROR`，不能发送部分结果。

当前 Host 保留持久会话历史，应用又在每轮提交完整保护快照，已确认图片／PDF 页可能随允许历史重复携带。例如同一对话先后加入两份各两页 PDF，合成出站曾观察到实际 `6` 张、唯一 SHA `4` 张；全部仍属于用户允许的历史，不是新增 provider 请求，也不是取了其他画面。本轮没有实现跨接受状态的附件水位去重，不能宣传“每页只传一次”或没有额外输入开销。验证需同时记录 actual／unique／duplicate 张数及 raw usage。由于 Host 还会累积历史，连续大 PDF 可能在本轮附件展开限额之前触及最终请求上限；必须明确失败，不能缩成部分页面。用户可以显式开启新对话，应用不能擅自清历史或换模型。

短按与长按、单击与双击必须分辨，当前单击等待 `220ms`；双击不能叠加两次播放切换。以上阈值和音量步进为项目默认，不属于用户指定数值或 Codex 取证结论。热键监听应解绑，隐藏或切离的播放器不能继续抢键；输入法、按钮、链接、文本域、选择框和聊天滚动均保持自身操作。

### 5.2 截图管线与能力边界

正式管线是用户快捷键 → 暂停 → 冻结当前可见应用 DOM → 按住拖选 → 松开确认 → 精确选区加入草稿 → 展开 AI 并聚焦输入 → 用户补充问题后发送。不会因松开鼠标自动调用模型。

[workspaceSnapshot](../../frontend/src/media/workspaceSnapshot.ts) 读取计算样式、当前显示的视频/Canvas、同源已显示图片和本地字体，以当前视口及滚动裁切生成浏览器本地冻结图。CSS 坐标与 `devicePixelRatio` 转换后，裁剪结果必须对应用户选择的真实像素范围；字节尺寸、裁剪坐标和后台来源尺寸相互校验。

- DOM 原图和重编辑原件只留浏览器本地，模型及后台只收到确认的选区图片。`origin="workspace"` 不冒充视频原帧，原图不另存桌面、下载或独立截图目录。
- 不使用 `getDisplayMedia`、系统全屏截图、浏览器控制、取相邻帧或补原帧来扩充范围。重编辑继续使用同一原截图和编辑根身份。
- 隐藏、视口外和滚动裁切外内容不作为可见截图内容。读取同源字体仅用于保持已显示文字；不以截图名义读取其他用户资料。
- 外域资源、不可读取的视频/Canvas、尚未就绪的画面、可见 iframe/object/embed 等不支持内容明确失败；不联网补取、不改走系统截图。相关错误包括 `CAPTURE_EXTERNAL_RESOURCE`、`CAPTURE_CONTENT_UNAVAILABLE`、`VIDEO_FRAME_UNAVAILABLE`、`CAPTURE_RENDER_FAILED`。
- DOM 重绘不天然等同操作系统截图。公式、分式、上下标、字体和滚动位置必须逐项做合成像素与人工可读性核对；边界数值通过不能掩盖某类公式缺笔画或位置错误。
- 快照、上传、来源登记、草稿保存各自可能失败。确认后的选区保留供明确重试或取消，不因失败替换原文字和其他附件；保存退出应等待这些已确认动作处理完毕。

### 5.3 视频进度条预览与拖动

- 悬停进度条按指针时间显示本地预览图与时间；拖动时圆点／时间立即跟随指针，不等待解码或播放位置保存。
- 拖动只改变待提交的预览位置。原本播放中的主视频沿原进度继续播放，原本暂停的保持暂停；不能在每次 pointer move／range change 中修改主视频 `currentTime`。
- 释放时只提交一次目标跳转，并延续原来的播放／暂停状态；取消拖动撤销待提交位置，不能形成额外跳转。
- 预览解码需丢弃过期结果并控制同时活动任务，快速拖动不能堆积 seek 或拖慢主播放。未就绪时不能把旧预览帧冒充新时间的已解码画面。
- 预览是本地 UI 能力，不能发布为聊天附件、执行快照或提供给模型补原帧／附近帧。只有用户另行主动截图并确认选区后，才沿既有截图管线提交。

当前模块划分为 [VideoControls](../../frontend/src/media/VideoControls.tsx) 管理独立的拖动位置与提交时刻，[SeekPreview](../../frontend/src/media/SeekPreview.tsx) 管理同源受控媒体预览。预览只接受带 `source_version` 的本项目视频内容路由，使用静音、`preload="metadata"` 的独立 video 且不调用播放；主视频的 `timeupdate` 不能覆盖正在拖动的圆点。预览最多一个 seek 在途，后续移动只保留最新目标，未完成以加载状态标识。隐藏／换源时清空 `src` 并 `load()` 释放该解码器；pointer cancel、Escape 或失焦撤销拖动而不跳转。组件单元检查不能替代真实 Chromium 对预览帧、持续播放和释放跳转的验证。

## 6. 文件、账号和聊天的数据契约

### 6.1 课程文件操作

每门课程一个真实本地根目录，课程显示名独立于根目录名。外部粘贴／拖入只复制，重名自动编号保留两份，已经在根内的资料保持其业务身份；内部剪切／移动是另一种明确操作。符号链接、目录联接、绝对路径穿越、`..` 和磁盘根目录不作为课程内操作的旁路。

真实变更必须具有 `operation_id`。前端在派发前保留操作身份，超时或断连后先读取该操作记录，不能换新身份自动重复移动、替换或删除。`prepared / filesystem_done / needs_review` 是需继续核对的状态；已完成结果可按原身份取回。部分复制、替换失败或文件与元数据均已改变时，不把不确定状态当作干净失败。

“从课程移除”只改变关联，不删除目录、聊天或截图；“删除资料”送 Windows 回收站，失败不能降级为永久删除。旧未绑定课程不能以空更新返回移除成功。既有真实用户资料不得为测试或迁移被自动搬运。

原生能力封装在 [native_files.py](../../backend/src/learning_app/native_files.py)，不把 Windows API 传播给前端。系统剪贴板只在显式粘贴时读取 `CF_HDROP`，不轮询；浏览器读到的文件内容通过稳定身份的 raw streaming 通道复制，单文件最多 `8 GiB`。复制已有目录按层级合并，同名文件编号保留；不能把目录合并解释为覆盖其中的旧文件。内部剪贴板／transfer 以当前课程根为边界，操作期间仍校验路径与来源。

回收站使用 Windows 8+ `IFileOperation / FOFX_RECYCLEONDELETE`，不是仅带 `ALLOWUNDO` 的 best-effort 删除；同时使用 early-failure，不提供永久删除回退。当前只支持本机固定卷，网络／可移动卷、根及链接目标拒绝并给稳定错误，不能把这些平台边界隐藏成“删除成功”。官方 flag 语义见 [Microsoft 文档](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-setoperationflags)；实际合成回收与使用注入 seam 的模拟测试分开记录。

文件正文只经已登记业务身份与版本路由返回；当前文本使用 `text/plain`、`nosniff`，媒体响应服从受限内容策略。HTML、SVG 等主动内容不嵌入同源阅读区，使用显式外部打开入口。文件名、扩展名和列表状态不授予模型读取任意文件的能力。

### 6.2 官方账号与模型

默认走官方账号，API Key 是用户主动选择的另一条路线。账号不可用、额度不足或模型无权限时，不自动切凭据或降低模型；问答故障不应使已可用的文件、播放和业务保存一起失效。

[AccountPanel](../../frontend/src/account/AccountPanel.tsx) 契约为 `connected`、`onChanged?`、`onClose?`。前端从 `/account` 读取公开状态，`/account/sign-in` 启动官方授权，在官方浏览器页面完成登录，再刷新状态；支持取消本次授权、退出、刷新以及显式 `/account/route` 切换。API Key 不在前端输入或读取，仍只来自项目私有配置；账号凭据由官方 Harness 管理。

公开 DTO 只含路线、可用性、授权阶段、官方授权 URL、经过筛选的资料、余额状态、模型目录等。`credential-stored` 表示已保存凭据，不独自证明额度或模型推理成功。余额未知保持 `unknown`，不显示成零；模型的图像能力与思考档位取实际目录，不把旧固定模型假定硬套账号路线。

健康状态分别呈现业务后台、Harness 和问答能力。`question_answering_ready` 是当前路线的独立本地属性，读取时不发起网络请求；Host 已连接不等于问答可提交。前端发送条件应使用问答能力，不只检查后台 `ready` 或 Host 状态。该属性也不是一次模型推理成功的探测结果。

不得把 Cookie、账号 token、Peer token、私有配置路径、完整内部协议或密钥写入前端构建、业务公共 DTO、提示词或日志。官方登录是用户在官方页面操作，不要求用户向开发聊天粘贴密码、Cookie 或 token。账号授权、只读目录/余额、真实模型推理属于三个不同验证结论。

### 6.3 草稿、发布、生成与恢复

服务端草稿为权威持久状态，包含文字、确认附件、条件、更正、引用、模型及思考选择。当前使用 revision 乐观并发、本地编辑保护、`250ms` 合并保存与串行 flush；切课程、新建/选择历史及退出前保存，失败保留原输入并明确提示。

新建空聊的初始草稿读取可能尚未返回。若当前视图没有本地未保存改动，且不存在读取中／上传中／失败未处理的文件、确认截图、待确认裁剪等资产，导航可以跳过该未就绪草稿的 `flush`，不等待空读、不向服务端写入虚构的空 revision。这个 pristine 分支只能位于全部附件／截图保护检查之后；本地 dirty 输入、版本冲突或待处理附件仍须阻止离开，不能用“初始草稿”名义吞掉内容。其他已脏的聊天控制器仍按既有串行保存规则处理。

提交前生成稳定 `submission_id` 并保留待确认内容。只有确认原提交已接受才按该身份清除匹配草稿；不同内容、新 revision 或新卡片不得被迟到回调清空。结果未知先查询原提交，普通重连不创建一份新提交。

生成状态、部分正文、停止、对账与最终用量来自正式业务服务。流式用量只更新快照，不逐块相加；缺字段保持未知。停止只取消对应 generation，不以关闭整个 Harness 宿主替代。换课程或关闭网页不等于退出后台，后台结果归原对话保存。
