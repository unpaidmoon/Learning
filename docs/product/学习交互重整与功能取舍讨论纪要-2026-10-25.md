# 学习交互重整与功能取舍讨论纪要

日期：2026-10-25。

同日续讨论已更新至[统一学习入口产品定位与交互需求收口](统一学习入口产品定位与交互需求收口-2026-10-25.md)，并形成[操作调整审阅清单](学习交互调整审阅清单-2026-10-25.md)。新增独立聊天、多课程工作区、未分类资料、Android 依附与共享进度等决定；问答来源面板现已明确取消。下文保留前轮记录，冲突处以续讨论为准；本次同样仅更新文档。

状态：本轮侧聊的阶段性讨论记录，包含已确认决定、未确认建议与暂缓细化事项。本次仅保存文档，未修改业务代码、设置、Skills、MCP 或运行数据，不表示交互改造已经实施或验收。

## 1. 讨论起因与方向

用户认为当前实现与预期相差较大，尤其是新增的“学习成果与任务”界面难以理解，许多设计没有充分考虑操作便捷性。

本轮明确选择：围绕阅读和 AI 对话自然完成学习。用户直接提出需求，由 AI 利用当前允许使用的上下文调用能力；不要求先理解成果类型、任务系统，再通过表单发起学习操作。

此前的场景闭环验证只能说明对应流程具有运行证据，不能代替用户对产品交互的认可。本轮重新确认的是产品方向及功能取舍，不重写此前实现和验证的历史事实。

## 2. 已确认的整体交互

### 2.1 对话作为统一能力入口

- 保留能力按模块提供，可采用 Skills、MCP 等合适方式；具体内部拆分和技术适配尚未确定。
- 日常从 AI 对话提出请求，例如整理资料、保存笔记、生成交互书、对照研究。
- 取消“学习成果与任务”界面，不再要求用户进入该界面选择成果类型、配置任务和查找结果。
- 保留功能的生成过程与完成结果沿原对话呈现；生成文档同时进入当前课程目录，可在中间资料区打开。
- 后台保存、进度、恢复等实现需要，不能直接变成用户必须学习的一套操作概念。

### 2.2 模块管理沿用 Harness

- 用户支持独立启用、停用模块。
- 设置页采用 DeepSeek Harness 原有页面，在其中的 Skills 页面管理这些能力。
- 不另建一套独立模块管理界面。
- Skills 页面如何承载底层 MCP 或本地服务，以及固定版本 Harness 的具体适配方式，尚未进行技术核实；不把管理入口的产品决定写成已验证的运行能力。

### 2.3 生成结果不默认打断阅读

用户接受以下行为：

- 生成讲义或笔记后，保持当前正在阅读的资料和位置。
- 在对话中给出结果入口，用户可自行打开。
- 用户明确说“生成并打开”或要求打开时，再切换中间资料区。

### 2.4 选中文字后添加到对话

用户提供 Codex 截图作为参考，要求采用选中文字后在旁边出现“添加到对话”的方式。

- 选区附近的操作入口统一为“添加到对话”。
- 独立“翻译”和“逐段对照”功能明确取消。
- 本轮早先接受过的翻译按钮、翻译浮层等方案已被上述最新决定替代，不作为保留需求。

讨论中提出的配套行为包括：点击后将选中文字和来源加入当前对话输入框，保留已有草稿，由用户补充问题并发送；显示菜单本身不触发模型请求。这些作为后续交互设计的建议保留，本轮没有逐项细化引用样式和完整操作细节。

关于资料覆盖，讨论过在可精确选取文字的 PDF、笔记、讲义、字幕正文及 AI 回答中统一提供入口；扫描 PDF 依赖文字准备，图片和视频画面仍走已有截图或框选路径。具体支持对象和触发细节尚未逐项确认，不据此宣称当前版本全部支持。

## 3. 已确认的功能取舍

| 功能或界面 | 本轮决定 | 保留范围与说明 |
| --- | --- | --- |
| 学习成果与任务界面 | 取消 | 保留能力从对话调用，生成文档进入课程目录 |
| 独立翻译功能 | 明确取消 | 取消专门按钮、浮层及对应功能流程；普通对话中的语言请求不因此受限 |
| 逐段对照功能 | 明确取消 | 不再保留为专门的文字对照任务或阅读功能 |
| 做题功能 | 取消 | 取消专门题集作答、评价、重做等功能；用户提交题目后的普通 AI 问答仍可使用 |
| 复习卡片功能 | 取消 | 取消建卡、翻卡、评分、FSRS 排期等专门功能 |
| 交互图 | 取消 | 包括此前提议的交互图 Skill，不保留函数参数图、关系图等专门生成能力 |
| 学习路线 | 取消 | 取消专门路线界面及进度管理；普通对话仍可讨论学习建议 |
| 作文批改与多轮对照 | 取消 | 取消专门批改流程、轮次对照及对应 Skill；不限制普通 AI 对话讨论文字 |
| 深入解题专用流程 | 取消 | 不设专门模式或流程；题目答疑、检查推导、另一解等由普通 AI 对话承担 |
| 讲义、笔记整理保存 | 保留 | 用户明确要求整理成文档或保存时执行，保存到课程目录；普通解释留在聊天中 |
| 交互书 | 保留，做成 Skill | 通过对话发起，保存到课程目录，在中间资料区分章阅读；内部交互暂不细化 |
| 资料对照与专题研究 | 保留，做成 Skill | 指定资料比较、核对依据，生成带来源引用的报告；明确要求时再联网查证，报告保存到课程目录，不另设独立调研面板 |

“取消功能”记录的是产品范围决定，不表示代码已经移除，也不构成删除既有文档、聊天、作答或其他用户数据的授权。

以上不是对整个项目全部需求的重新定稿。本轮未讨论的功能和既有权限、来源、数据保护规则，不因未列入此表而自动取消或扩大。

## 4. 交互书：保留但暂不细化

用户明确要求保留交互书并做成 Skill，随后明确表示“先不细化”。

讨论中曾建议目录导航、章节切换、展开例子或解释、引用跳回原资料、选字添加到对话等操作，但用户没有逐项确认。这些不能写成确定的交互书规格。

已取消的做题、复习卡片和交互图，不因交互书保留而自动恢复。
