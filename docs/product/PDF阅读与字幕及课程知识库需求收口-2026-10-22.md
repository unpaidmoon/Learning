## 1. 总体决定与旧规则调整

- 先讨论并补齐软件内的 PDF 阅读、选取和提问能力。
- AI 对话沿用 DeepSeek Harness 原有功能，不另建知识库专属聊天或一套自定义问答编排。
- 取消应用在每次提问前自动查字幕、查资料并预先补入正文的流程。
- 字幕读取和课程知识库检索分别做成 skill，均沿用 Harness 原有的发现、加载和触发机制。
- 用户仍可手动将文字、图片、资料和引用加入现有 AI 草稿，加入与发送分开。
- 默认当前课程，跨课程须由用户明确指定；仅在明确需要外部信息时联网。字幕未就绪、资料未命中不自动联网。
- 自动按题号或题意寻找原题的功能继续取消。

“不再自动补充”指取消应用层每轮预检索，不表示禁止 Harness 模型按原生 skill 机制自行匹配和调用技能，也不表示每次使用 skill 都必须让用户先手动启用。

本轮决定替换[需求总结](AI辅助学习项目需求总结.md)等旧材料中与其冲突的默认字幕／资料检索规则，其余既定边界继续有效。后续实施前需据此同步相关持续维护文档，不能只依据旧表述实施。

## 2. PDF 阅读与手动引用

### 2.1 阅读方式

- 在软件中直接阅读 PDF，沿用课程目录、中间资料阅读、右侧 Harness 对话的工作区。
- 默认连续上下滚动，记住每份资料的阅读位置和缩放比例。
- 提供缩放、适合宽度、旋转、页码跳转、PDF 自带目录和文字搜索等常规阅读能力。
- 有文字层的 PDF 支持直接拖选文字；扫描 PDF 也必须通过本地文字识别支持英语选词、选句和拖选。
- 一句话或一段文字跨页时，支持一次跨页拖选，形成一张文字引用卡片，保留涉及的各页来源。

### 2.2 公式、图形和多个选区

- PDF 公式和图形先采用局部框选图片的方式加入对话。例如，只需询问分母中的某个子式时，可以框选该局部。
- 本轮不要求把 PDF 公式识别为可编辑的数学表达式，也不以扫描公式的结构化拖选作为这批 PDF 能力的必要条件。
- 可以连续框选多个不连续区域，包括位于不同页面的题干、条件和图形。
- 每个图片选区分别形成可预览、移除的引用卡片，保留各自页码和位置，不强行拼成长图。
- 多张卡片加入同一份草稿，用户补充问题后可以一次发送；切换选取方式和翻页不丢失已有草稿。

PDF 公式框选范围不改变既有 AI 回答中公式精确引用的需求，两类来源的能力分别实现和验收。

### 2.3 加入对话与编辑

- 选中后可以直接点击“加入 AI”，将所选内容放入当前草稿，不先强制弹出识别文字检查或确认步骤。
- 用户需要时可以编辑选取内容，包括修正扫描识别错字；编辑是可选操作，不作为默认必经步骤。
- 这类编辑影响本次选取和后续使用的内容，原 PDF 保持原样。
- 引用卡片显示资料名、页码和实际选取内容，可检查和移除。
- 手动引用保存所选内容的快照和来源定位，不能只保存整份文档引用而在实际输入中扩大为整本资料。
- 聊天中的来源入口可以返回对应页面和区域。源文件更换版本或不可用时明确说明，旧引用内容继续保留。

### 2.4 扫描文字识别

- 采用本地 OCR，当前阅读页优先，随后后台逐步识别整份 PDF。
- 支持暂停，保存已完成结果并复用，再次打开无需重复识别整份。
- 暂停后保留已完成结果，提供明确的继续识别入口；跳到新页时优先满足前台阅读需要。
- 打开和翻页不等待整份识别完成。当前页尚未识别时仍可阅读和框选图片。
- 某页失败可以单独重试，其余页面继续可用；后台处理服从播放、截图和当前问答优先。
- 搜索仅覆盖已识别、已可用的内容，明确显示仍未处理的范围，区分未处理、失败和已处理但未命中。
- 本地后台识别整份文档不等于将整份文档发送给回答或翻译模型。

### 2.5 英语划词、划句翻译

- 这轮 PDF 阅读包含划词、划句翻译。
- 选中后提供独立的“翻译”和“加入 AI”入口；只选择文字不自动调用翻译。
- 点击翻译即可直接请求，结果在阅读区附近显示，查看后可继续原位置阅读。
- **翻译只提供用户选中的内容。** 不自动补所在完整句、相邻文字、整页或整篇文章；需要语境时由用户扩大选区。
- 允许按需编辑选取文字，再用于翻译或加入 AI，但不强制先编辑或检查。
- 翻译中不增加“继续问 AI”入口；用户主动使用独立的“加入 AI”功能。

### 2.6 暂缓范围

- 暂不做自动识别整篇英语文章及配套题目、自动形成跨页阅读片段并一键整体加入 AI。
- 高亮、划线和批注继续留到后续。
- 素材积累库、独立笔记和复盘系统不因本轮 PDF 需求启动。

## 3. 本地字幕与字幕 skill

### 3.1 保留的后台字幕能力

- 缺少可用字幕的视频，沿用本地自动转写方向；当前观看片段优先，其余课程视频后台排队。
- 支持按课程或视频暂停，持久保存处理进度和结果，重启后可恢复，已完成内容复用。
- 支持字幕显示和手动修改，保留原始转写、时间戳和手改记录，后台结果不能覆盖手动修改。
- 不增加字幕生成后的 AI 错字纠正或校准调用，不要求用户逐句审核。
- 播放、截图和当前问答优先；后台正常完成只更新进度，确需用户处理的问题再提醒。
- 已有资源模式、完成或长时间暂停后释放转写模型资源等原则继续适用，具体参数留待工程验证。

### 3.2 字幕读取改为 skill

- 提供一个用于读取当前问题时间戳附近字幕的 skill。
- 触发、发现和加载完全沿用 Harness 原有机制：模型可按技能名称和描述匹配后加载，用户也可通过原生显式调用方式使用。
- 不另设必须由用户手动启用的前置条件，不新增应用层独立分类、规划或每轮预检索。
- 使用本次提交绑定的视频来源版本和时间戳作为锚点，后续继续播放或跳转不改变这次问题的来源。
- skill 读取附近的相关字幕，回答需要引用时保留对应时间点，支持返回原视频位置。
- 具体附近时间窗和允许的有限扩展范围尚待设计与验证，不能自行扩展为整课检索。
- skill 需要的片段未就绪时，由业务调度优先处理必要小段；若整课批量队列已暂停，小段结束后批量队列仍保持暂停。用户可以停止当前处理。
- 字幕尚未就绪与读取后未找到相关内容分别说明，不据此自动联网。

字幕 skill 只提供字幕文字及来源信息，不读取或补取视频原帧、邻近帧、屏幕内容。问答看到的视频／屏幕图片仍限用户确认提交的范围及相关已提交历史。

## 4. 课程知识库

### 4.1 定位与入口

**知识库定位：按课程组织、可搜索、可引用、能返回原文的学习资料基础。**

- 资料检索结果可以打开原文，也可以加入现有 AI 草稿。
- AI 知识库检索做成 skill，沿用 Harness 原有触发方式；不另建知识库聊天系统。
- 索引提供检索能力，不代表应用在每次发送前自动检索，不代表资料正文预先进入模型上下文。
- 用户仍可直接手动选择资料或内容加入对话，不必先通过知识库检索。
- 原件原地引用，课程、资料、来源版本、索引和引用由本项目管理，不使用 Harness 内部身份替代业务资料身份。

知识库可服务知识点查阅、课程依据问答和多资料对照。具体首批任务清单及整章／整课归纳的分期，见第 6 节，不能把研究示例直接当作全部已授权的首批功能。

### 4.2 默认索引范围

- 课程文件夹内支持解析的 PDF、TXT、Markdown 等资料，默认自动安排索引，无需逐份再执行“导入知识库”。
- 用户可以排除某份资料或某个子文件夹；实际检索范围遵守排除状态。
- 后续支持 PPT、Word 后，沿用同一索引和来源规则；本轮决定不等于这些格式已实现。
- 临时聊天附件、聊天记录和截图不自动入库。
- 视频字幕继续通过时间戳附近的字幕 skill 提供，暂不纳入整课知识库搜索。
- 复用 PDF 阅读已有的文字／OCR产物，避免阅读识别和知识库解析各自重复处理整份文件。
- 默认仅检索当前课程；用户明确指定后才跨课程使用资料。

### 4.3 图文检索与读取边界

- 知识库检索可以提供文字，以及与命中内容关联的 PDF 公式、图表局部图片。
- 先通过文字定位相关内容，必要时允许 skill 读取对应局部图像，保留资料版本、页码和区域定位。
- 这项许可针对已纳入知识库的文档来源，不扩大成任意路径读取，也不自动发送整本资料。
- PDF 命中区域的图文读取与用户手动框选是不同使用路径；手动选择仍按第 2 节保持所选范围。
- 文档图文检索许可不能用于补视频或屏幕画面。
- 字幕、OCR 或解析文本不得静默推翻用户提交题图中的明确条件；必要条件或符号不完整时说明限制。

### 4.4 未命中时的回答

- 本次检索未找到相关内容时，允许 AI 继续用自身知识解释。
- 明确区分课程依据与通用解释，例如说明“本次检索未找到课程依据，以下是通用解释”。
- 用户明确要求“只依据这些资料”时，严格限制在指定资料范围内；缺少依据时说明无法从资料确认。
- 不编造资料引用，不把“这次没搜到”断言为“整门课程没有这项内容”。
- 区分尚未处理、处理失败、索引过期和已处理未命中；不因未命中自动联网。

### 4.5 来源、状态和恢复

- 命中项显示原文摘录、资料名和页码，必要时包含对应图文区域，可跳回原文。
- 引用绑定具体来源版本。文件同名替换、修改或失联时明确处理，旧聊天引用不得静默指向新版。
- 保存已经用于对话的引用内容；重建索引或原件不可用不应删除历史引用。
- 文件列表提供索引状态，详细进度和失败原因按需查看；某份资料失败不影响其余已可用资料。
- 后台处理使用受控并发、持久检查点和版本核对，播放、截图及当前问答优先。
- 检索结果与最终回答分别验证；索引构建完成不代表数学召回、图文理解或回答准确性已通过。

## 5. 技能接入与工程边界

以下是实现上述需求必须遵守的工程边界，不表示本轮已经完成接入：

- 原生 skill 负责描述适用任务和读取流程；真实资料访问由受限只读工具执行，不能只靠提示词约束权限。
- 执行层校验课程、来源版本、字幕时间窗或文档区域、返回量和取消状态。
- 不为字幕或知识库读取开放通用文件系统、任意命令、任意网络或自动补视频画面的能力。
- 模型和思考强度继续由用户选择，不为降低检索费用自动切换或降级。
- 保留实际请求、出站 attempt 和原始用量的可对账性；结果未知先对账，不叠加隐式重试。
- 采用已验证并固定版本的阅读、OCR、ASR和检索组件。具体引擎、索引方式、切段参数和时间窗由后续工程验证确定，不在本轮指定未验证组合。
- Harness 原生机制已有参考源码依据，但项目固定运行组合中的 skill 发现、加载、工具权限与调用尚需正式接通验证，不能将写入 `SKILL.md` 等同于可用。
