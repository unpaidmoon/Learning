# 统一学习入口产品定位与交互需求收口

日期：2026-10-25（Asia/Shanghai）。依据：用户在前轮[功能取舍纪要](学习交互重整与功能取舍讨论纪要-2026-10-25.md)基础上继续产品讨论，并明确要求“先把刚刚讨论的内容更新到项目，然后整理哪些操作需要修改，我统一阅览”。

本文记录本轮已确认决定，并单列未确认问题；[操作调整审阅清单](学习交互调整审阅清单-2026-10-25.md)供集中阅览。此次授权为文档更新和操作梳理，不启动业务实现、数据迁移、平台接入或 Android 开发。工作包状态只在 [MVP 计划](../plans/MVP开发计划.md)维护；其他聊天／分支已有授权不因本文件被撤销或扩大。

同日后续方案已收口：用户选择沿用 `codex/harness-desktop-flow` 定向改造，确认文档默认保存位置、未分类本地资料默认复制，并取消自动资料准备体系、OCR 和课程知识库索引；字幕只在用户明确要求时通过 Skill 处理。具体步骤见[Windows 定向改造执行方案](../plans/Windows学习工作区定向改造执行方案-2026-10-25.md)。本次要求是写成执行文档，仍未授权开始开发；以下对应条目已同步，不再保留为待定。

## 1. 已确认的产品定位

> 面向中国大学生、以 Windows 为核心的统一学习工作台。基于 DeepSeek Harness 的对话能力，接入各学习平台和本地资料，把资料管理、阅读与独立 AI 对话放在同一处，减少跨软件切换和内容搬运。用户自主学习、按需请求 AI 帮助，Android 作为依附 Windows 的移动协同入口。

- 跨平台内容统一接入是核心价值的一部分，不降为可有可无的附加来源；已有八平台需求继续作为具体范围依据。
- 核心活动是资料管理、阅读与对话。交互以减少操作时间和学习成本为目标，尽量沿用成熟操作和 Harness 已有能力。
- 用户自带模型服务，选择模型并自行承担模型调用费用。本产品负责连接与使用体验；这不等于只允许 API Key，也不取消既有官方账号连接路线。
- “打开就能用”不取消用户必要的模型连接、平台登录和授权；不要求用户理解任务系统、工具调用或内部处理流程。
- 学习方向、资料选择和直接操作由用户掌握；AI 根据用户需求协助理解、分析和整理。

## 2. 资料管理与独立对话

### 2.1 两项功能可以独立使用

- 中间主界面保留文件资源管理器。查找、打开、切换和整理资料由用户直接操作。
- AI 对话是独立功能，不要求先建立课程、选择资料或打开文件才能使用。
- 用户可以只阅读资料，也可以只与 AI 交流；普通聊天内容不必与学习资料有关。
- 用户可直接打开本地资料或平台内容开始学习，不强制先创建课程。

### 2.2 未分类工作区

- 提供一个没有指定课程的默认资料工作区，本轮称为“未分类”，用于存放散落资料和未归入课程的平台内容。
- 用户无需先创建、命名这个工作区；需要时再主动将其中资料整理进课程。
- 资料进入未分类工作区，不等于普通聊天自动关联整个工作区。
- 普通新对话默认不关联资料工作区。明确围绕当前资料提问时可以使用该资料；手动添加未分类工作区后，AI 才能按需查阅其中其他资料。
- 用户主动添加到未分类的本地资料默认复制到软件管理的文件夹，原文件保持原位；同名沿用自动编号保留两份的规则，不新增冲突选择。用户已选择复制，不采用原位置引用方案。
- 平台链接按既有规则保存为资料条目，完整下载仍由用户主动选择；AI 生成的新文件按默认保存目标落盘。本轮只确认行为，不自动批量复制或迁移已有用户资料。

## 3. 对话与课程工作区

### 3.1 课程作为可添加的工作区

- 课程相当于 Harness 项目工作区。在某课程中新开对话，默认将该课程加入这段对话的工作区。
- 一段对话可以关联多个课程。用户可以手动添加另一门课程，或在另一门课程中新开对话。
- 切换正在浏览的课程，不自动更换当前对话，也不自动替换或扩展该对话已添加的工作区。
- 利用 Harness 已有工作区选择与“添加工作区…”交互，不另建一套课程聊天分类或工作区管理流程。用户提供的桌面截图是产品入口参考，不证明本项目业务映射已适配完成。

### 3.2 添加工作区的含义

- 添加课程后，AI 在回答确有需要时可以按需查阅该课程资料，不要求用户逐份文件再次选择。
- 对话关联多门课程、用户未进一步缩小范围时，可按需求检索这些已添加课程；明确指定“只看高数”等范围时按指定范围执行。
- 工作区是可用资料范围，不是每轮自动发送的材料包；普通聊天不自动查资料、扫描全部工作区或联网。
- 用户围绕当前打开资料的明确提问，或主动提交的选区／图片，只提供对应内容的使用依据，不自动赋予整个未添加课程的检索范围。
- 保存的历史引用仍指向原资料和版本；切换资料或新增工作区不能改写旧回答的来源。

### 3.3 对话历史沿用 Harness

- 沿用 Harness 的统一对话历史入口及基本交互，支持继续已有对话；不另建按课程查找聊天的平行管理体系。
- 同一段对话只保留一份，添加多个课程不复制聊天，也不要求用户记住最初创建于哪个课程。
- 打开历史对话时恢复其消息及已添加工作区；浏览课程不筛掉历史，也不自动替用户切换对话。
- 既有业务历史、草稿、附件、执行归属与防重复提交保护继续保留。复用原生交互不意味着将 Harness 内部身份或事件作为跨端业务协议。

## 4. 阅读与 AI 的连接

### 4.1 按提问意图关联资料

- 用户可以自然指代当前资料，例如在 PDF 第 18 页询问“这页主要讲了什么”。在既有受限资料读取范围内取得对应页文字，不要求每次先选字、附文件或输入文件名和页码。
- 需要指定局部内容时，沿用选中文字“添加到对话”或主动截图；普通选中、复制不自动发起模型请求。
- 普通聊天不自动带上当前打开的资料。围绕已有引用追问时延续相关对话上下文，后来打开其他文件也不自动替换讨论对象。
- 视频／屏幕画面仍仅限用户确认提交的图片范围及相关已提交历史。自然指代当前资料不授予自动截帧、补原帧或读取选区外画面的能力。

### 4.2 AI 不主动介入

- AI 只在用户提出需求后行动，不因打开资料、翻页、停留或阅读时长而主动解释、推荐、总结或规划学习。
- 接到需求后，AI 根据上下文组织已有能力完成处理，不让用户逐步选择工具、任务类型和内部步骤，不把表单搬入聊天。
- 必须澄清的实质歧义、已有权限限制和外部写入确认仍按既定要求处理；减少操作不取消这些边界。
- 后续用户明确取消原先的自动资料准备体系及 OCR、课程知识库索引功能。不得在启动、导入、打开资料或普通聊天时自动扫描课程、提取全文、建立索引或识别扫描页；也不保留一套手动 OCR 功能作为替代。
- PDF 使用文件自带文字层直接阅读、选取和复制；没有文字层的纯扫描件保留图片阅读与用户主动截图提问。正常渲染／解析文字层及明确需求下的即时原文读取继续保留，不依赖预建课程知识库。
- 字幕做成 Skill，仅在用户明确要求读取、获取或生成字幕时处理；支持原生入口或自然语言表达，不能由打开视频、播放、普通问答或缺字幕自动触发转写。明确任务中的必要执行与结果保存机制仍可复用。
- 已有字幕、识别结果、来源和用户修改继续保存，不因功能取消自动删除；保留能力的后台保存、下载及明确请求的执行不被一并停用。

### 4.3 来源与结果

- 明确取消独立“问答来源”面板。来源放在回答引用处，用户点击后在中间资料区打开对应文件并定位原文，对话仍可继续。
- 不能准确定位时如实呈现已有来源信息，不猜测位置或静默指向新版本。
- 延续前轮决定：普通解释留在聊天；明确要求整理成文档或保存时执行，结果在原对话提供入口，生成文档进入资料管理体系。
- 生成完成不默认打断当前阅读或切换资料；用户明确要求“生成并打开”或主动打开时再切换。
- 在课程中新建的对话，生成文档默认保存到创建对话时的课程；普通独立对话默认保存到未分类工作区。添加工作区、切换阅读资料或课程不自动改变默认位置，用户明确指定时按本次要求保存。
- 默认保存位置只决定文件落点，不用于按课程分类聊天，也不扩大可读工作区或旧引用范围。

## 5. 平台接入的产品位置

- Bilibili、学习通、中国大学 MOOC、雨课堂、学堂在线、智慧树（知到）、Zotero、墨墨的具体功能与排除项，继续按各平台需求及[共用需求](平台接入共用准备需求收口-2026-10-24.md)执行。
- 各平台旧需求中的自动获取字幕、缺字幕自动转写及文档自动 OCR／知识库准备由本轮取消决定覆盖；资料来源和访问权限本身保留。字幕 Skill 明确执行时可以利用相应平台能力，不因导入就处理。
- 延续独立模块、默认关闭、按需启用和加载；用户手动选择来源和范围，不自动整账号导入。
- 已选平台内容进入统一资源管理和阅读／播放体系；允许先进入未分类工作区直接学习，也保留明确目标课程的导入方式。
- 导入、向模型提交、向平台写入是不同动作。平台访问权限、写入确认、旧来源版本与本地资产保护继续有效。
- 正式提交／计分及各平台已明确留在原平台的活动继续保留原边界；本项目取消专门做题／复习界面，不自动取消已确认的题目和批阅资料导入。
- 用户说明已在其他分支尝试平台实现。本轮未审计这些分支，不能把需求文档中的旧“未开发”句子当作当前实际状态，也不重复安排接入开发。

## 6. Android 的定位与已确认行为

### 6.1 依附 Windows

- Windows 保存资料与对话、执行 AI 请求；Android 作为同一学习环境的移动入口，不另外维护一套独立模型执行环境。
- 手机查看和继续的是 Windows 上同一段对话；继续获得新 AI 回答需要 Windows 在线且可连接。
- Windows 关闭或无法连接时，可以查看已缓存内容，不能继续获得新 AI 回答。具体缓存范围、连接方式和断线操作尚未细化，不承诺全部资料均已离线可用。
- 两端查看操作独立。手机翻页、切资料或查看其他对话，不带动电脑画面跳转；同一段对话的消息和回答共用。

### 6.2 共享阅读／播放进度

- 每份资料共用一份进度；设备打开资料时读取最新已保存进度，退出资料时更新这份进度。
- 阅读过程中两端不实时互相跳页或跳转播放位置。
- **无论该设备是否继续阅读，都以最后退出资料的设备位置为准；允许覆盖为更靠前的位置。** 不采用“只有位置变化才保存”或“总取最远位置”的规则。
- 示例：电脑停在第 18 页，手机在第 25 页先退出；随后电脑即使没有继续阅读，退出后共享进度仍更新为第 18 页。
- “退出资料”的具体事件边界、异常退出和断线后迟到更新的处理未细化，不以到达顺序等实现猜测替代上述产品规则。

### 6.3 手机输入

- 保留手机文字输入、拍照和选择图片，用户确认发送后交给 Windows 上同一段对话处理。
- 图片随聊天保存，不自动加入课程资料，与电脑端主动图片提问边界一致。
- 用户要求 Android 暂停界面细节讨论；底部面板、上下分屏、独立页面等建议均未定稿，不据此设计或开发。

## 7. 延续前轮已确认的功能取舍

以下为产品范围，不表示相关代码已移除；既有用户数据和历史成果不得随功能取消自动删除。

| 功能 | 决定 |
| --- | --- |
| 学习成果与任务界面 | 取消；保留能力经对话调用，结果在对话及资料区使用 |
| 独立翻译、逐段对照 | 取消专门按钮、浮层和流程；普通语言请求仍可在对话中完成 |
| 专门做题、复习卡片、学习路线 | 取消专门作答／判分／重做、建卡／排期、路线进度管理；普通学习问答保留 |
| 交互图 | 取消专门生成能力及此前提议的对应 Skill |
| 作文批改与多轮对照、深入解题专用流程 | 取消专门界面／流程；普通文字讨论、题目答疑和检查推导仍可使用 |
| 讲义、笔记整理保存 | 保留，用户明确要求时执行 |
| 交互书 | 保留，做成 Skill；内部细节按用户要求暂不展开 |
| 资料对照与专题研究 | 保留，做成 Skill；带来源引用，明确要求时再联网，不另设研究面板 |
| 模块管理 | 沿用 Harness 原有设置／Skills 页面；具体底层 MCP／服务映射需核实，不另建平行管理体系 |
| 问答来源面板 | 本轮明确取消，改为回答内引用与原文回跳 |
| 自动资料准备、OCR、课程知识库索引 | 后续明确取消；保留原生文字层和按请求即时读取原文，纯扫描件使用主动截图 |
| 字幕 | 做成 Skill，只有用户明确要求才读取／获取／转写，不自动后台准备 |
