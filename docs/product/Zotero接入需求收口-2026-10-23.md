# Zotero 接入需求收口

2026-10-24补充：共用入口、默认关闭／按需加载、连接／停用及写入确认按[共用准备需求](平台接入共用准备需求收口-2026-10-24.md)执行；主动导出／收录通过Harness原生“＋”、指令或对话发起并确认，不新增Zotero专属成果菜单或任务面板。独立责任与验收见[并行交接](../plans/八平台模块化并行开发交接方案-2026-10-24.md#44-zoterozotero)。功能和排除项保留，本轮仅文档、不开发。

日期：2026-10-23（Asia/Shanghai）。依据：本聊天先调研官方API和现成工具，再逐项grilling；用户最终明确“收口”。

本文是本轮Zotero接入范围的主要需求来源，与[需求总结](AI辅助学习项目需求总结.md)、[13场景需求](13场景学习工作台需求收口-2026-10-23.md)共同理解。实现与验收状态只在[MVP开发计划](../plans/MVP开发计划.md)维护。接口、版本、权限与候选工具的证据及限制见[专题调研](../../research/topics/Zotero官方API与现成工具接入范围调研-2026-10-23.md)，公开声明和源码核查不代表本项目已接入通过。

## 1. 定位、分期与本轮授权

- 以Harness为统一学习入口，接入用户选择的Zotero文献，沿用本项目阅读、翻译、提问、多资料比较、来源引用和成果保存能力。
- **本项目完整保存阅读成果；写回Zotero是用户主动选择的导出方式。** 本地成果保存、成果后续修改和连接文献库均不自动触发导出或持续双向同步。
- 当前13场景继续按已有范围与授权交付，Zotero接入不增加为其交付门槛，也不将现有阅读／研究能力移到后续平台阶段。
- 2026-10-24更新：后续共用接口收敛、平台独立并行开发、分别验收，不再要求等待B站完成；本文和交接方案不构成实际开工授权。
- **本轮只写入需求与同步文档，先不开发。** 不改业务代码、数据库、依赖或工具权限，不安装工具或插件、不启动服务、不登录账号、不读取私人文献、不发出平台写请求或模型测试。本条不撤销其他聊天已有实施授权。

## 2. 连接方式与文献库范围

- **本机Zotero优先，同时提供可选云端账号连接。** 两条路径分别识别、显示可用状态并验证，不将两种数据源默认视为同一时刻、同一版本的数据。
- 本机连接可读取实际已存在的附件、本地链接文件及尚未同步的笔记；使用时需要Zotero运行并启用相应本地接口。
- 云端连接用于不运行本机Zotero时访问已同步内容；文件取得受其实际存储位置、上传状态和授权范围约束。不能用云端旧内容冒充本机最新内容。
- 首版同时支持个人文献库和用户有权访问的群组文献库。保留库类型、库身份与条目身份，同名集合或文献不自动合并。
- 云端账号授权、本地读取和本地写入授权分别核对；对群组的可读、可写及文件权限分别处理，不由“群组可见”推定全部附件或导出目标可用。
- 连接切换或权限失效时明确提示，保留已有成果和来源；不通过静默切换账号或数据源来替代失败请求。

## 3. 手动选择导入内容

- 用户手动选择库、集合、文献，以及具体附件、已有笔记或批注；各类内容可以分别选择，不默认全库／全集合导入。
- 支持题录及其实际存在的作者、标题、年份、DOI、摘要等信息；题录存在不等于已取得论文全文。
- 笔记、高亮、评论及其来源位置纳入可选导入范围；保留来源和版本，与本项目新生成的成果分开保存。
- 同一文献可有多个附件，不能只拿首个PDF就称全部所选附件导入完成。一个条目在多个集合出现时保留组织关系，不因此复制成多个无关联来源。
- 导入资料与向AI提交内容分开。连接或导入不代表全部私人文献和笔记可以进入每轮模型上下文，仍按当前任务和用户允许的材料范围读取。
- 实际获取的内容、失败项、未开放或未取得的附件清楚标识；部分可读不冒充整篇／全库可读。

## 4. 文献条目与阅读体验

- 中间资源管理器按“文献条目”组织内容，每篇文献作为入口，显示标题、作者、年份和Zotero来源。
- 展开后查看用户选中的附件、已有笔记和批注；打开PDF后沿用本项目阅读、翻译、提问及进度保存能力。
- 本项目中的显示名修改、移动与整理只影响本项目，不修改Zotero题录或集合。文件路径、显示名变化不丢失文献身份、进度、问答和成果关联。
- 对本项目生成内容、用户自写笔记、原文摘录及导入的Zotero笔记保留来源区别，不将AI整理结果显示成论文原文或原作者笔记。
- 默认围绕当前课程／课题已关联的资料学习；换阅读材料和收放界面继续沿用已有对话及来源保护规则，不因Zotero入口另建一套科研聊天。

## 5. 附件保存、来源与版本

- **本机附件默认原地引用Zotero原文件，不搬动；用户可主动保存一份本项目副本。** 外部链接文件仍保留其实际来源身份。
- 云端附件取得后保存为本项目管理的副本，保留Zotero来源；文件尚未取得时只显示已有题录及实际状态，不宣称已可离线阅读。
- 保存本项目副本后仍使用同一文献条目、原有阅读进度、问答和成果，不另建一套独立记录。
- 保存文献、附件及其实际来源版本与文件校验关系；云端与本地实例的版本不得直接混用。旧回答与成果继续指向当时使用的来源，不能静默改指新文件。
- 原文件更新、移动或失联时明确提示。只有原地引用而没有保存副本的文件，失联后不能保证重开原件；已有问答、成果和已保存内容仍保留。
- 本地API返回的文件路径须受控解析和访问，不能成为任意本机文件读取入口；实际文件格式、完整性、权限和版本均需核实。

## 6. 已关联范围的变化提醒

- 允许后台检查用户已关联的库、集合或文献范围，发现题录修改、新增附件、笔记或批注变化后提醒。
- 用户手动选择要导入的新增内容或版本，不自动替换当前阅读材料、覆盖本地成果或把变化内容发送AI。
- 已有问答和成果保留当时的来源版本；Zotero删除内容时，保留本项目成果和已保存副本，不自动执行关联删除。
- 检查失败、权限失效和没有变化分别显示；后台任务沿用受控并发、检查点和恢复规则，不妨碍前台阅读与问答。本轮不指定未经验证的检查周期。

## 7. 本项目完整保存，主动导出到Zotero

- 本项目保留完整阅读成果及其历史；导出是用户主动选择的动作，不以Zotero可用或写入成功作为本地保存成功的前提。
- 首版提供两种导出形式：**新建笔记**和**文件附件**。笔记可包含用户选择的摘录、阅读笔记、摘要或AI整理内容；文件附件用于本项目已生成的报告等成果文件。
- 用户选择具体内容、形式及目标文献／集合，预览后确认；写入前核对目标账号、库身份和实际编辑／文件权限。
- 默认新建，不覆盖Zotero已有笔记、附件或题录；不将本项目资源整理动作变成远端元数据修改。
- 导出件保留来源信息，区分摘录、用户笔记与AI生成内容；只有可靠的出处和位置才写入相应引用信息。
- 本项目后续修改不自动更新或覆盖已导出件；再次导出是另一次明确动作。多文献成果应由用户选择实际归属，不擅自把一份成果附到全部参与文献下。
- 导出结果记录实际新建对象及回执。用户确认只覆盖本次所选内容，账号层授权不等于今后自动导出授权。

## 8. 引用、回跳与参考文献导出

- 阅读回答、笔记和多文献报告中的引用关联真实Zotero条目、所用附件及版本，而不仅是文件名或AI生成的作者年份。
- 点击引用可回本项目原文；有可靠页码或批注位置时精确定位，并提供打开Zotero对应来源的入口。只有题录、缺少可靠位置时按实际信息定位，不猜页码或批注标识。
- 支持所选文献导出为**BibTeX、RIS、CSL JSON**，以及按用户选择样式生成参考文献列表，供写作使用。
- 作者、年份、DOI及页码等缺失信息保持缺失，不由AI补造；文献条目身份和引用键分别处理，引用键变化不使旧来源关联失效。
- 引文格式文件和参考文献列表导出不等于Word／Overleaf实时双向引用集成，本次未额外确认其完整编辑器对接范围。

## 9. 库内检索与新文献收录

### 9.1 检索尚未导入的文献

- 普通学习问答默认使用当前课程／课题已关联资料。
- 用户明确要求在Zotero某个库或集合中查找时，可检索该范围内的题录。
- 找到后，由用户选择要导入或供本次AI阅读的文献、附件和笔记；为一次问答授权读取不要求永久导入全部内容，也不转成持续全库读取。
- 库内检索与联网查文献分开，不自动相互替代。资料未命中或附件未取得不自动联网；已有按题号或题意自动找题的取消决定继续有效。

### 9.2 主动收录新文献

- 用户提供文献信息，或在明确发起的联网研究中找到文献后，可主动选择“加入Zotero”。
- 展示可核实题录、查重结果及目标库／集合，用户确认后新建条目；模型猜测的题录不作为已核实来源。
- 有权取得的全文附件可单独勾选保存。题录保存成功与附件保存成功分别显示，不把只有URL或题录的条目当成全文已存入。
- 疑似重复项交给用户选择，不自动合并、覆盖或删除已有文献。
- 这一入口不构成默认全网抓取、自动下载所有发现论文或绕过实际全文访问条件的授权。

## 10. 首版格式范围

- PDF沿用本项目阅读、OCR、翻译、问答和来源定位能力，文字／扫描／混合PDF按相应条件分别验证。
- 本项目其他已支持或已确认格式沿用原有需求，不因Zotero接入缩减当前交付范围。
- EPUB、网页快照等新增格式，首版支持导入管理、保留来源和外部打开，内置阅读后续单独扩展。
- 格式可导入管理、能外部打开和可供本项目AI完整读取分别标识；Zotero能读某格式不等于本项目已经支持其内置阅读、版式或全部批注。

## 11. 接口依据、执行边界与待核实项

具体接口和固定源码证据见[调研](../../research/topics/Zotero官方API与现成工具接入范围调研-2026-10-23.md)。以下用于后续设计和验证，不是本轮运行结果。

| 项目 | 已核文档依据与后续约束 |
| --- | --- |
| 云端与本地连接 | Web API v3、本地API为不同来源路径；本地正式写入以Zotero 10+及实际兼容为前提，旧版读取不冒充可本地写回 |
| 身份和权限 | 云端key与本地key分开；本地读无认证、写key无细scope，应用须落实所选库／集合／对象范围及写操作白名单，不能只依赖授权弹窗或提示词 |
| 文件与索引 | 题录、索引纯文本、原附件、数据库批注及带批注导出PDF分别识别；索引不完整、默认页数上限或提取失败不得冒充整篇完整阅读 |
| 存储位置 | Zotero Storage、个人WebDAV、本机已下载文件和linked file分别核取得路径；云端有题录不保证云端有文件 |
| 写入与上传 | 笔记／条目创建及附件上传分别核成功，处理实际权限、配额、逐项回执、版本冲突和重复请求；HTTP成功不等于所有对象均已保存 |
| 来源和同步 | 本地实例版本与云端版本分开管理；导出成功不等于已经云同步或另一设备可见 |
| 工具选择 | Pyzotero、Zotero MCP、native MCP、Better BibTeX等仍为候选；未选定SDK、插件、发行制品或语义索引模型，不默认启用候选的全库、删除或任意代码执行工具 |

- 后续写入仅限本次确认的主动导出、新文献收录及其必要附件创建；不借普通聊天或现有只读资料工具绕过确认，不默认开放原件覆写、已有批注编辑、集合批量重组或远端删除。
- 凭据和私人文献数据不进入代码仓库；密钥由后端私有管理，不进入模型、前端脚本或日志。本地接口不得转发暴露为跨端通用文献端口，业务数据仍由本项目协议承载。
- 持久记录所选内容、目标、操作身份和实际回执；结果未知先对账，不自动重发整批。部分成功时保留成功项，避免重复创建笔记、条目或附件。
- 断网、限流、权限失效、取消和重启保留本地成果与待导出内容；不以删除本地成果或远端资产解决连接失败。
- 模型材料读取继续遵守当前任务范围和课程隔离；本次不扩大视频／屏幕画面输入，不因MCP或插件可读取而补取未提交画面。

## 12. 后续独立验收要求

下表为后续明确启动时的验收方向，不代表已开工或通过。确定性fixture、真实平台／账号、真实模型和实际窗口／学习体验分别报告。

| 路径 | 应验证的结果 |
| --- | --- |
| 两类连接 | 本机与云端状态和来源明确，未同步内容不混淆；版本不兼容、未启动或未授权可处理 |
| 库与选择 | 个人／群组库及实际权限正确；库、集合、条目、附件、笔记和批注可分别选范围，同名不串读 |
| 文献条目 | 多附件和已有笔记／批注关系保留，本地改名移动不改Zotero原件，不丢失历史 |
| 附件与副本 | 本地原位引用、主动保存副本、云端文件取得及完整性可核；同一条目沿用进度和问答 |
| 来源与更新 | 检测仅限已关联范围，提醒不自动导入或发AI；新旧版本、失联和删除不覆盖旧引用或本地资产 |
| 阅读及格式 | PDF和既定格式按原需求验证；索引覆盖不足、扫描件及新增格式能力如实显示 |
| 成果与导出 | 本项目完整保存不依赖Zotero成功；主动新建笔记／附件及目标、内容确认正确，后续修改不自动回传 |
| 引用与导出格式 | 真实条目和附件身份可对账，可靠位置可回跳；BibTeX／RIS／CSL JSON与所选参考文献样式输出可用，缺失字段不造数 |
| 检索与收录 | 库内范围、一次性阅读与永久导入分开；新题录查重与确认有效，全文文件结果单独核对 |
| 恢复和权限 | 本地／云端授权、群组角色、文件存储和配额、并发修改、部分成功、未知回执、取消及重启均有对应验证 |

实际账号权限、当前安装及插件兼容、文件取得、批注精确回跳、各引文输出与恢复行为均待实际验证。当前13场景或候选工具的测试不能代替本平台独立验收；本轮不填完成状态、不编造性能、工期或用户覆盖率。
