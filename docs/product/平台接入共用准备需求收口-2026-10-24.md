- 共用准备服务于Bilibili、学习通、墨墨背单词、Zotero、中国大学MOOC、雨课堂、学堂在线及智慧树（知到）8个独立模块；不将它们并为一个必须全部启用的连接器。
- 已有学习能力优先复用；新增能力只建设实际需要的一份，不建设任意第三方插件平台、在线插件市场或另一套聊天／播放器／阅读器／复习系统。
- 后续采用“冻结共用接口、平台分别并行开发、各平台独立验收”。这覆盖2026-10-23文档中必须依次推进、其余平台等待B站完成的串行安排；可用B站作为首个共用接口接入样例，不把B站验收作为其他平台协议和fixture工作的前置门槛。各平台仍需完成其全部已确认范围，不因并行而缩减。
- **本轮只写需求和交接文档，先不开发。** 不创建源码骨架、分支或worktree，不安装依赖、不改数据库／运行配置／业务代码，不连接账号、读取私人数据、下载素材、调用模型或发送外部写请求。本文和交接方案本身不构成后续实施授权，也不撤销其他聊天已有的13场景实施授权。
- 当前13场景与既有交付门槛不因平台接入而扩大或移后；已有实现、接口研究、计划和实际验收分别表述。

| 位置 | 用途 | 行为边界 |

| DeepSeek Harness原生“＋”、斜杠指令及自然语言对话 | 发现并调用当前可用操作；发起收词、导出、查询及任务状态查看 | 复用原生输入与指令机制，不将“＋”限制为附件按钮，不重建命令框架 |
| 既有对话及任务结果呈现 | 展示进度、缺口、操作回执与恢复入口 | 不新增平台专属任务面板；离开原页面后仍能找到持久任务 |

具体指令名、原生扩展点及呈现细节在实施时核对固定版本Harness制品和源码；本文不宣称现有客户端已完成这些入口或模块开关。不另写一套指令解析器，也不为接入绕过执行守卫。

## 3. 12项共用准备

### 3.1 八个模块默认关闭、按需加载

- 每个平台独立启用，初始全部关闭。设置可以列出可选平台及说明，这不等于加载其运行时或授予能力。
- 未启用模块不初始化SDK、启动外部进程、连接账号、检查更新或向Harness注册平台工具／skill说明。只启用一个，不连带加载另外七个。
- 代码可以随应用内置；重型依赖与进程按实际需要独立准备和加载。未启用平台缺依赖，不得阻塞本地学习启动。

### 3.2 区分启用、连接、停用与断开连接

| 用户动作 | 应有结果 | 本地资产与授权 |
| --- | --- | --- |
| 启用模块 | 开放该模块；缺依赖显示待准备，未授权显示待连接 | 不自动登录、导入、远端检查或写入 |
| 连接账号／本机服务 | 建立指定连接，按实际权限展示可用范围 | 连接成功不等于导入，也不等于允许任意外部写入 |
| 停用模块 | 阻止新的远端访问及后台检查，暂停相关远端任务，撤销后续调用能力 | 保留设置、既有授权和本地资产；保留授权不代表继续访问 |
| 断开连接 | 移除本项目保存的该连接登录凭据，令其不再可用 | 保留本地资料、历史、成果及旧来源身份；不宣称同时撤销供应商其他客户端授权 |
| 再次启用 | 使用原有设置，重新核对连接是否有效 | 不启用其他模块，不自动重新执行未知写入 |

模块是否启用、依赖是否就绪、连接是否有效、能力是否获准是分别记录的条件，不能用一个“已登录”状态代表全部可用。过期、失效、缺权限和模块故障提供明确原因与处理动作。

### 3.3 显式绑定连接身份

- 连接绑定平台、账号及必要的学校／服务器／文献库身份；导入、下载、检查及写入任务记录创建时的实际连接与范围。
- 切换账号、学校、服务器或本机／云端入口时，旧来源仍属于原身份，不静默迁移，也不拿新账号重跑旧任务。
- 不自动聚合多个账号；同名课程、班级、期次、收藏夹、集合不据名称合并。供应商相同、协议相似不代表权限相通。

### 3.4 统一手动选择导入

- 支持“指定课程→浏览平台或粘贴链接→手动选内容与范围→确认导入”，也支持不建课程直接打开用户所选平台内容，未指定课程时进入未分类工作区。课程不再是必经前置，不静默落到其他课程；临时资料的具体落盘方式待细化。
- 可复用选择树、分页、导入计划、重复操作防护和结果呈现；收藏夹、课程／班级／章节、文献与多附件保留各自关系，不强行压为同一种目录。
- 用户可分别选择各平台已纳入的资源类别与具体条目，不因连接或选择上层节点默认导入整个账号。墨墨词本与收词流程按其专有需求处理，不伪装为课程文件。
- 只对各平台原需求允许的已关联范围检查变化，通知后由用户选更新，不自动导入新增内容或替换旧版本。

### 3.5 导入资料与发送给AI分开

- 导入不等于把整门课、整个文献库或完整学习历史交给模型。普通聊天不自动带当前资料；读取由提问意图、对话已添加的工作区及明确提交的材料范围决定，继续遵守受限资料与视频／屏幕边界。浏览课程不自动扩展对话工作区。
- 需要查询未导入的远端资料时，由用户明确平台和范围；不自动扩大到其他课程、学校、账号或文献库。
- 字幕未就绪、来源缺失或检索未命中，不因此自动联网；不恢复按题号／题意自动找题。视频／屏幕仍只提交用户确认的图片范围与相关已提交历史，不借平台能力补画面。

### 3.6 Harness仅提供当前所需能力

- 导入后的内容优先走项目统一受限读源能力，平台协议和凭据留在后台；不为每个平台常驻一整套原始MCP工具。
- 原平台查询、墨墨收词、Zotero导出等，只在模块启用、连接有效、账号权限及本次任务范围均满足时提供窄能力。不是所有已启用模块都进入每轮上下文。
- 原生“＋”、`/name`和自然语言只是入口，不扩大执行权限；不开放任意终端、任意文件、任意URL或任意平台方法，不增加应用层每轮全平台扫描／自动检索。
- 请求创建与实际执行均检查启用状态、连接身份、owner及范围。旧对话留下的工具说明或操作句柄不能绕过当前授权。

### 3.7 外部写入在对话中确认

- AI先形成候选内容，向用户展示发送内容、目标平台／账号／词本或文献库及具体操作；用户确认后执行，不另建一套审批页面。
- 墨墨写入指定云词本并加入学习规划，`advance=false`；原句和译文作为可选项、默认不勾选，手动确认才发送。去重、已有词巩固及正式复习留墨墨等按原需求。
- Zotero成果主动导出、新文献收录按原需求分别确认；本项目保存或修订成果不自动触发写回。
- 账号、目标、操作或待发内容变化后重新确认；模块启用、账号连接、一次泛化同意或AI建议不能代替具体发送确认。
- 保存每次实际请求和逐项结果，部分成功只处理未完成项；结果未知先对账，不自动重发，不用整批重跑掩盖部分结果。无法可靠核实的项保持未知，供用户核对。

### 3.8 稳定资源身份及版本

- 将平台来源、所选连接、远端对象／期次、项目资源、本地副本、来源版本、进度、对话和成果建立可追溯关系；界面名和路径不是唯一身份。
- 在线条目保存本地、项目内重命名或移动后，沿用同一条目及学习进度，不创建断开旧历史的替代品，也不因此写改平台原件。
- 原件、平台派生件、Office转换件、课件页图PDF、平台字幕、ASR及用户修订分别标识；旧问答／引用保持旧版本，不静默指向新版。
- Zotero题录与多附件保留文献关系；墨墨词条、候选和远端写入回执保留语言学习语义，不一律套普通文件模型。观看进度仅在本项目保存，不上报课程平台任务点。

### 3.9 持久任务复用既有呈现

- 导入、下载、字幕处理、获准的变化检查及写入对账进入统一持久任务机制，保留任务身份、检查点、结果与可恢复状态，不各平台自建调度器。
- 保留后台持久执行及必要恢复，生成过程与完成结果沿原对话呈现，不要求用户理解任务系统或进入独立“学习成果与任务”界面；不新增平台专属任务中心。关闭网页不等于退出后台。
- 播放、截图和当前问答优先，后台受控并发并遵守各平台限流。断线、暂停、取消、依赖未就绪、权限不足、资源缺失、部分成功和结果未知分别处理。
- 当前持久任务代码是复用起点，不等于远端下载、平台限流或写入对账已经实现；所需窄扩展由共用负责人统一接入。

### 3.10 停用立即撤销远端能力

- 停用生效后拒绝新访问和旧上下文发起的调用；执行中的远端任务停止发起后续请求并保存检查点，不等待页面刷新才生效。
- 已出站请求无法承诺撤回；保留实际回执，停用不是撤销远端操作。迟到结果按原连接和操作记录，不能发布到后来切换的账号或任务中。
- 已保存本地资料、成果和已授权本地OCR／ASR仍可使用；仅在线资源需要平台时明确提示重新启用，不自动加载模块。
- 用户再次启用／连接并恢复任务时重新核对身份和权限；未知写入先核原回执及远端结果，不自动再发。账号过期或断开连接同样不得绕过访问检查。

### 3.11 私有凭据、依赖与故障隔离

- 凭据保存在后台私有配置／存储，不发给模型、不进入前端业务脚本、仓库或普通日志。UI仅使用连接状态、必要账号标识及脱敏错误。
- 共用私有存储、过期状态及连接管理；扫码、OAuth、本机授权、Cookie刷新等具体登录流程由各平台实现，不假设八家相同。
- 单个平台缺依赖、授权失效、协议变化或加载失败不拖垮本地学习和其他模块；平台内部协议与供应商SDK隐藏在本模块接口之后。
- 复用既有OCR／ASR，不逐平台复制；不因供应商工具方便而自动外发音频、删除用户资产或修改全局环境。项目依赖固定版本，正式运行不依赖临时探针。

### 3.12 共用接口先收敛，平台独立并行

- 共用负责人维护模块管理、连接状态、导入编排、来源映射、持久任务／回执及Harness权限；8个平台分别负责自己的协议、解析、配置、fixture及测试。
- 只冻结业务需要的小接口：资料来源、词汇同步、文献导出等按能力分别设计，不堆成大量可空方法的万能连接器。正式DTO／网络字段遵守现有生成契约，不在本文另造字段真相源。
- 共用入口、全局路由、数据库迁移、生成契约、锁文件和Harness guard集中协调。平台缺共用能力时提交明确接口需求，不复制底座，也不私改公共文件。
- 实施前从包含实际现行源码的核定基线开独立工作区，不能只取旧HEAD而遗漏当前未跟踪正式文件；运行数据、端口、数据库、浏览器profile及凭据不共写。具体交接与验收按[并行方案](../plans/八平台模块化并行开发交接方案-2026-10-24.md)。

## 4. 共用验收要求

| 场景 | 必须核验的结果 |
| --- | --- |
| 八模块全部关闭 | 本地阅读／播放／问答正常；没有平台SDK初始化、进程、工具／skill加载或后台平台访问 |
| 逐一只启用一个 | 每个平台分别验证；其余七个未加载、未连接、未被自动启用，不以B站通过代替其他七个 |
| 原生入口 | 设置、资源导入、原生“＋”／指令／自然语言职责一致；无重复聊天框、专属收词／导出菜单或新增平台任务面板 |
| 身份及范围 | 账号、学校、服务器、课程期次和库隔离；切换身份不改变旧来源，不因导入自动提交整库给AI |
| 停用／断开／恢复 | 旧上下文和已排队请求不能越权；已出站有回执，旧账号结果不串用；本地副本仍可学 |
| 同一条目与版本 | 下载、改名、移动沿用进度；更新建立版本；原件／转换／字幕／ASR及用户修订可区分，旧引用不改指 |
| 外部写入 | 目标和内容可审阅；变更需重确认；重复提交、部分成功、超时未知和恢复均不重复收词／创建对象 |
| 任务与故障 | 离开页面后任务可找回；后台让位前台；单模块缺依赖／失效不影响本地或其他模块 |

确定性fixture、真实平台／账号、真实Harness／模型以及实际学习体验分别留证。模块功能以各原需求逐项验收，未核实的权限、课程类型或接口路径保留缺口，不能把脚本可运行、静态源码支持或计划写完当作接入通过。
