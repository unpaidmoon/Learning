# AI 辅助学习项目需求总结

### 2026-10-25 统一学习入口定位与交互重整（文档收口，供集中审阅）

用户确认定位为面向中国大学生、Windows 核心、连接各平台及本地资料的统一学习工作台，基于 Harness 整合资料管理、阅读与独立 AI 对话，Android 依附 Windows，模型服务由用户自带。完整决定见[本轮需求收口](统一学习入口产品定位与交互需求收口-2026-10-25.md)，操作差异集中见[调整审阅清单](学习交互调整审阅清单-2026-10-25.md)。

- 不建课程也可聊天、打开本地或平台资料；未指定课程的资料进入默认未分类工作区，但普通聊天不自动关联整个未分类工作区。
- 课程作为可添加的对话工作区；在课程中新开对话默认添加该课程，一个对话可添加多个课程。浏览课程不自动切换对话或扩展工作区；沿用 Harness 原生工作区入口与统一历史。
- AI 按提问意图使用当前资料及获准工作区，普通聊天不自动带资料；AI 不主动介入阅读。来源直接放在回答引用处，点击定位原文，取消独立问答来源面板。
- 前轮取消的学习成果与任务界面、独立翻译／逐段对照、做题／卡片／路线／交互图／作文多轮／深入解题专用流程继续取消；讲义笔记、交互书与资料对照研究按已确认范围保留，经对话使用，不把任务表单搬入聊天。旧用户资产和历史证据保留。
- Android 共用 Windows 资料与对话，新 AI 回答依赖 Windows 在线；两端查看独立。每份资料共享进度，打开读取、退出更新，**无论是否继续阅读，以最后退出者的位置为准，允许回退**；保留手机文字、拍照与选图提问。

资料准备时机尚未决定；多工作区文档保存目标、未分类资料落盘及跨端异常细节待后续细化，Android 布局和交互书内部设计暂不展开。本次只写文档和梳理操作，不开始改造或新增验收；既有平台分支授权和历史交付事实不被撤销。与下方旧范围冲突处按本轮决定理解，实现状态仍只见 MVP 计划。

### 2026-10-22 精简界面、统一文字与交互动效追加收口

用户明确授权按界面评审方案直接实施，并进一步圈出不美观区域，强调“精简，只展示有用的信息，让注意力集中在需要的地方”；要求统一前端文字，并显式调用 reverse-engineer-anything 对照 Harness 优化交互与动效。整体继续左课程目录／中资料／右 AI，复用 Harness 视觉与原生输入、消息、菜单。

- 删除 AI 欢迎品牌、空态说明、重复课程／目录文字及常态项目数量。课程、文件页与对话标题为简洁导航，不展示内部 ID；设置合并一个入口。

### 0.2 议题 2：Harness 职责、复用与维护（已收口）

- **用户上下文为主：**绝大多数问题只使用输入框中的文字、图片、引用及当前问题相关的已提交历史与修正，少数确有信息缺口时才补字幕或资料。默认检索当前课程的字幕及关联资料，跨课程须由用户明确指定。
- **检索判断：**明确引用由程序优先定位；其余由主回答模型在正常回答过程中按需请求检索，程序控制来源范围、调用次数、结果量和等待开销。不默认增加独立 AI 分类环节，也不因题难、推导出错或模型低信心就自动检索。
- **来源可见：**自动附带课程名、资料名、已提交截图对应时间点等少量定位信息，并在输入框的截图或引用卡片上可见；这不等于预先读取字幕或资料正文。查找时显示简短状态，回答附可回看的来源，详细过程按需展开。
- **联网边界：**仅在用户明确需要外部信息时使用，例如要求查网页或询问最新考纲、官方公告。普通解题、字幕未就绪、课程资料未命中不自动触发联网。
- **等待与异常：**正常检索自动完成，单次未命中可在允许范围内有限调整，不逐次要求确认；真正失败或缺少必要信息时才提示。用户随时可以停止。内部采用超时和有限重试，具体预算待验证；结果未知的生成仍须先对账，不能盲目重发。首次有用内容的体验目标不等同于统一的检索硬截止时间。
- **字幕：**取消字幕生成后的 AI 错字纠正／校准，保留本地自动转写及原有手动修改能力，不另行增加后台 AI 纠错请求。
- **工具只读：**首版问答 AI 仅按需读取已提交内容、字幕、课程资料和已允许的网页；课程整理、改名、移动等变更由用户通过软件界面操作。软件正常保存聊天、截图及任务产物不受此限制。

### 0.3 议题 4：效率目标、回答组织与学习流程（已收口）

2026-10-20，用户确认本议题收口。以下为已确认需求；当前仍处于需求讨论阶段，不表示恢复应用构建或性能已经达标。

- **效率对照：**以用户现在的实际 Windows 流程为基线：暂停视频 → 截图快捷键 → 框选、调整 → 打开浏览器和 ChatGPT → 找到截图并上传 → 输入需求、发送 → 等待并看完回答 → 关闭浏览器、返回视频 → 全屏并播放。重点减少找图上传、应用切换及恢复播放的操作，并比较完整流程耗时。用户明确纠正过：其通常等待并看完 AI 回答后才返回视频，不能按“发送后立即继续看视频”设计主要流程；已确认的边播放边问答能力继续保留。
- **等待目标：**日常大多数问题从点击发送到出现足以继续学习的有用解题内容，目标为 10 秒以内；复杂证明、综合题或需要查询资料的问题允许更久，分别评估。状态提示或首个字符不能代替有用内容。完整回答耗时单独记录，具体达标比例与复杂问题时限尚未量化，均待实际验证。
- **回答组织：**完整题目先简短说明具体思路与理由，再连续给出完整解答，中间不要求点击“继续”或回答引导问题。关键步骤讲清理由，常规运算适当合并，需要时再局部展开；用户针对某一步追问时集中解释该步。不因这个输出顺序默认增加一次摘要模型调用，也不将输出顺序视为缩短模型思考时间的保证。
- **操作方式：**鼠标操作本身要方便，快捷键用于进一步提速，不要求用户先记住快捷键才能顺手使用。

## 4. 聊天与截图问答

### 4.1 输入方式

- 用户可以自行截图、粘贴图片，并补充文字后发送。
- 以内置播放器主动截图为主要入口，框选或裁剪后图片直接进入聊天输入区；同时支持粘贴外部截图。
- 支持将多张图片放在同一次提问中，例如分别提供题干、图形和已有步骤。
- 支持同时提交题目与自己的手写解题过程；明确要求检查错误或沿原方法继续时，优先检查已有步骤、解释卡点并沿用户思路讲解，普通解题仍默认完整解答。
- 截图编辑支持缩放、裁剪和拖动查看。
- 来自应用内视频的截图，应关联视频来源与时间点。
- 发送前能够查看本次提问附带的内容。

设计方向是保留原图及编辑关系，方便重新调整裁剪区域。截图编辑中「移动」的具体交互方式，在界面设计时细化。

提交给 AI 的图片以用户实际选择的内容为准，不自动从视频补取完整画面或附近画面。需要其他图形或题干时，请用户补充。

### 4.2 默认回答流程

1. 优先使用用户提供的图片、文字、引用及当前问题相关的已提交历史与修正；附带可见的少量来源定位信息。
2. 题目完整、清晰时，直接给出完整解答和解释。
3. 当前输入不足且可由讲解上下文补充时，按需读取当前视频的相关字幕。
4. 补充字幕后仍不足时，按需检索当前课程的关联资料；每一层足够回答就停止补充。用户已选取或提交的资料引用由程序解析来源位置，不据题号自动寻找原题。
5. 题干、关键符号或图形缺失且无法可靠确定时，请用户补充，不猜测条件，也不自动从视频补图。

默认不采用逐步提示、等待用户作答的辅导模式。完整题目先简短说明具体思路与理由，再连续给出完整解答；关键步骤解释理由，常规运算适当合并。用户可以连续追问某一步、某个小问或其他解法，需要时局部展开，不要求逐步点击“继续”。效率目标及待验证边界见第 0.3 节。

同次打开软件、同一课程内沿用当前对话，不强制按题拆分。打开软件、切换课程或用户主动点击“新对话”时，默认开始无旧聊天上下文的新对话；提供历史对话选择，选中后可接续。收起再展开右栏、进出全屏、同课程内切换资料均不触发新对话。切换课程时，上一课程尚在生成的回答继续在后台完成，归属原对话。界面保存完整聊天历史；发送给 AI 的上下文允许自动精简，保留当前问题的关键图片、条件和必要推导，较早内容按需摘要或取回。基础聊天交互沿用 DeepSeek Harness 的设计，具体接入能力仍需验证，不重新逐项询问已由该基线覆盖的通用操作。

### 4.3 自动检索

采用“用户已选取或提交的引用由程序解析来源位置，其余主回答模型按需请求检索”的方式，不默认逐题增加独立 AI 分类调用。绝大多数问题直接使用用户上下文；只有存在可由相关来源补足的信息缺口时才检索，不包含已取消的自动找题。典型情况包括：

- 用户要求按老师、讲义或课件中的方法解释，但现有上下文没有相应讲解。
- 需要取得指定来源中的定义、定理或推导依据，现有上下文尚未包含。
- 用户明确要求结合课程资料重新讲解，需取得相应原文。

题难、推导冲突、用户指出答案有误或模型自报低信心，不单独构成检索条件；先检查已有输入和推理。具体触发可靠性与预算仍需测试。默认范围是当前课程，跨课程须由用户明确指定；联网仅用于明确的外部信息需求，课程检索未命中不自动转为联网。

查找显示简短状态，回答附来源，详细过程按需展开。正常检索自动完成；单次未命中允许在授权范围内有限调整，真正失败或缺少必要信息时才提示，用户可随时停止。首版学习工具只读，软件正常保存聊天和截图等业务操作由项目负责。具体共识见第 0.2 节。

知识库检索与计算校验是不同能力：自动检索不代表每道题都会执行额外的计算验证或第二轮模型复核。

### 4.4 对话内容与公式的再引用需求（2026-10-20）

用户需要在阅读 AI 回答时，方便地选取有疑问的公式、文字或推导部分，加入当前提问，减少手动重述、跨应用截图及反复裁剪。移动端渲染后的 LaTeX 内容是重点交互对象，不能只验证普通文字复制或整条消息复制。

议题 7 已确认 Windows 支持公式中某个符号或局部子式的精确选取并加入输入框，同时提供整条公式、整步推导的快捷引用。具体控件、选择效果及下列其余设计建议仍待细化和验证：

- 已有文字和公式可直接引用，保留原始表达及对应消息位置，避免让用户手打 LaTeX 或依赖模型重新识别应用已有的公式。

### 6.2 本地转写流程

无可用字幕的视频，采用以下处理方式：

1. 在本机提取音频，进行 GPU 语音识别。
2. 按语音停顿等边界分段，保留必要的相邻上下文。
3. 一段转写完成后，即可用于字幕显示和检索。
4. 当用户提问依赖某段字幕时，优先处理该片段；尚未就绪与已处理但未命中分别记录。

2026-10-20 已确认取消字幕 AI 错字纠正／校准，不再安排后台模型纠错或等待校准后才回答。

无需等待整节视频处理完，才能播放、截图和提问。题目图片本身已经足够时，不等待无关字幕任务。

### 6.3 字幕使用与手动修改

- 保留原始转写、时间戳及用户手动修改记录，便于回查。
- 不逐句标记存疑内容，不要求用户逐段审核。
- 支持手动修改字幕；修改后更新相关检索内容。
- 设计上应避免后台结果覆盖用户手动修改。

字幕转写可能有术语或数学符号错误，不能静默推翻用户已提交题图中的明确条件。发生关键冲突时说明差异并请求确认；需要图像仍由用户提交，不自动补取视频画面。

### 6.4 等待时间与后台任务

- 导入课程后，对缺少可用字幕的视频自动安排整课本地转写，当前观看的视频优先，其余后台排队；支持按课程或视频暂停。
- 暂停批量转写后，当前问题需要时仍可自动临时处理必要的小段字幕；处理完后批量队列保持暂停，用户可停止当前处理。
- 当前播放位置和当前提问所需片段优先处理。
- 用户跳到尚未转写的位置时，优先处理目标片段，再继续其他任务。
- 已处理内容持久化保存，再次打开不重复转写整节视频。
- 字幕修正后只更新受影响的片段及索引。
- 界面显示整体处理进度，不逐句增加审核提示。
- 后台转写正常完成只更新进度，不弹窗、不发声音；需要用户介入的问题才主动提醒。完整结论见第 0.9 节。
- 检索尚未覆盖整节视频时，应区分「未处理到」与「没有找到」。
- 关闭学习网页后，后台任务继续处理，提供暂停和退出后台入口。
- 持久化处理进度，电脑重启或后台再次启动后支持恢复；默认手动启动，可主动开启开机启动。退出确认、有限自动恢复、局部故障与睡眠规则见议题 14 收口记录，具体效果待验证。

优化目标是减少当前学习操作的等待，不预先承诺整课转写时间或单次回答时延。

- 该需求与数学公式引用共同服务于“在当前内容上选取后直接操作”，不要求用户先转录、切换应用或截图裁剪。
- 英语功能在视频截图问答可用后加入，不进入第一版。PDF 具体支持范围仍待验证，素材库先不设计；目前没有英语 PDF 验收文件或已实现能力。

### 11.2 2026-10-20阅读理解交互历史（冲突部分以后续决定为准）

2026-10-20 用户提出整体阅读片段，并明确采纳上一轮其余阅读理解交互意见。已确认如下：

- 将完整文章及其配套题目作为一个阅读片段展示，支持跨页；用户点击“加入 AI”即可将该片段整体作为可检查的引用加入现有提问草稿。加入与发送分开，用户补充疑问后发送。
- 输入区清楚显示当前文章、来源页码及关联题目，允许预览、调整范围或移除。用户可以逐题提问，也可明确要求讲解全部题目，选中整篇材料不自动触发全部题目的回答。
- 用户可以简短询问某题为什么选某项、错误选项的问题或答案的原文依据。在已加入的阅读片段内对应题干与选项，不能凭题号猜题；片段不含所问题目或无法确定时，请用户补充选取，不跨资料自动找题。
- 回答围绕用户所问给出结论、原文依据与推理，并解释用户关心的选项区别；引用原文可回到 PDF 对应位置，便于中间阅读区和右侧聊天区对照。
- 同篇文章继续追问其他题目时复用已关联原文，并定位新的题干与选项，减少重复选择。输入区有简洁的当前材料提示，普通翻页不自动改变正在讨论的材料。
- 加入另一篇文章后更新后续提问的材料范围，已有聊天和旧回答关联的来源保留；不强制为每篇文章新建对话。
- 上下文以当前阅读理解的需要为准，支持完整的所选文章及配套题目，不自动扩大到整份 PDF 的其他文章或无关页面。材料尚未解析时，仍可通过用户选取的文字或图片提问。
- 划词翻译保留在阅读区，查看后可继续原位置阅读；不提供翻译中的“继续问 AI”功能。

### 11.3 尚待细化与验证

- 阅读片段自动识别、手动补建及一键加入AI的专用功能已于2026-10-23取消，不再安排该专用切分方案验证；自然语言任务继续遵守现有来源、范围和用户提交契约。
- 翻译入口和浮层的具体组织。现有建议为：选词选句后显示就近的翻译入口，单词优先解释本句中的含义、句子提供完整译文；仅选中不触发模型调用，点击翻译才请求翻译。
- 英语已确定在视频截图问答可用后加入；素材库按用户要求先不设计，不在本节继续展开。

可选中文字的 PDF 与扫描图片 PDF 需分开验收。扫描件的文字识别、选区与原页对齐方案仍待验证，不能将普通文字 PDF 的选择结果当作扫描件支持证明。当前只记录需求和建议，不进行应用实现或模型测试。
