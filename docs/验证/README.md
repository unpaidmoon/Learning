## 4. 统一观测和判定

1. 每次运行固定源码/制品hash、依赖版本、profile/工具/系统内容摘要、模型与思考、输出/调用预算、输入版本。模型别名不视为冻结云端权重。
2. 观察真实出站边界与工具body执行，不能仅用脚本预设“requests=0”充当网络计数；计数点失效即停真实派发。
3. 时间至少区分截图→草稿、发送→首增量、发送→首段有用内容、发送→完整回答、读完→恢复播放、完整学习流程及返工。首字/状态/题目复述不算有用解题内容，后来推翻的内容不算成功。
4. 用量区分原始provider可得字段、Harness对象、字段存在性和归一化投影；缺失为未知、累计不叠加，reasoning不重复加。失败/取消也算attempt，未结算不能补0。
5. 判定用 passed/failed/not_run/blocked_by_prerequisite/unknown；未执行不是通过，unknown不是未执行。安全拒绝的预期负例可passed；需要请求的信息缺失不算模型算错，但猜造条件算失败。
6. 单例关键错误即记该例失败。同类失败修复后复测原例和至少一个不同同类案例；原始失败不删除，不用只换容易样本宣称解决。
7. 生成取消必须有活动执行及取消/终态证据；关闭观察流、停止浏览器接收和杀宿主不能代替。取消后仍检查同对话可追问。
8. 严重权限越界、资产丢失/错归属、未知二次派发立即停止该组并保留证据。网络或来源不可用记录缺口，不推断方案不可行。
9. 清理前先保存证据和状态，只结束本次拥有的进程，验证端口/临时句柄释放；不批量杀Python/Node/Harness。禁止递归清理用户课程/资产目录。
