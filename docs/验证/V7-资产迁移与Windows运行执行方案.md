## 1. 假设与阶段拆分

资产部分验证一致导出/空目标导入、离线聊天公式截图、数据目录整体迁移；运行部分验证无开发环境双击、所属进程/组件隔离、有限恢复、睡眠和已确认设置。共享同一资产层与进程/对账基础，判定分别报告，不相互冒充。

受控视频试用只需安全启动/保存/退出及必要后台行为；建议日常独立试用尽早有统一入口。完整首版无需终端/开发环境双击与完整运行管理是已确认硬要求，不能自动前置为所有受控试用门槛。

## 2. 前置与测试资产

- 对应功能已经实现且有实施/故障验证授权；没有安装包不做静态“按钮存在”验收。
- 使用独立合成业务数据，单独空目标/已有数据目标/损坏包和迁移目录，冻结允许写入/故障路径；不对用户现用库做破坏性注入。
- 干净Windows普通用户/虚拟机或等价隔离环境获授权；记录系统版本/架构、运行库、浏览器、是否有开发工具/全局DLL。不得用开发机已有PATH掩盖缺依赖。
- 睡眠/重启/断电模拟/开机项和保持唤醒操作的范围明确；可能影响当前工作的系统级动作须有授权且先保存，不擅自改用户现用电源/注册表设置。
- 构建/签名/打包工具及各运行时/原生库来源、hash、许可和分发条件完整；本方案不预定PyInstaller必选。

合成数据至少：两课程与共享资料关联、归档课程、顺序明确的聊天、多张确认图、长/多行公式、部分回答/unknown生成、字幕原始及手改、播放/阅读位置、旧/新来源版本、任务/偏好。原件包含与不包含各一套清单；凭据/内部Peer和运行home不是用户业务导出内容。

## 6. 观测、通过与失败处理

记录每组初始/最终清单与hash、修订/消息/附件数量、导入与迁移边界、原位置可恢复性、独立离线资源访问、包体积/运行库/进程树/端口、设置与实际动作、恢复次数及unknown生成状态。

A/B通过依据：合成业务资产全部按范围一致，坏包/已有目标不自动覆盖，离线无需软件可看，跨盘失败可恢复且无用户原件改动。C通过依据：干净环境真实制品与默认行为通过，局部故障不拖垮其他能力，退出/睡眠/重启不丢已保存资产或触发未知重发。

资产丢失/错归属、目标自动覆盖、解包逃逸/越权、未知二次模型派发、误杀其他进程即失败并停止相关组。环境缺少条件记未覆盖；开发机启动成功不能填干净环境通过。修复后复测原故障和正常路径，保留原记录。

交付A/B/C分组报告、实际支持环境/依赖闭包/许可、恢复与未覆盖清单；不能只写“打包通过”覆盖所有功能。D-07汇总完整首版时，还需V3/V4/V5/V6与知识库实际任务证据。
